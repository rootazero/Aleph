## Detailed Findings

### Finding 1: Dead Abstraction — `create_tool_boxed` with ~350 Lines of Redundant Constructor Duplication
- **File & Line**: `src/executor/builtin_registry/definitions.rs:907-1264`
- **Severity**: P1
- **Invariant / Rule violated**: Occam's Razor Rule 1 & Decision Hierarchy 1 (Remove dead abstractions and accidental complexity)
- **Concrete Finding**: `create_tool_boxed()` is a 357-line function with ~80 match arms providing an ad-hoc, standalone factory for boxed tools. The file's own documentation (lines 12-14) admits: `"create_tool_boxed() is a name->tool table kept for ad-hoc, direct construction; it currently has no production caller, so it does not have to be kept in step with the constructor."` The production runtime constructs tools through `BuiltinToolRegistry::with_config()`. Only 54 tools return `Some(...)`, 26 explicitly return `None`, and ~100 tools fall through to `_ => None`. The sole caller in the entire workspace is a test (`slash_command.rs:895`) that uses it to inspect required schema fields.
- **Proposed Occam Simplification**: Demote or remove `create_tool_boxed`. For tests requiring parameter schemas of statically declared tools, query the schema from static definitions or `BuiltinToolRegistry` rather than maintaining a parallel, out-of-sync 350-line tool constructor. If public backward compatibility must temporarily be preserved, simplify `create_tool_boxed` to delegate to a minimal shared constructor helper or mark as deprecated.

### Finding 2: Fragile Coupling of Static Census to Production Log Statements (`info!("Registered schema for ...")`)
- **File & Line**: `src/executor/builtin_registry/dispatchable.rs:132-154, 191-200`
- **Severity**: P1
- **Invariant / Rule violated**: Occam's Razor Rule 1 & Decision Hierarchy 2 (Remove accidental complexity and brittle indirections)
- **Concrete Finding**: The source census in `dispatchable.rs::advertised_tools` discovers conditionally registered tools by scanning Rust source code for log lines matching `info!("Registered schema for X")` or `info!("Registered schemas for X, Y, Z")`. It splits strings around `" for "` and commas, and asserts that the discovered count is within a magic arbitrary range (`1 <= constructor_count <= 32`). This couples test verification to the exact phrasing of developer-facing log messages in `builder/constructor/mod.rs`. Any change to logging format (such as structured tracing `info!(tool = ...)` or rewording) silently breaks the test suite.
- **Proposed Occam Simplification**: Eliminate source-level regex/substring parsing of log messages. Conditional tools should either be declared in a static table of conditional tool names (analogous to `REGISTRY_ONLY_TOOL_NAMES`) or verified via runtime introspection on `BuiltinToolRegistry::with_config()` with enabled feature flags.

### Finding 3: Duplicated Inventory of Non-Catalog Builtins (`REGISTRY_ONLY_TOOL_NAMES` vs `REGISTRY_ONLY_DESCRIPTIONS`)
- **File & Line**: `src/executor/mod.rs:51-72` & `src/executor/builtin_registry/definitions.rs:1300-1372`
- **Severity**: P2
- **Invariant / Rule violated**: Engineering Criteria Shape 1 (同一事实的两份表述 / Two representations of the same fact)
- **Concrete Finding**: `REGISTRY_ONLY_TOOL_NAMES` in `src/executor/mod.rs` defines a static slice of 20 tool names registered outside the catalog. In `definitions.rs`, `REGISTRY_ONLY_DESCRIPTIONS` defines a list of 19 tool names paired with their `DESCRIPTION` constants, gated behind `#[cfg(test)]`. Because `REGISTRY_ONLY_DESCRIPTIONS` is test-only, `REGISTRY_ONLY_TOOL_NAMES` was created as an almost identical duplication of the same list to support `is_builtin_tool_name`. Furthermore, `capability_projection_diagnostics` exists in `REGISTRY_ONLY_TOOL_NAMES` but is omitted from `REGISTRY_ONLY_DESCRIPTIONS`, creating semantic drift between the two lists.
- **Proposed Occam Simplification**: Define a single production list of non-catalog registry tools (with their metadata or descriptions where accessible) and derive both `REGISTRY_ONLY_TOOL_NAMES` and the test byte-ratchet tables from that single source of truth.

### Finding 4: Type Safety Bypassed: Catalog Writes String Literals Instead of `<Tool as AlephTool>::NAME`
- **File & Line**: `src/executor/builtin_registry/definitions.rs:86-902` & `src/executor/builtin_registry/dispatchable.rs:93-99`
- **Severity**: P2
- **Invariant / Rule violated**: Decision Hierarchy 2 & 4 (Type safety sacrificed for text-scanner compatibility)
- **Concrete Finding**: Every entry in `BUILTIN_TOOL_DEFINITIONS` writes its description via the typed trait constant `<Tool as AlephTool>::DESCRIPTION`, but hardcodes its name as a raw string literal `name: "..."` (178 times) instead of `<Tool as AlephTool>::NAME`. This is because `dispatchable.rs` line 95 uses a primitive text scanner that strictly expects `name: "` followed by a double quote (`quoted_after`). As a result, the compiler cannot enforce that the catalog name matches the tool's actual `NAME` constant, allowing silent naming drift.
- **Proposed Occam Simplification**: Upgrade `quoted_after` or AST parsing in `dispatchable.rs` to accept `<Tool as AlephTool>::NAME` or `Tool::NAME`, and update `BUILTIN_TOOL_DEFINITIONS` to reference `AlephTool::NAME`, eliminating 178 redundant string literals and preventing name drift.

### Finding 5: Hand-Rolled Brace Parsing and String Token Matching Duplicating Runtime Verification
- **File & Line**: `src/executor/builtin_registry/dispatchable.rs:608-629, 648-713`
- **Severity**: P2
- **Invariant / Rule violated**: Occam's Razor Rule 1 & Decision Hierarchy 2 (Accidental complexity in test verification)
- **Concrete Finding**: Tests `disabled_diagnostics_registration_is_guarded_by_constructor_optional` and `disabled_diagnostics_dispatch_arm_is_gated_by_diagnostics_control_some` implement a 65-line manual brace parser (`find_matching_close`) to slice source files and assert the presence of specific code tokens like `"self.diagnostics_control"`, `"ok_or_else"`, and `"no DiagnosticControl configured"` in `tool_registry_impl.rs`. This brittle text scanning duplicates the behavior already thoroughly proven by `mod.rs:362-445` (`diagnostics_gate_runtime_tests`), which executes real runtime calls with `diagnostics_control: None` and `Some` and asserts proper fail-closed refusal.
- **Proposed Occam Simplification**: Rely on the comprehensive runtime integration tests in `mod.rs` rather than maintaining a fragile, hand-rolled brace parser that inspects token substrings in production Rust files.

### Finding 6: Redundant O(N*M) Test `test_all_builtin_tools_have_a_group` Subsumed by `every_accounted_tool_appears_in_some_group`
- **File & Line**: `src/executor/builtin_registry/groups.rs:333-347, 410-435`
- **Severity**: P2
- **Invariant / Rule violated**: Decision Hierarchy 5 (Consolidate genuine duplication) & Rule 1
- **Concrete Finding**: `test_all_builtin_tools_have_a_group` (lines 333-347) collects all group tools into a `Vec<&str>` and runs an O(N*M) linear search for each tool in `BUILTIN_TOOL_DEFINITIONS`. 60 lines later, `every_accounted_tool_appears_in_some_group` (lines 410-435) builds a `HashSet<&str>` and checks both `BUILTIN_TOOL_DEFINITIONS` AND `REGISTRY_ONLY_DESCRIPTIONS`, collecting all orphans in a single assertion. The former test is a strict, slower subset of the latter.
- **Proposed Occam Simplification**: Delete `test_all_builtin_tools_have_a_group`. The broader `every_accounted_tool_appears_in_some_group` already provides 100% of its test coverage with better performance and more informative diagnostics.

### Finding 7: Mixed Sync/Async Lock Primitives in `BuiltinToolConfig`
- **File & Line**: `src/executor/builtin_registry/config.rs:3, 26, 28`
- **Severity**: P2
- **Invariant / Rule violated**: Decision Hierarchy 2 & Concurrency Invariant Consistency
- **Concrete Finding**: `BuiltinToolConfig` mixes two conflicting `RwLock` primitives in the same struct: `generation_registry` uses `crate::sync_primitives::RwLock` (synchronous `parking_lot::RwLock`), while `config` uses `tokio::sync::RwLock` (asynchronous tokio lock). Mixing sync and async locking mechanisms in the same configuration struct causes cognitive overhead and lock-ordering pitfalls. In addition, ~40 struct fields use full crate paths (`crate::...`) instead of imports at the top of the file, despite 6 types being arbitrarily imported at lines 5-10.
- **Proposed Occam Simplification**: Normalize import hygiene: import shared types at the module root and standardize lock primitives or clearly alias them (e.g. `AsyncRwLock`) to make sync vs async lock boundaries explicit.

### Finding 8: Gratuitous Heap Allocations (35+ `String` Allocations) in Catalog Tests
- **File & Line**: `src/executor/builtin_registry/definitions.rs:4220-4275`
- **Severity**: P2
- **Invariant / Rule violated**: Decision Hierarchy 3 (Eliminate unnecessary allocations, clones, conversions)
- **Concrete Finding**: In `test_all_tools_defined` (lines 4220-4264) and `test_sessions_tools_defined` (lines 4265-4275), the tests collect `BUILTIN_TOOL_DEFINITIONS` into a `Vec<String>` via `d.name.to_string()`, and then execute 35 individual `assert!(names.contains(&"foo".to_string()))` checks. This creates 35+ redundant heap string allocations and 35 linear scans over a heap vector just to check static `&str` presence.
- **Proposed Occam Simplification**: Use `BUILTIN_TOOL_DEFINITIONS.iter().any(|d| d.name == "foo")` or a static set, avoiding all heap allocations and vector clones.

### Finding 9: `capability_projection_diagnostics` Omitted from UI `TOOL_CATEGORIES`
- **File & Line**: `src/executor/builtin_registry/groups.rs:20-326` & `src/executor/mod.rs:51-72`
- **Severity**: P2
- **Invariant / Rule violated**: Engineering Criteria Shape 3 (守卫的绿只覆盖它认得的那种形状) & Shape 7 (两端完整而中间没线)
- **Concrete Finding**: `capability_projection_diagnostics` is included in `REGISTRY_ONLY_TOOL_NAMES` in `mod.rs:55`, meaning `is_builtin_tool_name` recognizes it. However, it is missing from `TOOL_CATEGORIES` in `groups.rs`. It escapes the `every_accounted_tool_appears_in_some_group` test because that test reads `REGISTRY_ONLY_DESCRIPTIONS` (which omits it). As a result, when diagnostics are enabled, the Panel UI receives no category assignment for this tool.
- **Proposed Occam Simplification**: Add `capability_projection_diagnostics` to the appropriate category in `groups.rs` (e.g., `system_config`), and ensure `every_accounted_tool_appears_in_some_group` reads `REGISTRY_ONLY_TOOL_NAMES` rather than the partial `REGISTRY_ONLY_DESCRIPTIONS`.

### Finding 10: `is_builtin_tool_name` Linear Scan and Double-Indirection
- **File & Line**: `src/executor/mod.rs:81-86`
- **Severity**: P3
- **Invariant / Rule violated**: Decision Hierarchy 3 (Unnecessary linear search and double-indirection)
- **Concrete Finding**: `is_builtin_tool_name` runs an unindexed linear scan through `BUILTIN_TOOL_DEFINITIONS` (~178 items) followed by `REGISTRY_ONLY_TOOL_NAMES.contains(&name)` (20 items) and `TOOLS_OUTSIDE_DEFINITIONS.contains(&name)` (2 items). Since `name` is `&str`, `&name` is `&&str`, which is passed to `.contains()` across `&[&str]`. While fine for infrequent calls, `is_builtin_tool_name` is called during every skill registration and hook resolution.
- **Proposed Occam Simplification**: Since `REGISTRY_ONLY_TOOL_NAMES` is alphabetically sorted, use `binary_search` for fast lookup or construct a `phf::Set` / lazy lookup set if called on hot paths, and clean up the slice `contains` call to avoid double-referencing.

### Finding 11: `execute_plugin_tool_with_authority` Allocates an Async State Machine for a Static Error
- **File & Line**: `src/executor/tool_registry.rs:35-46`
- **Severity**: P3
- **Invariant / Rule violated**: Decision Hierarchy 2 & 3 (Unnecessary async state machine allocation)
- **Concrete Finding**: The default trait method `execute_plugin_tool_with_authority` allocates a boxed future (`Box::pin(async { Err(...) })`) solely to return a static error. This generates unnecessary async state machine scaffolding and heap pinning for a rejected path.

### Finding 12: Fragmented Handle Accessors on `ToolRegistry` with Fully-Qualified Type Noise
- **File & Line**: `src/executor/tool_registry.rs:48-92`
