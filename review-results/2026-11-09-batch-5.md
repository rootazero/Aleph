# Review Findings - Batch 5: src/executor Registry Impl & src/export

## Executive Summary
This static review covers 12 files across the builtin tool registry implementation (`src/executor/builtin_registry/registry/`) and self-contained document export (`src/export/`).
A total of **18 findings** were identified:
- **P1 (Critical Performance / Resource Churn)**: 1 finding (multi-megabyte redundant Base64 re-escaping in document export)
- **P2 (Design Debt / Accidental Complexity / Inefficient Dispatch)**: 8 findings (gratuitous `GatewayContext` deep cloning, 50-line delivery route duplication, dead struct fields, document size accounting mismatch against artifact store, single-pass escaping, link sanitizer eager allocations, collector/page accounting drift, multi-buffer document copy chain)
- **P3 (Hygiene / Minor Allocations / Boilerplate)**: 9 findings (unused imports masked by `#![allow(unused_imports)]`, static CSP runtime escaping, eager attribute computation, repetitive session injection boilerplate, `role_slug` allocation, trait impl file bloat with 800 lines of tests)

## Findings

### Finding 1
- **File & Line:** `src/export/page.rs:116`, `136`
- **Severity:** P1
- **Invariant / Rule violated:** Occam Decision Hierarchy (3): Redundant allocations, string copies, and multiple passes over multi-megabyte Base64 payloads.
- **Concrete Finding:** In `render_artifacts`:
  ```rust
  let encoded = BASE64.encode(bytes);
  ...
  data = escape_attr(&encoded),
  ```
  Artifact payloads inlined in the export document can be up to 4 MB per artifact (`MAX_INLINE_ARTIFACT_BYTES`) and up to 24 MB across all artifacts in a single document (`MAX_INLINE_TOTAL_BYTES`). Standard Base64 uses solely `[A-Za-z0-9+/=]`, which is provably free of any HTML markup characters (`<`, `>`, `&`) or attribute delimiter quotes (`"`, `'`).
  Despite this invariant, `escape_attr` is called on `&encoded`. `escape_attr` runs `escape_markup` (allocating a ~5.3 MB string for a 4 MB artifact) and two successive `.replace()` calls (allocating two additional 5.3 MB strings). For a single 4 MB artifact, `escape_attr` performs three redundant string allocations (~16 MB total) and three redundant memory scans. Under a full 24 MB inlined document budget, this causes ~100 MB of heap churn on a single export request.
- **Proposed Occam Simplification:** In `render_artifacts`, omit `escape_attr` on `&encoded` and interpolate `&encoded` directly into the `data:` URI attribute (`data = &encoded`). Base64 characters cannot cause attribute breakout.

### Finding 2
- **File & Line:** `src/executor/builtin_registry/registry/tool_registry_impl.rs:328-382`
- **Severity:** P2
- **Invariant / Rule violated:** Occam Decision Hierarchy (2): Accidental complexity & duplicated logic (Engineering Shape 1: "同一事实的两份表述").
- **Concrete Finding:** The `"loop_graph"` dispatch arm duplicates the entire 50-line delivery route injection implementation inline (reading `TurnContext`, fallback to `session_context_handle`, lock contention warning, filtering out empty channel strings, and stamping `__channel` and `__conversation_id`), rather than delegating to `self.inject_delivery_route(&mut args)` as `"cron_manage"` (line 817) and `"heartbeat_create"` (line 843) do.
- **Proposed Occam Simplification:** Replace the duplicated block (lines 328-382) with:
  ```rust
  let mut arguments = arguments;
  self.inject_delivery_route(&mut arguments);
  Box::pin(async move { self.loop_graph_tool.call_json(arguments).await })
  ```
  Eliminates ~50 lines of duplicate code and ensures delivery route semantics evolve in one place.

### Finding 3
- **File & Line:** `src/executor/builtin_registry/registry/tool_registry_impl.rs:598`, `1083-1084`
- **Severity:** P2
- **Invariant / Rule violated:** Occam Decision Hierarchy (3): Gratuitous deep clones of heavy context structures on per-call dispatch.
- **Concrete Finding:** In `"session_send"`, line 598 executes:
  ```rust
  let tool = SessionsSendTool::with_context((**context).clone(), caller_id);
  ```
  And in `"team_delegate"`, lines 1083-1084 execute:
  ```rust
  let mut delegate = tool.clone();
  delegate.set_context((**context).clone());
  ```
  In both dispatch arms, `(**context).clone()` performs an expensive deep copy of the entire `GatewayContext` struct by value on every invocation. `GatewayContext` carries numerous channel registries, store handles, and configuration references. In contrast, sibling tools such as `SessionsListTool` and `SessionSearchTool` take `Arc<GatewayContext>` with zero deep cloning.
- **Proposed Occam Simplification:** Change `SessionsSendTool` and `TeamDelegateTool` to accept `Arc<GatewayContext>` (or `Option<Arc<GatewayContext>>`), passing `Arc::clone(context)` instead of deep-cloning `(**context).clone()`.

### Finding 5
- **File & Line:** `src/export/mod.rs:86-93`
- **Severity:** P2
- **Invariant / Rule violated:** Occam Decision Hierarchy (4): Document size accounting & store limit mismatch.
- **Concrete Finding:** `exported_document_bytes(transcript_bytes, artifacts)` projects the document size as `transcript_bytes.saturating_add(inlined)`. In `artifact_publish.rs`, this projection is tested against `MAX_EXPORTED_DOCUMENT_BYTES` (`MAX_ARTIFACT_BYTES`) to reject oversized deliverables before rendering. However, the calculation omits the static HTML document shell and CSS (`export.css` alone is 7,799 bytes, plus DOCTYPE, `<head>`, metadata, and tag overhead). If a document's markdown and attachments are within ~8 KB of the ceiling, `exported_document_bytes` projects compliance, but `store.put()` subsequently rejects the rendered HTML at the store boundary after the renderer spends CPU building and encoding the document.
- **Proposed Occam Simplification:** Incorporate the constant shell and styling overhead (e.g. `const EXPORT_SHELL_OVERHEAD_BYTES: u64 = 8 * 1024 + 1024;`) in `exported_document_bytes`, ensuring pre-check projection matches what `store.put` actually receives.

### Finding 6
- **File & Line:** `src/export/collect.rs:37-45`
- **Severity:** P2
- **Invariant / Rule violated:** Occam Decision Hierarchy (4): Inconsistent budget accounting between collector and renderer.
- **Concrete Finding:** In `collect_artifacts`:
  ```rust
  let encoded = base64_encoded_len(record.size);
  ...
  inlined_total = inlined_total.saturating_add(encoded);
  ```
  `collect.rs` updates `inlined_total` using the metadata `record.size`. Later, in `page.rs` line 96, `render_artifacts` independently computes:
  ```rust
  let encoded = base64_encoded_len(bytes.len() as u64);
  ```
  If `record.size` differs from actual `bytes.len()` (e.g., due to updated metadata, stale store indexing, or partial read), the collector and renderer compute different running totals. This can cause the collector to read a multi-megabyte payload into memory only for `page.rs` to reject it from inlining, or vice-versa.
- **Proposed Occam Simplification:** In `collect.rs`, update `inlined_total` with `base64_encoded_len(bytes.len() as u64)` after the store read succeeds, keeping budget accounting strictly consistent with `page.rs`.

### Finding 7
- **File & Line:** `src/export/markdown.rs:63-67`
- **Severity:** P2
- **Invariant / Rule violated:** Occam Decision Hierarchy (3): Redundant allocations and triple string scanning in HTML escaping.
- **Concrete Finding:** `escape_attr` is implemented as:
  ```rust
  pub(super) fn escape_attr(s: &str) -> String {
      escape_markup(s)
          .replace('"', "&quot;")
          .replace('\'', "&#39;")
  }
  ```
  For every attribute escaped, this executes 3 separate heap allocations and 3 separate passes over the string (one in `escape_markup`, and two in `.replace`).
- **Proposed Occam Simplification:** Implement `escape_attr` in a single pass with a single pre-allocated `String` that escapes `&`, `<`, `>`, `"`, and `'` together in one loop, cutting 3 allocations down to 1.

### Finding 8
- **File & Line:** `src/export/markdown.rs:90-121`
- **Severity:** P2
- **Invariant / Rule violated:** Occam Decision Hierarchy (3): Eager string allocations in `sanitize_link_url`.
- **Concrete Finding:** `sanitize_link_url` immediately executes `let trimmed = url.trim().to_owned();`, allocating a `String` unconditionally. If `head_stripped.starts_with("//")`, `trimmed` is thrown away. Furthermore, for common URLs (`https://...`), it calls `percent_decode_scheme(raw_scheme)` which allocates a `String`, followed by `.to_lowercase()` which allocates a second `String`.
- **Proposed Occam Simplification:** Keep `trimmed = url.trim()` as `&str`. Check standard schemes (`raw_scheme.eq_ignore_ascii_case("https") || raw_scheme.eq_ignore_ascii_case("http") || raw_scheme.eq_ignore_ascii_case("mailto")`) directly without allocation or decoding; only decode and allocate for non-standard schemes or schemes containing `%`.

### Finding 9
- **File & Line:** `src/export/document.rs:38-49` & `src/export/session_html.rs:17-34`
- **Severity:** P2
- **Invariant / Rule violated:** Occam Decision Hierarchy (2) & (3): Multiple intermediate document buffer copies and reallocations.
- **Concrete Finding:** In `render_document_html` and `render_session_html`:
  - `render_page_head` allocates a `String`
  - `render_markdown` / `render_transcript` allocates a `String`
  - `render_artifacts` allocates a `String` (potentially up to 24 MB with inlined figures)
  - `body` allocates and appends all of them
  - `wrap_document` uses `format!` to allocate yet another full document `String`, copying `body` and `EXPORT_CSS`
  When an export contains inlined figures near the 24 MB limit, the payload is copied and reallocated multiple times across intermediate buffers.
- **Proposed Occam Simplification:** Use an output sink (`&mut String` or `std::fmt::Write`) to write the document header, body, artifacts, and closing tags directly into a single pre-sized buffer (`wrap_document_into`), eliminating multi-megabyte intermediate string allocations.

### Finding 10
- **File & Line:** `src/export/page.rs:40-58`
- **Severity:** P3
- **Invariant / Rule violated:** Occam Decision Hierarchy (3): Redundant runtime escaping of compile-time static string.
- **Concrete Finding:** In `wrap_document`, line 53 runs `csp = escape_attr(CSP)` on every document rendered. `CSP` is a compile-time constant literal (`"default-src 'none'; img-src data:; style-src 'unsafe-inline'"`). Calling `escape_attr` at runtime invokes 3 allocations and replaces static quotes on every render.
- **Proposed Occam Simplification:** Pre-escape the constant at compile time:
  ```rust
  const CSP_ESCAPED: &str = "default-src &#39;none&#39;; img-src data:; style-src &#39;unsafe-inline&#39;";
  ```
  and interpolate `CSP_ESCAPED` directly without runtime escaping.

### Finding 11
- **File & Line:** `src/export/page.rs:88-89`, `163-165`
- **Severity:** P3
- **Invariant / Rule violated:** Occam Decision Hierarchy (3): Wasteful eager computation and unnecessary allocations in artifact rendering.
- **Concrete Finding:**
  1. `let name = escape_attr(&art.filename);` is computed for every artifact, but in the `None` branch (omitted artifacts, lines 142-156), `name` is never used.
  2. `human_size(art.size)` outputs only digits, decimal point, space, and units (`B`/`KB`/`MB`), yet line 89 runs `escape_text(&human_size(art.size))`, creating a redundant `String` allocation.
  3. `is_image` (line 164) executes `mime.to_ascii_lowercase().starts_with("image/")`, allocating a new lowercase `String` for every artifact in the list.
- **Proposed Occam Simplification:**
  1. Compute `escape_attr(&art.filename)` only within the `Some(bytes)` branch.
  2. Use `human_size(art.size)` directly without `escape_text`.
  3. Implement `is_image` without allocation: `mime.get(..6).map_or(false, |s| s.eq_ignore_ascii_case("image/"))`.
