### Finding 1: ACP Tools Fail-Closed Violation via Silent `{}` Fallback
- File & Line: `src/executor/builtin_registry/builder/constructor/agent_acp_tools.rs:221-240`
- Severity: P1
- Invariant / Rule violated: Fail-Closed Schema Generation (Engineering Criteria Shape 8: "fail-closed 的答案被当成值消费，就反转成许可") & `core_tools::tool_schema` invariant.
- Concrete Finding: When serializing schemas for `acp_delegate`, `acp_switch`, and `acp_session_control`, the code calls `serde_json::to_value(schema_for!(...)).unwrap_or_else(|e| serde_json::Value::Object(Default::default()))`. Falling back to `{}` (an empty JSON object) tells the model that the tool accepts any arbitrary arguments or no arguments, converting a serialization failure into an invalid permissive schema. This explicitly violates the fail-closed invariant established in `core_tools.rs:17-43` where serialization failures must reject all arguments (`"additionalProperties": false`).
- Proposed Occam Simplification: Replace the custom `serde_json::to_value(schema_for!(...))` and its `{}` fallback with the unified fail-closed helper `super::super::core_tools::tool_schema::<T>(name)` or directly use `tool.definition()` as done for `agent_create` and `a2a` tools.

### Finding 2: Retrieval Tools Fail-Closed Violation via Silent `{}` Fallback
- File & Line: `src/executor/builtin_registry/builder/constructor/collab_session_tools.rs:538-544, 559-565, 581-587`
- Severity: P1
- Invariant / Rule violated: Fail-Closed Schema Generation (Engineering Criteria Shape 8: "fail-closed 的答案被当成值消费，就反转成许可") & `core_tools::tool_schema` invariant.
- Concrete Finding: `recall_context`, `memory_trace`, and `note_graph_query` each manually invoke `serde_json::to_value(schemars::schema_for!(...))` and on error fall back to `serde_json::Value::Object(Default::default())` (`{}`). Just like Finding 1, if schema serialization fails, the tool is advertised with an empty schema `{}` rather than a rejecting fail-closed schema (`{"additionalProperties": false}`). This bypasses `core_tools::tool_schema`.
- Proposed Occam Simplification: Route all three schema generations through `super::super::core_tools::tool_schema::<T>(name)`.

### Finding 3: `register_optional_tools` Takes 9 Redundant `Option<Tool>` Parameters Solely to Call `.is_some()`
- File & Line: `src/executor/builtin_registry/builder/optional_tools.rs:18-42` and `src/executor/builtin_registry/builder/constructor/mod.rs:1120-1132`
- Severity: P2
- Invariant / Rule violated: Occam's Razor (accidental complexity & unnecessary indirection) & DRY / P1 Low Coupling.
- Concrete Finding: `register_optional_tools` takes 11 arguments, 9 of which are `&Option<RuntimeTool<...>>` or `&Option<...Tool>`. Inside the function, none of the inner tools are ever inspected, invoked, or queried; only `.is_some()` is checked. Furthermore, whether each of these 9 tools is `Some` is deterministically derived from fields in `config: &BuiltinToolConfig` (which is already passed as the 8th argument). This forces all callers (including tests and `definitions.rs`) to pass 10 `&None` arguments across the boundary and requires `#[allow(clippy::too_many_arguments)]`.
- Proposed Occam Simplification: Simplify `register_optional_tools(tools: &mut HashMap<String, UnifiedTool>, config: &BuiltinToolConfig)`. Derive the enablement conditions directly from `config` (`config.memory_runtime.is_some()`, `config.generation_registry.is_some()`, etc.). Eliminate all 9 dummy `&Option<...>` parameters.

### Finding 4: Dummy Tool Instantiation and Arc Cloning to Query Static Schemas
- File & Line: `src/executor/builtin_registry/builder/optional_tools.rs:351-417, 444-486`
- Severity: P2
- Invariant / Rule violated: Occam's Razor (unnecessary allocations, clones, and throwaway instances).
- Concrete Finding: To register schemas for `cron_manage`, `heartbeat_list`, `heartbeat_create`, `heartbeat_update`, `heartbeat_delete`, `heartbeat_toggle`, `heartbeat_report`, `session_new`, `session_compact`, `session_set_topic`, and `session_set_mode`, `register_optional_tools` creates dummy instances of each tool (cloning `Arc<SharedCronService>`, `Arc<SharedHeartbeatService>`, `Arc<SessionStore>`), calls `tool.definition()`, clones `def.parameters`, and drops the tool instances immediately. In `constructor/mod.rs`, the actual instances of these tools are constructed a second time.
- Proposed Occam Simplification: Register schemas using `super::core_tools::tool_schema::<ArgsType>(name)` directly, matching how `memory_search`, `vault_store`, and other tools register their schemas without creating throwaway tool structs or cloning service `Arc`s.

### Finding 5: `session_context_handle` Inappropriately Gated and Coupled Inside `agent_acp_tools.rs`
- File & Line: `src/executor/builtin_registry/builder/constructor/agent_acp_tools.rs:101-108, 198` and `src/executor/builtin_registry/builder/constructor/mod.rs:1143, 1388`
- Severity: P2
- Invariant / Rule violated: High Cohesion & Low Coupling (P1, P2) & Inconsistent tool gating.
- Concrete Finding: `session_context_handle` is the central session context handle for `BuiltinToolRegistry`, read by the execution engine and session resolution methods. However, its initialization was placed inside `build_agent_acp_a2a_tools` and gated behind `if let (Some(ar), Some(wm), Some(sm))`. If `agent_registry` or `workspace_manager` is missing, `session_context_handle` is set to `None`, disabling session context injection for the entire registry even though none of the agent tools consume `session_context_handle`.
- Proposed Occam Simplification: Move the creation of `session_context_handle = Some(agent_manage::new_session_context_handle())` (or unconditional initialization) into `constructor/mod.rs` alongside `gateway_context` and `clarification_manager_cell`. Remove it from the return tuple of `build_agent_acp_a2a_tools`.

### Finding 6: False Fallibility in `build_collab_session_tools`
- File & Line: `src/executor/builtin_registry/builder/constructor/collab_session_tools.rs:24-28, 600` and `src/executor/builtin_registry/builder/constructor/mod.rs:1205`
- Severity: P2
- Invariant / Rule violated: Occam's Razor (unnecessary error indirection & stale contracts).
- Concrete Finding: `build_collab_session_tools` has return type `crate::error::Result<( ... )>`, but never returns `Err` or uses `?`. The doc comment claims it fails when note directories cannot be built safely, but note directory handling was refactored to `config.memory_runtime`. The signature forces `constructor/mod.rs` to write `Self::build_collab_session_tools(...)?`, creating the false illusion of fallibility.
- Proposed Occam Simplification: Change the return type from `crate::error::Result<T>` to `T` and remove `?` at the call site. Update the doc comment to reflect current behavior.

### Finding 7: Fragile Giant Tuples (21 and 22 Elements) Returned by Submodule Builders
- File & Line: `src/executor/builtin_registry/builder/constructor/collab_session_tools.rs:28-54` and `src/executor/builtin_registry/builder/constructor/coord_team_tools.rs:26-49`
- Severity: P2
- Invariant / Rule violated: API Robustness / Type Safety (P6 Simplicity, Shape 19: positional width fragility).
- Concrete Finding: `build_collab_session_tools` returns a 21-element tuple and `build_coord_team_tools` returns a 22-element tuple of `Option<Tool>` values. These giant tuples must be destructured positionally in `constructor/mod.rs:1156` and `1183`. Any reordering or insertion of sibling tools of identical type (`Option<...Tool>`) easily causes silent positional mismatches that the compiler cannot detect.
- Proposed Occam Simplification: Introduce lightweight internal structs (`CollabSessionTools` and `CoordTeamTools`) with named fields instead of anonymous 21- and 22-tuple returns.

- Concrete Finding: The exact 12-line boilerplate:

### Finding 12: Consecutive Duplicate Lock Acquisitions on `config.config`
- File & Line: `src/executor/builtin_registry/builder/constructor/mod.rs:416-428`
- Severity: P3
- Invariant / Rule violated: Lock Acquisition Efficiency / Minimal Knowledge.
- Concrete Finding: In `constructor/mod.rs`, lines 416-428 acquire `cfg.read().await` twice back-to-back: once to read `desktop.allow_global_pointer` and immediately again to check `get_effective_tools_config().is_clipboard_enabled()`.

- Invariant / Rule violated: Test Validity (Engineering Criteria Shape 2: "恒真的谓词等于没判" / Shape 4: "守卫要断言'效果到达了'").

### Finding 14: Over 30 Redundant Allocations of `current_agent_id`
- File & Line: `src/executor/builtin_registry/builder/constructor/collab_session_tools.rs:58-73, 145-155, 197-215, 263-273, 309, 333-359, 471, 513` and `coord_team_tools.rs:57, 77, 164-203, 267, 299, 327, 382, 470, 498`
- Severity: P3
- Invariant / Rule violated: Occam's Razor (redundant allocations & cloning).
- Concrete Finding: `current_agent_id` is a fallback string (`"main"`) passed into sub-builders as `boot_fallback_agent_id: &str`. In both `collab_session_tools.rs` and `coord_team_tools.rs`, it is converted to `String` and then cloned 15+ times across different tool construction blocks, even in blocks where the constructor only needed a borrowed string or where it is shadowed repeatedly.
- Proposed Occam Simplification: Pass `boot_fallback_agent_id: &str` directly to the tools or clone once only when moving ownership into tool structs.
