## High-Confidence Issues

### [High] `shared/logging/src/pii_filter.rs` — `StringVisitor` drops integer, boolean, and error fields

- **Location**: `shared/logging/src/pii_filter.rs:134-170` (`impl Visit for StringVisitor`).
- **Description**: The custom `FormatEvent` implementation collects event fields into a single string before PII scrubbing. It only implements `record_str` and `record_debug`. The `tracing::field::Visit` trait provides default no-op implementations for `record_i64`, `record_u64`, `record_bool`, and `record_error`, so any log field of those types is silently discarded from the formatted output.
- **Impact**: Legitimate error context is stripped from logs. Examples:
  - `tracing::info!(user_id = 42, error = e)` loses both fields.
  - `tracing::warn!(retry_count = 3, ready = false)` loses both fields.
- **Trigger**: Any structured log field that is not a string or a `Debug` value.
- **Fix applied**: Added `record_i64`, `record_u64`, `record_bool`, and `record_error` implementations that delegate to the existing `record_debug` path, so numeric/bool/error fields are rendered with the same key-name routing and scrubbed.
- **Suggested test**: Add a unit test that emits a tracing event with `i64`, `u64`, `bool`, and `std::io::Error` fields through `PiiScrubbingFormat` and asserts the formatted line contains the keys and values.

### [High] `shared/logging/src/pii.rs` — `generic_secret` regex only redacts the first token of multi-word quoted values

- **Location**: `shared/logging/src/pii.rs:28-52` (`PiiPatterns::generic_secret`) and `scrub_pii`.
- **Description**: The original regex `(?i)(...)(\s*[:=]\s*)("?)([^\s",}]+)` captured an optional leading quote in group 3 and the value (which stops at whitespace) in group 4. For a quoted multi-word secret such as `password = "my secret phrase"`, the value group matched only `my`; the replacement `${1}${2}${3}[REDACTED]` kept the quote and redacted one word, leaving ` secret phrase"` in the log.
- **Impact**: PII bypass for quoted credentials, passphrases, and API keys that contain spaces.
- **Trigger**: Any log line containing a credential-like key followed by a quoted value with spaces.
- **Fix applied**: Changed the value arm to match a complete double- or single-quoted string (`"(?:[^"\\]|\\.)*"` / `'(?:[^'\\]|\\.)*'`) or an unquoted single token, and changed the replacement to `${1}${2}[REDACTED]`, which drops the entire value including surrounding quotes. Added a regression test for double- and single-quoted multi-word values.
- **Suggested test**: The in-file regression test covers the exact shape; extend it to JSON values (`{"password": "my secret phrase"}`) and backslash-escaped quotes.

### [High] `shared/client/src/connection.rs` — failed reconnect leaks an orphaned read loop

- **Location**: `shared/client/src/connection.rs:161-212` (`AlephClient::reconnect`).
- **Description**: `reconnect` spawns a new read loop, then runs the `connect` handshake. If the handshake fails (auth refused, timeout, malformed response), the function returns `Err` with `connected` still `false`, but the read loop it spawned keeps running on the dead socket. Repeated failed reconnects accumulate zombie tasks.
- **Impact**: Resource exhaustion under persistent reconnect failures; the abandoned loop can also race with a later successful reconnect if the server eventually sends frames on the old socket (mitigated by generation check, but still wasted work).
- **Trigger**: Any reconnect attempt where the TCP+TLS open succeeds but the `connect` handshake does not.
- **Fix applied**: Captured the `tokio::spawn` `JoinHandle`; on handshake failure the read loop is aborted and a `Message::Close(None)` frame is sent to prompt the gateway to tear down its side. The success path is unchanged.
- **Suggested test**: Spin up a loopback server that accepts the WebSocket upgrade but replies to `connect` with `AUTH_REQUIRED`; assert that `reconnect` returns `Err` and that the task count / socket state does not leak across repeated attempts.

## Per-perspective findings

### Security

- `shared/logging/src/pii.rs` quoted-secret bypass — fixed.
- `shared/client/src/tls.rs` remains a pin-based trust model with no insecure bypass; loopback self-signed lookup is best-effort and silent on failure, which is documented. No new TLS TOCTOU introduced.
- `shared/client/src/connection.rs` reconnect no longer leaks tasks, reducing the reconnect-storm amplification surface.
- `shared/protocol/src/desktop_bridge/methods/input.rs` defaults missing `delivery` to `"global"` (the pessimistic reading), preventing a misconfigured helper from being misread as targeted.
- `shared/protocol/src/canvas.rs` `check_title` correctly rejects control characters and over-long titles; no path traversal surface in `retention.rs` because cleanup is scoped to the configured log directory.

### Logic

- `shared/ui_logic/src/connection/reconnect.rs` — `ReconnectStrategy::next_delay_jittered` applies a deterministic downward fraction. The doc says this avoids lockstep after a server restart, but a fixed `jitter_permille` produces the same delay sequence for every client using the same value, so it does not actually decorrelate reconnect storms. **Medium**. A real jitter needs a per-client random source; this is a design/API fix (add a random source or have callers supply a random permille) and was not changed to avoid adding a dependency in this round.
- `shared/client/src/connection.rs::call_with_timeout` checks `connected` before sending, but the check and the send are not atomic. If the read loop clears `connected` between the two, the send still proceeds and returns a `Connection` error, which is handled but is a TOCTOU. **Low/Medium**; impact is bounded by the existing error handling.
- `shared/client/src/session_resolve.rs` tie-breaking logic remains deterministic and correct; the `last_active_at` string comparison is valid because the server emits RFC 3339 timestamps.
- `shared/protocol/src/voice_text.rs` loop detectors correctly allow truncated final repetitions and preserve short genuine interjections.
- `shared/protocol/src/canvas.rs` `FracIndex::between` is strictly ordered and bounded for repeated head inserts.

## Conclusion

`shared/{client,logging,protocol,ui_logic}` is in substantially better shape than the 2026-08-25 review found, largely because the prior round's one High finding landed correctly and the contract modules continue to prevent cross-crate wire drift. This round found three new High-severity issues:

1. **PII filter formatting dropped numeric/bool/error fields**, stripping legitimate context from logs.
2. **PII redactor leaked multi-word quoted secrets**, a concrete PII bypass.
3. **Failed reconnects leaked read loops**, which can accumulate under persistent failures.

All three have been fixed in-tree with minimal, root-cause changes. The remaining Medium/Low findings are narrow and either require dependency changes (true random jitter) or are carry-forward items from the prior review.
