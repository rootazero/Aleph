## Summary

**Report file written to:** `/tmp/opencode/aleph-review/review-results/executor.md`

**Headline findings:**

1. **Critical R1 violation**: `constructor/mod.rs:262-276` directly imports `aleph_desktop_macos`, `aleph_desktop_linux`, and `aleph_desktop_windows` inside the core executor — a hard platform-API leak that contradicts the codebase's "brain-limb separation" principle.

2. **Critical wiring bug**: `set_config_patcher` at `start/mod.rs:1389` is a no-op for production boots because the `tool_registry` Arc has been cloned into `ExecutionEngine::new` first; the comment in `inherent.rs:38-49` explicitly warns this happens, and the boot path triggers the warning on every boot. `self_config` and `moa` tools ship without a `ConfigPatcher`.

3. **High race condition**: `MemorySearchTool` and `gateway/execution_engine/execute.rs:336` share a process-global `tokio::sync::RwLock<String>` for the session key. A long-running `memory_search` on a previous request can be read mid-flight and see a NEW request's session — a cross-session memory leak on concurrent requests.

4. **High R3/R4 violations**: `BuiltinToolRegistry` constructor doubles as a memory/compaction/dream infrastructure bootstrap, wiring 50+ subsystem `Arc`s. The executor is supposed to be a thin dispatch layer (R4: "pure I/O"); today it imports `crate::vision`, `crate::media`, `aleph_desktop_*`, `crate::memory::*` and builds pipelines inline.

5. **High R10-but-borderline**: `MemoryInjectionMode`-based gating is a static config partition, NOT a per-message heuristic — R10-compliant. Logged for awareness, not as a violation.

6. **Medium/Low items**: 17 medium-severity findings (input validation gaps, lifetime/borrow issues, config drift, dead `pub` seams) and 5 low-severity (file length, copy-paste imports, missing assertions). No R8 violations observed.
