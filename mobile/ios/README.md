# Aleph Panel — iOS Shell

A **thin native shell** (~90 lines of Swift) that hosts the existing Aleph WASM
panel in a full-screen `WKWebView` on an iPhone. It is **not** a UI rewrite — all
panel UI lives in `interfaces/webchat/src/platform/phone/` (Leptos → WASM) and is
served by an `aleph-server`. This shell only loads that panel and adapts the phone
form-factor (safe-area insets / `viewport-fit=cover`). See R2 (single source of UI
truth) and R6 (one core, many channels) in the root `CLAUDE.md`.

## Connecting

On first launch the app shows a native **pairing screen**: enter your Aleph
server address (`host`, `host:port`, or `http(s)://host[/route]?token=…`). The
target is probed for reachability, then stored in the **Keychain** (the token
never touches `UserDefaults`). To re-configure later, **shake the device** to
return to the pairing screen; an unreachable server also falls back to it
automatically.

The `PANEL_URL` launch env still takes priority (used by `generate.sh` /
`launch-local.sh` for sim/dev), so existing test flows are unchanged.

## No secrets in source

The connection target (server **IP + token**) is **never** committed. `PANEL_URL`
env still takes priority (used by `generate.sh` / `launch-local.sh` for sim/dev);
otherwise the app shows the native pairing screen and persists the chosen target
(with its token) in the **Keychain** — there is no `UserDefaults` token and no
`about:blank` fallback. Concretely:

| File | Committed? | Secret? |
|------|-----------|---------|
| `AlephPaneliOS/**/*.swift`, `project.yml`, `generate.sh`, `*.example` | yes | no — placeholders / runtime resolution only |
| `*.xcodeproj/` (generated by xcodegen; scheme embeds resolved `PANEL_URL`) | **no** (`.gitignore`) | yes |
| `launch-local.sh` / `*.local.sh` (your local copy) | **no** (`.gitignore`) | yes |

## Prerequisites

- macOS + Xcode (iOS Simulator), `xcodegen`, `xcrun simctl`
- A reachable `aleph-server` that embeds the current phone UI — either the repo's
  own `target/debug/aleph-server` (local) or a remote Debian core.

## Run it

### Option 1 — Xcode ▶ Run (local core on this Mac)

```bash
cd mobile/ios
./generate.sh            # bakes a fresh PANEL_URL into the gitignored scheme
open AlephPaneliOS.xcodeproj   # then press ▶ Run (local core must be up on :18790)
```

### Option 2 — simulator launcher (local OR remote Debian)

```bash
cd mobile/ios
cp launch-local.sh.example launch-local.sh   # the copy is gitignored
# edit launch-local.sh: set UDID + PANEL_URL (local 127.0.0.1, or your Debian IP+token)
./launch-local.sh
```

Get a token on the server with `./aleph-server bootstrap-token`. For a remote
Debian core the URL looks like `http://<DEBIAN_IP>:18790/settings?token=<TOKEN>`;
the server must be bound to `0.0.0.0` (see SECURITY.md trust model).

## On another machine

Clone the repo, then `cp launch-local.sh.example launch-local.sh` and fill in your
own IP + token. The secret stays in that gitignored copy and never enters git.
