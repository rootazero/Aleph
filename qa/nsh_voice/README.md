# T6 NSH Voice fixture / NSH Voice 联调夹具

This is a browser fixture, not a native, release, or speedup receipt. The TSX run needs a real `aleph-server` and an externally built **TSX Web Panel containing Voice**. The separate Classic comparison uses the Classic Web Panel embedded in that same server binary. It does not build Core, use the installed service, start an NSH shell, or test on a remote host. The T6 base `7b4c12e20` has Gateway Voice routes but not the T5 Voice module; use the integrated build to run this driver.

这是浏览器夹具，不是原生、发布或提速回执。TSX 需真实 `aleph-server` 和已构建的、含 Voice 的 **TSX Web Panel**。Classic 对照使用同一个 server 二进制内嵌的 Classic Web Panel。不构建 Core、不连接已安装服务、不启动 NSH 壳、不做远端验证。基线 `7b4c12e20` 有 Gateway 语音路由，但没有 T5 Voice 模块；联调需用集成后的产物。

## Run / 运行

Requires Python 3.11+ (Windows 3.13+ for private-directory ACLs), Node.js 20+, the repository Playwright dependency and a compatible installed Chromium, and FFmpeg with `libmp3lame`. `--chrome` or `ALEPH_BROWSER_LIVE_CHROME_PATH` can select an alternate executable as in S3. Supply known binaries, a bundled web directory with `index.html`, and a **new** output directory outside the checkout with an existing private parent. The runner records an optional `--nsh` asset hash only.

需要 Python 3.11+（Windows 因私有目录 ACL 需 3.13+）、Node.js 20+、仓库 Playwright 依赖及兼容的 Chromium、含 `libmp3lame` 的 FFmpeg。可用 `--chrome` 或 `ALEPH_BROWSER_LIVE_CHROME_PATH` 指定浏览器。提供已知可信的二进制、含 `index.html` 的 Web 产物目录，以及仓库外私有父目录下尚未创建的输出目录。可选的 `--nsh` 仅记录产物哈希。

```sh
python qa/nsh_voice/run.py --server "$SERVER" --panel-web "$PANEL_WEB" \
  --case success --clip short --warm 4 --output "$PRIVATE/short-01"
python qa/nsh_voice/run.py --server "$SERVER" --panel-web "$PANEL_WEB" \
  --case success --clip long --warm 4 --output "$PRIVATE/long-01"
python qa/nsh_voice/run.py --server "$SERVER" --panel-web "$PANEL_WEB" \
  --case limit --clip limit --output "$PRIVATE/limit"
# One fresh isolated run / fresh pairing per negative case:
for case in permission config-only cancel-stt cancel-chat disconnect; do
  python qa/nsh_voice/run.py --server "$SERVER" --panel-web "$PANEL_WEB" \
    --case "$case" --output "$PRIVATE/$case"
done
```

| Case / 步骤 | Required observations / 必需证据 |
|---|---|
| `success` | A fresh paired `/v1/ws` hello with `live_events`; no microphone on mount. One canonical WAV RPC → one STT reply → one `chat.send` with `voice_input: true`, `run_only: true`, and an idempotency key equal to the turn ID → exactly one run acceptance naming the Chat session, then that run’s terminal (both on the original hello socket) → one `voice.turn.synthesize` from the terminal's final text. Checks one nonempty Web Audio source start, natural `ended`, rearm, then user stop releases tracks. Ordinary Chat must still render through the same paired connection. The fixture checks exact Chat RPC/run counts and exact STT/TTS HTTP counts; it records all model HTTP calls, which may include auxiliary work. / 实际配对、挂载不采集、单次录音→识别→会话→终态→合成、播放源自然结束、重新监听、停止释放 track，普通 Chat 仍渲染。 |
| `permission` | Actual Chromium `getUserMedia` denial (`NotAllowedError`), no speech RPC, idle tracks. / 浏览器拒权、零语音 RPC、无活跃 track。 |
| `config-only` | Fixture configuration has TTS but no STT. The real Web Gateway reply is `not_configured`; no browser speech start, chat, or playback. / 配有 TTS、无 STT；Web Gateway 必须明确 `not_configured`，无浏览器识别、会话或播放。 |
| `limit` | 22 seconds of voiced synthetic input; Chromium mic processing is bypassed in this case only so the stationary tone reaches VAD. Require one canonical 640,000-byte PCM upload, no split/retry. Not a check of the exact wording of the limit notice or direct rejection of an oversized client RPC. / 仅本用例关闭 Chromium 麦克风处理，避免稳定音调被抑制；22 秒合成输入只上传一次 640,000 字节 PCM，无切片或重试；不验证提示文案或直接发超限 RPC。 |
| `cancel-stt`, `cancel-chat` | Wait until the loopback HTTP provider received the request, then click **Stop voice conversation**. Assert the exact turn’s cancellation ACK + `cancelled` STT reply, or `chat.abort` on the Chat receipt’s socket with its exact run, `run_only: true`, no `session_key`, and reply `aborted: true`, `dropped: 0`. Observe no subsequent synthesis/play/rearm within the bounded provider hold window. Require exactly one `CANCELLED` terminal after the abort request, before or after its ACK, and no completion for that Chat run. If the terminal names a session, it must match the Chat receipt. An ACK is not proof the external provider stopped computing. / 等实际 provider 请求进入，再点 **Stop voice conversation**；校验准确的 turn，或同一连接上仅按 Chat 回执 run 中止（请求含 `run_only: true`、不含 `session_key`；回执须有 `aborted: true`、`dropped: 0`），中止请求发出后须有且只有一条 `CANCELLED` 终态（可早于或晚于 ACK），如终态含 session 必须与 Chat 回执一致；无成功终态，且无后续合成、播放或重启采集。ACK 不代表 provider 停算。 |
| `disconnect` | Close the actual paired WebSocket while STT is in flight, observe its close, then wait for a distinct live hello (via Reconnect if exposed). Do not replay or rearm. This is not a full Gateway restart. / STT 处理中关闭真实 WS，确认旧连接关闭、新连接 hello，不重放也不重启采集；非完整 Gateway 重启。 |

The process reuses S2's temporary Gateway config/start and CLI pairing (`u-owner`), S3's browser/TLS pinning and v1 framing pattern, and the existing deterministic Chat response shape without the artifact tool. Both servers bind loopback, never the default port. Children receive a small environment allowlist plus fresh `HOME`, `ALEPH_HOME`, app-data and temp roots, with no inherited provider/API/proxy variables. Chromium uses a fresh profile and the fixture certificate SPKI, not an all-cert bypass; the page is restricted to its same origin and the selected WebSocket path. The config, test token, browser ticket, logs and generated media exist only in a private scratch directory removed on normal/handled exit. There is no OS egress sandbox; use trusted builds, and inspect for private scratch after a forced OS kill. Do not pass real credentials, recordings, or the installed service to this fixture.

沿用 S2 的隔离配置、启动、`u-owner` 配对；基于 S3 的 Chromium、SPKI 验证和 v1 帧方案，并复用已有 Chat stub 的确定性响应形状、不启用 artifact tool。两个服务仅监听回环且避开默认端口，子进程环境使用白名单，换成临时 HOME、ALEPH_HOME、应用数据及临时目录，不继承 provider/API/proxy 变量。浏览器用新 profile 和单一证书 SPKI，不做全局证书绕过；页面仅限本源和选定的 WebSocket 路径。配置、token、ticket、日志及音频只写入私有临时目录，正常或已处理的退出会清除。非 OS 出站沙箱；仅使用可信产物，若强制杀进程需检查私有临时目录。勿传真实凭据、录音或已安装服务。

## Classic comparison: scoped browser baseline / Classic 浏览器对照

Run both mounts with the **same** trusted server binary (including a real Classic WASM bundle, not a placeholder), Panel directory, Chromium and FFmpeg binaries, from one host. Keep short/long and cold/warm separate; alternate mount order across repeated invocations. Each invocation is an independent private Gateway/browser, not a mount switch inside a running service:

用**同一个**可信 server（内嵌真实 Classic WASM，而非占位资源）、Panel 目录、Chromium 和 FFmpeg，在同一主机运行；短长素材和冷热分组，重复时交替挂载顺序。每次独立初始化私有 Gateway 和浏览器，不在运行中的服务上切换挂载：

```sh
# For repeat runs use a new, private output name for every mount/clip/rep.
for clip in short long; do
  for mount in classic tsx; do
    python qa/nsh_voice/run.py --server "$SERVER" --panel-web "$PANEL_WEB" \
      --mount "$mount" --case success --locale en-US --clip "$clip" --warm 4 \
      --output "$PRIVATE/$mount-$clip-01"
  done
done
```

- **Mount and authority:** Classic uses the Gateway control-plane `/` fallback (`src/gateway/server/mod.rs`, `src/gateway/control_plane/assets.rs`) and same-origin `wss://127.0.0.1:<temporary-port>/ws` text JSON-RPC (`interfaces/webchat/src/context.rs`). The existing Gateway origin/loopback checks apply (`src/gateway/server/connection/{upgrade,auth}.rs`). The fixture neither mints nor fills a Classic ticket and requires a credential-less `connect` reply with `authorized: true`, `role: operator`, `needs_token: false`, and no device/user token or server-verified identity echo. This is the **implicit loopback owner**, not the TSX `/v1/panel/` → paired `/v1/ws` user identity. Only run on a trusted host: the isolated short-lived Classic port is still reachable by other local processes. / Classic 是回环临时端口下的根路径和 `/ws` 文本 JSON-RPC，经原有同源与回环鉴权授予隐式 owner；不生成配对票据、不替代 TSX 用户身份。同机进程仍可能访问临时端口，仅在可信主机运行。
- **Exact exercised path:** The English desktop composer opens `.voice-stage` and starts capture (`interfaces/webchat/src/platform/wide/views/chat/composer/voice.rs`, `interfaces/webchat/src/platform/wide/views/voice/mod.rs`). Both mounts share test STT/Chat/TTS settings and `[voice.streaming] enabled=false`. Classic must observe `voice.stream.start` → `stream_id:null`, then exactly one batch `voice.transcribe`, voice `chat.send`, and one `voice.synthesize` correlated to the accepted run/session and its exact terminal text. The shared fixture answer `PHASE9_RUNTIME_PROOF` has no sentence terminator, so this baseline requires exactly one **post-terminal tail flush**, not incremental sentence synthesis. To test overlap separately would require a punctuated answer delivered before an independently delayed stream end, and an observed TTS request before the terminal. The terminal-to-hook interval here is a timing proxy, not audible latency. The Classic URL/HTMLAudioElement player and streaming provider path are deliberately **not** baselines. `--mount classic` supports only successful English (`en-US`) short/long runs. / Classic 普通桌面输入框打开沉浸语音即录音，先实际观察流式能力明确关闭，再走批量识别、会话及终态后的尾段合成，按精确 run/session/终态关联。共享回复无句末标点，本夹具不验证增量句子合成；如需另测，须先发带标点的文本、独立延迟终态，并实际观察终态前的合成请求。终态到 hook 不是出声延迟；不测 URL 播放或流式 provider，仅支持英文成功用例。
- **Matched inputs versus divergent work:** Both get the identical generated fake-device WAV and deterministic provider implementation. Chromium uses `%noloop` so the file does not inject a second utterance during Classic playback. Only the duration-limit fixture overrides Chromium's synthetic input processing; neither the comparison nor product capture changes those settings. Both require the inline MP3 response to match the generated reply bytes and the **same** Web Audio hook to observe one nonempty scheduled source and natural end. They do not necessarily upload byte-identical STT input: Classic's VAD captures/pads at its AudioContext rate (see `interfaces/webchat/src/platform/wide/views/voice/audio.rs`), while TSX uses bounded mono 16 kHz. Receipts expose uploaded rate/PCM/base64 sizes and framed bytes (Classic JSON text vs v1 length-prefixed UTF-8, neither includes WS/TLS overhead), counts and provider HTTP bytes. Compare per-turn wire rows; only TSX adds the existing, separately recorded ordinary-Chat sanity turn to whole-run provider counts. These observations distinguish topology and workload; they do not count copies or allocate/measure peak buffers. / 同一生成音频与 provider、同一合成 MP3 字节、同一 Web Audio hook；Chromium 使用 `%noloop`，不在 Classic 播放期间循环注入第二句；两端 VAD、补齐和编码采样率不同，上传不保证逐字节相同。记录上传采样率和字节、RPC/HTTP 计数及帧字节，不含 WS/TLS 额外开销；不据此推导复制次数或内存峰值。

**Comparison boundary:** Report the matched short/long cold/warm strata **side by side**, not a speedup or a same-mount baseline. App mounts, security principals, capture/rearm, synthesis ordering, and upload payloads differ by design; a render or approved loopback signal and allocation/copy instrumentation are not present. Where assets or stages are missing, report unavailable and retain only the existing deterministic tests/source trace. / 只并列观察匹配条件下的冷热短长分组，不报同源挂载基线或提速；缺少声学或分配信号，缺产物时留作不可用。

## Read the receipt / 回执和可比口径

Only `receipt.json` survives. It contains harness revision and source hashes (including reused S2/Chat helpers), supplied asset/index hashes, OS/architecture, Chromium version/locale, media hashes and sizes, phase/results, per-method/event framed byte/count totals, and fixture provider HTTP body sizes and counts (recognized routes with the ephemeral test token). No URL, ticket/token, IDs, transcripts, audio data, DOM/screenshot, or application logs are exported. HTML index hash alone does not identify every Panel asset: preserve the exact build/manifest privately for comparison. Failures report a phase and named check (or error type), and can contain partial observations; they are not successful samples. A provider write count is bytes passed to its socket, not receipt or device playback.

只保留 `receipt.json`：含夹具版本与源码哈希（含复用的 S2/Chat 夹具）、指定产物或入口哈希、系统及架构、引擎与 locale、音频哈希和大小、阶段与结果、方法/事件帧数和字节、使用临时 token 的 provider HTTP 请求/响应体数据。无 URL、凭据、ID、转写、音频、截图或应用日志；入口哈希不能替代全产物校验，比对时私留对应构建或 manifest。失败阶段可能有部分观察，不是成功样本。provider 写出字节不等于客户端收到或扬声器播出。

- **Cold/warm:** `cold` = first turn on a fresh Gateway + Chromium instance; `warm` = subsequent turns on that same Gateway/browser and clip, stopping and restarting TSX after rearm, or closing and reopening Classic after playback. Neither implies a cold OS disk cache. Per stratum the receipt gives raw timings plus `n` and nearest-rank p50/p95; `n=0` yields `null`. Repeat fresh invocations for more cold samples (one per receipt). A p95 from one or a few samples is descriptive only. / 冷态为新 Gateway＋Chromium 第一次，稳态在同一配对及素材下重试，不代表 OS 冷缓存；按组记录原始样本、数量及最近秩 p50/p95，空组为 `null`。要增加冷样本须多次新建，少量样本的 p95 只作描述。
- **Match like-for-like:** hold host/engine version, locale, clip and generated response hashes, provider config/delays, mount, power/device/load and cold/warm strata constant for short/long. Join raw rows across matching successful receipts and recompute nearest-rank (`ceil(q*n)`), not an average of percentiles. Classic is a separate cross-mount stratum using the same generated media, providers and player hooks, not a same-mount speedup baseline. Real mic/loopback results must be kept separate. / 短长分别对照，相同系统/引擎/语言/媒体/插件/挂载/负载与冷热组；汇总匹配原始样本后重新取分位数，不平均分位数。Classic 单列跨挂载样本，真人麦克风或 loopback 另列，不报提速。
- **Measurement limits:** browser pipeline uses a generated tone *as fake device input*, deterministic transcription/Chat, and a generated MP3; actual browser decoding/start/end hooks are not an audible signal. Reported timings are observed v1 request/reply/acceptance timestamps and the browser→driver Web Audio start hook timing (includes hook delivery). First captured sample, acoustic end→STT, final→audible and end→audible, memory copies and peak buffering are **unavailable**. Traffic shows transport topology, not peak memory, copy counts, or latency improvement. / 夹具使用合成音调、确定性转写/会话及生成 MP3；真实 Web Audio hook 不等于真实出声，跨进程采样包含递送延迟。首采样、实际发声结束→识别、终态→出声、发声结束→出声、复制次数和内存峰值均不可用；帧拓扑不等于性能收益。

## Packaged native follow-up / 原生包后续实机

1. On a supported macOS host with an explicitly supplied packaged TSX-capable NSH and same-user Desktop IPC Gateway, use S2's private temporary `HOME`/`ALEPH_HOME`, non-default loopback port and owned Desktop IPC endpoint. Use `ALEPH_SHELL_PANEL=tsx`, `ALEPH_SHELL_PANEL_IPC=<owned-socket>` and `ALEPH_SHELL_HOTKEY=disabled` only for this isolated shell. Do not attach to a running user Gateway. Hash assets, record OS, selected locale, engine and on-device availability. Windows/Linux independently validate installed adapters only when assets are available; do not bypass their packaged TSX mount gate. / macOS 使用已获准同用户 IPC 的隔离 TSX 原生包及 S2 私有目录、临时端口和 socket，不附着用户 Gateway；记录产物及本机识别可用性。Windows/Linux 仅在可用时测已安装 adapter，不绕过 TSX 门禁。
2. Keep STT deliberately unconfigured so the installed recognizer is the only possible STT path; confirm permission and locale assets without downloading anything implicitly. Supply test-only Chat/TTS providers. For a real spoken reply use an authorized TTS engine and test-only credentials confined to the private config; the deterministic MP3 is only a tone and cannot pass a real spoken-reply check. Open Voice and verify the mic stays idle until Start. Speak a nonsensitive test phrase, allow natural finish, then verify **actual** recognition, exact terminal, speaker output and rearm. On another turn Interrupt during audible playback; verify audio stops, and switching away or disconnecting releases devices rather than replaying. Confirm Classic remains unchanged; for an offline-helper claim collect separately attributable adapter evidence rather than inferring from absence of Web RPCs. / 故意不配置 STT，核对录音权限、离线语言资源且不隐式下载模型；用专用 Chat/TTS，只有获准的真实语音 TTS 可验证真人可听答复。实测开页不采集、真人短句、已安装离线识别、已知终态及扬声器输出、打断与设备释放。Classic 不变及 helper 归属须单独取证。
3. For performance use calibrated native render timestamps or declared, approved loopback to measure **first audio**, synchronized with first captured sample/end of speech, correlated STT/acceptance/terminal, actual calls/bytes and separately instrumented allocation/copy/high-water counters. Record only numeric timings and evidence references privately, never live recordings or spoken text. Missing bundle, bridge, credentials, mic, speaker, permission, locale or timing signal makes that stage **unavailable**, not zero. / 性能测试须用原生 render 信号或声明且获准的 loopback；数字回执及引用留私有目录，不留真实录音或文本。缺资源、权限或信号则标不可用，不填零。
