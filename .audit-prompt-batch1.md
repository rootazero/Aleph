## What to look for (the 5 phases of the skill)

### Phase 1 — Scan seams
Producer/consumer parity at these seam types:
1. **Registration parity** — every `const NAME = "x"` or `register_*` and the consuming dispatch arm.
2. **Call-vs-handler parity** — every `mod.rs` re-export and every internal consumer.
3. **Config-reader parity** — every config field type and every non-test read of it.
4. **Stub sweep** — `// TODO`, `unimplemented!`, `todo!`, empty match arms, `&[]` config tables.
5. **Path/route parity** — name/path drift across the seam.

### Phase 2 — Enumerate candidates
For each candidate, list **file:line for both ends** (producer and consumer). If no consumer, say "no consumer found".

### Phase 3 — Triage (read-first)
For each candidate, **grep the consumer side for a live caller/reader** before deciding CONNECT/CUT/DECIDE.
A "missing handler" that is actually a dead consumer wrapper = CUT, not CONNECT.

### Phase 4 — Fix recommendations
For each finding, state:
- **file:line** of the producer
- **file:line** of the consumer (or "no consumer")
- **severity** (CRITICAL/HIGH/MEDIUM/LOW)
- **triage** (CONNECT / CUT / DECIDE)
- **reason** (one sentence)
- **proposed fix** (one or two lines)

### Phase 5 — Guard recommendation
If you find a pattern that recurs (e.g. a `register_*` table with no consumer list), suggest a single-source-of-truth refactor or a `KNOWN_SEVERED` baseline.
