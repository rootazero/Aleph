## 1. 三层 / Three layers

| 层 Layer | 位置 Location | 职责 Responsibility |
|---|---|---|
| ① Agent tools | `src/builtin_tools/browser_tools/{open,navigate,tabs,present,operation_publish}.rs` · `src/browser/cdp_backend/operation.rs` · `src/browser/live/{resource,lifecycle,owner_registry}.rs` | 工具调用产生 operation record 与 `PreviewResource`；producer seam 在 turn context 下发布 / 关闭。Tool calls yield an operation record and a `PreviewResource`; the producer seam publishes/closes under the turn context. |
| ② Gateway grant issuer / viewer transport | `src/browser/live/{grant,issuer,viewer_backend}.rs` · `src/gateway/handlers/browser_viewer.rs` · `src/gateway/server/browser_viewer_route.rs` · `shared/protocol/src/browser_live.rs` | 签发 / 撤销 grant（RPC）；`/viewer/browser/{consume,exchange,ws}` 认证与帧传输；wire 契约单一源。Issue/revoke grants (RPC); authenticated `consume`/`exchange`/`ws`; single-source wire contract. |
| ③ Panel / TUI presentation | `interfaces/webchat/src/platform/wide/views/browser/{model,viewer}.rs` · `interfaces/webchat/src/components/workspace_panel.rs` · `interfaces/tui/src/viewer_launcher.rs` | 只渲染与本地输入收集（R2/R4）；Panel 是 `WorkspaceBody::Browser`，TUI 只有本地 launch seam。Render + local input only (R2/R4). |

## 2. 当前调用链 / Current call chains

**Agent → 资源 / resource**

`browser_open` / `browser_navigate`（仍是活跃 agent 工具，**未删除**）→ `operation_publish`（open/navigate 是 browser-live resource 来源之一）→ `BrowserLiveProducer` seam（显式；使用 turn context、issuer、operation-bound target）→ gateway event `browser.live.resource` / `browser.live.closed`（可见性过滤：按 user/session/run，Connection/Artifact 类 topic 不下发）。

**Panel / 用户 → viewer（设计链路 / designed path）**

`browser.viewer.grant.issue`（RPC，Frames-only，显式 trusted origin）→ 启动 URL `<origin>/<path>#grant_id=…&nonce=…`（nonce 只在 fragment）→ `POST /viewer/browser/consume`（fragment nonce → ticket）→ `POST /viewer/browser/exchange`（ticket → WS 路径 + 轮换 secret）→ `GET /viewer/browser/ws` + 首帧 `AuthHello`（2 s 超时）→ `AuthOk`（先写后注册）→ `LiveViewerBackend`（attach 前读取 resource registry 授权）→ 精确 owner（`owner_registry`：`(browser_session_id, target_id)` 精确路由、compare-and-retire）。

> 注意：上述链路的 composition 已由 `BrowserLiveRuntime` 实现（§2.1），但**仅显式合法 origin 才安装真实 backend，默认 deny-only**；**独立 standalone viewer 链路**已在 Windows 单机由真实 Gateway/Chrome/WS/WASM DOM selector 验证（§6，跨多次独立运行的历史覆盖）；**完整 Native Panel**（Panel app 内 launch 点击、窗口级 QA）**未**验证（#56 仍 PARTIAL，window 5 失败于 `reveal_browser`，见 `docs/reports/verify-20261007/task56-native-real-window-5.md`）。The chain is now composed by `BrowserLiveRuntime` (§2.1), but the real backend is installed **only for an explicit valid origin; default is deny-only**. The **standalone viewer chain** has Windows real-machine selector evidence (§6; aggregated across separate runs); the **full Native Panel** (in-app launch click, window-level QA) does **not** (#56 still PARTIAL, window 5 failed at `reveal_browser`).

### 2.1 BrowserLiveRuntime composition

- **Compose / 组装**：`src/gateway/server/browser_live_runtime.rs`；**boot 注入 / injected at boot**：`src/bin/aleph-server/commands/start/builder/agent_init/mod.rs`。
- **共享件 / Shared instances**：同一份 `ResourceRegistry`、`ViewerGrantStore`、`BrowserLiveLifecycle`、event bus、`LiveOwnerRegistry`，以及 producer / issuer / backend，由 runtime 统一持有并注入。One shared registry/grant store/lifecycle/event bus/owner registry plus producer/issuer/backend.
- **安装条件 / Install gate**：仅当配置了**显式合法 origin** 才安装真实 issuer/backend；`None` 或非法 origin 仍走 deny-only seam。Installed only for an explicit valid origin; `None`/invalid keeps the deny-only seam.
- **TTL sweeper**：1 s 周期，missed tick 采用 `Skip`；`BrowserLiveRuntime` 持有 `ttl_sweeper: Option<JoinHandle<()>>`，但 `install_browser_live_runtime` 取出 producer 后会丢弃 runtime；Tokio `JoinHandle` drop **不会**取消任务，因此 sweeper 处于 detached 状态，直到 Tokio runtime shutdown 才结束。`GatewayServer` 目前没有 browser maintenance 的 shutdown seam（仅有 `reconciler_handle`）。1 s interval with `MissedTickBehavior::Skip`; `BrowserLiveRuntime` holds the `JoinHandle`, but `install_browser_live_runtime` drops the runtime after returning the producer; dropping a Tokio `JoinHandle` does not cancel the task, so the sweeper is detached until the Tokio runtime shuts down. `GatewayServer` currently has no browser-maintenance shutdown seam.
- **OwnerTerminalSink**：已接 `targetDestroyed` / engine end / lag（fail-closed）；精确 `profile + browser_session_id + target` 匹配；产生 grant revoke 与 closed 事件。present 发布后会做 route revalidation，关闭 ghost resource；late sink replay 为 one-shot。Wired to targetDestroyed / engine end / lag (fail-closed), exact profile+browser_session_id+target match, emits grant-revoke and closed events; after a present publish, route revalidation closes ghost resources; late sink replay is one-shot.
- **Resource 决策 RPC / decision RPC**：`browser.viewer.resource.decide` 已注册并有测试；Safe 需显式用户确认、revision CAS、`Refused -> Revoked`。**这不等于生产 viewer 已开放**。Registered and tested; Safe requires explicit user confirmation, revision CAS, `Refused -> Revoked`. This does **not** mean the production viewer is open.
- **Producer 不能发布 Safe / Producers cannot publish Safe**：`BrowserLiveProducer::browser_present` 与 `revise`（含 `PublishedPreview::revise`）统一经 `producer_redaction`（`present.rs`）：输入 `Safe` 降为 `Pending`，`Pending` 保持，`Refused` 保持 fail-closed（close + revoke）；`Safe` 只能由 `browser.viewer.resource.decide` 的 revision CAS 设置。Both `browser_present` and `revise` clamp producer `Safe` to `Pending` via one helper; `Refused` still fails closed; `Safe` is set only by the decision CAS (low-level registry `Safe` is unchanged). 低层 crate-private `ResourceRegistry`/`Lifecycle` 测试 fixture 仍可直接构造 `Safe`，仅 decision CAS 是生产批准路径；未来新增 production caller 须保持此边界。Low-level crate-private `ResourceRegistry`/`Lifecycle` fixtures can still construct `Safe`; only the decision CAS is the production approval path, and any future production caller must preserve this boundary.
- **Navigation generation internal gate**：内部 gate 已实现，`browser::live` 118/118 验证；wire r4 **未变**。限制：Obscura 的 event-less click navigation 未覆盖；subframe **刻意不 gate**；真实 Chrome 上的 owner navigation fence 已有 `navigate-fence` selector exit 0 记录（`docs/reports/verify-20261007/browser-live-final-run.md`、`browser-live-task51.md`；`.superpowers/sdd/2026-10-07-panel-browser-workspace/b-plan-real-machine-addendum.md` 在 Gateway PID 1740 重跑，各用新签发 grant）；Obscura 未验证。Internal gate implemented, wire r4 unchanged; limits: Obscura event-less click navigation and subframes (deliberately not gated) are not covered; the owner-navigation fence on real Chrome has recorded `navigate-fence` exit-0 runs (final-run, task51, B-plan addendum on Gateway PID 1740, each with a freshly issued grant); Obscura unverified.

## 3. 安全不变量 / Security invariants

1. nonce 仅在 URL fragment；不进请求行 / `Referer` / 日志；`Debug`/`Display` 一律脱敏。The nonce lives only in the fragment and is never logged or `Debug`-printed.
2. 严格校验 Origin、binding、resource、target；单连接 `next_secret` 轮换，已消费 secret 不可重放。Strict Origin/binding/resource/target checks; single-connection rotating secret, no replay.
3. 未认证 WS 只允许有界 auth 握手；`AuthOk` 之前不发任何业务消息 / 帧。Pre-auth WS is a bounded handshake only; no business frames before `AuthOk`.
4. 当前 issuer 仅授 **Frames** 能力；人类输入走 SSRF baseline + mutations gate。Issuer grants Frames-only; human input passes SSRF baseline + mutation gate.
5. 事件总线只带 resource / closed / intervention 三类；frame / state 只走专用 viewer WS。Bus carries resource/closed/intervention only; frames/state only on the dedicated WS.
6. 精确 owner 路由：不能按 profile 猜 owner，不能从 receipt 重建 owner；retired / unavailable 一律拒绝。Exact owner routing: never guess an owner by profile or rebuild from a receipt; retired → deny.
7. Redaction 为 Pending / Refused 时 Panel 不描述资源内容；Refused / Closed 的 tombstone 不含 target，旧 revision 不得复活。Pending/Refused resources are withheld; tombstones carry no target and never resurrect.
8. **Task21 TUI launcher 不调用 localhost / agent CDP**：它只校验 issuer 已产出的 URL，并作为单个 argv 元素交给系统 opener / 显式浏览器可执行文件（不经 shell）；`ViewerLauncherConfig::default` **disabled**，`launch` 返回 `LaunchError::Disabled` 且 runner 不被调用。The TUI launcher never talks to localhost/agent CDP; it is disabled by default and does not invoke its runner.
9. `NetworkContextGrant` / `BrowserContext` / proxy **未触碰**（受 Task0 gate 与网络上下文修订约束）。Not touched by this checkpoint.

## 5.1 已知政策边界 / Known policy boundaries

- **撤销不联动（policy 待用户决定）**：设备 / token / user 的 revoke 只降级 RPC identity，**不会**自动联动既有 viewer Frames grants 或已建立的 live WS；独立 capability 最长 600s，期间 resource close / 导航 / Refused / 手动 revoke 仍会结束它。已批准 spec §4.4：独立 browser、issuer identity 为 `User|Connection`；是否增加“管理性 revocation 联动 capability”**尚未决定**。**未**获得 production risk acceptance，**也未**做设备绑定。
- **list 与事件面可见性不同源（Task56 w6）**：`browser.viewer.resource.list` 只按 resource 的 viewer principal == verified user 过滤，**不**复用事件面 `ByBrowserLiveScope` 的 run->session 准入；两者对 owner 本人一致，但 session 级准入若未来收紧，list 需同步。`gateway.devices.list` 新增只读 `connected_since`（该设备所有 live 连接的最早 presence `connected_at`，离线为 null），用于证明 reload 后同一设备「旧连接全部关闭且新连接在线」；Panel 设备行渲染为 "Online · <time>"。List filters by viewer principal only (not the event-plane run->session admission); `connected_since` is a read-only presence witness.
- **Grant 容量 4096**：满时淘汰最早 deadline 的 grant 并关闭被淘汰的 viewer；**无 per-user quota**，存在跨用户挤占。**Resource 容量 256**：满时以 `CapacityExceeded` 拒绝新资源，**绝不淘汰**live 资源（review 最初的反向猜测已被反证）。
- 以上政策决策等待用户裁定；本文档不设计、不实施 wire 改动。
- **两处 review 修复已定向验收（scope-run；单测级 + 8 个 live PASS，**不等同**整分支批准）**：`src/browser/cdp_backend/mod.rs` 的 task-local scope 收紧；TUI launch 失败后的 grant cleanup / 撤销。Panel 墓碑风险未证实，本轮不扩大处理。

Known policy boundaries (open, user decision pending): device/token/user revocation downgrades the RPC identity but does not automatically revoke existing viewer Frames grants or live WebSockets; a standalone capability lives at most 600s and still ends on resource close, navigation, Refused or manual revoke. Spec §4.4 (standalone browser, issuer identity `User|Connection`) is approved; whether to add administrative revocation linkage is undecided. No production risk acceptance has been given and no device binding exists. The grant cap (4096) evicts the earliest-deadline grant and closes its viewer, with no per-user quota, so cross-user displacement is possible; the resource cap (256) rejects new resources with `CapacityExceeded` and never evicts a live resource. Core task-local scope tightening and TUI failed-launch grant cleanup have since been accepted via targeted verification (scope-run), which is not a whole-branch approval; the unproven Panel tombstone risk is not addressed here.
