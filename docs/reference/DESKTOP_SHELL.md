# 桌面宿主 / Desktop shell

`desktop/nsh-shell`（`aleph-nsh-shell`）使用 NSH 0.6.0 打开由 Rust Core 提供的 Leptos/WASM Panel。浏览器使用同一界面。Core 决定授权、会话历史、群组和实时运行状态。/ The NSH host opens the same Panel that Core serves to browsers and handles the native window, system integrations and packaged server lifecycle.

## 连接与服务 / Connection and service

- **Local** 默认使用 `http://127.0.0.1:18790`。宿主在后台启动随包 `aleph-server`，检查 `/ready` 和 `x-aleph-panel-shell: nsh-v1`，再挂载 Panel。遇到旧版或其他进程占用端口时保留监听者，并显示恢复指引。/ The readiness check admits a compatible Panel before opening the WebView. Startup failures offer a retry.
- **Remote** 经原生连接页配置。连接保存到 `~/.aleph/.desktop-shell-target`，切回 Local 时移除该文件。HTTPS 使用系统信任库。/ Remote uses an existing Gateway and system TLS trust.
- 普通退出保留服务供其他客户端使用。**Quit Aleph and Stop Server** 停止获准的本机服务；远端连接退出时保留远端服务。/ Closing the window hides it. The tray and summon shortcut restore it.
- [启动与切换 / Startup and switching](../../desktop/nsh-shell/src/local_service.rs) · [准入 / Admission](../../desktop/host/src/local_server/admission.rs) · [目标持久化 / Target storage](../../desktop/nsh-shell/src/target_store.rs)

## 系统集成 / Native integration

| 功能 / Feature | 入口与行为 / Entry point and behavior |
| --- | --- |
| 窗口、托盘、菜单 / Window, tray, menus | `app.rs` 注册热键，默认 `mod+shift+a`，环境变量 `ALEPH_SHELL_HOTKEY=disabled` 可关闭。`menu.rs` 提供显示、连接、刷新与退出动作。 / Tray and application commands share the same handlers. |
| 深链接与外链 / Links | `aleph://open` 唤起窗口。外链由宿主按当前连接重新校验后交给系统；产物链接在浏览器打开。 / The host handles deep links and validates external navigation. |
| 通知与登录启动 / Notifications and login launch | Panel 经类型化桥转发通知及登录启动请求，NSH 调用平台接口。 / The bridge also carries document-scoped credential calls; paired credentials live in OS secure storage. |
| macOS 隐私授权 / macOS privacy grants | `perm_monitor.rs` 观察屏幕录制和输入监控授权，新授权时仅对当前 Local 目标刷新服务。 / The monitor watches for newly granted screen and input permissions. |

共享契约在 [panel_shell.rs](../../shared/protocol/src/panel_shell.rs)，两端分别为 [NSH bridge](../../desktop/nsh-shell/src/panel_bridge.rs) 和 [Panel bridge](../../interfaces/webchat/src/app/shell_bridge.rs)。

## 构建与更新 / Build and update

`just shell-dev` 启动本机 NSH 开发入口，`just shell-build` 构建 Panel 与 Core，再用官方 `nsh package` 生成本机整包。`scripts/nsh_package.sh` 加入随包服务；macOS 同时加入 Swift Bridge 并对最终 bundle 执行临时签名。/ The release matrix builds macOS arm64, Windows x64 and Linux x64 packages from the same source. The NSH macOS package requires macOS 14 or later.

更新器在启动后延迟检查，托盘也可以手动检查。更新器先下载、校验签名和归档，再替换应用并重启。/ Packaged updates use the NSH manifest and detached signature. [Release assets and rollback](RELEASE.md) · [R7 cutover evidence](../superpowers/runs/2026-11-27-nsh-r7-cutover-receipt.md)

## Panel ↔ Daemon 资源嵌入链与刷新

`just wasm` 生成 `interfaces/webchat/dist`，`aleph-server` 构建时嵌入资源。安装包要显示新界面，需要依次重建 Panel、Core 和整包。/ Rebuild the embedded server after changing production Panel assets.

## NSH Panel migration / Panel 迁移

Leptos/WASM 是生产入口。以下 TSX 和 v1 工作通过各自的显式开发入口运行。 / The TSX and v1 slices below remain opt-in.

- **S0 基础 / Foundation:** [Gateway `system.hello`](../../src/gateway/handlers/system_hello.rs) on the legacy `/ws` path follows `connect`; it selects a compatible minor and advertises only implemented features. Its legacy limits are compatibility hints, not enforced bounds. / 旧入口的协商值不等于准入，也不代表旧 WS 已部署 IPC 帧上限。
- **S1-A 共享分发 / Shared dispatch:** The existing `/ws` path uses the [common RPC executor](../../src/gateway/server/connection/rpc.rs), and [Client pending calls](../../shared/client/src/connection/requests.rs) belong to one socket. S1-A itself mounted no listener. [Verification receipt](../superpowers/runs/2026-11-23-nsh-panel-s1a-shared-dispatch-verification.md). / 共享分发与请求隔离已验证，旧生产入口不变。
- **S1-B 本地只读 IPC / Read-only Desktop IPC:** An explicit `--desktop-ipc <socket>` mounts the [Unix listener](../../src/gateway/server/connection/local_ipc.rs) using [bounded frames](../../shared/protocol/src/framing.rs), same-account OS authentication, and the instance's live Core owner. The caller supplies a fresh path in its private directory each launch. The dedicated [NSH status command](../../desktop/nsh-shell/src/ipc_status.rs) queries `health` via the shared Client; WebView still uses its existing transport. / 不回退 TCP/WS；仅允许共享的 [`V1_METHODS`](../../src/gateway/server/connection/mod.rs)（S1 时为 `health`、`sessions.list`、`panel.capabilities.snapshot`；S3 与 Memory Nebula 分别增加会话和只读图谱方法，见下）。[S1-B 回执 / receipt](../superpowers/runs/2026-11-23-nsh-panel-s1b-desktop-ipc-verification.md) records macOS native verification; see the independent [Linux native retest](../superpowers/runs/2026-11-23-nsh-panel-s1b-linux-native-retest.md) for Linux. Windows production still refuses both opt-in commands; the [Windows Named Pipe receipt](../superpowers/runs/2026-11-23-nsh-panel-s1b-windows-named-pipe-verification.md) separates candidate evidence from the missing alternate-account gate. / Windows 生产入口仍拒绝，候选结果不代替异账户验收。
- **S1-C 浏览器只读接入 / Read-only Web v1:** The [native TLS listener](../../src/gateway/server/connection/web_v1.rs) mounts explicit same-origin `POST /v1/session` and `GET /v1/ws`. An active paired device or explicitly user-bound one-time ticket yields a short-lived host-only Cookie; it does not change the Core principal. `system.hello` precedes bounded binary calls limited to the same `V1_METHODS` as Desktop IPC (at S1 `health`, `sessions.list`, `panel.capabilities.snapshot`; S3 and Memory Nebula extend the allowlist with chat and read-only graph methods, below); hello carries an opaque per-principal `subject` (HMAC of the user under the shared-token secret) for client-side layout keys. / [S1-C 验证回执](../superpowers/runs/2026-11-23-nsh-panel-s1c-web-v1-verification.md)记录真实 Chrome 证据；旧 `/ws` 和现有 Panel 不换线，未支持代理终止 TLS。
- **S2 可定制 TSX 壳 / Customizable TSX shell (opt-in):** [`interfaces/panel`](../../interfaces/panel/nsh.json) is one TSX source (shell, layout editor, pairing form, Overview / Sessions / Capabilities modules) plus the Rust UI set [`aleph-panel-ui`](../../interfaces/panel/src/lib.rs) over the shared [panel model](../../shared/ui_logic/src/panel/mod.rs). [`PanelLayout`](../../shared/ui_logic/src/panel/layout.rs) persists only stable tab IDs under `aleph.panel.layout.v1:<endpoint>:<subject>`; a tab the snapshot no longer offers shows as unavailable and never runs. Desktop: the shell's `tsx-panel` feature with `ALEPH_SHELL_PANEL=tsx` mounts one embedded `AppView` ([`panel_surface.rs`](../../desktop/nsh-shell/src/panel_surface.rs); a second is refused) whose [host functions](../../desktop/nsh-shell/src/panel_host.rs) reach the Gateway only through the Desktop IPC socket named by `ALEPH_SHELL_PANEL_IPC`, with no WS fallback (macOS only). Web: [`web/host.js`](../../interfaces/panel/web/host.js) speaks the Web v1 framing, and the Gateway serves the package at `/v1/panel/` with a CSP only when `[gateway] panel_web_dir` is set ([`panel_routes`](../../src/gateway/server/connection/web_v1.rs)). Recipes: `just panel-tsx-test`, `panel-tsx-bundle`, `panel-tsx-web`, `shell-tsx-dev <socket>`. [S2 receipt](../superpowers/runs/2026-11-23-nsh-panel-s2-shell-receipt.md) (macOS real-machine Desktop + Chrome). / 默认渲染仍是 Leptos/WASM；TSX 壳需显式启用，DOM-ABI 社区 tab 在其中显示为不可用。
- **记忆星云 / Memory Nebula (opt-in):** Core advertises `aleph:memory-nebula` only when `graph.query`, `graph.search`, and `graph.node_detail` are registered. Desktop IPC and Web v1 expose exactly those graph reads, never graph mutations; registration is not a readiness promise. The [shared TSX module](../../interfaces/panel/modules/MemoryNebula.tsx) renders the same bounded scene and accessible list on both hosts. It does not fall back to legacy `/ws`. / 三个读取方法挂载才公布入口；运行时停用后仍按原权限与错误语义处理。旧 Leptos 图继续使用原入口，不渲染此 TSX 模块。
- **S3 会话纵切 / Chat slice (in the opt-in TSX shell):** `V1_METHODS` adds `chat.history`, `chat.send`, `chat.abort`; v1 writes keep the idempotency cache (`idempotency_key`). The hello feature `live_events` ([`Feature::LiveEvents`](../../shared/protocol/src/system_hello.rs)) is implemented only by the v1 endpoints (`V1_FEATURES`). Once negotiated, the Gateway pushes id-less frames that pass the same [`admit_event`](../../src/gateway/server/connection/event_admission.rs) as legacy `/ws` (ownership, scope, audience, projection), narrowed to `V1_EVENT_TOPICS` (`stream.run_accepted`, `stream.response_chunk`, `stream.run_complete`, `stream.run_error`, `connection.warning`). An oversized frame becomes `connection.warning` and the connection stays; bus lag sends the warning and closes. There is no replay: Chat refetches `chat.history` after a warning, a dropped desktop frame (`connection.stale`) or a reconnect. Both hosts deliver frames as the host event `aleph.event {topic, data}` ([`panel_host.rs`](../../desktop/nsh-shell/src/panel_host.rs), [`web/host.js`](../../interfaces/panel/web/host.js)); modules subscribe with SDK `on(topicPrefix)`. [`Chat.tsx`](../../interfaces/panel/modules/Chat.tsx): history → send (one v4-format key per attempt, built from `Math.random` because the desktop runtime has no Web Crypto) → streamed preview by `run_id` → refetch; Stop → `chat.abort`; a send lost with the connection is reported as unknown and never retried. Sessions rows open their session in Chat. The providerless (simulated) run path now checks session ownership like the real engine. [S3 receipt](../superpowers/runs/2026-11-24-nsh-panel-s3-chat-receipt.md) (macOS Desktop + Chrome). / v1 端点协商 `live_events` 后推送经同一准入的会话流帧；无重放，断线或告警后重取快照。Linux/Windows、Chrome 内真实输入法、桌面端 Stop 未验证。
- **富会话转录 / Rich Chat transcript:** The opt-in TSX hosts additionally negotiate `chat_transcript`. The bound V1 feed carries sanitized `stream.chat_tool` on the same stream as text; the shared V1 allowlist admits the scoped `chat.transcript_details`, `trace.tool_output`, and `context.breakdown` reads. / 两端共用一个 TSX 会话和 Rust 转录模型；全屏阅读器只切换 Panel 布局，不改变桌面窗口。详见 [Transcript Rendering](TRANSCRIPT_RENDERING.md#41-nsh-chat--nsh-会话) 和 [S3 QA](../../qa/nsh_s3_chat/README.md)。
- **两栏外壳与个人偏好 / Two-column shell and preferences (in the opt-in TSX shell):** [`Shell.tsx`](../../interfaces/panel/shell/Shell.tsx) is a fixed two-column frame: the left menu ([`Sidebar.tsx`](../../interfaces/panel/shell/Sidebar.tsx)) lists the `PanelModel` slots in `PanelLayout` order, then the connection state and a Settings entry that is not a tab, so it opens with no Gateway; only the right column shows the offline/pairing states. [`Settings.tsx`](../../interfaces/panel/shell/Settings.tsx) edits appearance (mode, accent, text size, corners, density), shortcuts, and the menu (the former top-bar Customize editor). Rules live once in the ungated [`shared_ui_logic::prefs`](../../shared/ui_logic/src/prefs/mod.rs) (`PanelPrefs`, `restore`, `theme_tokens`, `score`/`rank`, `resolve_bindings`), also used by the Leptos panel's appearance enums and command palette; TSX reaches them through `PanelModel.prefs / setAppearance / setBinding / normalizeKeystroke / resolveBindings / rankCommands` ([`lib.rs`](../../interfaces/panel/src/lib.rs)). Preferences are client-local under `aleph.panel.prefs.v1` (per device on Desktop; per origin, so per Gateway, on Web), never sent to Core. Commands ([`commands.ts`](../../interfaces/panel/shell/commands.ts)): shell ids `shell.palette` (mod+k), `shell.settings` (mod+,), `shell.scheme`, `shell.reconnect`, `shell.slot.1…9` (mod+1…9 on Desktop only; Chrome keeps them), one `open:<tab key>` per menu entry, and module commands from `sdk.commands.register` with ids `<tab key>/<local id>`, dropped with the module's SDK; in a conflict the command earlier in the list keeps the key and the later one loses it and is marked, a key the OS reserves disables only its own command. Text size goes through host function `aleph.fontScale` (Desktop: [`panel_surface.rs`](../../desktop/nsh-shell/src/panel_surface.rs) → `AppView::set_font_scale` on the main queue; Web: root font size in [`web/host.js`](../../interfaces/panel/web/host.js)); `null` follows the system. The Panel root takes the keyboard focus on its first sized layout, since NSH routes a surface's shortcuts only while the focus is inside it. [Receipt](../superpowers/runs/2026-11-24-nsh-panel-prefs-receipt.md) (macOS Desktop + Chrome; Linux/Windows not verified). / 固定两栏、设置不是 tab、偏好仅存客户端；Leptos 与 TSX 共用 `shared_ui_logic::prefs` 规则。
- **整轮语音 / Whole-turn voice (opt-in TSX):** A [shared status-only surface](../../interfaces/panel/modules/Voice.tsx) uses the ordinary Chat run, one bounded capture and transcription per turn, and one synthesis request after the matching final response. The native host uses Desktop IPC for private capture and owns playback; paired Web v1 captures in the browser and uses configured providers only. / TSX 语音仅呈现状态与操作，沿用 Chat 会话、不渲染语音文本；原生录音由 Desktop IPC 隔离，浏览器配对不继承离线识别权限。Neither path changes legacy Leptos voice, the default mount, or the release gate. / 不切换默认入口或发版门禁。
- **第六轮：会话恢复与历史翻页 / R6 session continuity and scrollback:** The opt-in TSX Shell keeps the selected conversation in memory while its endpoint and nonempty subject still match. A different identity clears the selection and any unknown-send notice; unconfirmed identities do not restore across connections. Chat re-reads Core history before enabling sends to that conversation and never auto-retries a send whose acknowledgement was lost. Tail and older-page reads share the existing `chat.history` admission; `scrollback` follows stable projected IDs and never grants access. A stale boundary calls for a new tail read; `before` retains its legacy timestamp semantics. Both mounts use the same keyed list and Rust merge model. `chat.transcript_details` still checks its latest 500 projection rows for run ownership; older prose is readable even when tool details are not. / 同端点、同一已确认主体仅在当前应用实例内恢复。结果未知时不补发；旧时间戳读法未变。没有持久事件重放，不改变默认宿主。测试入口：[continuity QA](../../qa/nsh_s3_chat/README.md)。
