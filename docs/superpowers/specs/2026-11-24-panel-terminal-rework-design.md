# Panel 终端可靠性与交互重构 / Panel terminal recovery and interaction

> 设计于 2026-11-24 获批。本文描述目标行为，不是当前架构契约。 / Design approved on 2026-11-24. This document describes intended behavior, not the current architecture contract.

## 目标与范围 / Intent and scope

把当前 Panel 的终端修到可日常使用：切换页面不误开或误关 shell，断线和缺帧能恢复到真实屏幕，输入失败可见，能用 IME 输入、复制终端文字并回看滚屏历史。用户已选择覆盖**默认宽屏 Webchat 与可选的模块化 Webchat**，两者继续共用 `aleph-terminal-ui`。既有 Gateway `PtyManager`、VT 屏幕、会话所有权、Capability admission、配置生命周期和多连接尺寸仲裁不交给 UI 或宿主。

Make both current Webchat mounts usable for daily terminal work: explicit shell lifecycle, recovery from disconnects and gaps, visible input failures, IME, copy, and scrollback. The same Rust/WASM presentation serves both mounts. The existing Core terminal Capability remains authoritative for processes, screens, policy, ownership and viewport arbitration.

**不做 / Non-goals:** 候选 `interfaces/panel` TSX、Desktop IPC/Web v1 写入口、手机端、TUI 改版、分屏、跨进程重启恢复、持久化 transcript、新 PTY/VT 引擎。不上报终端内容，不削弱授权，不自动重放不确定是否送达的操作，不在没有测量结果的情况下宣称更快。 / No TSX candidate mount, v1 write surface, phone/TUI redesign, splits, restart recovery, durable transcript, or replacement emulator. No terminal content telemetry, authorization regression, ambiguous effect replay, or unmeasured performance claim.

## 对比与方案 / Gap analysis and approaches

| 维度 / Dimension | 参考证据 / Reference evidence | Aleph 处理 / Decision |
|---|---|---|
| 会话、挂载、恢复 / Session, mount, recovery | t3code `b427708979`: `packages/client-runtime/src/state/terminal.ts` distinguishes initial attach from resume; `apps/web/src/components/PersistentThreadTerminals.tsx` separates view visibility from lifetime. | Keep server-assigned IDs and the existing attach semantics. Give the two current mounts one recovery policy. Opening the panel or recovering a connection never spawns a shell. |
| 背压 / Backpressure | t3code `apps/server/src/terminal/OutputProtocol.ts` budgets output and resyncs after overflow. | Keep sequenced grid frames and snapshots, not a credit protocol or raw VT replay. Bound UI queues and signal loss; recover through the existing attach. |
| 输入与焦点 / Input and focus | t3code `apps/web/src/components/terminal/terminalInputWriter.ts` serializes split writes; NSH `5e3b0f78a` `examples/gallery/demos/TerminalDemo.tsx` and [Terminal docs](https://nsh.dev/elements/terminal/) show committed composition and platform focus. | Order input, retain safe existing paste framing, isolate view focus from process lifetime, and never retry uncertain input. No new client parser. |
| 渲染与历史 / Rendering and history | [NSH App Stories](https://nsh.dev/apps/) is a discovery index. TermLevel `1f46e6a`, `docs/architecture/terminal.md`, keeps high-frequency terminal state in Rust; t3code `apps/server/src/terminal/Manager.ts` owns bounded history. | Use the existing Rust cell grid and history ring. Keep history out of hot frames and normal attach; do not persist raw streams. |

1. **选定：先重构当前 Panel / Selected: current Panel first.** Two mounts share a view and already talk to the production PTY Capability. This repairs shipping behavior without widening the experimental transport. The trade-off is that the TSX candidate remains without a terminal and will need its own transport design later.
2. **未选：同期接入 TSX / Not selected: include TSX.** `interfaces/panel/shell/sdk.ts` only exposes connection subscriptions; `src/gateway/server/connection/mod.rs` mounts only three read-only v1 methods. Adding a terminal there would require authenticated PTY writes, exact event delivery and backpressure across both v1 transports, not just a tab. No legacy WebSocket bypass.
3. **排除：换终端引擎 / Rejected: replace the emulator.** Using native NSH Terminal or Ghostty to parse a second raw stream would duplicate Aleph's server VT, modes, answers and history. Borrow UI behavior, not engine ownership.

## A. 先连线并修复 / Wire and stabilize first

- **同一订阅租约 / Shared coverage.** Default adapter switches from direct ephemeral subscribe/unsubscribe to `DashboardState::acquire_pty_topic` / `PtyTopicLease`; the modular SDK retains authorization, permission and lease checks. The terminal controller consumes confirmed coverage for exactly `pty.screen` and `pty.exit` on the current connection epoch before list/attach. Failed or stale partial acquisition drops both leases. A new epoch cannot be unsubscribed by an old cleanup. Local coverage/queue loss must be observable to the controller; preserve the existing in-tree SDK ABI where possible and keep generic non-PTY subscription behavior unchanged.
- **一个恢复流程 / One recovery loop.** Make ownership, connection epoch, selection revision and session ID the validation boundary for asynchronous responses. A delayed old list/attach cannot change the current tabs, screen or error state. Do not apply a reconnect list that predates a successful local spawn/close. After recovery, reconcile the authorized list and retain a still-available selected tab. Never treat an error as an empty list. Hide/detach the UI and release its observers/listeners/timers; only explicit close asks Core to stop the shell. A hidden legacy route must not acquire or retain unnecessary UI observers, timers or topic leases. The existing Core viewport constraint remains connection-scoped: hiding a view does not implicitly release it, and connection teardown still does. A new viewport ownership protocol is outside this design.
- **Snapshot then contiguous deltas.** Reuse `ClientScreen` and the canonical `pty.attach` snapshot. Deduplicate by `seq`; reject stale snapshots, wrong-session frames and noncontiguous replay. Bound both queued event delivery and in-flight attach staging by count and bytes; when a bound is hit, discard incomplete staging and mark it uncertain instead of applying a partial replay. An observed gap, overflow, or drain failure requests recovery without waiting for another frame. Reconcile the list as well when an exit notification may have been lost. Use one recovery in flight per current selection, bounded backoff and a visible manual retry after persistent failure. A new epoch or selection resets the relevant retry budget; idle steady state does not poll snapshots. This is recovery from observed loss, not a durable event guarantee.
- **显式副作用 / Explicit shell effects.** The blank state offers **New terminal**. Opening the route, remounting, reconnecting and closing the last tab never call `pty.spawn`. Disable the relevant action while a spawn or close is pending. Adopt a confirmed spawn once through the tab model; if an effect's outcome is unknown, refresh with `pty.list` rather than sending it again. Preserve Core's existing close/exit semantics and submit no commands from the background.
- **真实状态 / Honest status.** Preserve the last painted screen during transient recovery and label it reconnecting or stale. Show a retry action after bounded recovery stops. On confirmed absence, clear the selected view. Surface list, attach, input and resize failures without falsely claiming completion. Keep error updates scoped to the relevant owner, selection and epoch. Do not log keystrokes, pasted data, or private output.

## B. 再增强输入、显示和历史 / Then improve input, display and history

- **输入 / Input.** Keep the existing keymap for control/navigation keys. Use a focusable text-entry surface for IME and paste, tied to the visible selected terminal. Only committed composition is sent, exactly once; intermediate, canceled or stale composition is not sent. Existing bracketed paste is encoded as one UTF-8 input RPC when it fits `MAX_PTY_INPUT_BYTES` (65,536 bytes including framing); reject oversized paste with feedback before sending anything rather than splitting a bracketed operation across ambiguous RPCs. A bounded, per-selection FIFO serializes writes; flush pending local work on selection/epoch invalidation or unmount, never auto-retry writes. An already dispatched call is not claimed canceled; presenting an uncertain error does not authorize replay.
- **焦点、选择、尺寸 / Focus, selection, resize.** On explicit selection or New, restore terminal focus only if the terminal is still visible and the gesture has not been superseded; background updates do not steal focus. Hide/blur clears transient composition and drag interaction without changing PTY modes. Provide keyboard and pointer copy for selected painted text, including wide text; Ctrl+C without an active selection retains its existing terminal behavior (respect the platform shortcut convention). Keep one geometry calculation and coalesce rapid changes to the latest actual size; report it after an attach/switch/reconnect even if it equals the prior local size. Core remains the arbiter of actual frame dimensions. Release the ResizeObserver callback and cancel or invalidate outstanding animation work on teardown. Reuse existing styling and localized strings for the two mounts.
- **滚屏契约 / History contract.** Add a bounded read-only `pty.history` face using the same current-session `TerminalCapabilitySource` and ownership, live policy and generation checks as `pty.attach`. Define its operation, request and response in the shared Rust protocol; wire the actual Gateway registration and the built-in modular terminal permission. It is not an independent provider, not a v1 method, and does not attach a viewport. Use typed rows from the **existing** primary-screen ring (same styled-run conversion as screen patches), not ANSI, not a second copy of server history. Under the canonical screen lock, derive stable session-local row indices and select a page strictly before an optional exclusive cursor. No cursor means newest retained rows. Return oldest-to-newest rows, an older-page cursor only if more are retained, and an explicit evicted indication if the cursor predates the retained range. Eviction never reuses indices. Update the UI only for the current session, selection and connection. Bound each response by rows **and** serialized bytes; page construction must make bounded progress even under dense styling and report any single over-budget row explicitly, not silently skip it. The builder may choose conservative numeric page/cache bounds and encoding strategy subject to existing frame limits and test those boundaries.
- **滚屏交互 / History UI.** Fetch the recent page on demand; scroll or request older pages without shifting a non-bottom viewport as live frames arrive. Bound the client page cache. Provide **Back to live**; disable history in the alternate screen, and route keyboard input only to an explicitly active live terminal. History does not become editable and cannot trigger terminal replies. An old Gateway returning method-not-found leaves ordinary attach/input operational and visibly marks history unavailable. An empty page means no retained history, not a permission or transport failure. No search, export, clipboard upload or history across a stopped session in this iteration.

Example behavior, not a visual redesign / 交互示例，不更换视觉风格：

```text
No terminals yet. [New terminal]
[Shell ×] [+]  Reconnecting…          (last confirmed screen stays visible)
[Shell ×] [+]  History  [Older] [Back to live]
```

## 交付、清理与边界验证 / Delivery, cleanup and acceptance

- Land the reliability path first in the isolated `panel-terminal-rework` worktree. Remove terminal-only raw subscribe/unsubscribe, auto-spawn predicate and obsolete first-load paths, silent failure handling and leaked callback lifetime code when their replacements land. Do not remove shared generic subscription helpers or either mount while it is still used. After enhancement, audit permission/method faces, locales, docs and obsolete test expectations; update `docs/reference/FEATURE_LOCATOR.md`, `docs/reference/TERMINAL_RUNTIME.md` and any affected current references. Record the evidence separately from current contracts.
- Exercise state transitions with controlled out-of-order operations and real render assertions: initial subscribe failure then recovery, detach with partial acquisition, reconnect with delayed old success and failure, selection changes, gap during replay with no subsequent frame, both overflow paths, all shells closed, ambiguous spawn/close, and stale-input cancellation without replay. Test canonical history eviction and cursors with output still arriving, permission denial for another principal, provider revoke, alternate screen, old Gateway fallback, and multibyte paste limits.
- Compile and run relevant Rust/Panel tests in the isolated worktree. Rebuild the shipped default `interfaces/webchat/dist/` through `just wasm`, check the matching JS/WASM and Brotli assets, and commit the matching production artifact with the source changes. Use a separately built modular artifact for the existing host/protocol browser fixtures. Exercise the default Webchat route against its rebuilt asset as well. Verify recovery, scrollback, focus, cleanup and actual shell effects against an isolated live Gateway on the available platform; fixture-only coverage is not live evidence. Report native platform and IME gaps explicitly. Compare bounded queue/call counts and screen convergence with the existing path; defer parallel processing or other optimization until measurements justify it.
- Do not modify or merge `main`, push, or change the default desktop host. Commit the reviewed design, the implementation changes and the corresponding documentation only on `panel-terminal-rework`.
