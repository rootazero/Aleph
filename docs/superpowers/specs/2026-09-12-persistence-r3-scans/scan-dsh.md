# deepseek-harness — persistence / recovery pipeline scan

Read-only scan of `T:\Github\deepseek-harness` (main checkout, 2026-09-12). Note: the graphify graph is **stale** vs. source — it names `packages/session/session-persistence-sqlite/src/store.ts` and `session-persistence/src/coordinator.ts`, neither of which exists. Anchors below are from the live source, not the graph. Paths are relative to the repo root; `session-persistence-jsonl/` = `packages/session/session-persistence-jsonl/`.

## 1. The durable log / store

- **JSONL is the only session store; SQLite is derived-only.** One append-only log per session under `<root>/--<normalized-cwd>--/<encoded-id>/session.v3.jsonl[.zstd]`. The `SessionPersistence` service is `create/open/stat/list`, each returning a per-session `SessionHandle{read,append,flush,close}` — `packages/session/session-persistence/src/index.ts:1-201`; layout in `session-persistence-jsonl/README.md:60-80`.
- **Physical framing**: default is a concatenation of independent **checksummed Zstandard frames** (`ZSTD_c_checksumFlag: 1`), one frame for the header line and one per append batch — `session-persistence-jsonl/src/zstd.ts:19,48-116`. `compression: 'none'` writes raw newline-delimited lines. A root belongs to one encoding; mixed roots are rejected.
- **Record shape**: one JSON row per event; `sourceEventSeqs` runs of >=3 are stored as `[start,end]` pairs and expanded on read. Header line is `{type:'session', version, id, createdAt, cwd?, parentSession?, isSeeded, origin?, delegationDepth?, agentPreset?}` — `session-persistence-jsonl/src/format.ts:158-180`.
- **Materialize = temp-write + fsync + `link()` (never `rename`) + parent-directory fsync**; `link` EEXIST makes same-id races fail instead of clobbering — `session-persistence-jsonl/src/index.ts:1097-1160`. Windows uses write-through publish without replacement (`src/win32.ts`). `create()` writes nothing; the first `append` (or an explicit `flush`) materializes.
- **Append = write + `fsync` per batch; on write/sync failure `ftruncate` back to the prior length + fsync** so a retry cannot duplicate seqs — `index.ts:1246-1284` (`appendLines`, `rollbackAppend`).
- **Write-behind window**: `session/event` is a synchronous Cordis emit; the backend clones the event into the active write handle's buffer and arms a fixed `LIVE_WRITE_BATCH_MAX_DELAY_MS = 200` timer; `session/flush` cancels the wait, drains, and is the only durability barrier; `session/disposed` and backend teardown drain through `close()` — `session-persistence-jsonl/src/storage.ts:36,274-300,536-560`; the single flush entry point is `packages/core/session/src/index.ts:1144-1160`.
- **Cross-process single writer**: kernel `flock(2)` on `session.lock` beside the log (Win32: named kernel semaphore, no file); no expiry by design ("there is deliberately no expiry that could expropriate a stalled writer"); a crashed holder's lock dies with the process; POSIX re-verifies the locked inode still matches the path — `session-persistence-jsonl/src/lease.ts:1-45`. Two-process proof: `tests/lease.two-process.e2e.ts:34`. In-process, a second `open(id,'write')` rejects with `SessionAlreadyOwnedError`.
- **Corruption vs. torn tail**: a torn final Zstandard frame contributes only its complete decoded records; the write path truncates the torn bytes and re-appends the recovered records durably before its first new batch — `index.ts:889-963` (decode), `storage.ts:318-345` (`persistContiguous`). A raw-mode torn tail is one incomplete line, discarded. Checksum/structural failure inside a *complete* frame is `SessionPersistenceCorruptionError`; a future header version is `SessionFormatUnsupportedError` (distinct, fail-closed, carries the raw path in `SessionLocation`).
- **Schema versioning**: `SESSION_FORMAT_VERSION = 3` at `packages/core/session/src/types.ts:88` is the only hand-maintained writer number; `docs/session-format-status.md` records the latest *released* version (3, tag `dsh-v0.1.5-alpha.1`). Generations are immutable files (`session.jsonl` = v0, `session.v1.jsonl`, `.v2`, `.v3`, never renamed/replaced/deleted); adjacent migration packages `session-format-v0-to-v1`, `v1-to-v2`, `v2-to-v3` each own one step; a read-open migrates in memory; a write-open encodes the successor in ~1 MiB chunks, verifies it in a Worker Thread, re-checks the source revision, and publishes without overwrite — `session-persistence-jsonl/src/generation.ts:68-230`, `src/migration-verifier.ts:99`. Unknown event types refuse the log unless the envelope carries `ignorable: true` — `packages/core/session/src/known-event-types.ts:9-23` (generated list).
- **Rotation: NOT FOUND. Deletion: NOT FOUND** ("Nothing deletes session files" — README limitations). `stat/list` expose `sizeBytes` and a best-effort `revision` (device+inode+size+ns-mtime).

## 2. Event vocabulary (generated `docs/persistence-catalog.md`, 55 kinds)

- **Envelope**: `{type, seq (contiguous from 0), time (epoch ms), data, ignorable?, surfaceOp?, sourceEventSeqs?}` — `types.ts:404-495`. Only four **surface** types produce model messages: `system/message`, `user/message`, `assistant/message`, `tool/result`. Everything else is **log-only**: durable, replayable, never model history. All payloads must be lossless JSON (validated at `Session.append`, `core/session/src/index.ts` ~L520).
- **Turn structure**: `turn/start{turn}`, `step/start`, `step/end`, `turn/end{turn, reason}` with `reason.kind ∈ completed | aborted{reason} | blocked | error{LlmFailure} | max-tokens | interrupted` — `types.ts:200-221`. **Cancel** = `turn/end{aborted}` plus `assistant/message{interrupted:true}` holding the delivered prefix.
- **Model I/O**: `assistant/message{turn,step,message,stream,usage?,interrupted?}` **embeds the exact timed provider stream and token usage**; `assistant/attempt{turn,step,stream}` keeps failed/retried/cancelled/stream-error attempts without adding history; `request/header{header, reason: initial|resume|change|series, startsSeries?}`; `request/context{provider,model,contextWindow?,systemPromptUpdate?}`; `llm/retry`, `llm/retry-started`.
- **Tools**: `tool/call{turn,step,callId,name,arguments}` (log-only) ↔ `tool/result{turn,step,message,error?,meta?}` (surface, `sourceEventSeqs:[callSeq]`); `tool/ptc-dispatch-start`, `tool/ptc-dispatch` (programmatic tool calling).
- **Compaction**: `compaction/start{turn|null}`, `compaction/summary{summary, rawOutput?, llmStreamCall?, shadowedRange, shadowedSeqs, shadowedTokenCount, provider, model, usage?}`, `compaction/end{turn, error?}` — log-only lock bracket; the summary itself is a normal `user/message` with `surfaceOp:{op:'replace',startSeq,endSeq}`. `compaction/prune` records tool-result pruning replacements.
- **Config-as-events, last write wins**: `model/selection`, `permission/preset`, `approval/policy{policy, source?:'delegation'}`, `plan/mode{active}`, `sandbox/mode`, `agent-preset/selected`, `goal/change`, `schedule/change`, `todo/write{todos}` (whole list).
- **Lifecycle**: `session/end-seed{inherited?}` — written only by the `Session` constructor; marks the seed/live boundary and (tagged) the exact fork cut; also the epoch marker that makes an unmatched `compaction/start` from a dead lifecycle "stale". `session/title`, `session/title-llm-request`, `session-log-deepseek/delivery-accepted{throughSeq}` (incremental upload of the log as DeepSeek request metadata). `agent/inbox/spliced{target,start,removedCount?,inserted,outcome?}` — the durable queued/steer/next-step message lists.
- **Interaction**: `command/run{commandId,name,args?,source}` / `command/done{commandId,kind,text?,sourceEventSeq?}`; `approval/asked{id,toolName,callId?,reason?}` / `approval/decided{id,outcome}`; `hook/invoked{turn,point,dialect,matcher?,handlerId}` / `hook/result{...,decision,exitCode?,stderrSummary?,durationMs}`; `feedback/*`; `deliverables/presented`.
- **Multi-agent**: `subagent/descriptor` (child-owned, versioned), `subagent/catalog{childId,childCreatedAt,mode,label?}` (parent-owned), `subagent/model-selection-policy`; `team/member`, `team/task`, `team/message/queued`, `team/message/delivered` (all `version: 2`, whole snapshots); `tool-workflow/run-start|run-end|agent-start|agent-end`.
- **Facts vs derived**: the log holds facts only; every "state" (inbox, plan, permission, turn boundary, subagent identity, team board, title, stats, outline) is a projection unit folded from it. **NOT FOUND**: dedicated `skill/*`, `mcp/*`, plugin-mount, or thinking/reasoning events (reasoning lives inside the embedded assistant stream).

## 3. Checkpoints / snapshots

- **Semantic checkpoint policy** (three flush barriers, no config, no state): before the LLM stream is constructed (`llm/stream` waterfall), before a *top-level* tool body runs (`tools/execute`, after pre-execute/approval/guards; nested dispatches reuse the outer checkpoint), and at every `agent/pre-step` — `packages/session/session-checkpoint-policy/src/index.ts:63-81`. Fail-closed: adapter/tool body does not run if the flush rejects; cancellation while the tool flush is pending returns `ABORTED_BEFORE_DISPATCH` without entering the body.
- **Projection checkpoint cache**: one `{identity, rows:{unitKey:{ver,seq,val}}}` JSON per session under `<storages>/session_projcache/sessions/<id>.json`; written at create, `turn/end`, dispose, plus `writeEveryEvents` / `writeIntervalMs` throttles; identity = `formatVersion + createdAt + cwd + isSeeded + inheritedEventCount`; "the log leads, the cache follows" (cache row written only after the session flush); schema-invalid rows are moved to `.bak.<stamp>` — `packages/session/session-projection-cache/src/index.ts:114-200,292,363,379`; README "What the cache guarantees".
- **Workspace / file snapshot / undo / rewind: NOT FOUND.** No shadow git repo, no edit backups, no rewind command (`packages/fs/*`, `packages/workspace/*`; only `tool-str-replace-editor` in-memory ops).
- **Fork** = physical copy of the prefix up to the nearest completed `turn/end` into a *new* session id, with `isSeeded:true`, `inheritedEventCount = cut`, `parentSession`; the constructor appends `session/end-seed{inherited:true}` at the cut — `packages/api/session-controller/src/commands.ts:202-290`. No shared-ancestry storage: each fork duplicates bytes.
- "Resume from checkpoint" in the DB sense = cold projection folds skip the checkpointed prefix (`coldSnapshot`), never the event log itself.

## 4. Reduction to run state

- **Resume path** (`packages/core/agent-loop/src/index.ts:853-928`, `resumeWith`): `persistence.open(id,'write')` FIRST (excludes a concurrent resume; a live agent's handle holds the claim so `resume cannot crash-repair a turn owned by a live agent`), cold `handle.read(0)`, compute `interruptedTurnClosers(persisted)`, **append the closers through the same handle before publishing**, then `sessions.prepare({seed:[...persisted,...closers], meta: header, inheritedEventCount, eventState})` → `SessionPreparation` → setup → publish. Rollback closes the handle on any failure.
- **The reducer for a dangling turn** is `packages/core/session/src/repair.ts:27-135`: scans turn/step boundaries, registers tool-call blocks from `assistant/message`, records the `tool/call` seq, deletes on `tool/result`. Pending calls get synthetic error `tool/result`s — `TOOL_NOT_STARTED` (assistant block but no `tool/call`: "retry if still needed") or `TOOL_OUTCOME_UNKNOWN` (call recorded, no result: "retry only if read-only/idempotent; verify external state or ask the user") — then a synthetic `step/end` and `turn/end{interrupted}`; seqs continue the log, timestamps reuse the last real event (deterministic). `interrupted` is the one `TurnEndReason` no loop emits live.
- **Per-domain state** is rebuilt by pure projection units driven by `ctx.sessionProjections` on `session/created` (folds the seed) and every committed `session/event` — `packages/session/session-projection/src/index.ts:183-225`; e.g. inbox (`agent-loop/src/inbox.ts:32,188`), `turnBoundary` (`core/agent/src/types.ts:60-78`), plan, permission, subagent identity (last-wins, own-suffix seq gate), team (`agent-team/src/projection.ts`), schedule.
- **In-flight approvals**: `tool/call` is appended *before* `prepare()` (pre-execute → approval ask) — `agent-loop/src/tool-calls.ts:166-170,264`. A crash while awaiting approval therefore resumes as `TOOL_OUTCOME_UNKNOWN` though nothing ran; the unmatched `approval/asked` (no `approval/decided`) is available but the reducer does not consult it. Calls skipped after cancellation get a durable `tool/call`+`tool/result{TOOL_ABORTED_BEFORE_DISPATCH}` pair (`tool-calls.ts:245-260`).
- **Partial output**: only settled `assistant/message` / `assistant/attempt` are durable; "a hard process loss before settlement leaves no durable attempt stream" (`docs/architecture.md` §Session log). A *cooperative* cancel does finalize the delivered prefix as `assistant/message{interrupted:true}`.
- **Compaction crash**: an orphaned `compaction/start` blocks every compaction entry point unless a newer `session/end-seed` proves it belongs to a dead lifecycle — `packages/compaction/compaction/src/invariant.ts:116-132,303-306`.
- **Queued messages survive restart** via the `agent/inbox/spliced` fold; the inbox is the only queue (no second FIFO) — `docs/subsystems/subagent.md` "Continuable children".

## 5. Reduction to model context

- `deriveMessages()` folds only the ordered **surface** — `packages/core/session/src/surface.ts:487-566` (`foldSurface`, `SurfaceManager`). `surfaceOp:'append'` adds a node; `{op:'replace',startSeq,endSeq}` shadows a positional range; `sourceEventSeqs` must include every shadowed node, validated at `Session.append` (`surface.ts:300-302,437-439`). System prompt is surface node 0 (`system/message`); an empty rendering clears all system nodes.
- **Compaction** summary rides a `user/message` replace; the `compaction/end` lands last so a crash reads as an orphaned lock, never a false "done"; `compaction/summary` logs provider/model/usage/rawOutput so the one-shot request is reconstructable from log + code (`docs/subsystems/compaction.md:9-24`).
- **Prefix-cache protection across resume**: `foldRequestHeader` reconstructs the `EpochHeader{config, adapterDefaults?, tools?}` from the latest `request/header` snapshot (`core/session/src/request-header.ts:60-69`); the loop logs `initial` on first request, `resume` on the first request after a resume, `change` only when `headerEquals` fails, and `series` when the surface `replaceGeneration` moved (any replace — compaction, prune, or the resume repair append — starts a new request series) — `agent-loop/src/agent.ts:552-581`. Requests are frozen once and reuse frozen `Message` identities via a `WeakSet` so an unchanged prefix stays byte-identical (`agent.ts:93,605-610`). Cross-checked by `agent-loop/tests/request-cache.e2e.ts` and `request-reconstruction.spec.ts`.
- **"Model-visible ⟺ logged"** is enforced by a runtime invariant (`packages/core/session/src/invariant.ts`); a new model-visible input requires a new `SessionEventMap` member.
- `request/context` (route/contextWindow/systemPromptUpdate) is logged only on change and does not participate in header equality — `types.ts:371-377`.

## 6. Reduction to UI

- **Session listing** reads headers + identity-checked projection-cache hints only, never bodies ("a cache or Session-format upgrade never turns startup into a body scan" — `docs/subsystems/persistence.md` "Lightweight source revisions"); `cachedPredecessorTitle` may serve a stale title with sentinel `asOfSeq:-1` across a format edge.
- **Follow protocol** (`packages/api/session-controller/src/history.ts:119-240`): subscribe to `session/event`, `session/created`, and optionally `agent/assistant-stream` *before* the cold read; yield one `snapshot{header, cursor, records (paged), hasMore, projections{asOfSeq,values}, assistantStream?}`; then a gap-free tail — events below the cursor are dropped, a seq skip throws `gateway/internal`; on `session/created` after the snapshot, replay `snapshotEvents(cursor+1)`. A prepared (cold) session is promoted to live under the same follow.
- **In-flight assistant stream for late joiners** is a process-local accumulator with a `revision` (`history.ts:181-186`); Client continuity validation handles revision resets. Not durable.
- **Transcript reconstruction on the client**: Web Chat nodes derive from raw events plus persisted `tool/result.meta` (per-tool presentation payload "persisted so a UI bridge reproduces the card on replay", `tool-calls.ts:284-288`); `command/done.sourceEventSeq` lets a command card point at its domain event.
- Session-query keeps a bounded cold-read cache keyed on `stat().revision` and balances interrupted turns **in memory only** (never writes) — `packages/session-query/session-query/src/index.ts:121-130`, `docs/subsystems/persistence.md` "Crash recovery".
- Backwards paging uses a durable `throughSeq` cursor (`history.ts:73-92`).

## 7. Skills / plugins / MCP

- **MCP**: nothing persisted about servers or tool lists; reconnect is exponential backoff 500 ms → 30 s, 10 consecutive failures remove the tools until config reload — `packages/mcp/mcp-client/README.md:88-92`. An in-flight MCP call across restart is just an unmatched `tool/call` → `TOOL_OUTCOME_UNKNOWN`. Result images go to a content-addressed attachment store `<DSH_HOME>/attachments/v1` (never deleted, deduped) and are referenced from the log — `packages/attachment/attachment-local/README.md:53-55`; inline base64 never enters a session event.
- **Skills**: invocation is an ordinary `tool/call{name:'skill'}` / `tool/result`; **no `skill/*` event** (`packages/skill/tool-skill`). The skill catalog/loader is rebuilt from the filesystem at boot.
- **Hooks** (Claude Code / Codex bridges): `hook/invoked` / `hook/result` paired by `handlerId` — `packages/hooks/hook-protocol/src/types.ts:19-31`. A crash between them leaves an unmatched invoke; nothing re-runs the hook.
- **Plugin composition is not in the log**: `agent-preset/selected` (`packages/preset/agent-presets/src/session.ts:28`) plus header `agentPreset` record which preset composed the session, so resume re-composes the same tools/prompt; the actual Cordis tree comes from profile + patch files at boot. `subagent/model-selection-policy` records the allowed child routes before the first request.
- Terminal sessions do not survive process exit (`packages/terminal/terminal-bash/README.md:169`).

## 8. Subagents / multi-agent

- Each child is its **own session** with its own log; the header carries `parentSession`, `origin:'subagent'`, `delegationDepth` (persisted "so a recursion budget survives restart and resume"), `agentPreset` — `types.ts:61-130`. The parent logs `subagent/catalog{childId, childCreatedAt, mode, label}` (`packages/subagent/subagent/src/catalog.ts:21-40`, chunked-list projection); the child logs a versioned `subagent/descriptor{version:3, mode:'one-shot'|'continuable', provider, label, agentProvider?, agentModel?, reasoningEffort?, toolRestriction?}` inside its initial turn before its first request (`src/descriptor.ts:48-100`).
- **Continuable children**: at most one process-local Activation per session; `sendMessage` to an inactive child cold-resumes it; the Agent inbox is the only queue; final settlement awaits `sessions.flush` but tolerates failure (persisted state may then be stale) — `docs/subsystems/subagent.md:124-200`.
- **Enumeration** (`listChildren`/`listDescendants`) is a three-rung ladder: live watermark cache → projection checkpoint cache → cold `observeSession` fold; corrupt/unknown descriptors yield a `corrupt` diagnostic rather than hiding siblings — `subagent.md:267-290`.
- **Parent dies mid-one-shot**: the child log survives orphaned; parent resume yields `TOOL_OUTCOME_UNKNOWN` for the delegation call; there is no reattach or result harvesting from the child log. Child settlement never writes back into the parent log.
- **Agent Teams (experimental)**: roster/task/mailbox live in the Lead's session; `team/task` is a whole snapshot with `revision` compare-and-set; `blockedBy` DAG validated acyclic; `writeScopes` are advisory prefixes, **not locks**; owners are never auto-released; single-process only — `docs/subsystems/agent-team.md:56-84`, `packages/experimental/agent-team/README.md:32,128-132`. **No task lease/claim expiry anywhere in the repo.**

## 9. Recoverable side-effects & durability primitives

- **Intent-before-execute**: `team/message/queued` appended + flushed before dispatch; `team/message/delivered` only after the target durably holds the message in its inbox or history; recovery re-dispatches queued-minus-delivered in order and de-dups on the target by `TeamMessageSource.messageId` folded across inbox + history — `packages/experimental/agent-team/src/mailbox.ts:117-150,272-300,316-330`. `team/member{status:'provisioning'}` is flushed before the provider creates the child and reconciled on recovery against the child's own persisted session (`README.md:128`).
- **Two-phase markers throughout**: `tool/call`→`tool/result`, `compaction/start`→`end`, `hook/invoked`→`result`, `approval/asked`→`decided`, `llm/retry`→`retry-started`, `step/start`→`end`, `turn/start`→`end`, `command/run`→`done`, `tool-workflow/run-start`→`run-end`.
- **Schedule**: "persistence before decision" — every read/decision awaits the flush barrier; create/delete confirm only after a second post-append barrier, otherwise report `persistence_uncertain` and tell the model to re-list — `packages/schedule/schedule/README.md:42,80-82`.
- **Idempotency keys**: `seq` contiguity (`assertContiguous`, `storage.ts:323`), `callId`, `commandId`, `ApprovalRequestId`, `handlerId`, `TeamMessageId`, `CompactionId`. Every cross-boundary id is branded.
- **SQLite** appears only in derived stores: `storage-sqlite` (`PRAGMA user_version = 1`, `journal_mode` WAL by default, **no explicit transactions**, per-op atomicity from SQLite — `packages/storage/storage-sqlite/src/schema.ts:20,79`, `src/unit.ts:5`) and the FTS5 session-search index (`SESSION_QUERY_SQLITE_SCHEMA_VERSION = 8`, `BEGIN IMMEDIATE` batches, `application_id` check, and **schema mismatch = drop and rebuild the derived tables** — `packages/session-query/session-query-sqlite/src/schema.ts:8,56-70`, `src/index.ts:454-480`).
- **Storage-json** (used by the projection cache and settings) writes atomically through a per-record domain write chain with `invalidRecords:'backup-and-skip'` (`packages/storage/storage-json/src/atomic.ts`).
- **Leases with expiry: NOT FOUND.** Write ownership is a kernel lock bound to process life; team task ownership is manual.

## 10. Slash commands

- Every resolved command is logged as `command/run{commandId, name, args?, source}` when its handler starts and `command/done{commandId, kind:'success'|'error', text?, sourceEventSeq?}` when it settles — `packages/interaction/commands/src/index.ts:373-436,457`; an invariant checks the pairing (`src/invariant.ts:24`). `recordInput:false` omits `args` when a domain event already owns the payload.
- Commands are **never replayed**; they dispatch without a model turn and are audit + UI records. State-mutating commands write their own authoritative domain events, which *are* folded on resume: `/compact` → `compaction/*` + `user/message` replace; plan-mode toggle → `plan/mode`; permission preset → `permission/preset` + knob events; model switch → `model/selection`; sandbox switch → `sandbox/mode`; `/resume`-style prior-work retrieval reads the FTS index.

## Top 8 patterns worth porting to a Rust core

1. **`interruptedTurnClosers` as a pure function over the log** with two explicit recovery codes (`TOOL_NOT_STARTED` vs `TOOL_OUTCOME_UNKNOWN`), model-facing guidance text, deterministic seq/time, applied by the writer *before* publication and by cold readers in memory only — `core/session/src/repair.ts:27-135`.
2. **Three semantic flush barriers as a separate, stateless plugin** (before request, before top-level tool body, at pre-step), fail-closed, with nested dispatches reusing the outer checkpoint — `session-checkpoint-policy/src/index.ts:63-81`.
3. **`link()`-publish (never rename) + per-batch fsync + rollback-truncate on failed append + torn-tail recover-then-rewrite before the first new append** — `session-persistence-jsonl/src/index.ts:1097-1292`, `storage.ts:318-345`.
4. **Surface vs. log-only split with `surfaceOp: replace` and mandatory `sourceEventSeqs` coverage validated at append**, so compaction, pruning, and system-prompt updates are ordinary events and provenance is never lost — `core/session/src/surface.ts:300-302,437-439`.
5. **`request/header` fold + `reason: initial|resume|change|series` + `startsSeries` on any surface replacement**, plus frozen message identities — the prefix cache is protected by a logged fact, not by hoping the bytes match — `agent-loop/src/agent.ts:552-581`, `request-header.ts:60-69`.
6. **`ignorable: true` envelope flag + fail-closed refusal of unknown required types + immutable version-named generations with one-step adjacent migrations verified out-of-thread before exclusive publish** — `known-event-types.ts:9-23`, `generation.ts:121-230`.
7. **Projection-cache identity tuple (`formatVersion+createdAt+cwd+isSeeded+inheritedEventCount`) + "log leads, cache follows"** (cache row only after the session flush; a bad row is `.bak`'d and refolded) — `session-projection-cache/src/index.ts:114-200,292,379`.

## Top 5 things it does WRONG or leaves unrecovered

1. **Partial streaming output is lost on hard crash**: the provider stream is embedded only in the settled `assistant/message` / `assistant/attempt`; nothing durable exists mid-stream, so a long reasoning/text stream killed at 95% is gone (architecture.md §Session log; `types.ts:321-335`).
2. **No workspace/file snapshot, undo, or rewind**: disk side effects of tools are untracked; recovery pushes verification onto the model via the `TOOL_OUTCOME_UNKNOWN` text (`repair.ts:100-105`). Fork copies the log but not the working tree.
3. **Jobs, workflow runs, and terminals die with the process** and are not resumable: `jobs-local/README.md:12`, `workflow/README.md:128` ("No journaling or resume"), `terminal-bash/README.md:169`; `tool-workflow/run-start` has no resume consumer.
4. **`tool/call` is logged before the approval gate** (`tool-calls.ts:166`), so a crash during a pending approval resumes as "outcome unknown" although nothing ran; the `approval/asked`-without-`decided` fact is in the log but the reducer ignores it — an avoidable false alarm to the model. Same for an unmatched `hook/invoked`.
5. **No lease/expiry anywhere**: a wedged live writer blocks resume until its process exits (`lease.ts:11-14`); team task owners are never released; mailbox guarantee is process-local retry, not cross-process exactly-once (`agent-team/README.md:132`); subagent child settlement tolerates a failed final flush (stale child on resume). Minor: the projection registry's "whole-value event rule" (`session-projection/src/index.ts:13-16`) is contradicted by the delta-shaped `agent/inbox/spliced`.
