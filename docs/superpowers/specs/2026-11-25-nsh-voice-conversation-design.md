# NSH 整轮语音对话 / NSH whole-turn voice conversation

- **状态 / Status:** Proposal for approval; no implementation or platform acceptance implied.
- **基线 / Baseline:** `7807cf09c`, isolated `refactor/voice-conversation` worktree.

## 目标与方案 / Intent and approaches

在 NSH Panel 中进行只听、只说的对话。转写仍是正常 Agent 会话的输入，最终回复仍是语音合成的输入；两者都不在语音视图渲染。文字不驱动音频切段、网络请求或播报。显式打开普通文本会话仍按现有会话历史和权限显示消息；本次不改存储、会话保留策略或普通 Chat。系统识别是 STT 的离线兜底；本次不增加系统 TTS、浏览器识别或模型安装服务。

Voice mode belongs to the shared NSH TSX Panel, not to Tauri or Leptos. No duplicate business UI lives in the native shell. This is not a no-transcript-storage feature. Existing screen-reader labels describe controls, states, and actionable errors, never spoken content.

| 方案 / Approach | 取舍 / Trade-off |
|---|---|
| **整轮语音 + 已有本地识别器（用户已选） / Whole turn + installed recognizer** | 一轮录音一次转写提交，最终答复一次合成提交。去掉字幕 RPC 和逐句合成，避免重复编码与排队；长回复更晚开口是实际代价。 / Bounded batch capture and synthesis remove caption RPCs and the sentence queue; long answers can start speaking later. |
| 整轮语音 + 新模型分发 / Whole turn + model distribution | 能覆盖没有离线引擎的干净 Linux，但新增下载、校验、安装、更新与冷启动责任。 / Covers stock Linux without an engine, at the cost of a new model lifecycle. |
| 隐藏文字、保留分段 / Hide words, keep current streams | 容易保住短首音，但不解决分片和请求扇出；仍需处理流式识别与句子合成状态。 / Preserves latency opportunities but leaves fragmentation and fan-out. |

用户指定 NSH TSX 作为本轮唯一 UI 落点；不改 Tauri 或旧 Leptos 呈现，也不借语音项目切换 Panel 默认挂载。NSH 宿主的平台发行门禁不因本项目而绕过。

## 用户体验与生命周期 / UX and lifetime

```text
语音对话
● 聆听中                         [结束本轮] [退出]
● 正在处理                                         [取消]
● 正在播报                                         [打断]
```

Voice is a Core-advertised built-in Panel capability with one TSX module and its own normal conversation session. Opening the tab never acquires the microphone. Start, natural end-of-speech via VAD, and explicit finish all operate on the same capture; finish requires real voiced samples. Permission denial, no voice, device loss, limit, unavailable backend, and TTS failure have short error/status states. Finishing at the duration limit submits the bounded portion once, with a limit notice and no implicit continuation; device loss or cancel discards the clip. A spoken answer does not become visible on failure. No transcript widget, formatter, streamed caption, text preview, or alternate host view is added.

After playback, the active voice session returns to listening. Interrupt stops audible playback immediately and returns to listening; cancel while waiting invalidates the pending turn and aborts its known `chat` run. Do not read from the speaker by adding always-on microphone capture during playback: the first slice offers explicit interrupt, not automatic acoustic barge-in. Hide, switch away, exit, lose connection, or change device → stop local audio and invalidate the active turn. If a canceled `chat.send` later yields a run ID on that connection, abort the exact owned run; if a write's result is unknown after disconnect, do not retry. Do not cache clips, replay missed playback, or resume capture automatically after reconnect. Error messages and telemetry never echo spoken content.

## 纵向连线 / Vertical wiring

1. **Panel capability and host seam.** Use `interfaces/panel` module registration and the existing `PanelSdk`/`aleph.event` lifecycle. Core owns capability registration and request admission; the host reports local capture/playback availability without claiming that a speech recognizer is configured. Extend the typed host boundary only for audio I/O and activation lifetime; it must not choose providers or read arbitrary paths. Desktop uses authenticated Desktop IPC; Web (where exposed) uses the existing paired Web v1 origin and browser audio APIs, never browser speech recognition. Share the TSX state/presentation; keep native capture/play adapters and browser I/O adapters out of business logic. Do not expose or acquire the Gateway machine's capture/playback devices from a remote browser. In the baseline native TSX embedding is macOS-only; build speech adapters for all three platforms, validate adapters independently where embedding is gated, and report desktop end-to-end by actual mount. Windows/Linux NSH mount/admission promotion is not bundled with voice.
2. **Capture one utterance.** Reuse the existing classic VAD hysteresis/pre-roll and recorder normalization where portable, preserving current classic behavior; move a shared primitive only if both consumers can actually use it. On macOS reuse the existing Media/Bridge capture service and permission context where possible; its current record-start/stop has no live PCM/VAD readiness contract, so a scoped sample or level feed may be needed. Do not revive the old always-warm mic-meter system. Prefer bounded native buffers and a single sealed WAV over a per-sample TSX event stream. Browser adapter only handles capture, downsampling and playback, not a second conversation UI. The capture target is 16 kHz mono signed PCM16 WAV. Initial cap: 20 s = 640,000 PCM bytes + WAV header, under 854 KiB after Base64; reserve headroom for the JSON envelope. Enforce a byte/sample limit before allocation or enqueue, and validate declared WAV shape, actual sample count and negotiated wire limit before dispatch. Do not split a rejected utterance into independent messages. For a native clip already held by the Core-adjacent Bridge use one owner/sealed handle if it eliminates a return-and-upload copy; keep it private, bounded and scoped to the authorized connection, never expose a path string on v1. When the cap or codec changes, boundary checks across the transports must still agree.
3. **Transcribe once.** Reuse `resolve_stt_source` / `transcribe_with_source` for configured BYO local and cloud. Keep existing local-to-configured-cloud order where explicitly configured. When no usable configured source/credential resolves, ask the installed offline recognizer on the co-located compatible desktop only. Denied mic/file access, cancellation, invalid audio, throttling, and provider transport/auth/server failures do not initiate an unapproved second request; present a useful error. A missing credential during resolution is not a provider authentication failure after a network request. Keep credential values, audio and transcript out of logs. A remote Web request with no STT source gets an explicit configuration error; it must not silently run OS recognition on the Gateway server. Authorization comes from the accepting server's transport context: genuine same-user Desktop IPC with the owning desktop principal and the existing local platform adapter mounted for that Core instance. A gateway may select the offline branch only on that path; a legacy RPC, paired Web v1 session (including loopback), claimed local host flag or forwarded identity is not proof. This branch adds no support for a native NSH shell connecting to an off-machine Core. If Desktop IPC is available but the speech bridge, permission or language assets are missing, keep the voice tab available for configured providers and return a specific unavailable error if fallback is needed. Do not promise recognizer readiness in the capability snapshot.

离线授权只认服务端已验证的同用户 Desktop IPC、本机 Core 与本地平台 adapter 的真实挂载。Web v1（包括本机浏览器）只允许配置过的识别来源；不新增异机 Desktop IPC 连接。已挂载的语音能力不保证当前有识别器或语言包。
4. **Use existing chat.** Submit the final nonempty transcript to `chat.send` once with `voice_input=true`, the existing idempotency key and session/run ownership. Keep the turn bound to the exact returned session/run. Use `stream.run_complete.summary.final_response` for TTS after a successful run; ignore response chunks for synthesis and rendering, and do not accumulate them just in case. Standard `stream.response_chunk` chat frames may still traverse the existing authenticated feed; this slice does not suppress or change them for any subscriber. The prohibited wire traffic is legacy voice-audio frame RPCs (`voice.stream.*`), transcription/caption events (`voice.transcribe.delta`) generated by this turn, caption formatting, and sentence-by-sentence `voice.synthesize` calls. Measure at the transport boundary as well as the player so ignoring chat events cannot hide voice fragmentation. Handle terminal events arriving before `chat.send` answers with a bounded pending window keyed by run ID; unrelated runs never trigger audio. If the terminal event is missing, oversized, outside the window or has no final response, stop with a clear recoverable error rather than synthesizing a partial or another run's history. Ordinary Chat events, persistence, and legacy clients stay unchanged.
5. **Synthesize once, play once.** Reuse `voice.synthesize` / `generate_tts` with the existing sanitizer and configured speech-provider policy; make one logical TTS request per reply, no sentence splitting. A bounded existing provider fallback may make up to two attempts inside that one call; record actual calls in profiling. Use existing inline media when within wire budgets; play via one host operation scoped to the current turn. Accept supported media only, never a caller-supplied file path. Provider media that cannot be represented by the scoped transport/player (including an inline result over its negotiated response budget) yields a typed error, not silent loss or auto-splitting. Keep provider-native audio framing/decoding where needed for playback, not UI. No new media proxy, broad URL allowlist, or path-serving route. Prefer inline results for the first slice. End-to-end cancellation prevents late samples/old audio even if a provider cannot cancel remote compute.

## 原生识别 / Installed offline recognition

- **macOS:** reuse `DesktopPlatform` → typed Bridge dispatch → Speech. Under the explicit offline-only policy, read one bounded canonical WAV from Core's boot-configured staging root and close its descriptor before handing owned PCM to `SFSpeechAudioBufferRecognitionRequest`. Check locale and permission, require both `supportsOnDeviceRecognition` and `requiresOnDeviceRecognition`, and consume only the final result. Keep the ordinary Speech tool on its existing URL input. Clean up the staged file only after a strict success reply from the dispatched helper generation carries the matching operation ID and explicit input detachment, or after the exact helper that could still read it has been reaped. A cancel ACK or final transcript alone does not prove detachment. No Panel-wire change, new macOS minimum, model download or network fallback.
- **macOS（中文）：** 仅显式离线分支改用内存音频：从 Core 在启动时绑定的暂存根有界读取规范 WAV，关闭描述符后再把自有 PCM 交给系统 Speech。仍检查语言与权限、强制离线并只接收最终结果；普通语音工具继续用 URL。只有同一 helper 代的严格成功回执匹配操作 ID 且明确证明文件脱离，或确切可能读取该文件的进程已回收，才清理暂存。取消回执或最终文字本身都不是证明。不变更 Panel 协议、不提高 macOS 最低版本、不下载模型、不回退网络。
- **Windows:** run desktop SAPI in a private, early worker mode of the existing `aleph-server` executable. It owns COM and the installed recognizer token, accepts one bounded stdin request, and does not start a Gateway. Use an exact selected locale, or the platform default only when omitted. Aggregate final segments through end of stream; a successfully exhausted stream with no text is silence, not provider failure. A synchronous COM call cannot be safely preempted in-process: on timeout or cancellation the parent terminates and reaps that exact worker before allowing the clip to be deleted. This costs a process launch per turn but adds no shipped executable. / 复用现有服务程序的私有 worker，不启动 Gateway；由独立进程拥有 COM，收集到流结束。取消或超时须确认子进程已回收，才能删除录音；代价是每轮启动一次子进程。
- **Linux:** keep `[voice.local]` as the explicitly configured endpoint (existing STT precedence). Offline fallback uses locally provisioned `[desktop.offline_stt]` executable and model paths; Web/Panel RPCs cannot set them. Both paths must be absolute, the files regular, the model readable and the program executable by the daemon (effective access via Linux `faccessat2`). Where that check is unavailable, leave the fallback unmounted. The operator installs a CLI compatible with the supported whisper.cpp v1.8.3 invocation and accepts its provenance; path/access checks do not attest its version or digest. No PATH discovery, shell, download or network recognition. Bound stdout and the deadline; kill and reap the owning process before release. Test endpoint present → no CLI, endpoint absent with installed CLI/model → offline success, both absent → classified unavailable. PulseAudio/PipeWire provides input, not STT; Speech Dispatcher is not an STT fallback. / Linux 本地部署须提供绝对路径和可用文件。检查不认证 CLI 的版本或内容，不可验证权限时不挂载。
- **Shared contract:** use the platform Media boundary and shared protocol types; recognize a private owned clip rather than any user-provided filesystem path. Tie all temp files, native audio objects and queued work to the owning attempt; release on success, failure, limit, cancel and teardown. Keep fast fallback resolution a Core policy and platform APIs in their adapters. No cloud or browser fallback from the offline branch.

## 验证、性能与清理 / Validation, performance and cleanup

- Test the complete RPC allowlist/admission path and its denials, not just method registration. Verify configured-source precedence and zero cloud calls on the offline branch. Test final run binding including terminal-before-reply, unrelated sessions, connection warning/drop, stale completion, malformed/near-limit WAV, absent microphone/language/model, failed provider, canceled playback, over-limit output, and ordinary Chat remaining unchanged. Across a successful utterance assert one STT submission, one `chat.send`, one TTS submission, one playback and no `voice.stream.*` calls, no `voice.transcribe.delta` generated by the turn, no `voice.format`, and neither transcript nor reply rendered as text. Standard Chat events are allowed and ignored for voice rendering; confirm they do not trigger additional TTS. Use fixture engines for deterministic topology/error cases and record real-platform native success separately.
- Record matched before/after samples using the same capture fixture, STT/LLM/TTS selections and short/long answer sizes. Distinguish first captured PCM, speech end → final STT, STT → run acceptance, final answer → first audible buffer and speech end → first audible buffer. Report cold and warm p50/p95 (sample counts and host), provider request and audio copy/byte counts, and maximum buffer use; report unavailable runs instead of fabricating comparison. Reuse buffers/HTTP client where measured, no permanent warm worker solely on speculation. Primary regression gate is no extra copies or latency beyond actual sealed transport/provider work on the new path; whole-answer buffering can regress long-answer time-to-first-audio, which must be visible in the receipt rather than called an improvement. Do not claim a speedup without matched evidence.
- **Branch acceptance / 分支验收:** packaged shared TSX and both supported transport paths must pass deterministic full-turn and negative-path tests against a real Gateway, with fixture audio/providers declared. Web v1 retains its existing explicit pairing and deployment opt-in; ability to run a configured-source turn there neither enables Web by default nor counts as a native run. Verify real installed STT separately on the Windows and Linux installations accessible in this task. When access, an installed language/model or a required credential is unavailable, report the exact missing evidence; do not label that OS/platform chain as validated.
- **Native readiness / 原生可交付门禁:** do not claim macOS native readiness without a packaged NSH turn from real microphone through offline STT, real Gateway/Chat/TTS to actual speaker output, including interrupt. Windows/Linux each require installed STT success plus the same full chain after their native TSX mount clears its own gates; adapter tests or browser demos do not substitute for it. This worktree can hold an implementation candidate and its evidence without promoting a default mount, merging or releasing. Measure playback start from the audio API's actual start/render signal or a controlled loopback, not the synthesis RPC return time.
- Remove any obsolete helper/export introduced or made unused by the replacement; verify consumers before deletion. Classic `voice.stream.*`, captions, `voice.format` and `SentenceSplitter` still serve Leptos/other consumers at this baseline; do not remove merely because the NSH module does not use them. Do not fork a second set of chat/session/provider types. Update `docs/reference/FEATURE_LOCATOR.md`, `docs/reference/DESKTOP_SHELL.md`, and the relevant Desktop Bridge/runtime references only to the extent implementation and QA establish them. Keep proof under `docs/superpowers/runs/`; commit in the isolated worktree only.
