# Memory Self-Evolution: Closing the Existing Loop / 记忆自我进化：修复现有闭环

Status: approved on 2026-11-25. / 状态：2026-11-25 已批准。

## Intent and approaches / 目标与方案

| Approach / 方案 | Trade-off / 取舍 |
|---|---|
| Wiring only / 只修连线 | Correct provenance and run status quickly, but leave demonstrable correction loss and unsafe replacement. / 能很快纠正证据归属和运行状态，但留下已查证的反馈丢失与不安全替换。 |
| **Close the existing loop — selected / 修复现有闭环（已选）** | Repair ingress and status first, then make feedback progress auditable and replacement recoverable with the existing stores. Requires a narrow persisted protocol and failure testing. / 先修证据入口和状态，再复用现有存储使反馈进度可审计、替换可恢复。需要一份窄范围持久契约和故障测试。 |
| General recovery first / 先建通用恢复层 | Could eventually cover more stages, but would enlarge migrations and fault semantics before the current signals are trustworthy. / 将来可覆盖更多 stage，但会在当前信号尚不可信时扩大迁移和故障语义。 |

Success means a correction does not silently disappear behind a cursor, a recall hit accrues to the corpus that supplied it, and old Markdown remains live until its replacement is usable. Keep semantic decisions with the LLM; Rust validates evidence, scope, progress and I/O. Scheduled and manual Dreaming remain the entry points. Reuse existing Memory and Dreaming contracts; no new external service, exposed control plane, or index as source of truth. / 成功标准：纠正不会静默落在游标后方；召回证据属于实际提供笔记的语料库；替代笔记可用前旧 Markdown 仍在线。语义由 LLM 决定，Rust 验证证据、范围、进度和 I/O。沿用现有 Dreaming 自动与手动入口及 Memory 契约；不新建外部服务或控制面，不把索引变为事实源。

## 1. Wire existing evidence and status / 先修证据与状态连线

- Carry trusted `(owner, path)` from `ScoredFact.fact` through assembly to reflection. Inline or synthetic profile, Raw and Summary stay available for synthesis/citation but do not become note evidence. The LLM can see distinct opaque citation keys for equal paths under different owners; restore the existing public `NoteRef` path shape. Do not derive owner from the request, active project, arbitrary `extra`, or a model citation. Retain all real notes presented to the model as exposure evidence, independent of which ones it cites. Group writes per true owner through existing recall storage, with independent failure handling; keep the manual-reflection channel and dedup rules. / 从 `ScoredFact.fact` 传递可信的 `(owner, path)` 到反思；内联或合成 profile、Raw、Summary 可供综合和引用，但不计为笔记证据。同路径异主用不同内部引用键，外部 `NoteRef` 保留路径形状。不能从请求、当前项目、任意 `extra` 或模型引用反推归属。以给模型的真实笔记曝光为准，不要求模型实际引用。按真实所有者分组、独立处理失败，复用召回存储，保留反思 channel 与去重规则。
- Preflight required provider and embedder before recording `running`, starting a stage, or appending run history. A scheduled check without dependencies exposes an unavailable readiness reason through the existing Dreaming scheduling status, not a fabricated attempt. A forced run returns an actionable error; neither overwrites the last actual attempt. When ready, normal scheduler gates apply. Preserve existing meanings of timeout, error, stale running, cancellation and partial work. / 在写 `running`、执行 stage 或追加报告前检查 provider/embedder。缺依赖时通过现有调度状态公开不可用原因，不生成伪运行；手动触发返回可操作错误。两者均不覆盖上次真实尝试。就绪后仍遵循原调度门禁。不改变超时、错误、陈旧运行、取消与部分完成的语义。

## 2. Feedback consumption / 反馈消费

- Share one bounded selection helper between the `FeedbackDistill` stage and its activity admission gate. Persist a corpus-local commit cursor in the existing Dream state, backed by a stable correction append sequence committed with the raw index insert. SQLite anonymous `rowid` and seconds-resolution timestamps are not durable ordering contracts. Validate the production Markdown raw-store path and any compatibility implementation explicitly; unsupported stores must not impersonate a working consumer. Keep `get_raw_by_path_prefix_since` for other callers. / `FeedbackDistill` 和活动准入共用有界选择。在现有 Dream 状态中保存分区提交游标，顺序由与 raw index 插入同事务提交的稳定追加序号提供。不以匿名 `rowid` 或秒级时间为持久顺序。显式查证生产 Markdown raw store 及兼容实现；不支持时不得假装消费成功。保留其他调用方使用的时间查询。
- Atomically snapshot the migration boundary in the raw index. When an old feedback timestamp exists, treat rows already present at activation with timestamps at or below that mark as legacy; do not silently replay ambiguous historical effects. Keep preexisting newer rows and **all** post-activation inserts eligible, including a same-second or backdated correction. A corpus with no old mark starts with all its rows. Raw files are not rewritten; explicitly document the historical blind spot. / 在 raw index 中原子记录迁移边界。存在旧反馈时间水位时，仅把激活时已存在且不晚于旧标记的行视为历史；不静默重放历史上效果不明的纠正。激活前较新的行及激活后写入的所有行仍可处理，包括同秒和回填；无旧标记的分区从全部行开始。无需改写 raw 文件，文档说明历史盲区。
- Apply quorum to the bounded visible page, preserve the high/critical exception, and limit the commit to the bounded prefix actually presented for decision. Below-quorum evidence stays pending, never implicitly discarded. A resumable pending batch is eligible even without a new quorum. Share distill JSON decoding where contracts match; feedback requires typed, checked coverage of the presented source IDs (action evidence or explicit no-action). A syntactically valid empty action list alone does not consume corrections. Oversized, malformed, missing or out-of-batch references are rejected **before any write**. Existing deterministic gates still apply; record explicit skip and terminal policy rejection separately from applied and retryable/uncertain I/O. / 对有界候选页复用 quorum（保留高危/关键绕过），只提交实际交给模型决定的有界前缀。阈值不足保持待处理，不隐式丢弃；恢复未完成批次不需再满足新 quorum。契约一致时共享解析；反馈响应还须以动作证据或显式不处理覆盖展示的源 ID。只有合法空动作列表不能消费纠正；超量、畸形、漏答或批外引用须在任何写入前拒绝。保留现有确定性门禁；显式跳过、终态策略拒绝、实际落盘、可重试或不确定 I/O 各有记录。
- Keep **one bounded pending feedback batch per corpus** in existing Dream SQLite state. Store the selected IDs/cursor range and the validated plan **before** the first effect. Persist the per-action decision/receipt; a restart resumes the same plan, not another LLM interpretation. Before nonterminal file work, persist intent with canonical paths and sufficient expected pre/post state to recover (normalized stable content or fingerprints and stable invocation IDs; never infer identity from title alone). Read trusted disk state and verify its projection before accepting an already-published result. Pending and untouched effects can continue; a provably interrupted publish/retire can resume; unknown or conflicting disk state is surfaced and the cursor stays put, without overwriting external edits. Commit the cursor and release the pending batch together only after all decisions are terminal. The pending decision list is bounded by the batch cap; no append-only execution ledger. / 每个分区在现有 Dream SQLite 状态只保留一个有界未完成反馈批次。副作用前保存选择的 ID、游标范围与验证后的计划，并持久化逐动作决定/回执；重启继续原计划，不重新让模型解释。任何未完成文件动作前先记录意图、规范路径与可验证的前后状态（稳定内容或指纹和稳定调用标识，不能仅凭标题认领）。用可信文件状态及其投影验证认领。未执行或可证明的中断可继续；外部编辑或其他不确定冲突须显式报告、保留游标且不覆盖。全部决定终态后，同事务提交游标并释放待处理批次。计划大小受批次上限约束，不增设只增不减的执行流水账。
- A model/provider or pre-effect error leaves selection retryable. After any I/O attempt, do not re-run the whole night or blindly replay a batch; the next eligible scheduled/manual cycle can only resume its pending plan. Surface retryable/blocked feedback in the existing scoped Dream report/log, separate from landed effects. Forced run can revisit a corrected conflict, but is not a bypass. Keep the current daily scheduler policy for real attempts. / 模型、provider 或副作用前的错误保留可重试选择。开始 I/O 后不重跑整夜或盲目重放；下一次符合门禁的自动/手动运行只恢复该计划。通过现有按分区隔离的 Dream 报告和日志呈现待重试/阻塞，与落盘效果分开。手动运行能复查已处理的冲突，不是越权开关。真正开始过的运行维持现有每日调度策略。

## 3. Publish before retiring / 先发布后退役

Route `Supersede` through the common `NoteIndexer` writer. Read and verify the old note; preserve its bytes in a non-clobbering archive with lineage before retirement. For different paths, reject an unrelated existing destination; publish and verify the successor's durable Markdown and required note-index projection while the original stays live, recheck the original, and only then retire that original and its stale projection. Do not overwrite an original that changed. For the same path, archive first, then atomically replace the file, never unlink the live name, then verify/repair its derived projection. A failed retirement can leave two live notes, which must not be reported as a completed replacement. Verify note-index availability for normal recall; do not promise synchronous completion of all optional embeddings. / `Supersede` 收敛到 `NoteIndexer` 共用写入路径。读取并核对原笔记，退役前保存不覆盖旧归档的原字节与沿袭。不同路径若有不相关目标则拒绝；旧笔记在线时先持久发布并验证新 Markdown 及必需索引，再复核旧文，只退役原笔记与陈旧投影。不得覆盖已经变动的源。同路径先归档、再原子替换，不删除在线路径，随后验证或修复派生投影。退役失败可暂留两份在线笔记，不得称为替换完成。验证正常召回所需笔记索引，不承诺同步完成全部可选 embedding。

Use existing atomic note writes, projection repair and recall candidate/budget rules. Serialize competing **in-process** writes at the relevant owned boundary where needed; revalidate disk snapshots before destructive steps and stop on detected conflicts. Do not claim transaction isolation from arbitrary external editors or universal exactly-once across Markdown and SQLite. Do not change the recovery protocol of other dream stages; other `Supersede` callers still benefit from safer ordering. / 复用原子笔记写入、投影修复和召回候选/预算规则。必要时在归属边界内串行化**进程内**竞争写入；破坏性动作前校验快照，发现冲突则停。不会承诺针对任意外部编辑器的事务隔离，或 Markdown/SQLite 的通用恰好一次。不改其他 stage 的恢复协议，但共用的 `Supersede` 也采用安全顺序。

2. Establish the bounded source order and strict decisions; wire admission and consumption to the same selection contract. Implement safe note replacement and feedback effect recovery before activating new cursor advancement. / 建立有界来源顺序和严格决定契约，准入与执行共用选择；安全替换和反馈副作用恢复完成后才启用新游标推进。
3. Remove the obsolete reflector stamping, fabricated success branch, feedback timestamp boundary heuristic, duplicate decoders where genuinely equivalent, and old archive-before-publish retirement sequence. Do not remove shared watermark callers, raw time APIs, or legitimate citation paths. / 删除旧归属盖章、伪成功分支、反馈按秒扩展批次的启发式、真正等价的重复解析器及旧先退役后发布路径；保留其他水位调用方、raw 时间 API 和合法引用。
4. Validate actual effects: mixed owners and same paths, non-note exclusion, optional dependency combinations through both entries, same-second backlog beyond a page and migration old/new rows, malformed/incomplete vs valid explicit no-op, storage failure before/after publication and restart, same-path and occupied destinations, delayed retirement and diverged content, index retrieval of the successor, and no false `Applied`. Exercise real temporary Markdown/SQLite, then run scoped and wider memory suites as build resources permit. Calibrate `docs/reference/FEATURE_LOCATOR.md`, `docs/reference/MEMORY_SYSTEM.md` and `docs/reference/memory/DREAM_DAEMON.md` against landed behavior and record verification. Release commits remain in the isolated worktree; no push or main merge. / 验证真实效果：异主同路径、排除非笔记证据、两入口的可选依赖组合、超过一页的同秒积压与迁移前后行、无效/漏答与显式不处理、发布前后存储失败并重启、同路径与目标冲突、延迟退役与内容漂移、索引可召回新笔记、不会误报 `Applied`。先用真实临时 Markdown/SQLite 验证，再视编译资源运行专项与更广记忆套件。按实际行为校对三份 reference 并记录验证。提交留在隔离 worktree，不推送或合并 main。

### Out of scope / 本轮不做

No system-wide stage journal/DLQ, automatic approval or promotion, automatic rollback, retrospective reconstruction of pre-migration same-second losses, new saturation heuristic, or unmeasured performance claim. Keep post-write health explicitly observational. / 不做全局 stage journal/DLQ、自动审批或晋升、自动回滚、考古式重建旧水位下已遗落的同秒行、新饱和启发式或未测性能承诺；写入后健康分只作观测。
