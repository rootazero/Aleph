# Shell 输入的实效授权边界 / Shell Input Effect Authority

**状态 / Status:** 待批准；这是 [受控实时 JSONL 设计](2026-11-26-shell-capability-jsonl-design.md) 的 #19 修订，只细化授权与实际投递的排序，不撤回其策略、原生隔离和脱敏门禁。当前 [准入结论](../runs/2026-11-26-shell-capability-jsonl-verification.md) 仍是 NO-GO。 / Pending approval. This #19 amendment specifies ordering between authority and actual delivery; it retains the JSONL policy, native confinement and redaction gates. The current eligibility finding remains NO-GO.

## 意图与方案 / Intent and approaches

已经拿到一次性同意的 JSONL 写入可能在等待期间碰上撤销配对设备、停用账号、缩小执行权限、替换 Capability、停止作业或结束输入。必须让这些变更和**实际写入或关管**有先后：当变更先提交时，不能碰 pipe。 / A JSONL write that is waiting for its one-shot approval may lose its connection, permission, Capability or job. Order those changes against the actual write or close. If a disqualifying change commits first, do not touch the pipe.

| 方案 / Approach | 取舍 / Trade-off |
| --- | --- |
| **组合现有权威（已选） / Compose current authorities (selected)** | 真实变更源保持原有归属。仅为这条输入链路增加类型化的最终操作，并发争用直接失败；首发会较窄。 / Keep ownership with the real mutation sources. Add a typed final operation only for this route; contention denies the attempt and the first supported route stays narrow. |
| 新的全局授权闸或共享缓存 / Global gate or permission cache | 所有变更源都要双写或迁移；漏接会把失效的值当许可，且改动与本功能不成比例。不采用。 / Requires rewiring every writer or mirroring state; a missed publication can turn stale state into admission. Rejected. |
| 写前复验后排队 / Recheck, then enqueue | 复验与写入间仍有窗口；回执只能证明排队，不能证明效果。不采用。 / Leaves a gap and proves admission to a queue, not delivery. Rejected. |

## 可入场路由与绑定 / Eligible route and binding

- 首发仅考虑生产 `chat.send` 的已配对、当前连接仍有效且有人值守的 Panel WebSocket 路由。捕获点是受信任握手及连接表，而非 `RunRequest.metadata`。身份绑定以进程内类型传过 `handle_chat_send_with_engine` 到 scoped `bash` admission；其他入口、隐式 owner、无实时连接、回放和后台自主续跑都拒绝新输入能力。仍保留旧 `bash` 行为。 / Start with the production attended `chat.send` route on a verified live paired Panel WebSocket. Carry a process-local typed binding from the handshake and connection table through the real engine worker, not string metadata. Other entrypoints, implicit owners, disconnected clients, replay and unattended continuations are ineligible. Ordinary shell is unchanged.
- 一个不可复用的内存尝试绑定最终候选帧（或 close）、完整 `SessionId`、账号和配对设备、连接、当前 agent 实例、规范工作区、规则版本、精确 Capability 捕获与同一作业。后续 turn 可以重获新的可信调用绑定，但不能继承旧 turn 的权限或审批，也不能用同名 handler、换会话或登录重连替代原作业的授权绑定。候选帧不进入审批描述或台账。 / Bind a single in-memory attempt and immutable frame (or close) to the full session, account, device, connection, current agent, canonical workspace, policy revision, exact Capability capture and supervised job. Later turns need their own trusted caller binding and approval. A same-name handler, another session or a renewed connection cannot substitute for the job binding. Do not put the frame in the approval description or ledger.
- 使用现有 `ApprovalGate`，只接受本尝试的 `AllowOnce`；等待时不锁住权威。最终必须与当前生效的许可、启动策略和作业控制一致。仍具备权限的重复 EOF 返回 already-closed，无重复批准或操作。未知或旧值、不可用、超时及争用失败不消费下一次审批，且不能让本次在后台迟到执行。 / Await the existing Gate without holding authorities. Accept only this attempt's live AllowOnce; verify permission, launch policy and the same job at the effect. An authorized repeat EOF returns already-closed without another approval or effect. Unknown, unavailable, stale, timed-out or contended attempts do not wait in a queue or execute later.

## 最终操作与真实变更源 / Final operation and mutation owners

| 权威 / Authority | 最终操作使用的边界 / Boundary used at the effect |
| --- | --- |
| 账号、设备和连接 / Account, paired device and connection | 持现有连接表读 guard 核对同一存活连接、真实用户及设备。用同一 `SecurityStore` 数据库的零忙等待写保留事务（`BEGIN IMMEDIATE`，无需提交任何修改）同步其他连接的账号/设备变更；在事务内复核 active 账号、已批准未撤销的配对设备、实际角色和绑定。连接→security store 的顺序与设备 revoke 一致；不得继承正常 SQLite 的 5 秒 busy timeout。 / Check the same live connection under the existing table read guard. Reserve a no-wait immediate transaction on the same SecurityStore database to order mutations through other connections. Read the active account, approved unrevoked device, role and ownership there. Use connection → store ordering as device revoke does; never inherit the normal five-second busy wait. |
| 会话、agent、工作区、权限及文本策略 / Session, agent, workspace, permissions and policy | 使用真实 live `AgentRegistry` 和 app config 的读边界，按该路由的现有 scoped 权限派生方式验证。会话 tier、工作区、会话归档/替换不能只看 turn 副本；使用每个实际 store 的现有变更边界，首发只支持有证明的 backend。对文件 backend，`lock_metadata` 同步 `sessions.patch`，**不自动覆盖 archive**，须把 archive 的提交接到同一每会话边界或不启用该 backend。预先构造安全工作区标识及规则证明；最终确认对应的 mounted hook bundle 和配置仍是该证明所用版本。任何参与授权的 overlay 或更新源不能覆盖，即不开放该路径。 / Use the live agent registry and app config read boundaries, reusing that route's permission derivation. Session tier, workspace, archive and replacement need their real store mutation boundary, not the turn copy. For the file backend the existing metadata lock orders patch but does not automatically order archive; join archive to this per-session boundary or leave the backend unsupported. Prepare workspace and rule evidence before the final step and confirm the same mounted bundle and config there. An uncovered authorization overlay makes the route ineligible. |
| Capability 绑定 / Capability binding | 保留 provider→canonical registry→ownership 已有顺序；在受保护的 canonical 捕获上对照版本/精确 handler 身份，不能只比 descriptor。保留 `OwnershipTree::with_current_binding` 及注册表通用回调的无 I/O 契约。为 Shell 设计受限、不可从外部构造的提交操作，只能消费下行的一次性 pipe 动作；不接受任意闭包、通用 I/O 或重入。 / Keep provider → canonical registry → ownership order. Check exact handler identity or publication revision, not only descriptor equality. Preserve the no-I/O contracts of the general callbacks. Add a narrow, unforgeable Shell commit operation which can only consume the one-shot pipe action below; no arbitrary closure, reentry or general I/O. |
| 作业和实际 pipe / Job and actual pipe | 最里层使用同一 `ShellLifecycle` 控制边界，与 stop、已观测退出、EOF 排序；核对作业实例/输入前缀版本及运行期限。只在此处用 Linux 原子容量内的单次非阻塞写或关闭**唯一写端**，不等待读端、不投递队列。启动验收需证明没有 wrapper、父进程或其他进程保留读端副本；jq 实际退出后，即使还没上报退出，pipe 也必须拒绝投递。短写或效果不明时不得重发，应关闭输入并走已有监督停止。 / At the innermost job boundary, order the operation against stop, observed exit and EOF on that same lifecycle. Check the live job, accepted-prefix version and deadline. Write once within the verified Linux atomic bound, or close the sole writer, without waiting or queuing. Prove that no wrapper, parent or other process retains a read-end copy, so the pipe rejects delivery after actual jq exit even before the exit is observed. A short or ambiguous effect closes input and enters supervised stop; no resend. |

在最内层写入前，表中所有有效 guard 必须同时成立。允许在审批前或审批后预计算完整前缀规则证明；最终仅验证它用到的版本和已投递前缀仍一致。实现计划须画出可达的持锁顺序，并检查实际变更路径的反向依赖；进入最终区后不 `await`，用 try/零等待获取后续 guard，失败即释放。会话锁如需异步读文件，必须在最终区之前取得，并禁止在持它的路径上等待审批或其他权威。SQLite 等同步操作使用已有阻塞边界，开始时检查取消与绝对期限，不能让已取消的任务随后落地。禁止复制授权状态、扩大 API 或把权限判断转移给驱动。 / All applicable guards must remain valid together through the innermost effect. Precompute policy over the full prefix and candidate; at commit verify the relevant revisions and accepted prefix. The implementation plan must map acquired locks and inverse dependencies along actual writers. No await inside the final region; later guards are try/no-wait, released on contention. Prepare any asynchronous session read before the final region; never await approval or another authority while holding the session guard. Use existing blocking boundaries for synchronous database work; recheck cancellation and absolute deadline inside the final operation. No cached authority, widened API or driver-owned authorization.

## 证据与验收 / Evidence and acceptance

- 隔离探针已对真实 `SecurityStore::update_user`、`DeviceTokenManager::revoke_panel_device` 和真实非阻塞 pipe 测到：账号停用先提交 → 无候选字节；配对撤销先提交而账号仍 active → 无候选字节；写保留事务先取得 → 独立数据库写连接无法抢先提交，单条合成记录成功送达，释放后撤权可提交。这只证明数据库子边界，不证明整条 Gateway 路由。 / A disposable probe with the real store mutators and real nonblocking pipe observed zero bytes for account-first and device-first revocation, and a complete synthetic frame when delivery held the reservation before the independent connection tried to revoke. This proves only the storage boundary, not the mounted route. Raw probe evidence is retained locally at `.superpowers/sdd/2026-11-26-shell-capability-jsonl/store-order.log`. / 原始探针日志保存在隔离工作树的同一路径，未作为产品测试提交。
- **#19:** 真 Gateway 授权链路必须有写入和 EOF 正例；用真实变更源与可控屏障分别测账号停用/降权、撤设备/断连、权限配置/策略重载、agent 替换、会话权限或工作区失效、重新注册同 descriptor handler、stop/exit/EOF 先发生时，pipe 没有候选字节且未授权 EOF 不碰写端。反向测已提交帧不改写、后续授权失效、争用不延迟落地。只测错误码、复制状态或设置 mock 不算。 / Prove mounted positive delivery and EOF; use controlled barriers and actual mutation sources to cover account, device, connection, config, policy, agent, session/workspace, same-descriptor handler replacement and lifecycle races. Observe zero candidate bytes and no unauthorized close. In the reverse order confirm that a committed frame is not rolled back, later writes are denied, and contention cannot cause delayed delivery. Status-only and copied/mock authority tests do not count.
