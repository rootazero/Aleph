# Memory Wiki evidence chain / 记忆 Wiki 证据链

2026-11-26 · Builder-reviewed proposal; awaiting approval / 已完成独立可实施性复核，待批准 · Base / 基点：`0386bdfff`

## Intent / 目标

Make the same evidence chain usable by Dreaming, the `memory_trace` Capability, and the existing Panel note drawer. A note must not claim to derive from input the model did not receive. A trace must distinguish actual raw excerpts, references to other notes, missing evidence, and a model's provenance annotation. It must never claim that an annotation proves what a user did or did not say.

让 Dreaming、Agent 的 `memory_trace` 工具和已有 Panel 笔记抽屉复用同一条证据链。合成不得引用模型没有收到的输入；追溯须区分原始片段、来源笔记、缺失证据和模型标注。模型标注不是用户说过或没说过某句话的证明。

## Approaches / 备选路线

|---|---|
| **Repair and connect the existing chain — selected / 渐进重构现有证据链——已选** | Reuses NoteIndexer and the existing Memory/Tool Capability and RPC; no persistence migration. Legacy untyped references need explicit handling. / 复用 NoteIndexer、Memory/Tool Capability 与 RPC，无持久化迁移；必须明确处理历史无类型引用。 |

## Data flow / 数据流

### 1. Synthesis: use one input list / 合成：同一输入列表

Keep the existing category eligibility, maximum of 15 nonblank readable previews and 300 text characters per preview. Use stable category and path order, and consider further candidates when an earlier file cannot supply a preview. Fewer than three usable previews means no synthesis request and no write for that category; do not delete a prior summary. Use the same list to render the prompt and derive `links` and `source_notes`. Keep LLM text generation, the mutation gate and the shared `NoteIndexer` entry point. Remove the old all-paths write and any now-redundant manual directory creation, if the shared writer already owns that step.

保留现有分类资格，每分类最多 15 个能读取且非空的预览，每个 300 字符。分类和路径排序稳定，单个条目失败时继续寻找可用预览；实际少于三个则不发模型请求、不写入，也不删除已有综述。提示词和 `links`、`source_notes` 同源派生。保留 LLM、现有修改门禁和共用 `NoteIndexer`；移除旧的全路径引用，若目录创建已由共用写入口负责则移除重复代码。

### 2. Trace: resolve only within the authorized partition / 追溯：仅在授权分区解析

Keep the existing tool and RPC. At the Gateway, check visibility on the caller-supplied ID **before** resolving it. Use a recognized composed ID verbatim (`project_scope::is_composed_id`); recomposing it currently produces a ghost partition. Support explicit exact addressing for bare IDs as well via optional RPC field `exact_partition` (default `false`, requires `agent_id` if set). The Panel sends it for a note or raw row's storage address, so a row in a bare org partition is not silently moved to a personal partition. A stub opened from a share link continues to use the drawer's existing bare-org address. Legacy calls naming a base agent without the flag keep the existing scope resolver; the curated ledger remains such a call. Reuse the current `partition_visible` gate; the flag selects an address, never grants access. The builtin tool already takes its partition from the runtime. All forward reads, reverse lookups and raw fetches use the single resolved partition. Resolve exact note paths using the note path helper; reject malformed input instead of rewriting it into another note. No basename/fuzzy resolution, cross-partition fallback, or traversal through ordinary wikilinks. Validate the resolved partition as a single safe directory component. For Markdown and profile reads, require the partition to be the named child of the configured notes root, not a symlink alias for a sibling or an external directory, and require the resolved file to remain inside that partition.

Read each reachable note's Markdown once. On success, derive its frontmatter sources and marker-backed fact citations from those same bytes. Use the existing `sources_of` projection as a bounded fallback for a missing/unreadable/unparseable note, not as an additional source for successfully parsed notes; mark the response incomplete if a note had to use fallback. `RawSource` and `PriorNote` with a nonempty `source_id` specify an explicit reference type; inferred/system/legacy markers do not introduce a new citation. A `PriorNote` citation never falls back to a raw ID. For untyped frontmatter, prefer an existing exact raw ID; otherwise an accepted note-shaped path denotes a possible note and is checked exactly, with an unavailable-note edge on a miss. Other missing untyped IDs retain the existing pruned-raw representation. Never treat a successful raw fetch, a legacy missing reference, and a scoped note miss as proof of semantic support.

保留现有工具和 RPC。Gateway 先按调用方传入的 ID 检查可见性：已组合分区原样使用，避免二次组合；新增可选 RPC 字段 `exact_partition`（默认 `false`，开启时必须传 `agent_id`），让 Panel 对笔记、原始记录沿用行自身的存储地址，即使是未组合的组织分区。分享链接的占位笔记沿用抽屉现有的组织分区地址。不带标记的旧基础 ID 调用（如精选记忆的写入决策）保持原有 scope 解析，标记不扩大权限；工具仍由 Runtime 固定分区。正向、反向和原始行查询只用同一已解析分区。按规范路径精确查找，畸形输入不能被清洗成另一份笔记，不按 basename、模糊匹配、普通 wikilink 或其他分区补查，校验分区是单一安全目录名；读取 Markdown 或 profile 时分区必须是配置根目录下的同名子目录，不接受指向其他分区或外部目录的符号链接；解析后的文件也不得越出对应分区。每个可达笔记只读一次 Markdown，成功后从同一份字节解析 frontmatter 和逐事实引用；只在文件不可读、缺失或解析失败时有界回退到已有 `sources_of` 投影，并标为不完整。`RawSource`、`PriorNote` 的非空标记来源有明确类型，inferred/system/legacy 不产生新引用；显式笔记引用失败不改当原始 ID 处理。无类型 frontmatter 先匹配存在的原始 ID，再精确检查合法笔记形状，未找到则给出不可用笔记边；其他缺失 ID 保持原有 pruned raw 表示。追溯不裁决语义上是否支持某条陈述。

Walk note-to-note edges breadth-first with stable ordering, a visited set, and per-response budgets. Keep both distinct parents of a shared child, but expand the child once; deduplicate raw evidence by `(via_note, raw_id)` and note edges by `(note_path, source_path)`. Keep `notes` as the existing target/reverse-match list: `Note` returns the target only if it has readable Markdown or an exact index record; an invalid or wholly unknown target returns the empty shape. `Raw` uses the existing `notes_citing` union, and `ProfileSection` keeps section → sessions → raws → citing notes. `Raw` returns the exact requested row first when present and the requested evidence limit permits it. Keep curated write-decision behavior separate. Clamp returned evidence as today (500 hard ceiling; `max_results` applies only to evidence or write decisions), and independently cap note expansions (64), source/reverse candidates examined (500 across the request), and displayed root facts (100); bound note/profile file reads and cap fact/excerpt sizes. Apply limits before materializing query/fetch results where a source can fan out. Use ordered, budgeted lookups with one overflow sentinel where needed. A cut-off result sets `truncated`, distinct from missing input (`incomplete`). Batch scoped raw-ID lookups or reuse a per-call cache; do not add a background service or speculative parallel filesystem fan-out.

用稳定顺序广度遍历引用边，记录已访问节点。共同子节点保留两条父边但只展开一次。`notes` 保持目标/反查命中语义，Note 目标只有存在可读 Markdown 或精确索引记录时才返回，无效或完全未知的目标返回空响应。Raw 请求优先返回自己的原始行，ProfileSection 延用章节→会话→原始行→引用笔记，写入决策单独处理。证据仍有 500 行硬上限，`max_results` 只限制证据或写入决策；另外每请求最多展开 64 个笔记、检查 500 个来源/反查候选、显示 100 个目标事实，并限制文件读取及事实/片段大小。对会扩张的查询在取回结果前限流，必要时多取一条识别截断。预算截断与输入缺失分别表示；批量读原始行或使用单次调用缓存，不加后台服务。

### 3. Shared contract and Panel / 共享契约和界面

Use `aleph-protocol` as the single serialization contract consumed by Core and Panel, including RPC request addressing. The `memory_trace` tool schema continues to accept only the target, kind, and result limit. Preserve the existing `TraceKind` tags and fields (`target`, `notes`, `evidence`, `facts`, `write_decisions`), origin strings, 800-character raw previews, optional output field omission, and permissive reads of older responses. Add `note_sources` (parent `note_path`, `source_path`, availability status), `truncated`, and `incomplete` with empty/false defaults and omission. Keep fact annotations for the requested note only, rather than adding every intermediate note's content to the response. Keep the existing visibility-denied empty response indistinguishable from a missing target, with no storage touches on denial. The existing note drawer displays source-note edges, per-fact annotations, and incomplete/truncated states; old responses continue to show existing evidence. UI formats server fields; it does not re-resolve IDs, infer provenance, or pass a partition chosen from a source reference. Keep the existing curated ledger consumer working. Remove the redundant local DTOs and superseded read logic; do not create another public Capability or another view.

把 Core 和 Panel 的序列化契约收敛到 `aleph-protocol`，包括 RPC 请求寻址；`memory_trace` 工具参数仍只有目标、类型和结果上限。保持原 TraceKind 标签、字段、来源枚举字符串、800 字符原始预览、可选字段省略及旧响应兼容。新增 `note_sources`（父笔记、来源路径及可用状态）、`truncated` 和 `incomplete`；为空/false 时省略。只展示请求目标的逐事实标注。维持无权限与未知目标的空响应等价，无权限不触达存储。现有笔记抽屉展示来源边、逐事实标注和不完整/截断状态；界面不重解 ID、不推断、不从引用选择分区；保留精选记忆写入决策的展示和语义。清理重复本地类型和被替代的读取逻辑，不加新 Capability 或界面入口。

- Feed the production synthesis stage over 15 ordered fixtures, including unreadable/blank inputs; record the provider prompt and assert that persisted Markdown and SQLite sources/links name exactly the inputs it saw. Below the minimum, prove no provider call or write. / 通过生产阶段回放，直接比对模型输入、落盘、SQLite 投影；不足时断言无模型调用和写入。
- Through the shared indexer, exercise synthesis → source note → raw, explicit fact-only raw and prior-note citations, pruned raw IDs, missing note paths, duplicate edges, shared children/cycles, zero/limited/oversized responses, and a raw target with many citing notes. Test same names in the bare org and the personal partition, invalid paths and symlink escape. Through the Gateway with an active scope, prove that exact bare, composed, and legacy bare requests reach their intended partition, and that explicit addressing of an invisible partition gives the same empty shape as a miss. / 通过共享写入口覆盖真实链路、事实专属引用、缺失、去重/环、预算、原始目标优先，以及同名分区、非法路径、符号链接和网关拒绝/正常送达。
- Exercise shared serde fixtures in both old and new shapes, the existing drawer's evidence presentation, and the curated ledger. Run package checks and targeted regressions; report the actual UI validation method and any environment gaps. Update `docs/reference/FEATURE_LOCATOR.md` and `docs/reference/MEMORY_SYSTEM.md` against code, not just descriptions. / 覆盖新旧 wire 样例、抽屉呈现与决策记录，实报验证范围；以代码核对两份 reference。
- No backfill or inference about historical sources, no new search engine or index, no modification of Agent/Runtime capability registration, and no rollback or held-out evaluation runner for Dreaming. Exact internal helper boundaries, bounded query signatures, and drawer layout are builder decisions within these contracts. / 不回填历史、不推测证据、不增检索引擎或索引、不改 Capability 注册、不实现 Dreaming 回滚或验证集执行器。内部函数、限流签名和抽屉布局由实施阶段选择。
