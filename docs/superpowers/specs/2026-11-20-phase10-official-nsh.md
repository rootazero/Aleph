# Phase10 official NSH 0.6.0 boundary / Phase10 官方 NSH 0.6.0 边界

The installed release `nsh 0.6.0 (5541637)` and matching registry crates are the baseline. The 0.5 fork and its receipts are historical only. The [implementation plan](../plans/2026-11-18-phase10-nsh-shell-integration.md) defines acceptance; this specification replaces the fork API design. The operator-approved [2026-11-21 amendment](../runs/2026-11-21-phase10-acceptance-amendment.md) changes only Quit median and p95 limits to 1.30×; all other gates and original failure receipts remain unchanged. / 基线为本机官方 NSH 和对应发布 crate；旧补丁仅供追溯。2026-11-21 操作员明确批准仅放宽退出中位数与 p95 至 1.30×，其余判据与历史失败回执不变。

Official references / 官方参考: [Installing NSH](https://nsh.dev/docs/installation/), [Building with Rust](https://nsh.dev/docs/rust/), [macOS runner](https://nsh.dev/docs/macos/), [WebView messaging](https://nsh.dev/docs/web-view-and-video/#messaging-between-the-page-and-the-app), [desktop and single instance](https://nsh.dev/modules/nsh-desktop), [URL schemes and notifications](https://nsh.dev/modules/nsh). ## Window ownership / 窗口归属

The shell owns one NSH root and its existing external Panel WebView. Native close hides it; Dock and LaunchServices reopen it. Tray Show, tray Quit and the summon shortcut use public component-owned APIs. A visible focused window is hidden by the shortcut; otherwise the original window is shown and focused. A disabled shortcut is not registered. NSH writes placement only in its own storage; timed QA has no placement carryover. / 原生窗口、快捷键和菜单归 NSH 根组件；只有自己的窗口设置写入 NSH 存储，计时 QA 不沿用上次窗口位置。

Packaged launches are routed by LaunchServices on macOS, not `next_second_instance`. Build the actual `aleph-nsh-shell` binary and assemble a local signed `.app` whose `CFBundleExecutable` points to that binary and whose bundle ID matches the shell's `APP_ID`. Declare `aleph` in `CFBundleURLTypes` with role `Viewer`; this is not the generated `nsh package` Rust template, an installer, or a release signature. Targeted relaunch must identify the original process; forced new instances and direct invocation of a bundle's internal executable are not equivalent to system app launch. Do not change the default handler without separate approval. / 签署包含实际 shell 入口的本地应用包，包身份与 `APP_ID` 一致，并声明 `aleph`；不是模板打包、安装器或发布签名。macOS 由 LaunchServices 内容器重开原进程；强开或直接运行内部二进制不等价。不擅自改变默认处理器。

## Typed Panel boundary / Panel 消息边界

- Claim `aleph` in both the app bundle's `CFBundleURLTypes` and Rust `Root::url_schemes`. Accept exactly `aleph://open`, with no additional path, parameters, credentials or arbitrary destination. `next_url_scheme_open` is the native ingress for cold and warm events. Reject without logging the raw URL. No native replica of the Panel Router. / 应用包与 Rust Root 都须声明 `aleph`。只接受精确动作，拒绝时不输出原始 URL，不复制 Router。
- The root owns exactly one `next_url_scheme_open` listener and one `next_notification_press` listener. Both submit the same idempotent Chat action to one navigation worker (one in-flight action, at most one coalesced pending action). A valid notification click shows and focuses the original window before submitting to that worker. / 两个系统事件各只有一个根监听器，共用一个 Chat 导航任务；通知点击先唤回原窗口。
- The native host creates a random secret per launch and injects it only into the closure of a top-level bootstrap that first checks the exact configured loopback origin. The secret is not published in a global property, outgoing probe or action. The closure is the only code that posts authenticated, size-bounded registration, navigation replies or notification requests. `WebView.on_message` only gives the native host the body: all these message types require the secret before they can have an effect. Same-origin script is within the trusted Panel authority; the boundary does not claim to defend against a compromised Panel origin. / 每次启动生成随机凭据，仅精确 origin 的主帧启动闭包持有；不随探测或动作广播。原生端对登记、回执、通知都验证凭据；不承诺抵御已被攻陷的同源脚本。
- Each document generates an opaque identity. Native loading transitions invalidate bindings and outstanding probes; a fresh request challenge answered by that document's Router establishes or refreshes the binding after load. Late replies cannot bind a new generation: match the outstanding request and, for actions, the bound document. A notification must also match the bound document. The existing Router mounts one consumer, removes it on cleanup, and acknowledges the fixed Chat action only when its current location is Chat (including when already there). The bootstrap refuses an action addressed to another document. Probes have a deadline and may retry; an action sent without a matching success reply has an unknown outcome and is not blindly replayed. `ElementRef::post_message` itself has no delivery acknowledgment. No bridge is injected into browser views outside this shell. / 加载变化清除绑定和旧挑战，当前 Router 通过新探测建立绑定。动作必须匹配文档，实到 Chat 才回执；过期、异页或无回执不能当作成功，也不盲重放。普通浏览器没有壳桥接。
- Core decides `surface.notify`; the Panel relays only bounded title/body on its existing connection. No second Gateway client. When unfocused, that path only queries permission and presents only on `Granted`; `Denied`, `Unavailable` and `Default` are reported separately. Only the explicit tray action requests permission. The signed bundle supplies a notification identity and the NSH notification capability must permit the operation independently of OS authorization. Native admission is not observed presentation or click. / Core 决定通知并复用现有连接；非前台时只查权限，只在已允许时提交。默认、拒绝、不可用分开报告；只有显式菜单动作申请。包身份、NSH 能力、系统权限各自独立；受理不是展示或点击。

## Evidence and teardown / 证据与退出

The NSH root owns callbacks, its tasks and WebView. The collector verifies native exit and observed owned-member settlement. An independently managed Gateway must retain PID and process start identity; an isolated fixture is not installed-service proof. Preserve the existing Phase9 matrix schema, reducer and historical verdicts; apply the separately approved Quit-only amendment in its own assessment. Re-run shared Panel stream/disclosure and native cases against final code and served assets, then independent SPEC followed by distinct QUALITY. / 用原生退出、成员结算和 Gateway 启动身份验证资源边界；不改旧矩阵判据。最终源码须重跑共享 Panel 和原生用例并按序评审。

Public native APIs avoid fork maintenance but leave the shell responsible for the document exchange and explicit OS verification. This specification does not change title-bar controls or extend acceptance to other platforms. / 公开 API 省去维护 fork，但文档握手和原生验证仍由壳负责；本规格不改窗控，也不声称跨平台验收。
