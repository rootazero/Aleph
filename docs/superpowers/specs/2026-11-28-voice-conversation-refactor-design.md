# 默认语音对话生产链重构 / Production Voice Conversation Refactor

## 目标 / Intent

从默认 Leptos 沉浸语音入口验证完整的听说回合。用户说完后，识别文字只进入 Chat 一次，回复边生成边播，关闭和说话打断只撤回本回合拥有的工作。断线、降级和失败均有明确反馈。入口覆盖浏览器与 NSH 承载的同一 WASM Panel。普通输入框听写和显式启用的 TSX Voice 保持各自现有契约。 / Verify the shipped immersive voice loop in the browser and the NSH-hosted WASM Panel. Submit each utterance once, speak the reply progressively, and confine close and interruption to work owned by that turn. The composer dictation path and opt-in TSX Voice retain their contracts.

## 方案 / Approaches

用户选择先修默认生产链。先连接现有 Chat 精确取消、Gateway STT/TTS 和设备清理，再统一该入口的回合归属与失败规则。两套入口迁移期间需各自做兼容验证。另一方案让 Leptos 与 TSX 一起迁移到同一编排，能更早减少两处状态代码，但同一批验证会同时涉及分句播报、整轮播放、Web 配对和 Desktop IPC 授权。 / The operator chose to fix the production path first. Wire existing Chat cancellation, speech endpoints, and device cleanup, then consolidate turn ownership in the shipped entry. Validate compatibility across both mounts during the transition. Migrating both frontends together would retire duplication earlier and widen the initial proof surface to both playback strategies and transport authorization models.

## 回合所有权 / Turn ownership

- 语音打开时选择当前 Gateway 连接。重用 `DashboardState` 的连接 epoch 和 `rpc_call_at_epoch`，必要时增加保留 `RpcFailure` 的同路径调用。关闭、连接替换、上下文切换和说话打断在异步清理前同步撤回对应所有权。连接改变时结束语音会话并显示状态，由用户重新进入。 / Select the current Gateway epoch on entry. Reuse the epoch-pinned call path, retaining structured RPC failures where needed. Invalidate the affected owner synchronously before asynchronous release on close, connection replacement, context change, and interruption. Surface transport loss and require explicit re-entry.
- 当前语音回合有一个状态源，关联当前采集、正在提交的 Chat 及已接收的 run。以 Rust 的值与状态转换表达归属条件，沿用共享 UI 状态、字幕与分句规则。只在确有第二消费者的地方提取共享逻辑。视图连接麦克风、事件和播放。继续使用已有 Chat 会话路由、投影及 `session_dials_for_send`，保留 agent、模型、项目和执行参数。 / Keep one local owner for capture, pending submission, and the accepted run. Express ownership with Rust state transitions and reuse UI, caption, and sentence rules. Share logic where there is a second real consumer. Preserve existing Chat routing, projection, and session dials.
- 沉浸语音发送同时携带 `voice_input: true` 和 `run_only: true`。取消调用使用 `chat.abort { run_id, run_only: true }`，只使用确认归属的 run，且不发送 `session_key`。关闭或打断时已知 run 立即交给精确取消。回执晚到时，同连接上撤回该 run，回执不得修改旧视图、当前会话或播放。同一回合只发一次 Chat。远端已收到但回执丢失时显示结果未知，不重试、不依赖会话级取消，也不从共享会话事件猜测 run ID。 / Opt immersive sends into exact cancellation and keep `voice_input`. Abort only the owned run on the originating epoch. A late receipt on the same connection is cleaned up without rearming UI or playback. A lost receipt surfaces as an unknown outcome, with no inferred run ID or automatic resend.
- 实际生产 Core 在 `server_init.rs` 的正常与精确发送分支之间选择队列入口。精确回执只在当前进程有效，等待中的语音回合随 Gateway 重启终止。对于已认证且原本具备配对 Shell 上下文的请求，迁移沿用原上下文的捕获与校验，精确取消不得扩大 Shell 或其他工具准入。以真实配置 provider 的队列与运行中取消为验收，模拟运行覆盖保留为补充。 / The managed queue's receipt is process-local, so pending immersive turns end on Gateway restart. Preserve the existing authenticated paired-shell context and its checks where the request already qualifies. Prove queued and running cancellation using the configured-provider route as well as the simulated route. [Real Chat entry](../../../src/bin/aleph-server/server_init.rs) · [Queue worker](../../../src/gateway/busy_queue/spawn.rs)
- 正常完成只冲刷本轮未播的尾句。失败或取消停止本轮播放器和待处理合成，局部已有文字不能被当成成功的结尾。若收到 `run_joined`，结束该回执的语音等待，不接管另一个 run。先于 send 回执抵达的终态通过现有 Chat 事件路由归属。若终态已经撤销路由，迟到的回执不能再次登记活跃 run。为已有和新会话的实际事件顺序验证此点，终态事实仍由 Core 决定。新的回合不能接收旧回合的字幕、格式化、播放完成或错误。 / Flush the unsaid tail only on successful completion. Failure and cancellation stop owned playback and pending audio. A joined receipt finishes its own voice wait. Reuse Chat event routing for early terminals and keep a settled receipt from recreating an active route on late acceptance. Test both existing and new conversations. ## 采集与可降级识别 / Capture and recoverable recognition

- 保留 Worklet、ScriptProcessor 和 Web Audio/NSH WebView 适配，使用现有采集缓存和共享 VAD。按实际样本限长，覆盖超过余量的回调、尾帧、空录音及快速切回。每个回合最多提交一个识别结果。 / Keep existing device adapters and VAD. Enforce sample limits across callback boundaries and cover tails, empty captures, and rapid re-entry. Commit at most one transcript per turn.
- 保留正常流式字幕和低延迟提交。当流无法建立、被关闭、已知丢帧或语音段结束时无有效文字，在仍持有该回合的前提下，用一份保留的完整 WAV 调用现有 `voice.transcribe` 一次。既检查浏览器待发送队列，也检查 Gateway 的 `try_send`。识别提交前给最后一批语音帧一个有上限的接纳应答窗口。当前回合未能确认接纳时使用同一份 WAV 降级。接纳只表示 relay 入队，provider 未确认的识别结果仍按现有字幕与回合规则处理。RPC 扩展使用向后兼容的附加字段，保留未知和非持有 stream 的一致行为。仅明确禁用和现有连续失败条件为后续回合切换模式。正常流式回合不付额外转写成本。 / Retain live captions and the healthy stream's fast path. If the stream is unavailable, terminates, loses input, or produces no usable transcript, attempt batch STT once with the retained WAV. Observe loss in both the browser backlog and the Gateway queue. Allow a bounded reply window for the last speech frames. Fall back if their admission remains uncertain. An acknowledgment confirms relay admission only. Keep response additions compatible and preserve indistinguishable unknown and foreign stream behavior. [Capture queue](../../../interfaces/webchat/src/platform/wide/views/voice/audio.rs) · [Frame handler](../../../src/gateway/handlers/voice.rs)
- 停止流时先撤回本地帧和增量接收，再使用现有 `voice.stream.stop`，在原连接可达时清理迟到的 stream ID。复用既有 relay 的 pump 与容量界限。Gateway 的传统 `/ws` 断线后若没有回执，本轮客户端只能证明本地释放。服务器断线回收的更强保证需要单独的可验证清理契约。 / Revoke local frame and delta admission first, then stop the existing stream, including late IDs while the original connection is addressable. Reuse the relay pump and limits. Local cleanup is the observable guarantee after connection loss without a receipt.
- `voice.transcribe`、`voice.synthesize` 和现有生成 provider 仍由 Core 决定，语音只是这些已有能力的消费者。现有 Desktop Media Capability 的已安装识别仍走其获授权的 Desktop IPC，浏览器及远端不从 NSH 标记获得本机识别权限。本轮无新增公开 Capability 类型或平行 registry。 / Core remains authoritative for STT, TTS and provider selection. The installed recognizer remains admitted by the existing Desktop Media Capability through authorized Desktop IPC. A native document marker carries no recognition authority. The production voice UI composes existing capabilities through their entry points.

## 连线顺序与清理 / Order and cleanup

1. 固定实测基线。追加能重现关闭或打断误杀、回执竞态和有部分文字的失败的回归用例。 / Establish baselines and reproduce cancellation scope, receipt races, and failure with partial text.
2. 接通 epoch、精确取消、Chat 终态与音频清理。用一个回合所有者替换 `speak_gen`、`speak_run`、`active_run` 中重复的归属字段。将失败与自然完成统一到可测试的处理点，移除替代掉的裸 `chat.abort` 和独立清理分支。 / Wire exact cancellation, terminals and playback release. Remove duplicate run ownership, the legacy immersive abort call, and superseded cleanup branches.
3. 接通采集边界、流队列反馈和按回合降级。保留设备、provider 和 TTS 入口，清理确认无调用者的私有旧分支和误导注释。 / Wire input bounds, frame admission, and per-utterance fallback. Remove superseded private paths and stale comments.
4. 验证、校对 `FEATURE_LOCATOR.md` 语音定位段与相关 reference、记录 QA 证据并在隔离分支提交。 / Verify, reconcile the voice locator and references, record evidence, and commit in the isolated branch.

## 验收 / Acceptance

- 同一会话创建两个可区分的 run。关闭、打断或迟到回执清理只使本轮的 run 终止，后续 run 仍可完成。关闭发生在录音、转写、发送等待、已接收和播放时，均验证设备和本地播放释放，活跃连接下验证服务端资源效果。 / Verify run isolation and resource outcomes at each asynchronous phase, including a successful successor run.
- 录音 → STT → Chat → TTS 从默认生产入口可达。使用隔离 Gateway、受控 provider、真实 WASM 包和 `qa/nsh_voice` 的浏览器路径，补上健康流式的首句发生在 run 完成之前、同回合 WAV 降级只触发一次，以及失败与空结果各自回到可继续状态。通过已配对入口证明 Chat 参数和事件匹配。 / Exercise the shipped entry with a private Gateway, controlled providers and a real WASM bundle. Prove progressive synthesis, one batch fallback, recoverable failures and pairing-scoped Chat matching.
- NSH 使用同一构建产物验收语音入口、媒体权限、提示和清理。区分实际音频设备、受控输入与纯浏览器证据。报告短长语音的首字幕、结束到 Chat、首段 TTS/首音频、播放打断和资源释放中可实际测量的指标。对照相同素材和配置，并记录无法采集的阶段。 / Check the shared build in NSH and report device, controlled-input and browser evidence separately. Measure only observed latency and release boundaries on matched inputs.
- 运行共享 Rust、Gateway、WASM 检查和既有 TSX 夹具。回归需验证实际观察结果，包括发送次数、拥有的 run 是否停止、后续 run 完成、失败文字没有尾句合成、旧一轮无副作用。 / Run focused Rust, Gateway, WASM and existing TSX checks. Assert externally observable effects such as submission counts, exact cancellation, successor completion, and rejection of stale synthesis.
