# Computer Use Zahir projection and operator approval / 桌面投影与操作员审批

Status / 状态: builder check addressed; awaiting design approval. Branch / 分支: `refactor/computer-use`, based on scoped observation at `6a351411f`. No product changes in this design step.

## Intent / 目标

1. Prove that an eligible caller can discover and resolve the existing `desktop` Tool through Zahir and reach the existing governed executor. Discovery is not permission to execute. / 证明合格调用方能经 Zahir 发现、解析并到达同一受控执行入口；可见不代表获权。
2. Let an authenticated operator approve one eligible, already-admitted desktop mutation when `ApprovalPolicy` returns `Ask`. Resume the held call only; never ask the model to replay it. / 仅在 `Ask` 且调用已通过其他准入时，由已认证操作员批准这一次桌面动作；直接恢复原调用，不让模型重试。

## What exists / 现有接线

- `src/bin/aleph-server/commands/start/mod.rs` mounts `ProjectionHost` on `tool_registry_phase2` and later invokes `register_builtin_routers` with `BuiltinToolRegistry::unified_tools()`. `src/tools/handlers/builtin.rs::BuiltinRegistryRouter` projects the existing schema and delegates execution back to the built-in registry; the name `desktop` reaches `DesktopTool::call_json`. Previous documentation did not account for this late registration. Establish effective availability, ownership and guarded execution with a production-composition test rather than adding a second registration or relying on startup log text. / 先验证后置注册在生产组合里生效，不重复注册，不把启动日志当执行证据。
- `src/builtin_tools/desktop/mod.rs::check_approval` records `Allow` and `Deny`, but emits `approval_required` on `Ask`; it does not await a verdict. `ScopedToolService` has a separate tool-level confirmation gate. Its approval does not prove that an operator judged the actual desktop leaf and target. / 工具级确认不等于已审核桌面叶动作的真实目标。
- `src/approval/operator_requester.rs::request_operator_once` already supports operator-only, one-shot, bounded requests with cancellation cleanup. `ExecApprovalManager`, operator event delivery, Panel cards and `exec.approval.resolve` already exist. Reuse these; do not build a new requester registry, RPC, grant store, approval UI, or transport. / 复用既有操作员单次审批、事件和 Panel；不新造审批子系统。

## Approaches / 方案取舍

| Approach / 方案 | Trade-off / 取舍 |
|---|---|
| **Selected:** validate/fix the canonical projection, then request operator-once at the desktop leaf `Ask` boundary | Keeps the policy and actual dispatch in the same authority; requires explicit verified intent and cancellation wiring but protects against approving an ambiguous target. / 选择：复用唯一投影与叶级动作闸；需要绑定可验证目标，换来判定与执行的一致性。 |
| Mark the entire `desktop` Tool as requiring generic confirmation | Small wiring diff, but it asks for reads and batch envelopes, cannot distinguish the resolved target, and can cause duplicate or misleading consent. / 改动小，但只看工具名，不足以代替叶级判定。 |
| Send requests to every already-authorized origin channel | Useful later when each surface proves recipient identity, resolving authority and cancellation parity. First release is operator-only by user choice. / 原通道审批待身份与回执隔离逐端验证，本版不做。 |

## Projection and invocation / 投影与调用

- Keep one `desktop` entry of kind `Tool`, one handler/descriptor pair and one `OwnershipTree` generation. Verify after built-in registration, including a pre-registration snapshot, publication/subscription convergence, resolve and lease validation, one fake-platform invocation, and disposal/stale lease rejection. Fix only a demonstrated wiring gap. Read/resolve must not spawn a limb or trigger approvals. / 验证后置注册、投影收敛、租约、受控调用和撤销；发现或解析不启动平台调用或审批。
- A successful resolve is not an execution authorization. Preserve visibility, tool permission/tier, capability policy, owner/revocation and desktop hard guards. Use the existing `ScopedToolService` canonical route, which already owns the admitted handler and its `CanonicalEntryLease` and `BackendLease`. Carry that original identity into the held call. Immediately before a resumed mutation, use the current publication to verify the exact captured handler (including handler identity, since descriptor equality alone does not detect a same-name replacement), validate the original backend lease and recheck applicable policy. Invoke only the captured path; never resolve by name again to substitute a different handler. / 复用已有受控路由，携带原始 handler 与租约；恢复时验证原对象仍有效，不按名字换成另一份。
- Do not add a public invoke endpoint, widen visibility or change raw MCP/ACP behavior. Calling the raw router directly or presenting `approval_required` JSON cannot obtain or satisfy an interactive leaf approval. Revocation before the final pre-dispatch check blocks the effect; the check cannot retract a native operation already handed off. / 不扩大入口或可见性，不把拒绝响应当凭据；最终闸门拒绝已撤销的调用，不承诺撤回已交付平台的动作。

## Operator-once flow / 单次审批流程

1. Keep `classify_approval` and existing `ApprovalPolicy` as the desktop decision source. `Allow` and `Deny` retain behavior. For `Ask`, require a governed, attended live call and a usable deadline. Use a bounded redacted operator card with action category and verified target (app identity and, when used, window ID), not caller-supplied labels as proof. Omit text to type/paste, clipboard/AX values, images and other sensitive input. Make clear the operator is authorizing an operation on the shown application, not endorsing hidden text or a presumed semantic UI effect. / 复用 `Allow/Deny/Ask`；卡片只显示操作种类和已验证对象，不透出输入正文或画面。
2. Use the existing authenticated operator panel and `request_operator_once`. The absolute deadline already computed by `ScopedToolService` for the call is authoritative; honor any earlier enclosing deadline exposed by the caller and the enclosing cancellation token. Pass the effective absolute deadline and the caller-interest cancellation child into the admitted, owned desktop invocation, not ambient `TurnContext` or user JSON. Wait at most 60 seconds within that budget. A dropped waiter cancels the pending approval; the held handler must also check cancellation and deadline after acquiring the existing desktop lock and immediately before native dispatch. Do not cancel or replay a native operation already handed off. No desktop lock while waiting, grant key, session/always approval, model verdict, or cross-call reuse. Missing context, no route, expiry, cancel or denial preserves refusal. / 受控调用负责绝对截止时刻与取消信号，持有原调用的任务必须实际消费它们；等待不占锁，恢复和交付前再检查，不落持久授权。
3. Resume the same held payload on `Approved` only, acquire the existing desktop lock, then honor Escape, hard guards and current deny/revocation before dispatch. Revalidate the original resolved subject, rail, and window/coordinate mapping if applicable. Use the resulting prepared intent for dispatch; do not look up the target by name a second time during dispatch or fall back to global. If the platform cannot prove process instance identity or changed geometry for a window-relative action, refuse rather than treating same PID or same title as proof. The platform contract may add the minimum typed identity evidence needed for this check; OS APIs stay in limbs. This prevents drift across the wait; it is not a new guarantee that an app's content remains unchanged inside the approved target between two native calls. / 恢复后重新验证准入、进程实例、投递轨及适用的窗口/坐标；证据不足或漂移则拒绝，无全局回退，不宣称 UI 内容静止。
4. Preserve `effect`, scoped post-observation, and audit from the existing tool. Record the human decision separately from platform delivery; audit redacted metadata, without sending private payloads to the approval record. Existing generic tool gate remains authoritative where configured; a verdict there cannot satisfy the leaf-only decision. / 审批结果和动作投递是不同事实；不把通用审批替当精准叶级批准。

## First slice and non-goals / 首版边界

- Begin with standalone macOS input on the actual **targeted rail** (`click`, `double_click`, `type_text`, `key_combo`) when the current limb can prove its actual process and any claimed window. This includes no global keyboard input: even a named selector on the global rail does not prove who receives the keystrokes. Only key/pointer gestures that complete within the one invocation are eligible. Do not extend interactive `Ask` to batch or its nested leaves, global input, clipboard writes, launch/quit, AX writes, or hold/release yet. These retain existing admission and structured refusal; no new block on an existing `Allow` path. The batch path currently holds a re-entrant desktop lock across children; waiting there would require a separate change. / 首版只对能验证目标的独立 macOS 定向叶动作开启交互；其他 `Ask` 仍拒绝，既有 `Allow` 不变。批次不在锁内等待。
- Do not add Windows/Linux proof implementations, new app privileges, launch background services, touch live permissions, add `EffectClaim` producers, or implement safe replay. No main merge or push. / 不加跨平台实现、权限、EffectClaim 或自动重放，不推送合并。

## Acceptance / 验收

- Production-composed fixture demonstrates one descriptor and real handler resolution, denied/stale scopes cannot invoke, and no duplicated descriptor or tool registration. / 用生产组合证明实际出现且走同一 handler，拒绝或过期租约不执行。
- Fake-platform tests demonstrate: no dispatch before verdict; non-operator cannot resolve; approval performs exactly one invocation; two simultaneous approvals cannot authorize each other; denial, timeout, cancel, expiry, no operator path, unsupported targets, same-PID process replacement, window or policy drift, and stale or same-name replacement of the lease-bound handler cannot dispatch. Test that dropping the waiter or expiring the deadline after approval but while waiting for the lock prevents even a later approval resolution or lock acquisition from causing a mutation. Show cancellation removes the pending request and that another session can acquire the lock while it waits. / 验证实际送达与消费结果，而不只断言 request 被调用。
- Verify no raw arguments leak to cards, record or non-operator event streams; unchanged reads/denies, ineligible/blocked behavior, batch stop and post-observation/effect. Run relevant Rust integration tests; only run live native tests with separate authorization. / 验证脱敏、观测、权限与批次兼容，真机另授权。
- Update `docs/reference/FEATURE_LOCATOR.md` and applicable approval/Bridge references to distinguish mounted discovery, permission and native availability; commit in the isolated branch. / 校对参考并在隔离分支提交。
