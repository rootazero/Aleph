# Agent Shell Capability 重构 / Agent Shell Capability Rework

状态：设计稿，待审批。产品代码未改。 / Status: proposed, awaiting approval; no product code changed.

## 意图 / Intent

让 Agent 的 `bash` 能及时交还控制权、续读有界输出、确认取消真的生效，并在沙箱和授权都能证实的前提下给运行中命令发送输入。改造现有 Tool Capability，而不是再建执行器或把 Panel 人用终端变成 Agent API。旧调用默认行为、权限键、工作区隔离和输出保护不能因新增入口而变弱。

Let the Agent's `bash` yield control promptly, continue reading bounded output, distinguish requested cancellation from proven cleanup, and write to a running command only when both sandbox and authorization can support it. Extend the existing Tool Capability rather than build another executor or expose the Panel terminal to agents. Existing invocation defaults, permission keys, workspace isolation, and output protections must not regress.

1. **分阶段增强（已选） / Staged extension (selected):** 先修执行、续读、关闭；再接 stdin/EOF 且后端逐个证明，默认无交互。保住现有 Capability 边界；代价是要维护旧形态与新形态并行的契约，也可能出现跨平台的 stdin 可用性差异。 / Repair execution, output continuation, and teardown first; then add opt-in stdin/EOF per verified backend. This preserves the existing capability boundary at the cost of compatibility adapters and potentially uneven platform availability.
2. **仅修非交互 / Noninteractive only:** 更快验证清理和输出，不解决后续输入。 / Easier to verify, but leaves follow-up input out of scope.
3. **完整 Agent PTY / Full Agent PTY:** 更接近 Codex 的 REPL 能力，但需要独立的沙箱、终端、输入授权和各端回收契约，不应借道 Panel `pty.*`。 / Supports REPLs, but requires a distinct sandboxed terminal contract and cannot borrow the human terminal.

## 第一阶段：现有链路先连实 / Stage one: connect and prove the existing path

- **入口 / Entry:** 保持 `bash` 名称、默认前台调用、现有 `background` 和 `poll`/`wait`/`kill`/`list`。可选 `yield_ms` 让启动调用从登记开始以有界窗口等待首批回执，可在审批尚未完成时返回 `starting`；选择它即允许同一进程在本次调用之后继续，不延长执行截止。省略 `background` 或设为 `false` 时沿用前台默认/上限；只有显式 `background: true` 才使用旧后台预算，组合 `yield_ms` 只是改变首次观察窗口。窗口内得到终态就返回结果；否则返回同一个可续接的 `process_id` 和真实状态。所有可续接任务均遵守现有后台准入、受管 worktree 禁止脱离、会话与全局并发上限。 / Preserve the public tool and legacy calls. `yield_ms` bounds initial observation from reservation, including while approval is pending, and permits continuation without raising the execution deadline. Only explicit `background: true` uses the existing background budget. Return a terminal result if settled, or the same ID with truthful state. All continuable jobs obey existing detached-job admission, owned-worktree restrictions, and quotas.
- **单一准入与 driver 接缝 / One admission path and driver seam:** `BashExecTool` 仍经 `CodeExecTool` 的共享命令准备和 `WorkspaceSandbox::prepare_command`，沿现有 `Sandbox::execute` → `OsSandboxDriverTrait::run` 路径显式传入可选的 shell 生命周期控制，交给当前平台启动处与 `run_child_with_drain`。OS child 和 containment handle 由已存在的 driver 路径拥有；registry 只持控制和观察能力。不要扩展浏览器专用 `ManagedSandbox::spawn_managed`，不要增加独立执行器或 host fallback。不支持控制的 driver 必须明确拒绝相应操作，不能悄悄忽略控制。保留 `CodeExecTool` 普通调用和非 shell 消费者；分离启动所需的审批路由、调用方和无人值守上下文与后续授权，不用任务局部变量或 PID 充当授权权威。 / Reuse command preparation and the existing `Sandbox::execute` → `OsSandboxDriverTrait::run` path; pass optional typed shell lifecycle control down to the current platform launch and common drain. The backend owns the OS child and containment; the registry owns control and observation. Do not extend the browser companion's managed-spawn contract, add an executor, or fall back to host spawn. Drivers that cannot honor control reject it explicitly. Preserve normal CodeExec callers and keep launch context distinct from follow-up authority.
- **生命周期 / Lifecycle:** `ProcessRegistry` 是 Agent shell handle 的唯一所有者视图。占位是 `starting`；同一个 driver 确认已启动受限的 OS 子进程才推进 `running`，这并不证明包装器内的目标程序已开始运行。`kill` 保留原调用形状，发出幂等取消后立即返回当前状态（通常是 `stopping`），调用方用 `poll`/`wait` 观察清理；只在确认预启动取消阻止了 spawn，或确认已启动的受管进程完成终止、回收及有界 drain 后，才发布 `killed`。旧终态先赢则返回原终态，不改成取消成功。保留准入拒绝、启动失败、运行超时、自然退出等各自诊断，晚到回执不能复活终态。配额覆盖 `starting`/`running`/`stopping`，未确认收尾不释放占位；journal 恢复仍只是墓碑，不能复活 handle。服务关闭先封住启动，再发取消并有界等待已拥有的操作；到界报告未确认清理，不伪造 `killed`。浏览器 supervisor 不变。 / Reservations are `starting`; `running` confirms a sandboxed OS child, not the payload inside a wrapper. An idempotent `kill` returns current state immediately, usually `stopping`; use `poll` or `wait` to observe cleanup. Only a proven pre-spawn cancellation or verified teardown publishes `killed`. Other terminal states are not overwritten. In-flight starts and unconfirmed teardown retain capacity. Shutdown seals admission and waits within its budget, reporting unconfirmed cleanup honestly; journal and browser ownership semantics otherwise stay unchanged.
- **I/O 与回收 / I/O and teardown:** 先开始两个方向的输出读取，初始 stdin 与运行截止并行；保持默认关闭 stdin，不吞掉 pipeline 的退出码。自然退出、超时、取消均有有限 drain；排空达到截止要回收读写任务，保留已获输出并区分截断和未排净。取消/超时通过 backend 已拥有的 OS 进程或 containment handle 终止并显式等待。取证必须区分直接子进程与进程树；只在有 containment 证据的配置声称整树回收。没有可靠整树语义的后端/配置不得声称可确认整树，亦不得为它开放可续写 stdin。 / Run both drains before feeding startup input, under the execution deadline; retain EOF and exit-status semantics. Bound draining in all exit paths, reclaim the I/O work and surface truncation or incomplete drain. Signal and explicitly reap through the owning backend. Prove direct-child vs tree cleanup separately, and do not claim tree cleanup or enable writable stdin without proven containment.
- **续读 / Continuation:** 新增 `process_action: "read"`，`process_id` 必填，首次省略 `cursor`。返回有界 stdout/stderr 增量、状态、下次游标与显式丢失/扣留。各流按原始字节位置记账，不拿脱敏后的文本索引切原始缓冲；基于带上下文的尾窗先门控，再投影增量，无法安全映射的区间不返回文本。暂待后续字节才能判定的区间不推进；已覆盖、确定扣留或终态仍无法安全判断的区间以结构化缺失/扣留范围推进，不静默跳过。检测到 block-class 时对 `read` 锁存拒绝，不能等环缓冲覆盖后再从下一游标解除拒绝。终态沿用同一有界尾窗和坐标，随现有条目保留策略回收，不切到坐标不同的完成结果、不持久化 raw。旧 `poll` 仍是尾窗。独立游标不消费其他读者的输出，跨进程、会话、重启或未来的游标失败。wire 编码、块大小与安全边界算法由计划定。 / Use non-consuming cursors in the same per-stream source coordinates before and after exit, never indexes in transformed text. Gate with context before projecting deltas. Hold the cursor for undetermined fragments; advance past explicitly reported lost or permanently withheld ranges. A detected block-class refusal remains sticky for `read`, even after ring overwrite. Retain only the same bounded in-memory tail with the existing entry lifetime, never persist raw bytes or switch to the differently formatted final result. Reject wrong-process, wrong-session, previous-boot and future cursors; keep legacy `poll`.

## 第二阶段：受控 stdin/EOF / Stage two: controlled stdin/EOF

- **公开契约 / Public contract:** 显式 `keep_stdin_open: true` 才保留 pipe，且必须是 `background` 或 `yield_ms` 的可续接调用。`process_action: "write_stdin"` 要求非空、有限 UTF-8 `input`，不拼接换行；`close_stdin` 送 EOF 并不可逆，同一活进程重复关闭不再发效果。普通命令、已退出或跨会话 handle、由启动脚本占用的 stdin、无可靠 containment 的 backend 都拒绝，不静默降级。CLI/Panel 人用 PTY、Ctrl-C 仿真、任意二进制、重启恢复 stdin 均不在范围。 / Opt-in pipe-only input on a continuable job. `write_stdin` takes bounded, nonempty UTF-8 verbatim; `close_stdin` sends irreversible EOF. Reject incompatible launches, existing startup-script input, wrong ownership, dead handles, and unsupported backends. No PTY, control-key emulation, arbitrary binary input or restart recovery.
- **授权 / Authorization:** 仅在基线沙箱、无额外启动能力提升、且当前执行策略允许该通道时开启。后续每次写入、首次 EOF 都是独立效果，通过既有 `bash` scoped gate，另经已有可审计 exec approval 做一次性审查；不能借启动审批、session grant 或截断后看似相同的片段放行。任意 stdin 可能被解释成指令，不能靠字符串分类假定是数据；若当前权限有不能在续写路径上同样执行的硬性限制，则该配置禁用续写。审批显示目标进程和经过现有脱敏的精确请求概况，拒绝超出可审阅上限的载荷；不把原始 payload 放进日志、journal、回执或审批记录。未挂审批、无人值守、权限撤销、同会话不同执行绑定一律 fail closed。 / Require baseline sandbox policy and a current scoped permission plus separate one-use approval for each write or first EOF. Treat stdin as potentially executable, not intrinsically data: disable it where an applicable hard restriction cannot also be enforced. Review a bounded, scrubbed request tied to the exact payload and live process. No remembered or startup grant, no raw-payload records, and no execution without current attended authorization.
- **执行绑定 / Execution binding:** 续写绑定完整 `SessionId`、现有调用路径可证实的有效主体与权限来源、规范化工作区身份、启动时有效沙箱策略和该 handle 的 live control identity。不同 run/turn 或审批路由不单独使其失效；主语或权限来源、工作区、沙箱约束变化，或当前 `bash` 权限不再允许，均拒绝写入并要求新建进程，而不是尝试追认既有子进程。准入与审批后复验从现有权威重读，不把缓存的启动 grant、PID、`TurnContext` 或字符串 session label 当成授权证明。若某条 dispatch 路径不能获取可信主体或复验可撤回的权限，则在该路径明确禁用续写。 / Bind continuation to the full session ID, provable principal and permission origin, canonical workspace, effective launch sandbox policy, and exact live control. A later run or turn can continue; changed authority, workspace, sandbox restrictions, or lost permission requires a new launch. Before effect, re-read existing authorities rather than trusting a startup grant or captured context. Where the binding or revocation cannot be verified, disable continuation for that route.
- **串行与竞态 / Serialization and races:** 单个活进程由唯一 stdin writer 串行提交、关闭；不同进程不共享写锁。不要跨审批等待持全局 registry 锁。审批后按上述绑定复验，并与 cancel/EOF 在单进程控制点仲裁；超时、退出、取消唤醒排队写入。部分或不确定写入要报告可能有副作用，不自动重试。支持标记只由已验证 driver 给出；先验证本机 Linux 的隔离配置，不把 `bwrap` 存在当成 containment 证明。macOS、Windows 或其他未获证据的配置默认明确不支持。 / Serialize effects per live process without blocking unrelated jobs; after approval recheck the binding and arbitrate against cancel/EOF at that process. Teardown wakes pending writes. Report partial or uncertain effects without automatic retry. Only verified drivers advertise support; the presence of bwrap alone is not proof, and all unverified configurations remain unsupported.

## 验收、删除与文档 / Acceptance, removal, and docs

- 先用实际隔离子进程复现启动 stdin/output 背压、自然退出之后继承管道未关闭、取消后 OS 仍未收尾；分别验证正常结束、截止、启动前取消、运行中取消、重复取消、服务关闭。假 driver 测状态竞态，真实 sandbox 验证门到进程的效果；不得以 mock 证明 OS 行为。 / Establish failing cases and verify both orchestration races and observable process effects. A mock does not prove OS teardown.
- 通过真实注册的 `bash` 工具 schema/dispatch 验证旧调用、首批返回、并行进程、游标跨会话和数据缺失、终态与 journal、输出保护和使用限制。第二阶段还必须验授权失败写零字节、审批期间退出/撤权/关闭、EOF 确实到达、stdin 背压和部分写入，以及不支持平台无副作用。 / Verify registry-to-driver wiring, legacy compatibility and stream protection, then prove denial causes no writes, EOF reaches the child, racing changes fail closed, and unsupported paths have no effects.
- 清理被新托管生命周期替代的后台 Task abort、转接和重复终态分支，先核实调用者；保留 browser managed contract、人用 Terminal RPC 和未被替代的前台接口。验证以后校对 `docs/reference/FEATURE_LOCATOR.md` §3.7/§3.15、`docs/reference/SANDBOX.md`、`docs/reference/PROCESS_MANAGEMENT.md`、`docs/reference/TOOL_SYSTEM.md`，有需要才更正 `docs/reference/TERMINAL_RUNTIME.md` 的边界。证据逐平台标明实际运行、编译检查或未验证，不把 Linux 结果外推。 / Delete superseded background-only glue after checking consumers; keep unrelated contracts. Update the paired reference docs with verified behavior and explicit platform evidence.

不做：第二执行运行时、第二权限体系、持久化命令输入或流、任意会话接管、人用终端改造、主分支更新。 / Out of scope: a second executor or policy system, persistent stdin or streaming, session takeover, Panel terminal changes, or updates to `main`.
