# 受控实时 Shell JSONL / Controlled Live Shell JSONL

**状态 / Status:** 待批准；仅设计。复用第一阶段 Shell 交付。本稿获批后，仅替代[通用 stdin 设计](2026-11-26-shell-capability-stdin-design.md)的输入范围和策略证明；原生隔离、授权、脱敏和独立实现终审仍是门禁。[通用模式的 no-go 证据](../runs/2026-11-26-shell-capability-stdin-verification.md)不撤回。 / Pending approval, design only. Builds on Stage 1. If approved, it replaces the scope and policy proof of the generic stdin design, not its confinement, authorization, redaction, or independent implementation review gates. The generic no-go finding stands.

## 意图和取舍 / Intent and Approaches

Agent 需要在一个受控 `bash` 作业里逐条提交 JSON 值、在 EOF 前读取每条处理结果，然后结束输入。首版是数据流，不是任意解释器、任意 CLI 问答、人用终端或密钥通道。 / The Agent needs to send successive JSON values to one supervised `bash` job, read each result before EOF, then end input. This is a data stream, not a general interpreter, arbitrary CLI prompt handling, human terminal, or secret channel.

| 方案 / Approach | 取舍 / Trade-off |
| --- | --- |
| **受控实时 JSONL（已选） / Controlled live JSONL (selected)** | 固定可信程序、参数、过滤器、输入帧与输出形状；保留同一进程内的往返，但新增消费者要单独证明契约。 / Fixed trusted binary, arguments, filter, frames and output; retains live exchange in one process, but each future consumer needs its own proof. |
| 先缓冲、到 EOF 才启动 / Buffer and launch at EOF | 可沿用通用启动 stdin，但读不到实时结果；不满足本轮目标。 / Reuses generic startup stdin, but loses live results. |
| 任意解释器逐块审批 / Approve chunks for arbitrary interpreters | 审批不是文本规则，也没有可信记录边界；不采用。 / Approval cannot replace textual rules and a generic interpreter has no trusted record boundary; rejected. |

## 产品契约 / Product Contract

- 仍是现有 `bash` Capability。显式 `stdin_profile: "jsonl_inspect"` 启动，必须同时提供 `background: true` 或 `yield_ms`；不接受 `cmd`、启动 stdin、调用方自选程序/参数/环境、额外写路径或放宽沙箱的参数。原有 `bash` 默认保持不变。 / Existing `bash` Capability only. The explicit profile requires background or yield; no command, initial stdin, caller-selected executable/args/env, extra writable path or sandbox elevation. Ordinary calls are unchanged.
- `write_stdin` 只接收一个**显式存在**的 JSON `record`（允许 JSON `null`，不等同字段缺失），用现有 JSON serializer 产生一条紧凑 UTF-8 记录和一个换行。序列化后含换行上限 **4,096 字节**，同时不能超过实测 pipe 原子写限制；直到 EOF 的总记录字节上限 **16 KiB**，若现有规则的无截断预算更小则取更小值。拒绝超限，不截断、不拆帧、不自动重试。 / A write accepts exactly one present JSON value, including null. Serialize one compact UTF-8 line with newline; cap each line at 4,096 bytes including its newline and at the verified atomic pipe bound, and cap the whole stream at 16 KiB or the stricter lossless policy budget. Reject excess; never truncate, split or auto-retry.
- 首发只启动受信任的宿主 jq（本机 `/usr/bin/jq`，不从 `PATH` 选择，也不让工作区控制其二进制或只读依赖），直接通过已有 workspace/driver 执行，无外层 shell。固定参数为 `-M -c --unbuffered` 和固定过滤器 `{kind:type, count:(if type == "array" or type == "object" then length else null end)}`。选项、环境和过滤器不来自记录。结果只含有限的 `kind` 与容器 `count`（标量为 `null`）；不回显值，不承诺字节级保真。 / Use only a trusted system jq and its trusted read-only dependencies, no PATH lookup or shell wrapper, through the existing workspace/driver. The literal args and filter above produce only a root kind and container count; no value echo or byte-for-byte round trip.
- `close_stdin` 无 `record`，确认后关闭写端。同一授权主体重复关闭只返回 already-closed；既有 `poll`、`wait`、`read`（按游标）和 `kill` 继续使用同一 process ID。写入回执表示 frame 已提交给 pipe，不声称 jq 已处理；处理结果须从读侧观察。 / Close takes no record; a repeat by the still-authorized principal is idempotent. Existing process faces retain the same ID. A write receipt proves delivery to the pipe, not processing; observe results on the read side.

```text
bash {stdin_profile:"jsonl_inspect", yield_ms:1000}       → process_id: 42
bash {process_action:"write_stdin", process_id:42, record:[1,2]}
bash {process_action:"read", process_id:42}             → {"kind":"array","count":2} + cursor
bash {process_action:"close_stdin", process_id:42}      → closed
```

## 硬规则证明 / Hard-Rule Proof

1. 固定 jq 启动仍先经过 `WorkspaceSandbox` 的实际启动核验。写入前，把固定启动命令与**所有已投递记录 + 候选记录的精确字节**构造成等价的 `SandboxCommand` 启动文本视图。提取并复用当前两个 hook 的文本判据及规范化，不复制规则集，也不迭代执行带审批、写日志或计费副作用的完整 hook。策略若不能无副作用地等价复用、不能覆盖整个候选前缀、或含另外无法覆盖的适用要求，拒绝 profile 或此次写入。警告与阻断不得互换。 / Keep actual launch admission. For each write, evaluate the fixed launch text plus the exact full accepted-prefix bytes and candidate frame as the existing prepared-stdin policy would see it. Reuse both hooks' text predicates and normalization without rerunning side-effectful hook behavior. Reject when lossless coverage or predicate equivalence cannot be proved, or another applicable requirement is uncovered. Preserve warning vs. block semantics.
2. 策略每次看完整前缀，而不是逐块独立匹配。因此任何通过后实际投递的**完整记录前缀**都必须通过原有文本阻断；允许保守地拒绝当下匹配、未来可能不匹配的前缀。固定 jq 数据解析保证已投递的较早记录不能执行或改变后续过滤器。记录必须一次完整写入，才可更新已投递前缀；一旦投递不明，关闭该输入端、拒绝重试并走受监督停止，不伪造回执。记录只进进程内有界暂存，结束后丢弃。 / Every delivered complete-record prefix must pass the existing hard text decision. Conservative overblocking at an intermediate frame is acceptable. Fixed jq parses data, cannot execute a record or change the filter, and accepts only complete frames through this interface. Advance the accepted prefix only on confirmed complete delivery; an ambiguous effect closes input, refuses retry and enters supervised stop. Keep the bounded transcript only in memory and discard it at settlement.
3. 用无害合成文本构造跨记录规则和分别接受、联合拒绝的前缀；还要对实际内置硬规则及 operator 配置在预算内，与启动 stdin 入口做判据对照。任何绕过规范化、跳过规则、区间截断、或策略版本变更后复用旧判据的正例都会阻断交付。 / Use a benign synthetic cross-record rule and a separately allowed / jointly denied transcript as an effect test. Differentially compare the committed predicates with actual startup-stdin decisions for built-in and operator policies within the budget. Normalization gaps, skipped rules, truncation, or stale policy proofs block delivery.

## 写入授权、原生隔离和私密性 / Effect Authorization, Isolation and Privacy

- 首版仅考虑已配对、有人值守且能从 live 权威证实主体的 Gateway Agent 入口。不能凭缺失角色、请求字符串或 session 快照推导权限。绑定完整 `SessionId`、主体、授权来源、规范工作区、策略版本、Capability 绑定和实时作业控制；`write` 和首次 `close` 必须有人通过现有 Gate 给本次 `AllowOnce`，不接受 standing grant。写入内容不进入审批动作。不可变候选帧仅在内存绑定本次尝试 ID，不接受其他尝试的同意。 / Consider only a paired attended Gateway Agent route with live authoritative identity. Bind session, principal, permission source, workspace, policy revision, capability binding and live job controller. Require a fresh one-shot decision for each write and initial close, never a standing grant or raw record in the approval. Bind the immutable pending frame to a unique attempt ID only in memory; a response for another attempt cannot be exchanged for it.
- 审批等待不占权限锁或进程控制锁。先对不可变策略版本计算文本判据；最终效果要在实际撤权源及同一作业 stop/EOF 的同步边界内证实该版本、权限与控制仍有效，然后做一次已验证的非阻塞操作。不用 `OwnershipTree::with_current_binding` 的本地提交回调藏 I/O；其契约不允许 I/O。只入队、再次读快照或先复验后在别处写都不算。若既有撤权权威无法与最终效果排序，入口不开放。 / Await approval without authority or process locks. Evaluate against an immutable policy revision, then revalidate it, permission and control at the actual revocation/stop/EOF boundary and perform one verified nonblocking operation. Do not hide I/O in the OwnershipTree's local-only callback. A queue or a second snapshot cannot prove ordering. No live route without that proof.
- 保留已批准的 Linux 原生门禁：可信只读工作区和运行时挂载、无外网/提权、私有有界 scratch、有效 CPU/内存/PID 限制、实际原子写能力和全组退出，无 cgroup 软降级。当前开发用户不能写 cgroup 挂载点；需要在不更改常驻服务或宿主权限的独立委派环境验真。仅 jq 在当前主机运行成功不是上线证据。 / Keep the approved Linux native gates, including read-only trust roots, no external network/elevation, bounded private scratch, effective CPU/memory/PID limits, atomic pipe capacity and verified whole-group exit; no soft cgroup fallback. The local cgroup mount is not writable to this user. A disposable delegated environment must prove real confinement without changing the running daemon or host permissions. A jq smoke check is not release evidence.
- 在首次持久化/广播之前由现有投影所有者识别新 profile、输入动作或 `record` 字段（包括非法组合）。只保留结构化安全字段，不记录原参数对象、原始 `record`、输入片段或回显诊断；保留关联 ID 和已知字节计数。对该 profile，只允许固定输出形状进入既有 live tail、终态和 journal 路径；jq 原始 stderr 不进入这些路径，异常只记不含正文的结构化错误。 / Identify the new profile, input actions or record field before initial persistence or broadcast, even on invalid combinations. Project only safe structural fields, correlation IDs and a known byte count, never the original argument object, record, fragments or echoing diagnostics. Only the fixed result shape reaches existing live and terminal output and journal; withhold raw jq stderr and report structured errors without input.

## 验收、职责和非目标 / Acceptance, Builder Latitude and Non-goals

- #18：先验明现有文本等价和实际撤权源，证明至少一个 eligible 的 Linux 路由及原生环境。要测批准后撤权/停止/退出、跨会话、跨记录文本阻断均使 pipe 收到零候选字节；合法正例须实际到达 jq 并在 EOF 前产出。无正例不开放 schema。 / Prove policy equivalence, live authority and at least one eligible Linux route/profile first. Observe zero candidate bytes on denial or races and a real jq result before EOF on success. No eligible case, no published schema.
- #15：真 Gateway → scoped `bash` → 签名审批 → Workspace → 原生 driver，验证多次逐条处理、非回显、游标、EOF、原生回收、背压、超时和脱敏；回归不交互的 Shell。#16：对最终提交及原生证据独立终审，审阅失败不能以自审替代。 / Prove real end-to-end writes, no echo, read cursor, EOF, cleanup, backpressure, deadline and redaction, and regress ordinary shell. Independently review the final implementation and evidence; do not substitute self-review.
- 由 builder 决定复用后的函数位置、IO 类型、测试夹具与审批文案。在已批准门禁之外，不加任意 filter、本地脚本、任意 CLI 输入、可写工作区、macOS/Windows、自动重试或第二个执行器。只在 `shell-capability-stdin` 工作树提交，不变更 main、不推送。 / Builder chooses code placement, I/O types, fixtures and approval wording under these constraints. No configurable filter, local script, arbitrary CLI, writable workspace, other OS, auto-retry or second executor. Isolated branch only; no main changes or push.
