### 0.2 你的第一条命令是 `git status --porcelain`（**每个 agent，无例外**）

不是读计划。脏 ⇒ **有人死在这里**（上一轮同一形状发生过三次：harness 中断 / 账号 session 上限 / 本机 schannel TLS 抖动，见记忆 `windows-git-schannel-tls-flake`），而**接手的那个 agent 拿到的是全新 prompt，不知道那些改动存在**。

1. **第一条命令是 `git status --porcelain`。**
2. 接着 `git diff --stat` 与 `git diff`，**读完再判断**。这批改动往往正是计划要而提交里没有的部分。
3. **不许 `git checkout --` 掉它**，除非你已经证明它编译不过且修不动；要丢也先 `cp` 到 `<scratchpad>/` 再丢。默认动作是**验证后提交**（`<scope>: <task> part N — <what>`）。
4. 报告里 `tree_clean` 只有在**你自己**跑过 `git status --porcelain` 且为空时才填 `true`。**上一个 agent 说过 clean 不算。**
