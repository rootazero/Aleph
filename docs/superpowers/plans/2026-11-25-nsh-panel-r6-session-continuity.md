# NSH Panel R6 Session Continuity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 Desktop IPC 与同源 Web 的同一 TSX Panel 中恢复所选会话，并按 Core 的规范转录顺序向前翻页。 / Resume the selected conversation and read older history in canonical projection order.

**Architecture:** Shell owns only in-memory navigation and the outcome-unknown marker; Core still owns session authority and pagination. The shared Rust Chat reducer owns committed-history assembly, detail joins and live state; TSX initiates reads and renders the existing keyed NSH List.

**Tech Stack:** Rust, serde, rusqlite/FileSessionStore, shared-ui-logic, NSH TSX, macOS Desktop IPC, same-origin Web v1.

**Spec:** `docs/superpowers/specs/2026-11-25-nsh-panel-r6-session-continuity-design.md` (`b64791c51`).

## Global Constraints / 全局约束

- Work only in `.worktrees/nsh-panel-r6` (`nsh-panel-r6`); no edits, commits, merge or push on `main`. One writer per worktree. The parent owns integration; delegate only independent deliverables, specialized review or isolated QA.
- No new RPC, dependency, registry, storage index or host-specific product path. No authorization/allowlist changes; Core visibility precedes session row/cursor checks. Keep legacy `before`, omitted limits, response shape and malformed timestamp behavior.
- At most 200 projected rows per opt-in request, at most 12 requested detail runs per page; the existing 500-row detail attribution check stays. Read committed prose independently of replay details.
- No persistent selection/drafts, automatic resend, implicit abort, durable replay, frozen history snapshot, terminal mount, Capability hot refresh or host cutover. No promise that a retained-ID rewrite or recovery insertion in an already-read range is detected.
- Rust/shared/API gates include `just test-shared` per `docs/reference/DEVELOPMENT.md`; local QA must use disposable data, isolated Gateway and loopback fixture provider. Never point QA at a live installation.

## Review Focus / 优先检查

1. A late send reply after unmount, or after a subject switch: no stale selection, no retry; only same-subject Chat sees the dismissible notice. Task 1.
2. A hidden Chat or denied first history read: neither an orphan intent nor a send to a missing key. Task 1.
3. Equal timestamps, healed sequence holes and NULL anchors: no skipped or duplicated rows, and append at the tail does not move a previous boundary. Task 2.
4. Removed or ambiguous cursor, foreign cursor, and older Core ignoring the new request: no fallback page interpreted as historical data; no authorization oracle. Tasks 2–3.
5. An older page landing during tail reconcile with a split run and a late detail reply: no live-state replacement or duplicate tool groups; reset visibly if the retained prefix cannot be joined. Task 3; rendered anchor verified in Task 4.

### Task 2: Read bounded history in projection order / 接 Core 规范顺序

**Files:** `shared/protocol/src/{session_thread.rs,lib.rs}` (only change `lib.rs` if module export is needed); `src/gateway/session_store/{types.rs,mod.rs,sqlite_backend/mod.rs}`, `src/gateway/session_manager/{ops/crud.rs,tests.rs}`, `src/gateway/handlers/chat.rs`.

**Interfaces:** Add `ChatHistoryScrollbackRequest { before: Option<String> }`, `ChatHistoryScrollbackResponse { requested_before: Option<String>, next_before: Option<String>, status: ScrollbackStatus }`, and `ScrollbackStatus::{Ready, StaleBoundary, ContinuationUnavailable}` (snake_case on the wire) in `aleph_protocol::session_thread`. Optional `scrollback` in request opts in; absent `scrollback.before` reads the tail. Opt-in response adds `scrollback` and `messages[].message_id: String`, leaving the other fields and old response unchanged. `requested_before` echoes the accepted boundary (`null` for the tail). Only `Ready` can return a continuation; `Ready` with no continuation is the normal end. `StaleBoundary` returns no rows and no continuation. `ContinuationUnavailable` returns the readable rows but no continuation because more rows exist and the next boundary cannot be encoded within budget. Core validates `limit ∈ 1..=200`, default 200 for this mode only, and rejects combining it with old `before`. Use URL-safe unpadded base64 JSON `(version, canonical_session_key, message_id)` as a non-authorizing token, with version `1` and a 4096-byte encoded-token limit; reject unsupported version/invalid encoding/foreign key after session admission. Keep all cursor handling inside Core.

**Store interface:** Replace the two scalar paging parameters with `SessionStore::history_page(&self, key: &SessionKey, read: HistoryRead) -> Result<HistoryPage, SessionStoreError>` and the corresponding `SessionManager::history_page`. In `session_store/types.rs` add `HistoryRead::{Legacy { limit: Option<usize>, before: Option<DateTime<Utc>> }, Scrollback { limit: usize, before_row: Option<String> }}` and `HistoryPage.scrollback: Option<ScrollbackRead>` where `ScrollbackRead::{Ready { next_row: Option<String> }, StaleBoundary}`. Normalize wire inputs in the handler; keep one store call, including the existing one-read guard. Update direct legacy Rust callers to construct `Legacy`, without changing other history consumers. `next_row` is the oldest returned projected row's ID (the first in ascending delivery order) only when one more row exists.

- [ ] **Write Rust regressions.** In the existing cross-backend history fixture in `src/gateway/session_store/mod.rs` add `both_backends_scroll_back_in_projection_order`: insert a legacy prefix, then event seq `30`, a legacy row anchored to `30`, and healed seq `20` at the same timestamp. With size 2, read the tail, append seq `40`, request the older page, and assert concatenated non-overlapping IDs equal the pre-append whole-window order `[legacy_prefix, seq20, seq30, legacy_after30]`; final cursor is absent. Add size-1, empty, removed-boundary and ambiguous file-reference cases. In `handlers/chat.rs` assert stale is distinguishable from empty, continuation is strictly exclusive, opt-in IDs match stable `MessageRecord.id`, `requested_before` round-trips, foreign/malformed tokens fail, invisible and missing sessions give the same response even with an otherwise invalid token, limits 0 and 201 reject (1 and 200 are accepted), and legacy `before`/wire keys still match existing tests. Cover an over-budget next boundary using a file record with a large legacy ID: rows remain readable, `status` is `continuation_unavailable`, and `next_before` is null.
- [ ] **Run red:** `cargo test --locked -p alephcore --lib scrollback` and `cargo test --locked -p aleph-protocol session_thread`. Verify failures identify the missing contract or behavior.
- [ ] **Implement storage and response.** Default (file) `history_page` uses one existing already-ordered `get_history(key, None)`, rejects absent or ambiguous boundary IDs, and slices the exclusive prefix. SQLite keeps the connection lock across count, boundary lookup and page read; the same output mapper returns the canonical message ID. Use SQL CTE ordering on `TRANSCRIPT_ANCHOR_SQL` over the complete session, apply the exclusive `(anchor, id)` predicate outside that CTE, and read `limit + 1` descending then return the retained rows ascending. Match projected IDs by source seq bound to the session and legacy IDs by their unprojected rowid; do not use the mapped string ID for SQL ordering. In SQL treat NULL anchors explicitly as preceding numeric anchors, preserving `id` ties. Keep the timestamp predicate and select path for `Legacy` unchanged. The handler maps `Option<ScrollbackRead>` and attaches opt-in fields after the existing session visibility decision, never before it. Update only comments that describe a single old paging mode as the full current contract.
- [ ] **Run green:** `cargo test --locked -p alephcore --lib scrollback`, `cargo test --locked -p alephcore --lib history_page`, `cargo test --locked -p alephcore --lib history_reports_the_whole_transcript_alongside_the_window_it_serves`, and `just test-shared`. Confirm no new query/order source guard fails. Commit `feat(chat): add bounded scrollback in projection order`.

### Task 3: Merge older pages without touching live state / 接回共享转录与列表

**Files:** `shared/ui_logic/src/transcript/chat_panel.rs`, `interfaces/panel/src/lib.rs`, `interfaces/panel/modules/Chat.tsx`, `interfaces/panel/modules/chat/TranscriptList.tsx`, `interfaces/panel/App.test.tsx`; regenerate declarations only through the existing NSH flow.

**Interfaces:** Expand `ChatState::replace_history(history: Value, details: Value) -> Value` to apply authoritative tail reads. Add `ChatState::prepend_history(history: Value, requested_before: String) -> Value` and `ChatState::apply_history_details(run_ids: Vec<String>, details: Value) -> Value`; expose thin `ChatModel` binds. Snapshot still contains existing row/live summary plus `nextBefore: string|null`, `scrollbackReset: boolean`, and `continuationUnavailable: boolean`; a rejected/mismatched reply returns `null`, not a new timeline. Distinguish request-echo validation, genuine page end, retry, continuation unavailable and stale; only a stable-ID window gets a cursor. TSX makes RPCs and gates completions; the Rust model, not TSX, joins committed rows and groups. A separate TSX page status feeds the existing `TranscriptList`, which renders `Load older messages`, keeps the existing scroll anchor and exposes retry/refresh where appropriate.

- [ ] **Write Rust and NSH regressions.** `older_page_preserves_live_run_and_deduplicates_split_run` asserts older response active fields are ignored, merge exact keys after prepend, late details do not add a second tool group, and Stop still targets the live run. `tail_refresh_keeps_confirmed_prefix_or_reports_reset` exercises overlap and a disconnected tail; after reset an in-flight older result with the old boundary cannot splice in. `legacy_tail_cannot_be_used_as_older_page` checks no scrollback when the field is absent and mismatched-echo/ID-less responses are rejected. `older_page_failure_is_retryable_without_losing_visible_rows` checks failed request, retry, end, and stable former first-visible key after prepend. Assert `continuation_unavailable` retains the page, shows that more history could not be loaded, and never becomes an end-of-history notice. Assert empty detail, failed detail and run outside attribution scope never hide body; keep existing focus-return, warning-reconcile and early-live-stream tests.
- [ ] **Run red:** `cargo test --locked -p shared-ui-logic --features panel chat_panel` and `just panel-tsx-test`; expected new merge/scrollback assertions are red.
- [ ] **Implement one committed assembly.** Keep a mounted-session ordered committed buffer in `ChatState`; use `message_id` for new row keys and retain the timestamp/occurrence fallback only on an old tail. On prepend, validate the echo, current boundary and stable IDs, then prepend once while retaining live/sealed/pending data. On tail refresh, split the previous list where the new first row occurs and keep only the proven older prefix; the authoritative tail replaces everything after it. If there is an old prefix but no usable overlap (including a missing boundary or response reset), discard old state and signal a visible refresh. Do not use details or an older page to rehydrate active run state. Use one map of committed detail groups by run, prune against committed runs/reset, and reuse the existing one-placement rule across a split run. A detail apply only updates represented runs and does not reapply activity. `limited` remains visible whenever requested detail was bounded, missing or failed.
- [ ] **Wire the view.** Request `scrollback: {}` on tail; send `scrollback: { before }` only after the first response opts in. Read details separately for at most 12 distinct run IDs per page; render body first and ignore late results on session/mount change or reset. Serialize only older requests, not live event handling; use a snapshot/cursor guard in addition to SDK generation. Treat missing/incorrect continuation responses as failures without changing committed rows. `Load older messages` uses the existing `TranscriptList` `keyExtractor` and `maintainVisibleContentPosition`; keep status/control outside the keyed row sequence. Delete the old TSX-only detail truncation and competing history application paths subsumed by the shared model. Do not replace tool readers or the native list.
- [ ] **Run green:** `just test-shared`, `just panel-tsx-test`. Verify a held Web/NSH fixture returns an older page without hiding an ongoing stream or shifting the key used by focused readers. Commit `feat(panel): prepend older history in the shared transcript`.
