# NSH Chat Transcript Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 NSH 原生 TSX 与同源 Web fallback 交付可交错流式转录、工具详情、Markdown 与 Context。 / Ship one rich streaming transcript on native NSH and its Web fallback.

**Architecture:** Gateway V1 从已授权事件投影最小展示字段，复用现有历史、trace 和工具输出事实源。两个宿主通过同一条有序流把数据交给 Panel Rust UI set，复用共享 transcript reducer；TSX 只管理可见交互。 / V1 authorizes and minimizes disclosure; shared Panel Rust reduces; TSX renders.

**Tech Stack:** Rust, serde, Tokio, aleph-protocol, shared-ui-logic, NSH 0.6.0 Rust/WASM UI set and TSX, V1 local IPC and Web WS.

**Spec:** `docs/superpowers/specs/2026-11-24-nsh-chat-transcript-design.md` (`5a290a9fb`, approved).

## Global Constraints / 全局约束

- Use `.worktrees/chat-stream-experience` (`chat-stream-experience`); do not edit, merge or push `main`. One writer in this worktree; reviewer/specialist children are read-only unless explicitly handed an isolated slice. / 隔离分支，一处一写者。
- NSH TSX and `/v1/panel/` only. No default mount, release gate, Tauri, Leptos, TUI behavior or tool execution changes. / 不借机切换默认入口。
- Core retains capability/authorization authority. No new store, registry, external service, LLM summary, raw trace RPC exposure, body DLP claim or unpersisted catch-up. / 不新增第二权威或安全保证。
- Keep existing assistant text and legacy wire behavior. New tool data never includes raw args, reasons, progress, private trace or full output. / 旧客户端不变；新增工具载荷默认拒绝。
- Bounds for this feature: 24 KiB serialized per rich tool frame/individual detail; 384 KiB serialized replay response including framing; at most 12 requested runs and 80 returned tool deltas per response. Existing Web and IPC limits remain ceilings. Before TSX adoption retain at most 64 unmatched frames, 256 KiB total, for at most 10 s; on overflow/expiry discard and reconcile, not retry. Cap displayed full-output accumulation at 256 KiB per open card with explicit stop. / 预算按序列化字节计，不靠 UI 隐藏。
- The Opus review identified real failure modes (counter IDs, separate feeds, oversized records, replay/live ambiguity). Keep the approved UI-side reducer rather than adding Gateway view state; derive rich tool identity from source run/call, use one typed stream receiver, and accept the approved run-level reconciliation instead of inventing a historical watermark. / 采纳故障证据，不暗改获批的架构。

## Review Focus / 审查重点

1. Existing generic summary fallback may expose arbitrary args; an attended run and unfamiliar tool must not bypass the allowlist (Task 1).
2. Same session may contain repeated assistant text, multiple runs, and a stale result after switching; match by proven run, not text or wall clock (Tasks 2–3).
3. Separate host queues may reorder text and tools even if the server sends them in order; assert the rendered order on both real transports (Tasks 1, 3, 6).
4. Diff and tool page boundaries must not present malformed Unicode, stale pages, or expired output as complete (Tasks 1, 2, 4).
5. Markdown and Context data can be malformed/crafted or absent; never react to fake Mermaid boundaries or present unknown counts as zero (Task 5).
