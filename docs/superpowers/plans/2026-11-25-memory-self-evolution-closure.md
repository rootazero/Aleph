# Memory Self-Evolution Closure Implementation Plan / 记忆自我进化闭环实施计划

> **Delivery / 交付：** Implemented on `memory-self-evolution`. The steps below retain the original execution checklist; see the [verification receipt](../runs/2026-11-25-memory-self-evolution-closure-verification.md) for observed results and limits. / 下文保留原实施检查单；实测结果和边界以验收回执为准。

**Goal:** Close the existing loop from scoped evidence to verified note effects without reporting work that never ran or consuming feedback that was never decided. / 修复从分区证据到可验证笔记写入的现有闭环，不虚报运行，也不吞掉未决反馈。

**Architecture:** Keep the existing Memory and Dreaming interfaces. Preserve trust provenance in-process; translate readiness once in Core and render it in existing clients. Use a bounded correction append sequence in the existing raw index DB and one resumable batch per corpus in existing Dream SQLite state. Markdown remains authoritative for notes. / 沿用现有 Memory 和 Dreaming 接口；可信来源仅在进程内传递；Core 派生就绪状态、客户端呈现。复用 raw 索引库与 Dream SQLite，每个语料库只持久保留一个可续批次；笔记以 Markdown 为准。

**Tech Stack:** Rust, Tokio, rusqlite/SQLite, shared serde wire schema, existing Leptos Panel and CLI, temporary real Markdown/SQLite fixtures. / 使用现有 Rust、Tokio、SQLite、serde 协议、Leptos 与 CLI；故障测试使用临时真实 Markdown/SQLite。

**Approved design / 已批准设计:** [2026-11-25-memory-self-evolution-closure-design.md](../specs/2026-11-25-memory-self-evolution-closure-design.md), `c46bf6562`. All writes and commits stay on `memory-self-evolution` or explicitly isolated derivative worktrees; no changes to `main`, pushes, or cross-session build directories. / 所有写入、提交仅在隔离分支或派生工作树；不改 `main`、不推送、不共用其他会话的编译目录。

### Order, ownership, and test runner / 顺序、分工与测试约束

- Tasks 1 and 2 are independent product slices. Assign them to separate writers in isolated derivative branches only if the parent is concurrently progressing the other slice; integrate and verify both before starting feature work. Tasks 3 (append order) and 4 (replacement safety) are also independent after that integration. Task 5 consumes both; Task 6 is integration, documentation and independent review. No parallel writers to one worktree, and only one native Core test build at a time. / 1、2 独立，先集成验收；随后 3、4 独立；5 依赖 3、4，6 做集成、文档与独立评审。父代理同时推进不冲突工作时才并行派发；同工作树不并写，Core 原生测试不并编。
- Parent owns the contracts, reviews every diff and integrates each staged commit. Use Luna or an available Flash model for bounded mechanical/test work, Sol or Kimi Pro for cross-module contracts and final review, Opus only for unresolved architectural decisions. If a provider hits a quota/network error, report the failed run and select another eligible model; no non-Flash DeepSeek. / 主代理负责契约、逐片验收与整合；机械任务用 Luna/Flash，跨模块契约与终审用 Sol/Kimi Pro，最难架构决策才用 Opus；限额或网络故障换合规模型。
- The commands below assume a reserved test process in the worktree. Isolate `HOME` **and** `ALEPH_HOME`, preserve absolute `CARGO_HOME`/`RUSTUP_HOME`, use worktree-owned `CARGO_TARGET_DIR`, set `CARGO_BUILD_JOBS=1`, `CARGO_INCREMENTAL=0` and `CARGO_PROFILE_TEST_DEBUG=0`; verify lld availability before passing its linker flag. Keep flags unchanged between runs to reuse compilation. / 运行以下命令前隔离双 HOME，保留工具链位置，使用工作树专属目标目录和单 job、无 debug info；确认 lld 后再启用，避免重复编译。
- Every task adds only regressions that distinguish the old failure from the new behavior. Capture the expected failure before the fix and the passing focused run after; a compile failure unrelated to the regression is not a red test. Record logs and environment in the evidence report, not in Git. / 只加能区分旧缺陷和修复后的回归；先确认预期失败再确认通过，编译故障不算红测；日志不进 Git。

## Task 3: Establish stable correction ordering and the legacy fence / 建立纠正追加序与旧水位边界

**Files:** `src/memory/store/raw_memory.rs`, `src/memory/store/markdown/{raw_memory,raw_memory_tests,store_impl}.rs`, `src/memory/store/sqlite/schema/session_ddl.rs`, `src/builtin_tools/flag_user_correction.rs` only if needed to share the existing prefix ownership.

- [ ] **Red:** In a pre-upgrade raw DB, seed corrections before/at/after an old mark. Initialize with and without a mark, then append more than two pages of same-second/backdated corrections, repeat or ignore a duplicate, remove a row, reopen and continue. Assert every eligible ID arrives exactly once in strictly increasing append order and old filtered rows stay excluded. Inject malformed or missing Markdown for a selected index row: selection errors instead of skipping over an unreadable row. / 用真实迁移、续页、重开、坏文件验证序号与数据不丢失。
- [ ] **Server-owned order:** Add a correction-only raw-index side table with explicit SQLite `INTEGER PRIMARY KEY AUTOINCREMENT`, unique raw ID, and owned corpus metadata, not a second body store. Backfill existing matching rows in deterministic `(created_at, rowid)` order once during atomically installed schema; anonymous `rowid` is only a migration tie-break, never an external cursor. Ensure the raw insert paths append the real inserted row in the same transaction, only after a successful index insert, and raw deletion maintains the new index without sequence reuse. Use one canonical correction-path prefix. / 同事务安装、回填、追加；ignore 不造幽灵序号，删除不复用序号，raw 文件不改写。
- [ ] **Fence and selection API:** Expose a bounded `RawMemoryStore` correction page carrying `(seq, RawMemory)`, with explicit unsupported default errors. On first use per corpus, capture the committed append high-water and provided legacy mark in one raw-DB transaction; repeated reads reuse that snapshot. Eligible condition is `seq > committed_seq AND (legacy_mark absent OR seq > activation_seq OR created_at > legacy_mark)`, restricted to the owning corpus and ordered by `seq ASC`. Never activate with a fabricated zero mark after a legacy read error; once activated, raw metadata is authoritative. Keep `get_raw_by_path_prefix_since` unchanged. Do not cut the production stage over yet. / 同事务冻结迁移边界，严格从序号分页，缺契约报错，本步不切换生产消费者。
- [ ] **Green and commit:** `cargo test --locked -p alephcore --lib memory::store::markdown::`; `cargo test --locked -p alephcore --lib memory::store::sqlite::schema::session_ddl`; `cargo test --locked -p alephcore --lib flag_user_correction`. Commit `feat(memory): sequence raw corrections in their owning index`. / 迁移、存储及真实入口回归通过后提交。

## Task 4: Make the common note replacement safely resumable / 收敛共用笔记替换路径并支持验证恢复

**Files:** `src/memory/notes/indexer.rs`, its existing test modules (or `src/memory/notes/indexer/distill_effect.rs` for one cohesive unit if required), existing atomic utilities and NoteStore projection APIs; no feedback stage activation here.

- [ ] **Red:** Build real NoteIndexer/Markdown/SQLite fixtures. With a deterministic error while publishing or indexing the successor, the original must stay readable and indexed; with retirement failure the successor and original both remain and the action is not Applied. Exercise a same-path replacement, an unrelated occupied destination, archive collision, external edit/disk divergence, and normal recall of the eventual successor. / 真实文件与 SQLite 夹具检验发布失败、退役失败、同路径、目标冲突和正常召回。
- [ ] **Prepare without side effects:** The common writer derives canonical paths under existing vault rules; build a serializable, crate-private prepared effect using actual planned normalized content/fingerprints, trusted prior disk state and stable identity. Freeze lineage, stable archive name and successor bytes once. Use explicit terminal non-effect for Skip and genuine no-ops, not a fake write. Share rendering/path logic with `apply_distill_action`; do not duplicate generic Markdown writers. / 只读准备阶段固定路径、前后状态和归档身份；复用原有写入逻辑，不复制 writer。
- [ ] **Publish and verify:** Use app-owned serialization across competing in-process mutators that touch those paths and recheck disk state before destructive steps. For different paths: collision-safe archival, publish successor, require matching durable Markdown and recall-required note projection, recheck original, then retire its file and stale projection. Same path: archival then atomic replacement with no unlink window, followed by verified projection. Content equality must be checked against expected state; missing unrelated paths/projection errors cannot imply success. Use a non-clobbering archive and stop on unexpected bytes. Optional embeddings stay asynchronous. / 受管写入串行并复核磁盘；不同路径先验证新文，后退役旧文；同路径始终在线；不等可选向量。
- [ ] **Recover using the same code:** Exercise resume from original-only, archived-but-unpublished, successor-published/partial projection, both-live before retirement, and retired file with stale projection. Verify then repair only matching known states; leave external edits and unrelated destinations unchanged. Reuse this path for `Supersede` outside feedback without introducing recovery state for other stages. Remove the old delete-first arm. / 原写与恢复使用同一套条件；非反馈阶段也走安全替换，不新增恢复日志。

- [ ] **Persist and execute:** In existing Dream SQLite state store one versioned, bounded corpus record `(committed_seq, pending)`; compare-and-set `pending` against expected committed sequence so two starts cannot silently replace a plan. Prepare serially from the prior action's settled state, so two actions touching one note do not share a stale preimage. Charge the existing cycle budget before each new effect and account for an unfinished reserved effect on resume without charging an already settled action again. Persist terminal receipt only after verification; on restart use saved decisions/receipts and the Task 4 verifier. Keep the pending record on retryable or uncertain I/O; verify archive, file and projection before claiming applied. Unknown persisted versions/corruption or unproven disk states report blocked, never clear pending. A row appended after activation but timestamped before the old mark must remain pending until committed. Remove only duplicate parsing bodies with equivalent contracts. / 自动和手动走同一条生产线，复用报告；清除旧批次和无条件推进逻辑，不删其他调用方接口。

### Explicit bounds / 明确边界

No generic stage journal or DLQ, automatic promotion/approval, retroactive replay of ambiguous legacy rows, blanket exactly-once or rollback guarantee, saturation heuristic, or performance claims without measurement. The on-disk note and index are separate stores; external editors are not transaction participants. / 不引入通用 stage 日志、DLQ、自动晋升与批准；不自动重放歧义历史，不承诺跨存储恰好一次、自动回滚、饱和启发式或未经测量的性能。外部编辑器不参与内部事务。
