# Phase 7 I3 Production Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 接通已批准 I3 的共享 Policy 准入、真实 PTY/Panel capability 与 Zahir 高级事件/同源审计，并用生产构造链和真实效果重新验收。

**Architecture:** 保留 canonical Tool registry、同一 `Arc<OwnershipTree>` 和现有 PTY owner；special registry 的一条 immutable record 持有 descriptor/full schema/handler/source capture。所有相关入口到同一个 domain admission/effect seam；真实 Panel 等待 render ack，独立高级事件 API 使用有界单源记录和现有实时身份/会话授权。工具 adapter 使用 `Weak<ZahirFacade>`，避免 registry→handler→facade→registry 强引用环。

**Tech Stack:** Rust、现有 tokio/async-trait/serde/schemars；shared `aleph-protocol`；Leptos/WASM Panel；既有 Gateway WS/PTY；现有 Cargo、Bun/Node 和本机浏览器验证工具。无新依赖。

**Spec:** `docs/superpowers/specs/2026-11-07-phase7-i3-production-integration-design.md`（APPROVED，D-T=A）。调查：`.superpowers/sdd/2026-11-05-phase7-advanced-capabilities/i3-production-recon.txt`。执行方法已选 SDD；本计划先交用户审阅，不再询问执行方法。

## Global Constraints

- 「现有 `OwnershipTree` 是 capability owner/generation 的唯一权威；PtyManager 仍是 PTY session/provider owner 的原有权威。」不新增 descriptor/handler/owner 的第二权威表。
- 「Production operations 为 `input / attach / resize / close`；spawn/list 由现有 config-gated manager ingress 提供。」D-T=A 已批准；三流库原名/行为保留、未挂载，不宣称 raw stdout/stderr。
- 「配置首版 **启动时应用**，调用事实实时读取。」修改配置准确报告 Restart，不能假称热生效。
- 「不含当前 candidate、包含其他占用，strict-below。」Tool 单位为实际 running operation，PTY 单位为 canonical sessions；不是全局原子 reservation。
- 「Core 只做类型化 I/O 与 owner/lifecycle」；DOM/聚焦键鼠在 Panel；不碰 `src/harness/`，不做 GPUI、平台 API、全局输入或第二终端 runtime。
- 「旧 `subscribe(Scope, Cursor) -> CapabilityChangeStream` 和 metadata cursor 语义不变」；不以 Invalidated 冒充审计，不把 Tool Cursor 当 advanced sequence。
- 「区分 **subscriber 失权** 与 **被观察 target 已撤销**」；后者仍向当前合法的 recorded audience 发送最后 revoke/deny，前者立刻停投。
- 「首版 live-only，无 durable replay/cursor 恢复保证。」审计不含正文/terminal bytes/按键/secrets/raw error strings；失败 sink 不改许可或已完成效果。
- 保留 root `config.lock` / `config.toml`、已批准设计与旧验收；不改权限、checker、阈值、ignore 或重试策略。无 merge/push/安装/清理或真实用户服务操作授权。
- 一棵树任一时刻一个 implementer/reviewer；任务交回源码所有权后才换席。实现前遵循 mandatory reuse/research：先复用仓库，再做已授权只读 GitHub code/library docs 调查；不把私有源码/需求发到搜索服务。
- `Zahir` 没有 Send/Sync supertraits；不得为 event worker 全局增加它们，亦不声称 resolver 跨线程。只有 owned receiver/其本地 audience callback 必须 Send。
- 每个执行/审查worker在源码探索前先 `graphify query` / explain / path 定向；不更新/重建graph或安装工具。Controller派席brief必须附此规则、当前expected HEAD/status、允许文件与唯一时间所有权；worker不嵌套派源码代理。Scratch/build目录使用记录过的绝对路径，不假设Bash环境变量跨工具调用持久化。

## Review Focus

1. **Configured target 尚未附着/替换 incarnation**：必须拒绝，不退化成 no-controller allow。Task 1 `configured_pending_and_replacement_never_fall_back_to_allow`。
2. **审批期间事实改变、Memory caller 取消但实际任务仍跑**：最新事实决定准入，计数跟实际任务。Task 2 `post_approval_facts_and_memory_ownership_reach_effect`。
3. **PTY 满额时释放、disabled boot、stop→reenable**：close/stop 不被 allocation limit 卡死，旧 generation 拒绝且不因注册初始化 disabled manager。Task 4 `full_pty_can_close_and_old_capture_cannot_restart_it`。
4. **UI 两 tab/用户与迟到 ack**：只能正确 surface 的真实渲染 ack 报成功；取消/卸载不误关 PTY。Task 5 `two_surfaces_ack_input_and_unmount_are_isolated`。
5. **订阅后降权 vs target 撤销、空闲 recv 的 shutdown**：失权零泄露、合法 revoke 可见，关闭不会等待自己。Tasks 6–7 `revoked_target_is_visible_but_demoted_subscriber_is_not` / `idle_forwarder_drains_and_joins_after_producer_close`。

## Contract Ledger / 冻结的接口与工程值

下列全部是 **NEW**，除注明现有类型；其 owning task 同时定义类型/错误/导出。后续任务引用，不重新命名。

- Task 1：config `CapabilityConstraintsConfig = BTreeMap<String, CapabilityConstraintRule>`；key 用末尾 `/` 分割成现有 `CapabilityId`，只在 Config::validate/compile 校验，不在 dispatch 再解析。Rule 字段：`time: Option<TimeWindowConfig {start_hour:u8,end_hour:u8}>`、`resource: Option<ResourceLimitConfig {unit: ResourceUnit,max_active:usize}>`、`required_conditions: BTreeMap<String,bool>`。`ResourceUnit::{ActiveCalls,PtySessions}`，`max_active > 0`；时间复用现有 `TimeConstraint::new`（UTC/exclusive end/overnight），不自造时钟规则。
- Task 1：`pub(crate) CapabilityCallContext::from_trusted_parts(actor:OwnerRef,principal:Option<String>,session_key:Option<String>,workspace:Option<String>,connection_id:Option<String>,call_id:String)->Self` 只由已验证caller/speaker/owner/TurnContext边界调用；字段 getter：`actor:OwnerRef`、`principal/session_key/workspace/connection_id:Option<String>`、`call_id:String`。不用 agent ID 当用户，不把 routing key/PTY UUID 转为 ACP SessionKey；无实际 ACP binding 时 actor 可 Runtime，audience 独立持真用户/session。
- Task 1：`ResourceUse::{Allocate,Existing,Release}` 由 typed owner operation 决定，不接受客户端授权字段。`PolicyFactSourceKey {provider:ProviderId,generation:u64,target:CapabilityId,incarnation:u64}` 来自真实source capture，字段private、Eq/Hash；`pub(crate) PolicyFactSourceKey::for_source(provider:&ProviderHandle,target:&CapabilityId,incarnation:u64)->Self` 只由拥有该真实handle/capture的facts reader调用，使用provider原子snapshot；不能含每次request随机值。`ConstraintFactsSource: Send + Sync` 提供 `fn source_key(&self)->PolicyFactSourceKey`、`fn supported_conditions(&self)->&'static [&'static str]`、`fn supported_units(&self)->&'static [ResourceUnit]`、`fn snapshot(&self, call:&CapabilityCallContext, unit:Option<ResourceUnit>, other_active_calls:usize)->Result<ConstraintContext,ConstraintViolation>`。通用 Tool 支持 `provider_ready`/ActiveCalls；PTY 支持 `provider_ready`/PtySessions和ActiveCalls（按所选unit读取实际session数或本attachment实际operationcounter）；UI 支持 `attachment_ready`/ActiveCalls。`PolicyEngine::resource_unit(&self,id:&CapabilityId)->Option<ResourceUnit>`只读startup配置；owner据typed操作与该unit决定ResourceUse：ActiveCalls下每个非Release调用为Allocate；PtySessions下spawn为Allocate、input/attach/resize为Existing、close为Release。未知 reader/unit 在 attachment 时拒绝，不静默忽略。
- Task 1：`PolicyEngine::with_shared_tree(tree:Arc<OwnershipTree>, rules:CapabilityConstraintsConfig)->Result<Self,PolicyDenial>`；原 `new(OwnershipTree)` 保留无新增 rules 行为。`prepare_attachment(&self, lease:&BackendLease, facts:Arc<dyn ConstraintFactsSource>)->Result<PolicyAttachment,PolicyDenial>`；`admit_runtime(&self, lease:&BackendLease, attachment:Option<&PolicyAttachment>, call:&CapabilityCallContext, resource_use:ResourceUse)->Result<RunningCapabilityCall,PolicyDenial>`；`withdraw_attachment(&self, attachment:&PolicyAttachment)`；`is_configured(&self,id:&CapabilityId)->bool`。`PolicyAttachment` 内部绑定 exact lease source key/owner generation/controller AND PolicyFactSourceKey；同一稳定Tool ingress指向两个live surface/session时，两个factsource attachment可同时存在，不能按canonical名称互相替换/重置usage。`withdraw_fact_source(&self,key:&PolicyFactSourceKey)` 在真实source关闭时撤销/移除对应restriction entries（可扫描同一restriction map，不造第二source索引）；旧running guard只保留到实际operation结束。`RunningCapabilityCall` 非 Clone RAII，随实际 operation drop。没有配置返回无计数 guard；有配置无 attachment 必拒绝。当前 attachment 变化不复活旧 controller。

- Task 7：topic **`capability.event`** 仅含 immutable audit record/envelope；UI功能 topic **`capability.ui.display`** 单独投向 exact owner connection+mount。`CapabilityEventBridge::start(receiver:EventSubscription,bus:Arc<GatewayEventBus>)->Self` 仅 capture owned Send receiver/bus，不 capture `Arc<dyn Zahir>`；`async join(self)->Result<(),CapabilityBridgeError>` 等 recv排空→Closed；新error `CapabilityBridgeError::{Join,Publish}` 对外只给固定reason。bridge遇hub Lagged时明确发 **`capability.event.status`** `{state:"lagged",incomplete:true}`（operator-only、无其他用户id/traffic count），记录日志后继续；直接scoped Zahir receiver保留typed Lagged，二者不伪造audit序号或replay。`PolicyEngine::stop_admission(&self)` 在本任务增加，原子地拒绝新admit、不阻止最后owner events/revoke。`GatewayCapabilityEventAccess` 只持现有 connections/SessionStore/EventVisibility handles；不是权限数据库。

## Task 1: Typed Startup Restrictions and Shared Policy Runtime
