# Shell 输入与撤权同步实施计划 / Shell Input Effect Authority Implementation Plan

> **For agentic workers:** Use `superpowers:executing-plans` for the serial changes below. Use a fresh independent reviewer for the final implementation (#16). Steps use `- [ ]` for tracking.

**目标 / Goal:** 在已配对、有人值守的 Panel `chat.send` 路由上，把实际撤权与 JSONL 写入或 EOF 排成同一个可验证的顺序。 / Order real revocation against actual JSONL delivery or EOF on the attended paired Panel `chat.send` route.

**架构 / Architecture:** Keep the current mutation owners; pass a typed live origin into only the real Panel run, then compose the existing guards with a typed terminal pipe operation. Approval and prefix evaluation happen outside that operation. No executable command input and no public JSONL arguments until the separate #18 gate passes. / 不迁移变更权威，给真机 Panel run 携带类型化来源，用既有 guard 组合到一次有界的最终操作；不接任意命令，不在 #18 通过前公开 JSONL 参数。

**技术栈 / Tech Stack:** Rust/Tokio, existing SQLite security store, file session store, canonical Tool registry/ownership, existing Linux lifecycle. / Rust/Tokio、现有 SQLite 安全库、文件会话后端、Tool registry/ownership 和 Linux 生命周期。

**设计 / Spec:** [#19 实效授权边界 / effect boundary](../specs/2026-11-26-shell-input-effect-authority-design.md) (`b0f0eea07`); [JSONL 实施计划 / JSONL implementation plan](2026-11-26-shell-capability-jsonl.md) (`abd2781ef`). Comparison base for product source: `854505aa6`.

## 全局约束 / Global Constraints

- Only `.worktrees/shell-capability-stdin` / `shell-capability-stdin`; no main changes, merge, push, host privilege changes or new dependency. Use a short-path disposable HOME/ALEPH_HOME for native tests, no competing Core builds. / 只写隔离分支，不改 main、宿主权限或依赖；私有临时目录跑测试，不并发编译 Core。
- Reject unsupported or uncertain facts, including unsupported session backends, unknown store identity, a stale proof, unavailable guard, expired attempt, or a noncanonical Tool entry. No fallback to role strings or copied policy, no queue, no auto-retry. / 缺少权威证据即拒绝，不用角色字符串/快照，不排队补写或自动重试。
- Only an immutable, single-use attempt may consume a live `AllowOnce`; no frame in approval, logs, events or evidence. Fixed jq parse-only profile; each frame is at most 4,096 bytes including newline and may be further limited by the verified atomic pipe bound. Total raw input is limited to 16 KiB or the stricter lossless policy bound. EOF carries no data. / 一次审批只给不可变的本次尝试；本文只接既定 jq 数据流，保留字节预算，不落盘。
- Ordinary shell, generic registry callbacks and their no-I/O semantics are unchanged. Database reservation is read-only in effect (`BEGIN IMMEDIATE` plus rollback), busy timeout zero. No async wait in the final critical section, no registry callback accepting general I/O. / 不改普通 Shell 或通用回调语义；数据库只做无等待写保留，不写权限状态。

### Task 1: Carry a live origin; order session mutation / 连接来源与会话变更

**Files / 文件:** `src/gateway/server/connection/{dispatch,rpc}.rs`, `src/bin/aleph-server/server_init.rs` (`handle_chat_send_with_engine`), `src/gateway/busy_queue/spawn.rs`; `src/gateway/session_store/{mod,file_backend/mod,file_backend/meta}.rs`; colocated regressions.

**Interfaces / 契约:** `PairedShellOrigin` is an opaque, process-local binding issued only in the authenticated Panel WebSocket dispatch, after existing checks. It captures a live connection authority (not a role snapshot). `current_paired_shell_origin() -> Option<PairedShellOrigin>` reads the scoped binding; the mounted Panel entry explicitly carries it across its worker spawn, with existing `spawn_queued_run` callers retaining no new authority. `ShellSessionGuard` is an opaque session/store-scoped witness. `prepare_shell_session(&self, key: &SessionKey) -> Result<ShellSessionGuard, ShellEffectDenied>` uses the canonical file store, otherwise fails closed. Scope these types to the necessary Rust owners; the binary boundary may forward but not construct the origin. / 不允许从参数、元数据或持久队列构造授权。

- [ ] Add `shell_origin_cannot_be_replayed_or_rebound`: verified Panel WebSocket receives a binding; a legacy/implicit owner or metadata-only request, fallback `agent.run`, replayed queue entry, guest, and a newly connected socket for the same user cannot use the old binding. A queued live attempt checks the original connection at delivery; dropped connections are denied.
- [ ] Add `shell_session_guard_orders_archive_and_same_key_recreation`: use real file store `patch_session` and `delete_session`; while the witness is held a concurrent mutation cannot commit. After release, change `exec_tier`, archive, and recreate under the same key; the old job must not match the new incarnation. Include missing/corrupt metadata and transient stale workspaces as denials. Run the named Core tests before the change to establish red (first missing seam, then old mutation behavior).
- [ ] Carry the binding on the real `chat.send` worker path without copying it to generic metadata, RunRequest reconstruction, durable queue or resume. Reuse the file backend's existing per-session metadata lock for `patch` and order the actual archive/recreation writers with it. Fail closed for any backend/mutation not covered. Read under the session guard before entering the final region; do not wait for approval or any other authority while holding it.
- [ ] Run the new Core tests plus `cargo test --locked -p alephcore --lib gateway::session_store::file_backend`, `gateway::caller_identity`, and `gateway::busy_queue`; build `aleph-server` to verify actual route wiring. Expected: new and prior regressions pass; no public JSONL schema or route grant with an unsupported origin. Commit only in an integrated candidate with useful consumers; keep unmounted proofs private.

Run the targeted Core test, expecting red on the old snapshot-only behavior.
- [ ] Factor the current paired/active predicate so the transaction sees these facts consistently. Use a store-owned no-wait connection to the same database, or a store-owned guard that safely restores the default busy timeout on every exit; never change the timeout globally or leave a busy handler changed.
