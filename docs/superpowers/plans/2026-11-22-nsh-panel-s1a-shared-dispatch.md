# NSH Panel S1-A Shared Dispatch Implementation Plan / 共享分发实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Keep the operator’s selective delegation policy: delegate independent work or expert review, not every task.

**Goal / 目标:** 让旧 `/ws` 和测试中已绑定主体的入口走同一个 Gateway 普通 RPC 执行路径，并让后续原生传输复用 `AlephClient` 的请求关联与关闭语义。S1-A 不发布新传输。

**Architecture / 架构:** 先把已有 lane、幂等和 live dispatch 从 WS 循环提出来，再用同一连接表证明已绑定入口不会落入旧 loopback 兼容身份。Client 请求状态按 socket 持有；WS 握手、读写、事件投递仍是适配层。代价是连接调度不能整个抽成一个通用循环：反向 RPC、UI ack 和事件转发仍要由各传输阶段逐项接线验收。

**Tech Stack / 技术栈:** Rust 1.99.1, Tokio, Axum, Tungstenite, existing `aleph-client` / `alephcore` / `aleph-protocol`; no new production dependency.

**Spec / 规格:** [Accepted design §5, §7–8](../specs/2026-11-22-nsh-panel-modular-refactor-design.md) · [S1 roadmap](2026-11-22-nsh-panel-migration-roadmap.md) · [S0 plan and baseline](2026-11-22-nsh-panel-contract-foundation.md). Implementation baseline `750f355ec94366715855b2d96b896949cedc469c` plus this plan commit.

## Global Constraints / 全局约束

- 仅在 `.worktrees/nsh-panel-refactor` 的 `nsh-panel-refactor` 提交；不得改 `main`、在用服务/凭据/端口或发布配置。测试使用内存或临时目录和 `127.0.0.1:0`；注册测试只存在于 fixture。
- 旧 `/ws` 仍是 text JSON，首请求仍须 `connect`；保留原响应、连接重认证、权限、限流、节点反向 RPC、订阅及事件可见性。不得把测试预绑定入口注册进 Router，也不挂载 S0 framing。
- 一个 `HandlerRegistry`、`MiddlewareChain`、连接表及 process-shared lane/幂等状态；不从请求参数采信用户、设备、权限或项目身份。保留 Core 调用者 task-locals、方法权限及 Panel 项目解析；没有 `None ⇒ internal` 的网络入口。
- 现有 Gateway `IdempotencyGuard` 是 TTL 内存去重，不是 durable retry；保留 `-32030`，不引入持久 cache、自动重发或 exactly-once 承诺。
- 无 UDS/Named Pipe、`/v1/ws`、HTTPS Cookie、真实认证初始化、协商上线、TSX、snapshot/replay 或 Tauri 变更。S1-B/C 各自证明 I/O 与实际 OS/Web 主体接入、事件/关闭、限额和期限；测试接缝不计真机证据。
- 每次 Cargo 调用先执行 `python qa/browser_live/check_memory.py`（至少 `4294967296` bytes，Core 链接建议 `10 GiB`）；用 `--locked`，串行运行。下文 `gate` 是 `gate() { python qa/browser_live/check_memory.py && "$@"; }`，在 worktree 根定义。先记基线退出码和工具链；门禁拒绝、编译失败不算测试 RED。失败保留，不以跳过换通过。

## Review Focus / 审阅重点

1. 已撤销、换主体或消失的已绑定连接在等待 lane/cache 后不得执行 handler 或拿到结果；含真实 loopback 地址（Task 2）。
2. 相同幂等 key、不同 RPC ID：只执行一次，返回各自 ID；同 key 跨主体不共用，项目选择不能回放旧成功（Task 1）。
3. 授权后的普通成员在两条分发路径只能看到自己的真实会话；远程来源限流与调用者限流都不能被共用代码漏掉（Tasks 1–2）。
4. 关闭测试连接只释放该连接的订阅和 reverse-RPC waiter，不关闭另一连接或 Core 会话（Task 2）。
5. 旧 socket 晚到的 reply、send error 或 EOF 不能完成、清空或标死新 socket；调用取消也不留下待处理记录（Task 3）。

### Task 3: Keep Client pending requests with their socket / 请求关联归 socket 所有

**Files:** Create `shared/client/src/connection/requests.rs`; modify `shared/client/src/connection.rs` and its existing tests. Independent of Tasks 1–2; integrate on the same branch after verifying disjoint edits. Do not implement a transport framework or change protocol types.

**Interfaces:** In `requests.rs`, connection-module-private `RequestState::new() -> Self`, `reserve(self: &Arc<Self>, id: String, during_handshake: bool) -> CliResult<PendingCall>`, `resolve(&self, id: &str, result: Result<Value, JsonRpcError>)`, `mark_ready(&self) -> bool`, `is_ready(&self) -> bool`, `close(&self)`; `PendingCall::wait(self, timeout: Duration) -> CliResult<Result<Value, JsonRpcError>>` and `Drop`. `connection.rs` binds one `Arc<RequestState>` and immutable writer handle to each socket epoch; capture both together for requests, reader callbacks and explicit close. Preserve public `AlephClient::{connect,connect_with_credential,call,call_with_timeout,reconnect,close,is_connected,stream_continuity}` signatures.

- [ ] **Pin WS baseline.** `gate cargo test --locked -p aleph-client --lib`; capture count and actual wire baseline. Existing tests cover `connect` before handing out client, event queue pressure, a dead socket failing a pending request, stable event receiver across reconnect and a superseded loop not clearing live state.
- [ ] **Add seam and WS tests.** `pending_requests_resolve_out_of_order`: reserve `"1"` and `"2"`; resolve `"2"` then `"1"`, each gets its own result. `socket_close_is_terminal_for_its_pending_calls`: use two states both with `"1"`; resolve/close old, assert its other pending call returns Disconnected and old cannot become ready; new stays ready and only resolves from new reply. `cancel_or_timeout_removes_only_its_reservation`: drop one call and time out another; pending count is zero after both, others continue, late response ignored. `reconnect_does_not_resend_or_route_old_writes_to_new_socket` uses the real WS fixture and barriers: leave an old RPC unanswered, close/reconnect with successful `connect`, finish a new call, assert new peer saw only its handshake and new RPC and old waiter returned Disconnected; arrange an old event attempt after epoch replacement and use a new event as a receipt barrier. Previously enqueued events retain the existing continuity semantics. Preserve retry signal: disconnect after request send is an unknown business outcome, not proof the server rolled back.
- [ ] **Verify RED.** `gate cargo test --locked -p aleph-client --lib connection::requests::tests::` with the new internal interfaces stubbed; observe failure of epoch/cancellation assertions. Keep existing WS cases passing until changing the implementation.
- [ ] **Move correlation without coupling to WS.** RequestState owns `Handshaking → Ready → Closed` (Handshaking can also close) and pending senders in one short synchronous lock, never across `.await`. Only internal handshake can reserve while Handshaking; closed never reopens. Drop removes its reservation; close drops its own senders promptly. Keep existing monotonic string request ID allocation, serialization before reserving, classification, timeout/error mapping and no wire logging. Each request binds to one socket before reserving; its send (including server-request replies) cannot use the replacement writer. EOF, send failure and explicit close close that epoch only. Reconnect atomically replaces the writer/state pair under existing reconnect serialization, closes superseded pending entries, and exposes Ready only after successful `connect`; preserve generation tracking and stable receivers. Fence both stream and topic delivery plus continuity bookkeeping at the enqueue/record boundary, not only at loop entry; never await queue capacity while holding the current-epoch guard. Initial handshake/reconnect failure closes the candidate state and stops its reader; no new request limits or auto-resends in this phase.
- [ ] **Verify and commit.** `gate cargo test --locked -p aleph-client` passes; `gate cargo check --locked -p aleph-cli -p aleph-tui` verifies current consumers compile. Format touched files and `git diff --check`, then commit `refactor(client): bind pending RPCs to socket epochs`.
