# Agent Shell Capability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Use Pi agents only, and delegate only independent deliverables, specialist work or independent review as authorized by the user.

**Goal / 目标:** Make Agent `bash` yield and resume bounded output truthfully, reap its owned processes, and enable writable stdin/EOF only where the existing security floor and OS containment are proven. / 让 Agent `bash` 可限时交还控制权、续读有界输出、如实确认回收，并只在原有安全地板和 OS containment 均已证明时开放 stdin/EOF。

**Architecture / 架构:** Reuse the existing `bash` Tool Capability, `CodeExecTool`, `WorkspaceSandbox` and OS drivers. One driver owns its child; one registry owns the Agent process record. Output continuation projects the existing tail rather than owning a second stream. / 复用现有工具、命令准备与沙箱链路；driver 拥有进程，registry 拥有 Agent 记录，增量读取只投影既有尾窗。

**Tech Stack / 技术栈:** Rust 1.99, Tokio, existing `tokio-util`, Serde/Schemars, current bwrap/Seatbelt/Windows backends. No new dependencies. / 现有 Rust、Tokio、协议与沙箱，零新增依赖。

**Spec / 设计:** [`docs/superpowers/specs/2026-11-26-shell-capability-rework-design.md`](../specs/2026-11-26-shell-capability-rework-design.md), reviewed design commit `565336508`.

## Global constraints / 全局约束

- All writes and commits in `.worktrees/shell-capability-rework` on `shell-capability-rework`; do not change `main`, merge or push. Initialize the pinned `plugins`/`skills` submodules, if required, only in this worktree. / 只改隔离检出；需要时只在那里初始化固定子模块。
- `bash` remains the public Capability and permission key. Preserve existing aliases, default foreground/EOF, legacy `poll`/`wait`/`kill`/`list` argument shapes, browser companion `ManagedSandbox`, and human `pty.*`. No host fallback, shell-specific second permission store, persistent raw output, or persisted handles. / 保持工具权限键、默认行为与无关消费者，不增加旁路或持久化原始流。
- Foreground default 60 s and ceiling 170 s; explicit background default 3600 s and ceiling 14400 s; `wait` default 60 s and ceiling 170 s; process quotas 8/session and 32/server, retained entries limit 64. Detached jobs cannot enter an owned worktree. `yield_ms` accepts integers 1–10000 and changes only the first observation window. / 原有预算、配额与 worktree 限制原样保留，新增 `yield_ms` 不改变执行截止。
- Native fixtures use disposable filesystem state and `ALEPH_HOME`; isolate tests that mutate process-global environment, registries or journal. Build only one Core test binary at a time; use existing lld/low-debug profiles when RAM is limited. Compare audit results to the exact base in equivalent worktree setup. / 原生夹具隔离；不并行重编 Core；同配置对照门禁基线。
- English code comments, bilingual project docs. A test double can prove wiring or ordering, not native containment. Unverified platforms must not advertise writable stdin. / 测试替身不证明 OS 行为，未验证的平台不宣称支持。

## Review focus / 审阅重点

1. A cancellation racing approval or spawn cannot create a late orphan or release capacity early (T2). / 审批及启动竞态。
2. A child exits while an inherited pipe remains open, and captured bytes are still returned (T1). / 继承管道不阻塞收尾。
3. Matching a protected pattern across reads or ring overwrite never releases an unsafe suffix (T4). / 分片和覆盖后不能泄漏。
4. Shutdown cannot admit another shell after sealing; browser services remain separately owned (T2). / 关机与新启动仲裁。
5. A policy string split across multiple writes is not made safe by separately approving each chunk; policy/authority changes during approval fail closed (T5). / 分片审批不等于满足命令策略，撤权后零副作用。

### T5: Prove stdin eligibility, then connect it / 先证准入，再连 stdin

**Files:** Inspect and use `src/sandbox/{factory,security_kernel_hook}.rs`, `src/sandbox/command_policy/mod.rs`, `src/tools/scoped/dispatch.rs`, `src/sandbox/exec_approval/{action,gate}.rs`, `src/sandbox/platforms/linux/bwrap.rs`, `src/sandbox/{shell_control,workspace/mod}.rs`, `src/builtin_tools/bash_exec.rs`. Put retained proof in T6; do not land an unreachable input subsystem. / 与既有 dispatch、命令策略、审批及 driver 取证，不留不可达功能代码。

**Gate / 实现门:** The production factory retains a hard-block command policy even when configurable rules are disabled. `CommandPolicyHook` and `SecurityKernelHook` examine the launch command, including prebuilt stdin, not the future input of an arbitrary interpreter. One approval per write does not make arbitrary pipe chunks policy-equivalent. Before any public schema or writer, prove a supported input path can enforce the existing hard restrictions and re-read authoritative dispatch permissions after a pending approval, and prove containment on the exact native Linux config. If any proof fails, finish stage one, leave generic follow-up input unexposed, and record the exact failed criterion. An application-specific, fixed data protocol would narrow the approved scope and requires a separate product decision; do not silently choose one or relax the command floor. / 生产配置总保留硬性规则；单块审批不能替代策略。只有策略等价、可复验撤权、原生 containment 都有证据时才开放；否则保留明确的未交付事实，不加摆设字段、死 writer 或降级绕路。

**Conditional interfaces / 过门后的接口:** `keep_stdin_open: Option<bool>` on continuable launch; `input: Option<String>` exactly for `write_stdin`; `close_stdin` has no payload. `ShellControl` owns a single writer slot: `write_stdin(&self, input: &str) -> Result<StdinWriteOutcome, ShellInputError>` and `close_stdin(&self) -> Result<StdinCloseOutcome, ShellInputError>` async, reachable only after a once-only authorization bound to the exact bytes/process. Input ceiling 4096 UTF-8 bytes, further reject anything whose scrubbed review cannot fit the existing 200-character summary; no auto newline, no retries. Unsupported startup mode or backend is rejected before asking for approval or launching. / API 仅在过门后公开；4 KiB 硬上限不绕过 200 字符现有审批展示预算。
