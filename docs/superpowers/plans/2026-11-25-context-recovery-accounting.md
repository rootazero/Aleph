# Context Recovery and Fold Accounting Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bound durable fold recovery without weakening logical erase, and make the manual-fold gain check measure the exact persisted summary text. / 有界恢复、不放宽逻辑擦除、按实际摘要判定收益。

**Architecture:** Replace the whole-session restore read with a synchronous, session-scoped visitor inside one SQLite read transaction. Core derives folds from existing checkpoint types, verifies the entire requested inclusive range, then renders one bounded result. Manual accounting changes the summary producer, not the ledger schema or provider metrics. / 复用现有事件日志、折叠派生逻辑与工具注册；不增加存储或 Capability。

**Tech Stack:** Rust 1.99.1, async-trait, Tokio, rusqlite/FTS5, serde/serde_json, existing Core Tool Capability.

**Spec:** [2026-11-25-context-recovery-accounting-design.md](../specs/2026-11-25-context-recovery-accounting-design.md), approved design baseline `a378e6aba`.

**Execution record / 执行记录:** See the [verification receipt](../runs/2026-11-25-context-recovery-accounting-verification.md) for completed checks and deviations from the original checklist below. ## Review Focus / 重点反例

1. Later hard-erased row outside the first page: request rejected before any output; a different session at the same seq is not a witness (Task 2).
2. Still-witnessed later row with undecodable payload: earlier page can succeed, but a page that requires that row fails without partial text (Task 2).
3. Escaped JSON and multibyte UTF-8 cross the page boundary: offsets progress and replay yields the exact body, including whitespace (Tasks 2–3).
4. `u64::MAX`, invalid byte cursor, absent FTS or unsupported store: no silent range widening, panic, or misleading no-fold reply (Task 2).
5. Bare summary smaller but persisted framed text not smaller: no writes and no retirement; legacy accounting unchanged (Task 1).

### Task 2: Replace the whole-session restore reader / 替换整段恢复读取

**Files:** `src/session/store.rs`, `src/builtin_tools/decompress.rs` (both unit test modules). Use the actual `SqliteEventStore`, not an implementation mirroring the old algorithm. Before replacing the old reader, capture baseline per Task 3 Step 1.

**Interfaces:** Internal Rust only except additive tool properties. Use `FoldRestoreSpan { start: EventSeq, end: EventSeq }` with checked inclusive bounds. `SessionEventStore::with_fold_recovery(&self, session_id: &SessionId, read: &mut (dyn FnMut(&dyn FoldRecoverySnapshot) -> Result<(), SessionError> + Send)) -> Result<(), SessionError>` is async and object safe; the default returns a deliberate unsupported storage error. Inside the transaction the visitor calls `FoldRecoverySnapshot::fold_events(&self) -> Result<Vec<SessionEvent>, SessionError>` and `FoldRecoverySnapshot::visit_verified_span(&self, span: FoldRestoreSpan, visit: &mut dyn FnMut(SessionEventRecord) -> std::ops::ControlFlow<()>) -> Result<FoldSpanStatus, SessionError>`. Use `FoldSpanStatus::{Readable, Empty, Denied}`; invalid caller coordinates are rejected before visitation. The snapshot never exposes an unchecked payload reader. Keep these internal to Core (doc-hidden if a public trait requires public signature types). Do not leak rusqlite types into the trait. Tool validation and rendering errors are reported by `decompress_fold_span`, not mislabelled as DB errors; capture the tool result once in the outer caller.

- [ ] Add file-backed store cases using `SqliteEventStore` and the existing append/retire API. Assert `Err` without transcript for a late erased row with a same-seq witness in another session, including a request where the first renderable row alone fills a page; verify another read after `Retire::From` cannot return a previously readable page. Start a separate case with a valid witness, then corrupt only the later payload (past the next page's one-row lookahead). Assert an earlier page succeeds and the page requiring that row returns an error with no partial page. Add an unsupported-store/FTS-absent test and assert no misleading empty recovery for an unavailable storage path. Retain existing tests for legacy/nested folds, `foreign-owner` note, cross-session fold ID, no-fold and invalid ranges; add any of these not currently asserted. Record RED on the lazy-decode case while the old path is present.
- [ ] Implement the SQLite snapshot and metadata read. Hold the existing connection guard and open one read transaction; keep all visitor calls synchronous inside it. Select canonical lowercase `fold_recorded` and `compaction_performed` using `event_type_tag`/existing index; order by seq, including retired metadata. Decode with `decode_row` and pass just these events into `list_folds`. Do not add a second fold resolver. Preserve no-fold result for valid snapshots; cap unknown-ID listings and distinguish out-of-range/unknown/empty/denied. Drop the transaction before calling `notify_current_lifecycle(RestoreRequested)`.
- [ ] Implement `visit_verified_span`. Use PK-bound `seq >= start AND seq <= end` with checked conversion and no `end + 1` overflow. Under the same snapshot, stream ordered retired seqs and ordered FTS seqs filtered by the same `(session_id, start..=end)`; merge by numeric sequence, scanning FTS once (SQLite may sort identities). For each unproven retired seq, fetch that payload by PK and apply the existing `event_content_text` nonempty predicate; error on corrupt needed rows, skip only `decode_row`'s explicitly ignorable variants, deny before invoking the visitor for any retired content without a witness. Distinguish an unavailable FTS query from no matches. After verification, stream the selected rows by PK and stop decoding as soon as `visit` breaks; never collect or render the rest first. Delete the replaced method and row type once `rg 'load_events_with_retirement|RetiredEventRow' src` finds no callers.
- [ ] Add `decompress_oversized_unicode_page_reassembles` using Chinese, emoji, quotes, backslashes and line breaks. Call again with each returned `next_from_seq`/`next_from_byte` (reopen the SQLite file midstream), assert strictly increasing `(seq, byte)`, exact reassembled body after removing only display labels, `estimate_tokens_smart(&serde_json::to_value(&page).unwrap().to_string()) <= read_backstop_tokens()`, and `truncated == next_from_seq.is_some()`. Assert an offset in the middle of the emoji, at/beyond end, no explicit fold/start, budget too small for any rune, reversed bounds and overflow are explicit errors. Existing multi-event pagination must still reassemble; give its fixture room for JSON overhead, not an exemption. Record RED before adding cursor behavior.
- [ ] Add `SessionDecompressArgs.from_byte: Option<usize>` and `SessionDecompressResult.next_from_byte: Option<usize>` with default/omit when absent. Normal page boundaries still use `next_from_seq` alone. Inside `decompress_fold_span`, admit each complete line if it fits; if an empty page cannot fit a complete event, choose a nonempty UTF-8 prefix within budget and return the same seq plus its next byte. Validate input against the exact first addressed body, not the next renderable event. Account for role/seq label, notes, escaping and continuation fields; size the same compact `serde_json::Value` used by the model channel (`src/tool_output/ingress.rs::flatten`) with the existing smart estimator and cap at `read_backstop_tokens()`. Try no unbounded render of an oversized first body merely to test it: bound candidate slices before encoding and recheck the complete returned response. Do not silently return an empty, truncated page that cannot advance. Once the page is full, use at most one eligible lookahead event to determine the cursor; no eager suffix decode after that. Preserve existing rendered content set and note conventions.
- [ ] Run `cargo test -p alephcore --lib builtin_tools::decompress::`, `cargo test -p alephcore --lib session::store::` and `cargo test -p alephcore --lib context::compact::folds::`. Expect pass, no old read-path call sites. Defer the recovery commit to Task 3 so dispatch evidence and changed references ship with the behavior.
