### B4-01 [P1] `summarize_slice` collapses cancellation into deterministic truncation, committing degraded state on cancelled turn
- Location: `src/context/compact/compactor.rs:1176-1181` (`ContextCompactor::summarize_slice`)
- Failure mode: When `summarize_bounded` aborts on `cancel.cancelled()` and yields `SummarizerOutcome::Cancelled`, `summarize_slice` collapses `Cancelled` into `Failed` and returns `Ok(deterministic_truncation(messages))` instead of propagating an error. Consequently, `perform_session_split` believes summarization succeeded, proceeds to emit `RunFinished` on the parent, seeds the child session with a degraded truncation, commits two SQLite transactions, registers the child epoch with the router, and returns `SplitTo(child)`. The harness then switches sessions and proceeds on the child, permanently mutating the database and corrupting the session state despite the user cancelling the turn.
- Evidence:
  ```rust
  Ok(match self.summarize_bounded("slice", &prompt).await {
      SummarizerOutcome::Summary(s) => s,
      SummarizerOutcome::Failed | SummarizerOutcome::Cancelled => {
          deterministic_truncation(messages)
      }
  })
  ```
- Suggested fix: Do not collapse `Cancelled` into `Failed`. Return `Err(anyhow::anyhow!("compaction cancelled"))` on `SummarizerOutcome::Cancelled`. This allows `summarize_pretail` in `perform_session_split` to fail before emitting any batch, and allows `manual::compact_session` to abort before committing `Retire::Through`.
- Confidence: 0.95

### B4-02 [P1] `snap_out_of_open_run` fails to protect open runs without closers, causing `FinishWithoutStart` contradiction
- Location: `src/context/compact/manual.rs:663` (`select_cut`) calling `src/context/compact/event_snap.rs:52-85` (`snap_out_of_open_run`)
- Failure mode: When `/compact` is called while a run is currently open (e.g. model invoking the `session_compact` tool or via the Panel slash fast path), `openers` contains the open run's `RunStarted` at an index `< cut`. However, `snap_out_of_open_run` only sets `crossing` when a matching `RunFinished` is encountered in `events`. Because the run is open, it has no `RunFinished` yet, so `crossing` remains `None` and `cut` is not pulled back. Consequently, `manual.rs` soft-retires `events[..cut]`, which includes the open run's `RunStarted`. When the run subsequently completes and emits `RunFinished`, `reduce_run` sees a live `RunFinished` with no preceding live `RunStarted`, causing a fatal `LogContradiction::FinishWithoutStart` on all subsequent turn reductions and crash recoveries.
- Evidence:
  ```rust
  SessionEvent::RunStarted { run_id, .. } => {
      openers.entry(run_id.as_str()).or_default().push(idx);
  }
  SessionEvent::RunFinished { run_id, .. } => { ... }
  ```
  (Any opener remaining in `openers` without a matching `RunFinished` is ignored, leaving `cut` unmodified).
- Suggested fix: In `snap_out_of_open_run`, after scanning `events`, inspect all remaining unmatched openers in `openers`. If any open run has `opener < cut`, update `crossing = Some(crossing.map_or(opener, |c| c.min(opener)))` to ensure that `cut` is pulled back before the open run's `RunStarted`.
- Confidence: 0.95

### B4-03 [P2] Missing cancellation check and propagation in `LoopDirective::SplitSession`
- Location: `src/context/compact/directive.rs:331-369` (`apply_budget_directive`)
- Failure mode: Unlike `CompactAndContinue` (which passes `cancel` to `compact_for_session`) and `CompactToFit` (which passes `cancel` to `compact_to_fit_and_note`), `LoopDirective::SplitSession` calls `perform_session_split` without passing `cancel`. Furthermore, if `perform_session_split` returns `Ok(outcome)`, `apply_budget_directive` unconditionally returns `DirectiveOutcome::SplitTo(child)` without checking `if cancel.is_cancelled()`. If cancellation fires before or during the split, the function ignores it and returns `SplitTo`, causing the think loop to proceed to the child session instead of stopping.
- Evidence:
  ```rust
  let split_child = match (compactor, registrar) {
      (Some(compactor), Some(registrar)) => {
          match crate::context::compact::session_split::perform_session_split(
              session,
              registrar.as_ref(),
              compactor,
              session_id,
              events,
              tail_start,
          )
  ```
- Suggested fix: Check `if cancel.is_cancelled() { return DirectiveOutcome::Cancelled; }` before invoking `perform_session_split`, thread `cancel` into `perform_session_split`, and check `if cancel.is_cancelled() { return DirectiveOutcome::Cancelled; }` before returning `DirectiveOutcome::SplitTo(child)`.
- Confidence: 0.90

### B4-04 [P2] Manual compact `tokens_after` calculation ignores framing overhead, allowing prompt bloat
- Location: `src/context/compact/manual.rs:471-507` (`compact_session_with_fabric`)
- Failure mode: `tokens_after` is measured only against `&body` (`let tokens_after = estimate_tokens_smart(&body)`), and `tokens_after` is recorded as `summary_tokens` in `FoldRecorded` and checked against `tokens_before`. However, the actual `SystemMessage` inserted into the session log contains `{SUMMARY_MARKER}\n{SUMMARY_FRAMING}\n\n{body}`, which adds ~250 characters (~60-70 tokens). If `tokens_before - tokens_after` is small (< 60 tokens), the compaction reports saving tokens and passes the `tokens_after < tokens_before` check, but the resulting prompt is actually larger than before compaction.
- Evidence:
  ```rust
  let tokens_after = estimate_tokens_smart(&body);
  ...
  if tokens_after >= tokens_before {
  ...
  content: format!("{SUMMARY_MARKER}\n{SUMMARY_FRAMING}\n\n{body}"),
  ```
- Suggested fix: Measure `tokens_after` against the full formatted summary content (including `SUMMARY_MARKER` and `SUMMARY_FRAMING`) before comparing with `tokens_before` and recording `summary_tokens` in `FoldRecorded`.
- Confidence: 0.85

### B4-05 [P3] Redundant boundary calculation and dead code guard in `compact_inner`
- Location: `src/context/compact/compactor.rs:459-554` (`compact_inner`) and `src/context/compact/compactor.rs:419-444` (`compression_window`)
- Failure mode: `compact_inner` calculates `effective_tail`, bounds checks `messages.len() <= effective_tail`, and computes `cut_end = snap_boundary_forward(...)` at lines 459-479. Then at line 533 it calls `self.compression_window(messages, fresh_tail, transient_tail)`, which re-computes `effective_tail`, re-checks `messages.len() <= effective_tail`, and re-computes `cut_end = snap_boundary_forward(...)`. Finally, lines 546-554 check `if window_start >= window_end`, which is provably dead code because `compression_window` returns `(start < end).then_some(start..end)`.
- Evidence:
  ```rust
  let cut_end = snap_boundary_forward(messages.as_slice(), messages.len() - effective_tail);
  ...
  let Some(window) = self.compression_window(messages, fresh_tail, transient_tail) else { ... };
  ...
  if window_start >= window_end { // Dead code: compression_window guarantees window_start < window_end
  ```
- Suggested fix: Remove the dead code check `if window_start >= window_end`. Either have `compact_inner` use `compression_window` from the start, or pass `cut_end` into `compression_window` to avoid duplicate boundary snaps.
- Confidence: 0.95

### B4-06 [P3] Gratuitous string allocations and join in `reapply_cached` hot path
- Location: `src/context/compact/compactor.rs:964-969` (`ContextCompactor::reapply_cached`)
- Failure mode: On every compaction turn in steady state (where cache reuse hits turn after turn), `reapply_cached` creates a `transcript_text()` String for every message in `c.start..cut_end`, collects them into a `Vec<String>`, and joins them with `\n` into `window_text` solely to compute `tokens_before = estimate_tokens(&window_text)`. The joined string is immediately dropped and never used as a prompt.
- Evidence:
  ```rust
  let window_text: String = messages[c.start..cut_end]
      .iter()
      .map(UnifiedMessage::transcript_text)
      .collect::<Vec<_>>()
      .join("\n");
  let tokens_before = estimate_tokens(&window_text);
  ```
- Suggested fix: Accumulate estimated tokens per message directly via `messages[c.start..cut_end].iter().map(|m| estimate_tokens(&m.transcript_text())).sum()` without collecting into an intermediate vector or joining into a large allocation.
- Confidence: 0.90

### B4-07 [P3] Gratuitous `UnifiedMessage` allocations during reverse token accumulation in `select_cut`
- Location: `src/context/compact/manual.rs:647-649` (`select_cut`)
- Failure mode: `select_cut` iterates backwards through `events`, calling `event_to_message(&events[cut - 1].event)` on each event. `event_to_message` allocates and clones `content.text` into a new `UnifiedMessage` solely to call `estimate_tokens_smart(&m.text_content())`. For long histories with large messages, this allocates and drops hundreds of strings per `/compact` invocation.
- Evidence:
  ```rust
  let cost = event_to_message(&events[cut - 1].event)
      .map_or(0, |m| estimate_tokens_smart(&m.text_content()));
  ```
- Suggested fix: Extract a zero-allocation token cost estimator for `SessionEvent` directly (or inspect `content.text` without constructing a full `UnifiedMessage`).
- Confidence: 0.85
