### B2-01 [P1] Exact-equality check on `output_tokens` and `output_bytes` rejects valid external context plugins
- Location: `src/context/fabric/runtime.rs:1174-1180` (`ContextFabric::invoke_request`)
- Failure mode: The wire contract specification in `src/context/fabric.rs` (lines 45-48, 1262-1279) permits conservative over-claims of token and byte counts (`claimed >= measured`, and `claimed < measured` is refused as `SizeUnderstated`). However, `runtime.rs:1174` enforces strict equality (`!=`). Because `measured_tokens` is derived from an internal heuristic (`estimate_tokens_smart` with hardcoded CJK and code ratios), any external plugin (WASM, MCP, Node/HTTP) that calculates tokens using a standard model tokenizer (e.g. tiktoken) or provides a safe upper bound will be rejected with `ContextFabricError::MalformedOutput("result measurements do not match serialized output")`.
- Evidence:
```rust
if response.output_bytes != serialized.len() as u64
    || response.output_tokens != measured_tokens
{
    return Err(ContextFabricError::MalformedOutput(
        "result measurements do not match serialized output".into(),
    ));
}
```
- Suggested fix: Align `runtime.rs` with `fabric.rs` contract by checking `response.output_bytes < serialized.len() as u64 || response.output_tokens < measured_tokens`, or rely solely on `response.validate_for(...)` which already enforces honest size claims.
- Confidence: 1.0

### B2-02 [P1] `canonicalize_path_string` drops root slash on absolute paths and ignores Windows backslashes
- Location: `src/context/file_ops.rs:88-105` (`canonicalize_path_string`)
- Failure mode: `canonicalize_path_string` iterates `trimmed.split('/')` and drops empty strings `""`. For absolute paths like `"/etc/hosts"`, the leading empty component before `/` is skipped, canonicalizing it to `"etc/hosts"`. If a conversation accesses both workspace `"etc/hosts"` and system `"/etc/hosts"`, both resolve to identical canonical keys, causing `file_op_supersede` to falsely stub out the read of `"/etc/hosts"` upon a write to `"etc/hosts"`. Furthermore, root path `"/"` canonicalizes to `""`, and Windows paths containing `\` are not normalized because `split('/')` ignores backslashes.
- Evidence:
```rust
for component in trimmed.split('/') {
    match component {
        "" | "." => {}
```
- Suggested fix: Track whether the path is absolute (`let is_absolute = trimmed.starts_with('/') || trimmed.starts_with('\\');`), normalize `\` to `/`, and preserve the leading `/` when rebuilding components (returning `"/"` for root path).
- Confidence: 0.95

### B2-06 [P2] N+1 RwLock read acquisitions in `phase_entries`
- Location: `src/context/fabric/runtime.rs:988-1009` (`phase_entries`, `eligible_keys`, `descriptor_for`)
- Failure mode: `phase_entries` calls `self.eligible_keys(...)`, acquiring and releasing `self.registry.read().await`. Then for each key in `keys`, it calls `self.descriptor_for(&key, ...)`, which again acquires and releases `self.registry.read().await`. If there are N registered context capabilities, `phase_entries` performs N + 1 separate read lock acquisitions on the Tokio RwLock, causing lock thrashing under concurrent load and introducing a TOCTOU race where descriptors can be modified or revoked between the two checks.
- Evidence:

let mut entries = Vec::new();
for key in keys {
    if let Some((descriptor, mode)) = self.descriptor_for(&key, session).await? {
```
- Suggested fix: Acquire `self.registry.read().await` once in `phase_entries` and collect matching descriptors and modes in a single atomic pass.
- Confidence: 0.95

```
- Suggested fix: Remove lines 1143-1147 since `validate_grant` already validates and rejects credentials.
