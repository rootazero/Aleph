### B6-001 [P1] `ToolPermissionsConfig::explain` swallows glob compilation errors and fails open to `Allow`
- Location: `src/config/types/policies/tool_permissions.rs:142` (`ToolPermissionsConfig::explain`)
- Failure mode: An operator configures an override to deny or gate tools matching a pattern (e.g. `"*_secret" = "deny"`). If the pattern fails regex compilation in `approval::try_matches_glob` (e.g. pattern exceeds the bounded regex complexity budget or contains malformed syntax), `matches_glob` swallows the error and returns `false`. `explain` silently skips the override, causing `resolve` to fall back to `default` (typically `Allow`). The dangerous tool executes without permission check or denial.
- Evidence:
```rust
for (pattern, action) in &self.overrides {
    if !is_glob_pattern(pattern) || !crate::approval::matches_glob(tool_name, pattern) {
        continue;
    }
```
- Suggested fix: Call `crate::approval::try_matches_glob(tool_name, pattern)`. On `Err(_)`, fail closed: if the rule's action is `Deny` or `Ask`, treat the rule as matching so uncompilable patterns cannot silently grant access to denied tools.
- Confidence: 0.95

### B6-002 [P1] `GenerationConfig` cross-modality provider shadowing and invalid reference rejection
- Location: `src/config/types/generation/config.rs:224-226`, `306-310` (`GenerationConfig::merged_providers`, `GenerationConfig::validate_provider_reference`)
- Failure mode:
  1. In `merged_providers()`, `seen` stores only provider names (`HashSet<String>`). If a provider is configured in `image_providers` (e.g. `[generation.image_providers.openai]`), its name is added to `seen`. Then the legacy `self.providers` loop skips any entry with `seen.contains(name)`, completely dropping all other modalities (such as speech or transcription) defined under `[generation.providers.openai]`.
  2. In `validate_provider_reference()`, `typed_maps.iter().any(|(map, _)| map.contains_key(provider))` checks ALL typed maps regardless of modality. If `default_speech_provider = "openai"` is configured and backed by `[generation.providers.openai]`, but `[generation.image_providers.openai]` also exists, validation erroneously rejects `default_speech_provider` with `references unknown/disabled provider 'openai'`.
- Evidence:
```rust
for (name, cfg) in &self.providers {
    if seen.contains(name) {
        continue;
    }
```
and
```rust
if typed_maps.iter().any(|(map, _)| map.contains_key(provider)) {
    return Err(format!("generation.{field} references unknown/disabled provider '{provider}'"));
}
```
- Suggested fix: In `merged_providers()`, track `seen: HashSet<(String, GenerationType)>` so typed providers only shadow legacy providers for the specific modality they configure. In `validate_provider_reference()`, only reject if the typed map for the *current* `gen_type` contains the provider: `if typed_maps.iter().any(|(map, map_type)| *map_type == gen_type && map.contains_key(provider))`.
- Confidence: 0.95

### B6-006 [P2] `dot_paths_intersect` is asymmetric and violates empty path contract
- Location: `src/config/types/policies/exec_tier.rs:859-861` (`dot_paths_intersect`)
- Failure mode: The documented contract specifies: "An empty path is the whole config." When called with `dot_paths_intersect("", "policies.exec_tier")`, it returns `true`. However, when called with `dot_paths_intersect("policies.exec_tier", "")`, it returns `false` because `b.is_empty()` is not checked. In addition, it allocates two `String`s with `format!` on every invocation.
- Evidence:
```rust
fn dot_paths_intersect(a: &str, b: &str) -> bool {
    a.is_empty() || a == b || a.starts_with(&format!("{b}.")) || b.starts_with(&format!("{a}."))
}
```
- Suggested fix: Check `a.is_empty() || b.is_empty()` to ensure symmetry and honor the empty path contract. Eliminate heap allocations by using non-allocating slice prefix checks:
```rust
fn dot_paths_intersect(a: &str, b: &str) -> bool {
    a.is_empty() || b.is_empty() || a == b
        || (a.starts_with(b) && a[b.len()..].starts_with('.'))
        || (b.starts_with(a) && b[a.len()..].starts_with('.'))
}
```
- Confidence: 0.95

### B6-007 [P2] `GenerationDefaults::validate` accepts `NaN` and `Infinity` for numeric constraints
- Location: `src/config/types/generation/defaults.rs:144-166` (`GenerationDefaults::validate`)
- Failure mode: If a user configures `duration_seconds = NaN` or `guidance_scale = NaN` or `Infinity`, IEEE 754 float comparisons `duration <= 0.0` and `scale < 0.0` evaluate to `false`. Validation succeeds, and non-finite floats propagate into generation parameter payloads, causing serialization errors or downstream API rejections.
- Evidence:

```rust
    if duration <= 0.0 {
        return Err(format!("..."));
    }
}
if let Some(scale) = self.guidance_scale {
    if scale < 0.0 {
        return Err(format!("..."));
    }
```
- Suggested fix: Explicitly validate finiteness: `if !duration.is_finite() || duration <= 0.0` and `if !scale.is_finite() || scale < 0.0` (matching the pattern used in `spend.rs:deserialize_ceiling`).
- Confidence: 0.90
