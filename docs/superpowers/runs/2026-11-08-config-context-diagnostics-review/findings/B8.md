### B8-01 [P0] Active session directory deletion during lazy migration when workspace equals agent dir
- Location: `src/config/agent_resolver/mod.rs:289-328` (`AgentDefinitionResolver::resolve_one`)
- Failure mode: If `workspace_path == agent_dir` (e.g. operator configured `[agents.defaults] workspace_root` to match `agents_root`, or points both roots to the same directory), `old_sessions` and `new_sessions` resolve to the exact same path (`agent_dir/sessions`). During migration, every session file matches `if dest.exists() { continue; }`, resulting in zero files copied while `all_copied` remains `true`. The subsequent `fs::remove_dir_all(&old_sessions)` then deletes the entire live `sessions/` directory, causing catastrophic loss of all existing session history.
- Evidence:
```rust
let old_sessions = workspace_path.join("sessions");
...
let new_sessions = agent_dir.join("sessions");
...
if dest.exists() { continue; }
...
if all_copied {
    let _ = fs::remove_dir_all(&old_sessions);
```
- Suggested fix: Guard against path equality prior to attempting migration:
```rust
if workspace_path == agent_dir || old_sessions == new_sessions {
    return;
}
```
Also compare canonical paths `if let (Ok(a), Ok(b)) = (old_sessions.canonicalize(), new_sessions.canonicalize()) { if a == b { return; } }` to guard against symlinked root equality.
- Confidence: 1.0

### B8-02 [P1] `apply_patch_to_table` writes non-inline table headers inside array of tables, corrupting TOML
- Location: `src/config/agent_manager/crud.rs:569-574, 602-610` (`apply_patch_to_table`)
- Failure mode: When updating an agent's `subagents` or setting `identity` on an agent where `identity` was previously absent, `apply_patch_to_table` inserts a standard `Item::Table(Table::new())` rather than an `InlineTable`. Any subsequent `[[agents.list]]` entry in the file violates TOML specification (redefining table as array of tables), corrupting `config.toml` and causing the daemon to fail on next boot with duplicate key/table redefinition errors. - Evidence:
```rust

    .entry("identity")
    .or_insert(toml_edit::Item::Table(toml_edit::Table::new()));
...
agent_table["subagents"] = toml_edit::Item::Table(t);
```
- Suggested fix: Use `toml_edit::InlineTable` for `identity` and `subagents` in `apply_patch_to_table` (mirroring `model_ref_to_item`), or call `inline_nested_tables(agent_table)` before saving.
- Confidence: 1.0

### B8-03 [P1] `validate_filename` accepts multi-segment paths containing path separators
- Location: `src/config/agent_manager/crud.rs:474-483` (`AgentManager::validate_filename`)
- Failure mode: A caller supplying a multi-segment path like `sessions/test.json` or `sub/doc.md` bypasses `validate_filename` because `Path::new(filename).components()` breaks the string into `Component::Normal("sessions")` and `Component::Normal("test.json")`. The loop matches all `Component::Normal(_)` and returns `Ok(())` without checking for path separator characters (`/` or `\`). This allows `read_file`, `write_file`, and `delete_file` to access and mutate files inside arbitrary subdirectories (such as `sessions/`) under `agent_dir`, breaking the contract that operations are restricted to single file names in the agent identity directory.
- Evidence:
```rust
let path = std::path::Path::new(filename);
for component in path.components() {
    match component {
        std::path::Component::Normal(_) => {}
        _ => {
            return Err(AlephError::invalid_config(format!(
                "Invalid filename '{filename}': must not contain path separators or traversal"
            )));
        }
    }
}
```
- Suggested fix: Explicitly check that `filename` contains no path separators and represents exactly one normal component:
```rust
if filename.contains('/') || filename.contains('\\') || filename.contains(':') {
    return Err(AlephError::invalid_config(format!(
        "Invalid filename '{filename}': must not contain path separators or ':'"
    )));
}
```
- Confidence: 1.0

### B8-04 [P1] `read_file` and `write_file` follow symlinks outside agent directory
- Location: `src/config/agent_manager/agent_files.rs:68-73, 88-95` (`AgentManager::read_file`, `AgentManager::write_file`)
- Failure mode: `require_contained` performs only lexical normalization (`normalize_path_lexically`) and does not resolve or check symlinks. If a symlink exists inside an agent directory pointing to an arbitrary host file (e.g. `/etc/shadow` or `~/.ssh/id_rsa`), `read_file` follows the link via `fs::read_to_string`, exfiltrating host files. Similarly, `write_file` invokes `fs::write(&path, content)` which writes through the symlink, overwriting target files outside `agent_dir`.
- Evidence:
```rust
let path = agent_dir.join(filename);
self.require_contained(&agent_dir, &path)?;
fs::read_to_string(&path)
...
fs::write(&path, content)
```
- Suggested fix: Check symlink status using `fs::symlink_metadata(&path)`. Reject if the path is a symlink. For existing files, verify that `path.canonicalize()?` starts with `agent_dir.canonicalize()?`.
- Confidence: 0.95

### B8-05 [P1] Synchronous lock polling and blocking disk I/O executed on async Tokio threads
- Location: `src/config/agent_manager/toml_ops.rs:62-67` (`AgentManager::with_config_write`)
- Failure mode: When called from async RPC handlers (`agents.create`, `agents.update`, `agents.delete`), `with_config_write` calls `with_file_lock`, which executes a blocking spin-loop calling `std::thread::sleep(10ms)` for up to a 5-second deadline, accompanied by synchronous `fs::read_to_string`, `write_atomic`, and directory `fsync` calls. Because these calls run directly on Tokio runtime worker threads without `tokio::task::spawn_blocking`, any lock contention or slow disk write blocks the thread, causing latency spikes and thread pool starvation across the daemon.
- Evidence:
```rust
pub(super) fn with_config_write<T>(&self, f: impl FnOnce() -> Result<T>) -> Result<T> {
    let mut lock_path = self.config_path.as_os_str().to_os_string();
    lock_path.push(".lock");
    crate::utils::atomic_io::with_file_lock(std::path::Path::new(&lock_path), |_| Ok(f()))
```
- Suggested fix: Offload blocking agent manager write operations to `tokio::task::spawn_blocking` at the handler boundaries in `src/gateway/handlers/agents.rs`.
- Confidence: 0.95

### B8-06 [P2] `list_files` follows symlinks, violating documented invariant
- Location: `src/config/agent_manager/agent_files.rs:35-41, 122` (`AgentManager::list_files`)
- Failure mode: Line 122 documents that `list_files separately skips symlinked entries`. However, `list_files` calls `entry.metadata()`, which traverses symlinks. If an entry is a symlink pointing to a regular file outside the directory, `metadata.is_file()` returns `true`, listing the target as a workspace file. If the symlink is broken, `entry.metadata()` returns an error, failing the entire `list_files` RPC with `AlephError::IoError`.
- Evidence:
```rust
let metadata = entry
    .metadata()
    .map_err(|e| AlephError::IoError(format!("Failed to read metadata: {e}")))?;

if !metadata.is_file() {
    continue;
}
```
- Suggested fix: Inspect entry file type with `entry.file_type()` instead of `entry.metadata()`. Skip any entry where `file_type.is_symlink() || !file_type.is_file()`.
- Confidence: 1.0

### B8-07 [P2] `write_file` in `agent_files` writes non-atomically, risking file truncation

- Suggested fix: Use `crate::utils::atomic_io::write_atomic(&path, content.as_bytes())` to ensure atomic staging, fsync, and rename.
