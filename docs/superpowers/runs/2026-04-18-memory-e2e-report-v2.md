## 4. Five fixes applied (commit `966b7b432`)

### 4.1 `init_schema` migration ordering (Bug #1 from v1)

**File**: `src/memory/store/sqlite/schema.rs`

Move `migrate_recall_signals_note_path(conn)?;` BEFORE `conn.execute_batch(RECALL_SIGNALS_DDL)?;`. Drop stale `idx_recall_fact_id` and `idx_recall_dedup` indexes before recreating under the new `note_path` column. Old databases now survive `init_schema`.

### 4.2 `sessions` table missing `state` column (Bug #2 from v1)

**File**: `src/gateway/session_store/migration.rs`

New private helper `ensure_sessions_columns()` runs PRAGMA-guarded `ALTER TABLE sessions ADD COLUMN <col> <ty>` for each missing field (`state`, `metadata`, `label`, `model`, `model_provider`, `parent_session_key`, `compaction_count`, `auto_reset_at`, `input_tokens`, `output_tokens`) before the legacy migration SELECT. The legacy SQLite → file backend migration now completes silently on any historical schema.

### 4.3 L0 capture from gateway turns (Bug #3 from v1 — the big one)

**Files**: `src/gateway/agent_instance.rs`, `src/builtin_tools/agent_manage/create.rs`, `src/bin/aleph-server/commands/start/builder/agent_init.rs`

- New field `AgentInstance.raw_memory_writer: Option<Arc<dyn RawMemoryStore>>` + builder `with_raw_memory_writer(...)`.
- `AgentInstance.add_message()` now writes `RawMemorySource::Transcript` rows into `raw_memories` for every persisted user/assistant turn (system/tool messages skipped).
- `AgentRegistry` got a `set_raw_memory_writer()` method (interior mutability via `RwLock`) that propagates the writer to every lazily-instantiated AND every dynamically-registered agent.
- Server startup (`agent_init.rs:702`) wires `memory_db` into the registry's writer immediately after construction.
- `AgentCreateTool` got `with_raw_memory_writer()` for symmetry with the registry path (used when the LLM creates agents via tool calls).

After this, gateway WS turns produce `raw_memories` rows immediately — verified Phase 1 (8 turns → 21 rows) and Phase 0 sanity (1 turn → 2 rows).

### 4.4 CompressionService picks up Transcript raws across all agents (Bug #4)

**Files**: `src/memory/compression/service.rs`, `src/memory/store/raw_memory.rs`, `src/memory/store/sqlite/raw_memories.rs`

- `CompressionService.compress()` previously hardcoded `DEFAULT_AGENT="main"` — never compressed `test-memory-validation`'s raws. Now iterates over `database.unprocessed_agent_ids()` and aggregates results.
- New `RawMemoryStore::unprocessed_agent_ids()` trait method (default impl returns `["main"]` for in-memory test stores) with a SQLite impl querying `SELECT DISTINCT agent_id FROM raw_memories WHERE is_processed = 0`.
- Removed the historical `r.source != Transcript` filter at line 187 of `compress_to_notes` — Transcript was excluded on the assumption a separate per-turn pipeline existed; that pipeline never landed, and the Bug #3 fix above writes Transcript rows that the filter then dropped silently.

### 4.5 FTS5 phrase escaping (Bug #5 — discovered when first compression run failed)

**File**: `src/memory/store/sqlite/notes.rs`

`search_notes_fts` now wraps the input query as a quoted phrase (`"..."`) with embedded quotes doubled (`""`). Raw user content routinely contains `[`, `]`, `(`, `)`, `:`, `^`, `*` — all FTS5 reserved tokens — causing `fts5: syntax error near "["` failures during compound-ingest's "find related notes" step. Phrase-quoting keeps the input literal.

### 4.6 Quality-of-life additions

- **`src/memory/notes/ingest/prompts.rs`**: strengthen the compound-plan prompt with explicit per-op-kind JSON examples (`{"kind":"create",...}`, `{"kind":"append",...}`, etc.) so the LLM doesn't drop the discriminator.
- **`src/memory/notes/ingest/ingestor.rs`**: new `strip_kindless_ops()` helper silently filters ops missing the `"kind"` field before strict serde parsing, so a single malformed op doesn't fail the whole batch (which would leave raws unprocessed forever).
- **`tests/scripts/ws_send.py`**: aligned RPC schemas (`shared_token` not `auth.token`; `topics: [str]` not `pattern: str`; `input` not `message`); switched the streaming loop to a wall-clock timeout (per-frame timeout was reset by `system.tick` heartbeats, hanging the script forever); added `--break-on` early exit by precise method/topic match.

## 6. Remaining gaps (recommended follow-ups)

### 6.1 SCHEMA.md auto-bootstrap

`index.md` and `log.md` get auto-generated by `compound_ingestor` after each compress pass. `SCHEMA.md` does not — it appears to need explicit creation, possibly during agent initialization or via the `note_schema` tool. Adding a "bootstrap minimal SCHEMA.md if missing" step inside the orientation layer's first-write path would close this without changing semantics.

### 6.2 `memory_reflect` / `query_filer` provider wiring

Server log clearly states `MemoryReflector not wired (no embedder or provider)` even though the gateway has a configured embedder + provider. The wiring should follow the same pattern as the L0 raw_memory writer (Bug #3 fix): construct the dependency at startup and pass it down through `BuiltinToolConfig` to `MemoryReflector`. The pieces all exist; only the assembly is missing.

### 6.3 Dream daemon tick visibility

`DreamDaemon background task started` is the only Dream-related log line. The 60-second tick loop (`tokio::time::interval`) does not emit at INFO level whether it ran or skipped. Either:
- Bump the tick log to INFO so operators can observe daemon health, or
- Add a `dream.heartbeat` event to the gateway event bus so external clients can subscribe

Until then, the only way to observe Dream Daemon behaviour is through `dream_status` / `dream_reports` writes, which only happen on a successful run.

### 6.4 ProfileSynthesizer trigger path

`USER.md` only fires after a SessionEnd raw is processed. `session.delete` RPC currently calls `manager.delete_session` (file-backend rotation) — it does NOT transition `SessionManager.set_state(stopped)` which is the only path that emits a SessionEnd raw. Either:
- Have `session.delete` also call `set_state(stopped)` on the matching SessionManager, OR
- Add a separate `session.end` RPC that explicitly fires the SessionEnd hook

### 6.5 `note_path` double-`.md` cosmetic

LLM returns `note_path` like `"personal/zou-guojun.md"` and the writer appends `.md` → `personal/zou-guojun.md.md`. Either strip a trailing `.md` from the LLM input or make the writer detect-and-skip when the path already ends in `.md`. Cosmetic only — wikilinks in `index.md` use the correct single-`.md` form because they're rendered from `note_path` directly.

### 6.6 `recall_signals` table not populated

Even though `memory_search` / `memory_browse` / `memory_explore` fired correctly during Phase 3, `recall_signals` rows count = 0. The retrieval tools return results but the telemetry hook that should write `(note_path, query_hash, day_bucket)` is either never invoked or also gated on a missing dependency. Affects `NoteDecay` (which uses `last_accessed_at` derived from `recall_signals`) — without this, even rarely-accessed notes look "fresh".

## 10. Verdict

**Core memory pipeline (L0 capture → L1 compression → notes → wiki retrieval): SHIPPED.**

The five-bug fix is a genuine unlock — without it, every WS-mediated conversation produced zero L0 rows and the entire L1/notes/retrieval/dream/orientation layer had no data to operate on. The fix is small (+280 lines), self-contained to the memory + gateway boundary, and adds a single new trait method. No other subsystem touched.

**Peripheral memory features (orientation SCHEMA/USER, query filer, dream daemon visibility): NEEDS FOLLOW-UP.** Each is a distinct wiring gap with a clear remediation in §6.

**Recommended next session**:
1. Wire `memory_reflect` / `MemoryReflector` from `BuiltinToolConfig` (small, follows Bug #3 pattern)
2. Add explicit `dream.heartbeat` log line in the daemon's tick loop
3. Add `set_state(stopped)` call to `session.delete` handler so SessionEnd → ProfileSynthesizer fires
4. Bootstrap an empty `SCHEMA.md` on first compression if absent

These are quick wins (≤1 day) that would close the remaining gaps and give a clean H1-H10 hard pass.
