## 1. Executive Summary

Batch `MEM_RUNTIME_EVENTS` covers 28 files implementing the Memory subsystem's runtime lifecycle, event-sourced state mutation and reconstruction, synthesis reflection, and transcript indexing.

The audited subsystem exhibits strong architectural invariants:
- **Single append funnel**: All event writes pass through `MemoryCommandHandler::append`, preserving partition tags and fail-closed undecided sentinel (`!undecided`) semantics.
- **Fail-closed admission & lifecycle**: `MemoryRuntime` strictly gates resource activation across states (`Off` → `Starting` → `Running` → `Draining` → `Failed`), with monotonic task retention and atomic admission counters.
- **Prompt security fences**: Retrieved notes in `MemoryReflector` are isolated inside `<retrieved_note>` tags with tag neutralisation to prevent prompt injection.

Static review identified 28 distinct Occam's Razor candidates:
1. **Dead code & compiler warnings**: Unused `MemoryRuntime::provider(&self)` (zero callers across repo); test-only `MemoryRuntime::worker_stop(&self)` missing `#[cfg(test)]`; dead unused parameter `_last_reconcile` in `run_one_tick`.
2. **Hot-path allocation elimination**:
   - In `handler.rs`, `cmd.note_path` is cloned into `fact_id_ref` across 5 mutation paths purely to satisfy post-move projection logging.
   - In `reconcile_once`, `missing_files` and `stale_files` vectors are cloned into `ReconcileReport` purely because they are iterated in subsequent tracing calls.
   - In `packet_adapter.rs`, `escape_fence` executes 6 chained heap string replacements on every note field even when no `<` tag exists, and `push_str(&format!(...))` allocates temporary formatting buffers.
   - In `transcript_indexer/indexer.rs`, `chunk_text` collects sentences into an intermediate `Vec<&str>` and clones the whole chunk string instead of using `std::mem::replace`.
   - In `events/mod.rs`, `EventActor::from_str` allocates an intermediate lowercase string on every parsing attempt.
   - In `projector.rs`, `fold_events_to_note` clones the entire `serde_json::Value` syntax tree for `NoteMigrated` instead of deserializing directly from the borrowed value.
3. **Control flow & indirection simplifications**: Flattening nested `match` boilerplate into `let-else` constructs in `embedding.rs`, eliminating unnecessary closure indirection in `current_reconciler`, and removing redundant double-async wrapping around `RecallWriter`.
4. **Architectural boundary preserves (REJECT/DEFER)**: Preserving intentional task-local future boxing in `context.rs` (erasing stack frames across 8 optional scopes), keeping fine-grained tool settings locks in `search.rs`, and preserving partition consensus deduplication in `consolidate_facts`.

## 3. Invariant Safety Pre-Flight

1. **Event-Sourcing Append Funnel & Dual-Write Invariants**:
   - `the_handler_funnel_is_the_only_memory_event_writer` remains satisfied: all event appends route through `MemoryCommandHandler::append`.
   - `partition` assignment semantics (`Some(agent)`, `None` → `!undecided`) remain completely untouched.
   - Dual-write to notes filesystem (`project_to_notes`) maintains identical best-effort error handling and error log event generation on failure.
   - Idempotency and monotonically increasing `seq` are preserved for all commands.

2. **Public API & Wire Contracts**:
   - All public command structs (`CreateNoteCommand`, `UpdateContentCommand`, etc.) in `commands.rs` retain their existing field types and signatures.
   - All `MemoryEvent` variants, serde tags (`#[serde(tag = "type")]`), and legacy aliases (`FactCreated`, `fact_id`) remain 100% wire-compatible.
   - `MemoryRuntime::status()`, `start()`, `stop()`, `operation()`, and `embed_batch()` signatures remain identical.

3. **Concurrency & Async Cancellation Safety**:
   - In `MemoryRuntime::drive()`, combining lock checks and `inner.bundle.take()` retains dropping the `inner` lock prior to calling `bundle.close()`, preventing lock-holding across blocking I/O and maintaining dead-lock free teardown.
   - In `tasks.rs`, `MemoryTasks::poll_completed` keeps all pending handles intact, only removing observed handles.
   - In `context.rs`, task-local boxing via `optional_scope` is deliberately preserved to avoid exponential stack frame explosions.

4. **Security & Prompt Injection Invariants**:
   - In `packet_adapter.rs`, `escape_fence` fast-path (`!s.contains('<')`) preserves identical tag neutralisation: any string containing `<retrieved_note>`, `</retrieved_note>`, `<title>`, etc., continues to be replaced with square bracket neutralised equivalents.

5. **Performance & Allocation Impact**:
   - **Transcript indexing**: Eliminates 1 intermediate sentence `Vec<&str>` allocation and 1 full-chunk `String` clone per chunk boundary via `std::mem::replace`; avoids redundant clones of `database`, `agent`, and `session_key` inside the chunk loop.
   - **Event mutations**: Eliminates 1 `fact_id_ref` clone per mutation in `handler.rs`.
   - **EventActor parsing**: Zero heap allocations on happy-path parsing in `from_str`.
   - **Note migration replay**: Zero syntax-tree cloning in `fold_events_to_note` via `MemoryFact::deserialize(snapshot)`.
   - **Synthesis prompt formatting**: Eliminates 6 heap string allocations per field when notes lack `<` tags, and eliminates temporary `format!` buffer allocation by writing directly into `body`.
