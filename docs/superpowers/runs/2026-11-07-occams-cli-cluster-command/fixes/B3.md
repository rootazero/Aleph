## F1 — B3-M1: admission no longer fails open when the device store cannot be read

- **`src/cluster/enrollment.rs:100`** — new `NodeAdmission::StoreUnavailable { detail: String }`
  variant: the store could not be read or written, so the center **cannot tell** whether the
  node is revoked. It is a *non-admitted* outcome (never `Admitted`), and it is **retryable**
  (not a terminal refusal).
- **`src/cluster/enrollment.rs:526-534`** — the old degrade branch
  (`"node device lookup failed; admitting on LAN-trust"` → `Admitted { node_id, minted: false }`)
  is **gone**: a `get_device` error now returns `StoreUnavailable`.
- **`src/cluster/enrollment.rs:485-486`** — a `match_by_name` read error in the unknown-id branch
  returns `StoreUnavailable` (it used to converge onto *some* row, which could have adopted a
  revoked peer).
- **`src/cluster/enrollment.rs:516-517`** — a failed **backfill** write returns
  `StoreUnavailable` instead of logging and admitting anyway (this closes the
  `B3-P2-04` "writes failed but the node was admitted" half).
- **`src/gateway/server/connection/mod.rs:1217-1222`** — the connect seam maps
  `StoreUnavailable` to **no `node` payload at all**.

**Why "no `node` payload" is the retryable shape (verified against the node client):**
`src/bin/aleph-server/commands/node.rs:124` `parse_connect_verdict` returns `None` when
`/result/node` is absent, `run_session` (`node.rs:445`) turns that into
`Err("center did not register this node: …")`, and `handle_node` (`node.rs:252-…`) routes it
through the generic arm → `"node session error: …; retrying in …ms"`. So an absent payload is
exactly "the center did not register me, back off and try again" — the node retries and never
registers. A *terminal* refusal instead reuses the existing `"deregistered"` status (see F4),
so **no new status vocabulary** was introduced.
- **`src/gateway/server/connection/mod.rs:1066-1090`** — the admission call itself now runs
  inside `tokio::task::spawn_blocking` (F6); a `JoinError` is mapped to
  `NodeAdmission::StoreUnavailable` (never a silent drop, never a success).

**Adjudicator risk note — addressed:** `grep -rn "NodeAdmission::" --include="*.rs" src/` finds
exactly **one** consumer of the enum outside its own module — the connect seam
(`src/gateway/server/connection/mod.rs`), which now matches all five variants exhaustively
(`Admitted`, `Deregistered`, `IdentityConflict`, `Ambiguous`, `StoreUnavailable`). No other
match site exists, so adding a variant cannot leave a non-exhaustive match behind.

## F2 — B3-P1-05 + B3-M2: deregister is revoke-first, and repeating it is idempotent

- **`src/cluster/enrollment.rs:750`** — `deregister_node` now **revokes first**: the durable
  `revoke_device` write happens **before** the session eviction and **before** the
  `node.disconnected` publish. A failed revoke write returns `Err` — nothing is evicted, no
  event is published, and no success is claimed.
- **`src/cluster/enrollment.rs:889`** — `revoke_node_device` now returns
  `Result<bool, DeregisterError>` instead of a bare `bool`:
  `Ok(true)` = newly revoked, `Ok(false)` = the row was **already** revoked (idempotent success)
  or there is no row at all, `Err(StoreUnavailable)` = the write did not land (the row is still
  active) or the store could not be read.
- **`src/cluster/enrollment.rs:825`** — `resolve_deregister_target` gained a **tier ①**:
  `store.get_device(query)` — an exact-`device_id` lookup that **sees revoked rows**
  (`list_devices()` hides them). Tier ② (`resolve_enrolled_node`, `enrollment.rs:677`) still
  uses the **active-only** list for *name* matching, and tier ③ stays the online registry's
  fuzzy match.
- **`src/gateway/handlers/cluster.rs:155-161`** — the old
  `"partial state — online session evicted but device record NOT revoked"` warning is **gone**:
  with revoke-first, `device_removed == false` now means exactly one thing — *the row was
  already revoked* (an idempotent repeat) — which is logged at `info`, not `warn`.

**Adjudicator risk note — addressed (the name branch stays active-only):** the finding's
"see revoked rows" requirement applies **only** to the exact-id tier. `resolve_enrolled_node`
(`enrollment.rs:677`) still reads `store.list_devices()` (active rows only), so a *name* that
now only matches a revoked row still resolves to `NotFound` — an offline node deregistered by
name is not resurrected by a second name-based call. The new test
`a_repeat_deregistration_by_exact_id_is_idempotent` (`enrollment.rs:1527`) pins both halves:
the **exact id** repeat succeeds idempotently, the **name** repeat still returns `NotFound`.

## F3 — B3-P1-01: re-enrollment recovery is explicit (delete the node's identity file)

- **No code change to the store** and **no reactivation**: the finding's R2 policy choice was
  resolved as *"enrolling again creates a NEW identity; the node must drop its persisted id"*.
  There is deliberately **no** "list revoked rows" API and **no** un-revoke path (an un-revoke
  would be an implicit re-grant of a bearer credential).
- **`src/cluster/enrollment.rs`** (module doc) — the admission contract now states that the
  **presented id is authoritative**: a node that presents an ACTIVE `device_id` is admitted
  under *that* id even if its `device_name` differs from the stored one (the id is the bearer
  secret the node persisted; the name is a mutable display label — renaming a machine must not
  change its identity). Under LAN trust the id **is** the credential; this is policy, not an
  oversight.
- **`docs/reference/CLUSTER.md:205-209`** — new operator-facing blockquote
  *「被注销的节点怎么回来(唯一恢复路径)」*: delete the node's identity file
  (`~/.aleph/node/<name>.json`) → the next boot presents **no** id → first boot adopts the
  operator's re-enrolled row **by name** or mints a fresh one. The center never revives a
  revoked row, and there is no "list revoked rows" API.
- **`src/builtin_tools/node_manage.rs:67`** — the tool's description now says the same thing
  ("Reversible only by enrolling the name again AND having the node delete its identity file,
  so it comes back as a new node.").

## F4 — B3-P1-02: an ambiguous first boot fails closed (no third ghost row)

- **`src/cluster/enrollment.rs:106`** — new terminal outcome
  `NodeAdmission::Ambiguous { name: String, count: usize }`.
- **`src/cluster/enrollment.rs:568-575`** — the first-boot `NameMatch::Ambiguous(n)` branch no
  longer logs *"minting a fresh node id"* and mints a **third** row; it returns
  `NodeAdmission::Ambiguous` with the offending name and the number of colliding rows.
- **`src/gateway/server/connection/mod.rs:1193-1200`** — the connect seam turns that into the
  **existing terminal status** plus a `reason`:
  `{"status":"deregistered","reason":"<n> enrolled nodes share the name '<name>'; an operator must deregister the duplicates by id"}`.
  The `reason` field is the `IdentityConflict` precedent — **no new status vocabulary**; the
  node client already treats `"deregistered"` as terminal.
- **`src/bin/aleph-server/commands/node.rs:124-133, 151-166, 448-450`** — the node client
  carries the center's refusal reason end-to-end: `ConnectVerdict::Deregistered { reason: Option<String> }`
  → `struct Deregistered { reason: Option<String> }` → the exit log prints
  `"node was refused by the center: <reason>"` when a reason is present.
  **Backwards compatible**: an old center sends the status alone → `reason == None` → the node
  prints the *old* message byte-for-byte (`node.rs:252-…`).
- **`src/cluster/enrollment.rs:1233`** — the old test
  `ambiguous_name_mints_fresh_rather_than_guessing` was **replaced** by
  `ambiguous_first_boot_is_refused_instead_of_minting_a_third_row`: it asserts the terminal
  `Ambiguous { name, count: 2 }` outcome **and** that the device table still holds **two** rows
  (no third ghost row).

**Adjudicator risk note — addressed:** the wire shape is unchanged for every existing consumer
(`status` is still `"registered"` or `"deregistered"`); `reason` is a purely additive field.
`parse_connect_verdict` (`node.rs:126`) checks the **status first** and only then requires
`node_id`, so the `reason`-only refusal payload (which carries no `node_id`) is still parsed as
terminal — verified in the new test `connect_verdict_carries_the_centers_refusal_reason`
(`node.rs:753`).

## F5 — B3-P1-07: a first-boot write failure is no longer a successful ephemeral enrollment

- **`src/cluster/enrollment.rs:142`** — `mint_node_device` now returns a typed
  `Result<String, MintError>` (`MintError::Unaddressable(String)` / `MintError::Store(String)`)
  instead of a bare `String`, so the caller can tell "the name can never be addressed" from
  "the row could not be written".
- **`src/cluster/enrollment.rs:613-615`** — a **store** failure during the first-boot mint
  returns `NodeAdmission::StoreUnavailable` (retryable). The old
  `"node enrollment failed; using ephemeral id"` path that handed the node a random UUID it
  would then persist as authoritative is **gone** — the center now has no durable row for it.
- The **unaddressable-name** case keeps its ephemeral-UUID fallback (`enrollment.rs:596-607`):
  a name that normalizes to nothing can never be addressed later, so a throwaway id is the
  honest answer there — and it is the *only* remaining ephemeral-id path.

## F6 — B3-P1-03: the store-touching critical sections moved off the Tokio workers

The three functions stay **synchronous** (the whole read-then-write sequence, including
`NODE_NAME_LOCK`, still happens inside one call). Only the **call sites** became async:

- **`src/gateway/server/connection/mod.rs:1066-1072`** — `admit_node` runs inside
  `tokio::task::spawn_blocking(move || crate::cluster::admit_node(&store, presented_id.as_deref(), &device_name))`.
  A `JoinError` becomes `NodeAdmission::StoreUnavailable` (`connection/mod.rs:1085-1089`).
- **`src/gateway/handlers/cluster.rs:66`** (`cluster.enroll`) and **`cluster.rs:143-146`**
  (`cluster.deregister`) — both run in `spawn_blocking`; a `JoinError` maps to
  `INTERNAL_ERROR` with an explicit "the … task did not complete" message
  (`cluster.rs:109-113`, `cluster.rs:198-202`) — never a silent drop, never a success.
- **`src/builtin_tools/node_manage.rs:87`** and **`:111-120`** — the tool's `enroll` /
  `deregister` actions likewise run in `spawn_blocking`; a `JoinError` becomes
  `AlephError::tool("… the … task did not complete (…)")`.

**Adjudicator risk note — addressed (no gateway lock is held across the await):** the connect
seam's `ctx.connections.write().await` guard is dropped (`drop(conns);`) **before** the
admission block, so the new `spawn_blocking` await cannot be holding a gateway lock; the other
two acquires in that function (`:239`, `:408`) live in earlier scopes. The closures capture
only owned `Arc`s (`SecurityStore`, `NodeRegistry`, `GatewayEventBus`) and owned `String`s, so
each closure is `'static + Send` and no borrow crosses the await.

## F10 — B3-P2-04: the peer-presented id is bounded (the fingerprint derivation is unchanged)

a storage migration, not a review fix. The bound above removes the unbounded-write half of the
finding; the prefix-collision half is left for an explicit migration decision.

- **`CLUSTER.md:140-167`** — the admission table now has **seven** rows: revoked id → `Deregistered`;

  text was reversed.
- **`CLUSTER.md:282`** — the offline-resolver pointer now says

- **`CLUSTER.md:429-437`** — the wire table row for the connect reply now shows
  `node:{ node_id, status:"registered"|"deregistered", persist, reason? }` plus a note that the

## Not done (and why)

- **Reactivation of a revoked row on `cluster.enroll`** (the R2 alternative) — **deliberately
  not implemented**: it would let an ordinary enrollment resurrect a revoked **bearer id**. The
  chosen recovery (delete the node's identity file) is documented instead (F3).
- **A "list revoked rows" store API** — **not added**: it would only exist to serve a
  reactivation flow that was rejected.
- **Fingerprint derivation** (`truncate_on_char_boundary(id, 16)` → a complete-id
  collision-resistant digest) — **not changed** (F10): it changes the on-disk key of every
  enrolled node and is a migration decision, not a review fix.
- **`docs/reference/FEATURE_LOCATOR.md`** — **not updated**: it narrates the historical
  enrollment rework (including the old `reuse_by_name` symbol name) and was not in the
  "files you may touch" list.
- **No build, test, `cargo check` or `clippy` was run** (builds are forbidden in this phase).
  Correctness was reasoned about by hand; `rustfmt` (which parses the files) was run as a
  syntax check, and the diff was re-read line by line (types, borrows, moves, match arms,
  closure captures).
- **The Panel crate (`interfaces/webchat`)** was **not** touched: it does not depend on
  `alephcore`, and the only wire change is the additive `reason` field on the connect reply.
