## F1 — B2-01: the malformed-catalog rule now fails closed on all three dispatch paths

- **`src/cluster/registry.rs:494`** — deleted the flag-dropping `pub fn resolve(...)` 2-tuple;
  `resolve_with_catalog` is now the ONE resolver. Its doc states the invariant explicitly.
  (The old `resolve` lived at registry.rs:373-379 before the change.)
- **`src/cluster/registry.rs:122`** — added `pub catalog_malformed: bool` to `NodeMatch`.
- **`src/cluster/registry.rs:545`** — `resolve_all_by_tags` populates `catalog_malformed: n.catalog_malformed`.
- **`src/builtin_tools/node_file.rs:76`** — now calls `resolve_with_catalog`; **`node_file.rs:91`**
  refuses a malformed catalog with the exact error shape `node_invoke.rs:81-86` uses
  (`AlephError::tool("node '<n>' declared a malformed command catalog; refusing to invoke")`).
- **`src/builtin_tools/node_invoke_many.rs:62`** — `invoke_one` refuses a malformed-catalog node with
  the same per-node `{"node":…, "node_id":…, "ok": false, "error": …}` shape the existing
  "not declared" branch already uses.

**Adjudicator risk note — addressed:** `grep -rn "NodeMatch" --include="*.rs" src/` →
`NodeMatch` is only *constructed* at `registry.rs` (`resolve_all_by_tags`) and only *read
field-wise* in `node_invoke_many.rs`. **No consumer destructures `NodeMatch { .. }`**, so adding
the field breaks nothing.

**Deviation (must be reviewed):** the instruction's premise ("its only caller is `node_file.rs`")
was **incomplete**. `grep -rn "\.resolve(" src/cluster/registry.rs` found **4 additional call
sites**, all inside registry.rs's own `#[cfg(test)] mod tests` (registry.rs:1158, 1194, 1195, 1198
post-fix). I did **not** keep `resolve` returning the flag (that would leave two byte-identical
public resolvers — the duplication the fix exists to remove). Instead I migrated those 4 test
call sites to `resolve_with_catalog` (identical assertions, same semantics) and deleted `resolve`.
Reverting to the literal fallback is a 4-line change if the reviewer prefers it.

## F3 — B2-03a: the schema length probe no longer materializes the schema twice

- **`src/cluster/registry.rs:898`** — new `struct LimitedSink` with `impl std::io::Write`: it counts
  the bytes the serializer offers and **refuses** (returns `io::Error`) once the total would pass
  `MAX_COMMAND_SCHEMA_BYTES`.
- **`src/cluster/registry.rs:942`** — `bound_commands` now measures through
  `serde_json::to_writer(&mut sink, &command.schema)` instead of
  `serde_json::to_string(&command.schema).map_or(usize::MAX, |s| s.len())`.

**Adjudicator risk note — addressed, the two error cases are branched explicitly:**
- *oversized* → the sink refused → the **existing oversized-schema rejection path** is taken:
  the same `tracing::warn!(... "declared an oversized command schema; dropping it")` line and
  `command.schema = json!({})`.
- *unserializable* (any other serialization error) → a distinct branch that also stores
  `serde_json::json!({})` — the exact value the old `map_or(usize::MAX, …)` fallback produced
  (fail-closed).

**Behaviour notes:** a schema of exactly `MAX_COMMAND_SCHEMA_BYTES` is still kept (the sink
refuses only *past* the limit), and an oversized one is still dropped — so the retained-set
behaviour is unchanged. The only difference is the log's `bytes` value: the sink stops at the
limit, so it reports the bytes *observed before refusing* (a lower bound) rather than the exact
total. Noted in a code comment.

## F7 — B2-10: `deregister` returns the removed session

- **`src/cluster/registry.rs:332`** — `deregister` now returns `Option<NodeSession>` (the removed
  session) instead of `bool`, mirroring `forget`.
- **`src/gateway/server/connection/cleanup.rs:74`** — the disconnect path is now
  `if let Some(session) = ctx.node_registry.deregister(conn_id) { … }` and builds the

**Adjudicator risk note — addressed:** the event is published **exactly when a session was
actually removed** (`Some(session)`); when `deregister` returns `None` (another connection already
removed it) **nothing is published** and `touch_device` is not called — same as the old
`if deregister { … }` guard, but the identity now comes from the same critical section.

**`node_identity_by_conn` was NOT deleted.** It still has a live production caller at
`src/gateway/server/connection/mod.rs:322` (the anti-spoof identity stamp), plus test callers in
`registry.rs` and `src/gateway/server/handler.rs`. It is out of this batch's scope.

preserves the assertion's meaning exactly. This file was **not** in the "files you may touch"
list; the alternative was leaving the crate uncompilable.
