## Whole-turn acceptance / 整轮验收

Use [the fixture guide](../../../qa/nsh_voice/README.md) for paired browser tests with an isolated real Gateway and deterministic voice providers. The test input is synthetic. Browser audio-source start and natural end hooks prove decoded playback lifecycle, not sound from a speaker. Native verification separately requires the packaged app, granted microphone and speech permissions, supported locale assets, and a real playback/interrupt observation. / 配对浏览器测试使用隔离的真实 Gateway、确定性语音服务及合成输入。浏览器音频节点开始和自然结束只证明播放生命周期，不代表实体扬声器真实出声。原生验证另需正式打包架构、麦克风与识别授权、已安装语言资源及实际播放和打断证据。

**Final paired Web / 最终配对 Web：** Chrome 158 with the same-source Gateway and assets passed the positive smoke and all six matrix cases: exact 640,000-byte PCM limit, microphone denial, configured-only STT, in-flight STT cancellation, in-flight exact Chat cancellation, and disconnect without replay. The positive turn uploaded once, accepted one persisted Chat run, synthesized only its final reply, ended one nonempty Web Audio source naturally, and released capture on Stop after rearming. Voice displayed neither recognized nor reply text; ordinary Chat displayed its own reply. The cancellation case observed one `CANCELLED` after the exact abort, no successful terminal and no synthesis; it does not establish whether an external provider stopped computing. The limit case bypasses Chromium processing only for its stationary synthetic input, not in the product or comparator. / Chrome 158 用同源 Gateway 与资源通过正向冒烟和六个矩阵用例：恰好 640,000 字节 PCM 上限、麦克风拒权、Web 仅配置识别、在途识别取消、在途 Chat 精确取消、断线不重放。正向每轮只上传一次，接受一个持久化 Chat run，只合成最终回复；非空音源自然结束，重新监听后 Stop 释放采集。Voice 不显示转录或回复，普通 Chat 正常显示回复。取消用例在精确中止后只观察到一个 `CANCELLED`，无成功终态及合成；不证明外部服务已停止计算。仅时长夹具的固定合成信号绕过浏览器处理，产品及对照均不改设置。

**Native hardware attempt / 原生硬件尝试：** With authorization to request permissions, the same signed app received Start in the real Voice UI against an isolated Gateway with no configured STT. It never reached Listening. Core Audio enumerated two output devices and no input/default input. Before and after the attempt, read-only probes of the signed Bridge reported microphone and speech recognition ungranted. The fixture did not accept system dialogs, did not send any provider request, stopped its Gateway cleanly, and removed scratch data. Actual native capture, on-device transcription, audible playback and interruption remain unverified. / 获准发出授权请求后，同一签名包在真实 Voice 界面触发开始，隔离 Gateway 不配置 STT，但未进入监听。Core Audio 仅枚举到两个输出设备，没有输入或默认输入；尝试前后对签名 Bridge 的只读检查均显示麦克风和语音识别未获授权。夹具未替代用户确认系统弹窗，未发送任何服务请求；Gateway 正常退出并清除临时数据。原生实际录音、本机转录、出声和打断仍未验收。

## Performance and resource evidence / 性能和资源证据

The NSH topology sends at most one clip and one logical synthesis RPC per completed turn. The voiced clip cap is 20 seconds, 320,000 samples, or 640,044 canonical WAV bytes. Native capture keeps PCM out of the TSX bridge; Web owns an encoded upload. These are design limits, not measured copy counts, memory peaks, or latency gains. / NSH 完成一轮最多提交一个录音片段及一个逻辑合成 RPC；录音上限 20 秒、320,000 样本、640,044 标准 WAV 字节。原生 PCM 不穿过 TSX bridge，Web 则上传编码录音。这些是设计限制，不是实测复制次数、内存峰值或延迟收益。

All five fresh pairs per clip completed with four additional turns per mount in each pair: 5 cold and 20 warm observations per clip and mount, with no excluded pairs. Classic `/ws` is its nonstreaming STT plus terminal-tail synthesis path; paired TSX `/v1/ws` uses whole-turn Voice. Both mounts used the same final R8 build and harness. / 两种挂载同用 macOS 27.2.1 arm64、Chrome 158.0.8127.37、同一隔离 Gateway 程序、`en-US`、相同生成的短/长录音与确定性服务。每个长度五对新实例，每对每种挂载再采四轮，得到各 5 个冷样本及 20 个暖样本，无剔除。Classic 是 `/ws` 非流式识别与终态尾段合成，不是分句流式基线；配对 TSX `/v1/ws` 为整轮语音。两边使用同一份最终 R8 构建及夹具。
