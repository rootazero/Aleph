## 1. Executive Summary

Batch `ORCH_HARNESS_B` covers 17 files implementing the Orchestrator subsystem's harness bridge execution pipeline, system prompt assembly, ephemeral public-telecom isolation, deterministic session replay adapters, session seeding, and comprehensive unit tests.

The audited subsystem enforces core architectural invariants:
- **SSOT Event-Sourced Lifecycle**: Every run begins with a server-authored `SessionEvent::RunStarted` (stamped with the engine run ID and typed provenance) and terminates with `SessionEvent::RunFinished`.
- **Public Telecom Isolation**: Weak public SMS callers are strictly partitioned into ephemeral in-memory SQLite stores with `NullToolService` (or effect-free `request_private_lookup`), never touching owner transcripts, memory, or tools.
- **Fail-Closed Replay Authorization**: `ReplayAdapter` requires exact match across 7 eligibility gates (mounted handler, matching schema version, identical contract fingerprint, and non-empty effective input) before issuing single-use `ReplayPermit`s with sealed `ReplayAdmissionToken`s.
- **Per-Run Boundary Scope**: Counters (`iterations`, `tool_calls_made`, and `final_text`) are strictly scoped to events occurring after the current run's `RunStarted` marker to prevent cross-turn transcript leakage in reused sessions.

Static review across the 17 assigned files identified 22 candidate findings:
1. **Hot-Path Redundant Allocations (11 FIX-NOW candidates)**:
   - `last_user_query` unconditionally allocates a heap `String` on every turn (`s.clone()`, `prompt.clone()`, or `str::to_string()`), even though its only caller passes it directly as a borrowed `&str` to `build_system_prompt`.
   - In `runner_impl.rs`, `final_text` clones the full string payload of `content.text` or `content.thinking` on *every* intermediate assistant turn in the loop, only to overwrite it on the next turn.
   - At the completion of `runner_impl.rs::run()`, `serving_model: Some(gauge_model.clone())` and `serving_provider: Some(cost_provider.clone())` clone strings that are never accessed again in the function.
   - `session_id.to_key_string()` is called 6 separate times in `runner_impl.rs::run()`, re-formatting and allocating 6 identical heap strings per turn.
   - In `public_run.rs`, `run_isolated` clones `content.text` in the loop and then re-allocates a second string via `final_text.trim().to_string()`. Additionally, `let provider_name = llm.name().to_string()` is eagerly allocated on every public turn solely for an error logging branch.
   - Compile-time string constants in `public_run.rs` (`PUBLIC_SYSTEM_PROMPT`, `PUBLIC_LOOKUP_PROMPT_ADDENDUM`, `PRIVATE_DRAFT_PROMPT_ADDENDUM`) are concatenated at runtime using `format!`.
   - In `ReplayAdapter::prepare`, `req.effective_input.clone()` eagerly clones the entire `serde_json::Value` syntax tree before executing 7 early-return rejection gates.
   - In `session_seed.rs::seed_messages`, `origin.clone()` is cloned on the final message iteration where `origin` could be moved by value.
   - In `prompt_build.rs`, `build_agent_catalog` eagerly clones `a.id: String` for every plugin subagent even when already present in the map, `strands` allocates an intermediate `Vec<String>` before joining, and `merge_stable_memory_envelopes` reallocates via `format!` instead of reusing buffer capacity.
2. **Control Flow & Indirection (1 FIX-NOW candidate)**:
   - In `runner_impl.rs`, `SessionKey::from_key_string(&session_key)` is called twice on the identical string within 50 lines.
3. **Defensive Checks & Security Invariants (10 REJECT candidates)**:
   - Retaining path sanitization in `is_safe_agent_path_component` (path traversal and NTFS stream guard).
   - Retaining actor and token matching in `ReplayAdmissionToken::matches` (replay privilege escalation guard).
   - Retaining marker-anchored boundary slicing in `per_run_records` (session contamination guard).
   - Retaining prompt version verification in `check_version`.
   - Preserving test helper structures and wildcard imports in unit test modules.

## 3. Invariant Safety Pre-Flight

1. **State Machine & Execution Lifecycle Invariants**:
   - `FlowExecution` and `AgentHarness` transitions (`Init` → `Running` → `Completed`/`Failed`/`Cancelled`) remain strictly atomic.
   - Post-run settlement (`cb.on_complete_with_outcome`) continues to execute unconditionally before error propagation, ensuring the single-source terminal event is emitted on both successful and errored runs.
   - `CancellationToken` propagation is fully preserved across all joining branches and child task boundaries.

2. **Public API & Contract Stability**:
   - `HarnessRunner` trait methods and signatures (`run`, `run_public_text`, `run_private_draft`, `estimate_context`) remain completely unmodified.
   - `FlowOutcome`, `FlowStreamEvent`, and all `SessionEvent` variants (`RunStarted`, `RunFinished`, `UserMessage`, `AssistantMessage`, `SeedProvenance`) maintain identical fields, serialization tags, and wire formats.
   - `last_user_query` returning `&str` instead of `String` is an internal `pub(crate)` function whose only caller already consumes `&str`; all test assertions comparing with string literals (`assert_eq!(last_user_query(&input), "...")`) remain 100% compatible.

3. **Security, Sandbox & Replay Invariants**:
   - Path-traversal protection in `is_safe_agent_path_component` is preserved verbatim.
   - In `replay_adapter.rs`, the fail-closed sequence is preserved: `effective_input.is_none()` continues to refuse immediately (C4), followed by `stored_identity`, closed registry, missing entry, cold status, and contract fingerprint checks (C5/C6), preventing any unverified replay.
   - `ReplayAdmissionToken::matches` multi-attribute equality guarantees that replay tokens remain strictly bound to their original invocation context and caller identity.

4. **Performance & Allocation Impact**:
   - **Per-Turn Query Extraction**: Eliminates 1 heap `String` allocation per turn in `last_user_query`.
   - **Intermediate Assistant Messages**: Replaces multi-turn string cloning with a single terminal reference copy in `runner_impl.rs::run()`, eliminating N-1 string allocations in multi-turn runs.
   - **Terminal FlowOutcome Construction**: Moves `serving_model` and `serving_provider` by value, avoiding 2 heap string allocations at the end of every run.
   - **Session Key String Hoisting**: Reduces `session_id.to_key_string()` from 6 formatting passes down to 1 pre-computed string per run.
   - **Replay Preparation**: Prevents cloning `serde_json::Value` syntax trees when any of the 7 eligibility checks fail.
   - **Public & Ephemeral Runs**: Eliminates runtime `format!` overhead for static system prompts and replaces double-allocation in `run_isolated` final text extraction with a single post-loop allocation.
