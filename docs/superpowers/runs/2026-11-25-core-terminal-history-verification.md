# Core-side terminal history evidence / Core 侧终端历史证据

Linux x86_64, 2026-11-25. This is a run receipt for the core-side `pty.history` path on `main` at `d8af6c6f2`; it is not the terminal architecture reference. / 这是 `main`（`d8af6c6f2`）上 core 侧 `pty.history` 链路的验证回执，不是终端架构参考。

| Original failure / 原失败 | Repair / 修复 |
| --- | --- |
| `history_uses_live_capability_admission` compared the rendered tool error of a foreign-owner request against an absent-session request and found two different denial classes: `special capability resolution failed: NotVisible` against `special capability resolution failed: Unknown`. The only thing that separates the two is whether the guessed session id exists, so the refusal was an existence oracle for the sessions on the host. / 同一测试比较「非属主请求」与「不存在会话」两个渲染后的工具错误，得到两种拒绝类别；两者唯一差别就是被猜的 session id 是否真实存在，拒绝因此成了宿主机会话的存在性预言机。 | `src/capability/zahir_facade.rs`: `invoke_terminal_gateway` now folds `ResolveError::NotVisible` into `ResolveError::Unknown` for the caller, through the new `terminal_denial` helper. The resolve observation keeps the true variant for the audit trail; only the refusal the caller sees is folded. / `invoke_terminal_gateway` 现在通过新增的 `terminal_denial` 辅助把 `NotVisible` 折叠为 `Unknown`；解析观测仍记录真实变体供审计，只有调用方看到的拒绝被折叠。 |
| The same assertion compared whole error strings, but `src/security/content_sanitizer.rs` stamps a random boundary id (`rand::rng().random::<[u8;8]>()`) into `<<<EXTERNAL_UNTRUSTED_CONTENT id="...">`, so two refusals could never be equal even with an identical denial class. / 同一条断言比较的是整串错误，但 `content_sanitizer` 每次都会盖上随机的 boundary id，两次拒绝即使类别相同也永远不可能相等。 | `src/gateway/capability_terminal_tests.rs`: new `denial_payload` helper reads the text inside the external-content boundary, and the assertion compares those payloads after masking the target id. / 新增 `denial_payload` 辅助读取外部内容边界内的正文，断言在遮蔽目标 id 后比较这些正文。 |
| Six further tests failed in the same run with `driver join failed: task ... was cancelled` from the shared PTY driver: the first panic dropped the runtime that owned the driver task, `src/gateway/pty/manager.rs` treated the cancelled join as a failed stop and kept the handle, and every later test inherited the dead driver at its first `deactivate()`. / 同一轮里另有六个测试以 `driver join failed: task ... was cancelled` 失败：首个 panic 丢弃了持有 driver 任务的 runtime，`manager.rs` 把被取消的 join 判为停止失败并保留了 handle，之后每个测试都在首次 `deactivate()` 继承这个已死的 driver。 | No production change: the cascade was a consequence of the first failure, and it disappeared once the denial classes matched. / 未改动生产代码：级联是首个失败的连带结果，拒绝类别一致后即自行消失。 |
