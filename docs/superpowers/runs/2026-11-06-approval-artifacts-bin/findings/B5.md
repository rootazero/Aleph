### B5-001 [P1] Stop can SIGTERM/SIGKILL a recycled unrelated PID
- Location: src/bin/aleph-server/daemon.rs:162-195 (handle_stop)
- Failure mode: The server crashes or the machine reboots, leaving `.ipc-endpoint.json` with its old PID; the OS later reuses that PID for an unrelated process; `aleph-server stop` trusts the endpoint PID as authoritative and sends SIGTERM, then SIGKILL, to the unrelated process.
- Evidence: `let endpoint_pid = endpoint.as_ref().and_then(|ep| i32::try_from(ep.pid).ok());` followed by `let Some(pid) = endpoint_pid.or_else(|| read_pid_file(pid_file))` and `stop_running_process(pid)?`; the only validation is `is_process_running(pid)`, which checks liveness rather than process identity.
- Suggested fix: Before signaling an endpoint-derived PID, validate identity using an unforgeable process-start identity (for example, Linux `/proc/<pid>/stat` start time recorded in the endpoint) or require a live authenticated IPC handshake; preserve the existing PID-file fallback safety check and never treat a stale endpoint PID as sufficient proof.
- Confidence: 0.97
