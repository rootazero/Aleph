## Cross-transport semantic comparison

- Operator normal and channel fallback use `approval_timeout_for_current_turn()`: attended requests have no expiry and unattended requests use the bounded default. Operator single-use additionally applies an explicit caller deadline/cancellation token and denies on either.
- Node approvals always use `DEFAULT_APPROVAL_TIMEOUT_MS` (120 seconds); the node driver has no cancellation input and maps an unanswered request to `timeout`. Guardian judge calls have a 30-second provider deadline, after which they escalate to the human transport; the human transport's timeout then governs the final result.
- Operator and node fail closed on timeout (`Timeout`/denial), while an undeliverable operator request is `Unavailable`. The node requester diverges by accepting `publish_frame(Ok(0))`, producing a delayed timeout instead of immediate `Unavailable` (B3-002).
- The operator manager permits concurrent pending cards. Guardian's breaker intends one half-open probe, but its state transition does not reserve the probe (B3-001). Normal operator/channel waits have no explicit cancellation token; task cancellation drops the wait and exposes the no-expiry leak in B3-003. Node cancellation is represented only by its bounded timeout.
- No reviewed path converts an ordinary timeout into approval, and the operator single-use path additionally rejects a decision consumed at or after its deadline. The divergences above are delivery, cancellation-lifetime, and provider-concurrency semantics.

### B3-001 [P2] Half-open guardian breaker admits a provider stampede
- Location: `/home/zou/data/workspace/Aleph-wt-review/src/approval/guardian_requester.rs:96` (`GuardianBreaker::allows`, called by `GuardianApprovalRequester::breaker_allows`)
- Failure mode: After the breaker cooldown, one approval changes the state to `HalfOpen`; concurrent approvals observe the same state before the first judge call records its result, all call the provider, and a supposedly single recovery probe becomes an unbounded burst during an outage.
- Evidence: `BreakerState::Closed | BreakerState::HalfOpen => true`; `if cooled { self.state = BreakerState::HalfOpen; }`; `self.breaker.lock()...allows()` is released before `self.judge(action).await` at `/home/zou/data/workspace/Aleph-wt-review/src/approval/guardian_requester.rs:101-107,248-255`.
- Suggested fix: Atomically reserve the half-open probe (for example, transition to a distinct in-flight state or store a probe lease) before releasing the mutex; preserve concurrent calls in `Closed` and reopen/reset the reservation exactly once on the probe result.
- Confidence: 0.99

### B3-002 [P1] Node approval treats an undeliverable prompt as a live request
- Location: `/home/zou/data/workspace/Aleph-wt-review/src/approval/node_requester.rs:124` (`run_node_approval`)
- Failure mode: If the center has no event subscribers, or all subscribers have lagged out, `publish_frame` returns `Ok(0)`; the node path treats that as successful delivery, waits the full 120-second default, and returns `timeout` even though no operator could have answered. The node caller is unnecessarily parked and receives the wrong transport outcome (`timeout` instead of `unavailable`), unlike the operator requester.
- Evidence: `if let Err(e) = event_bus.publish_frame(&GatewayEventFrame::ApprovalRequested {` at `/home/zou/data/workspace/Aleph-wt-review/src/approval/node_requester.rs:124-132`; `let typed_count = ... 0`, `let str_count = ... 0`, and `Ok(typed_count.max(str_count))` at `/home/zou/data/workspace/Aleph-wt-review/src/gateway/event_bus.rs:450-484`; the next node step is `await_registered(...).await` at `/home/zou/data/workspace/Aleph-wt-review/src/approval/node_requester.rs:153-155`.
- Suggested fix: Treat `Ok(0)` exactly like `Err(_)`: remove/resolve only this pending registration as unavailable, preserve the node's fail-closed mapping, and keep the existing distinction between an unanswered delivered card (`timeout`) and a prompt that reached nobody (`unavailable`).

### B3-003 [P2] Aborting an attended approval defers zombie cleanup until a later registration
- Location: `/home/zou/data/workspace/Aleph-wt-review/src/approval/operator_requester.rs:477` (`OperatorApprovalRequester::request_approval`) and `/home/zou/data/workspace/Aleph-wt-review/src/approval/adapters.rs:199` (`ChannelApprovalBridgeAdapter::request_approval`)

The next `register_pending` sweep can remove it, but if no later approval is registered it remains as hidden map memory until process shutdown; repeated cancellations can accumulate stale entries during idle periods.
- Evidence: `let wait = self.manager.await_registered(...); ... None => wait.await` at `/home/zou/data/workspace/Aleph-wt-review/src/approval/operator_requester.rs:475-479`; `None = the no-expiry sentinel` followed by removal only after `rx.await` at `/home/zou/data/workspace/Aleph-wt-review/src/exec/manager.rs:590-612`; the no-expiry sweep retains only an open sender at `/home/zou/data/workspace/Aleph-wt-review/src/exec/manager.rs:1264-1269`, and the sweep is invoked only when a later registration begins at `/home/zou/data/workspace/Aleph-wt-review/src/exec/manager.rs:536-539`.
- Suggested fix: Give ordinary registrations a cancellation-safe generation guard whose `Drop` removes its matching entry even when the receiver is already closed; preserve resolved entries and avoid stamping Deny or cascading siblings during cancellation.

### B3-004 [P2] Fallback routing loses the operator fallback across channel teardown
