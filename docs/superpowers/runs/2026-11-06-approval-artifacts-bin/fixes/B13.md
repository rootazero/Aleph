# Fix report — B13 (aleph-migrate CLI)

## B13-01 [P1] Re-indexing an existing database retains sessions absent from the source
- verdict: fixed
- files: src/bin/aleph-migrate/index.rs:11-52
- change: `run_index` now builds the schema, sessions, attachments, and FTS data in a fresh temporary database beside the destination. It renames the completed database over the target only after all indexing succeeds, so rows absent from the current source cannot survive in the replacement.
- risk: Replacing the database changes its inode and temporary-file permissions rather than updating the original file in place; no public callers changed.

## B13-02 [P1] A mid-index error commits a partially updated target
- verdict: fixed
- files: src/bin/aleph-migrate/index.rs:23-48
- change: All index writes now go to the temporary database, whose owned temporary path cleans it up on early return. The old destination is not renamed over until session indexing, FTS construction, statistics collection, and connection shutdown have succeeded, preserving the previous database on errors.
- risk: The rename publishes a complete replacement but does not fsync the parent directory, so power-loss durability is not additionally guaranteed.

## B13-03 [P1] Removing a transcript leaves its old FTS content searchable
- verdict: fixed
- files: src/bin/aleph-migrate/index.rs:337-355
- change: The per-session `DELETE FROM session_transcripts_fts` now runs before the transcript existence check. A missing transcript therefore removes stale FTS rows and skips only the subsequent read and insert.
- risk: None beyond the intended deletion of stale FTS content; existing transcripts are still deleted and reinserted as before.

## B13-04 [P1] Attachment metadata lookup errors are exported as “no attachments”
- verdict: fixed
- files: src/bin/aleph-migrate/export.rs:263-271, src/bin/aleph-migrate/export.rs:339-349
- change: A parameterized `sqlite_master` query now verifies whether the attachments table or view exists before `PRAGMA table_info` runs. Only verified absence returns an empty list; schema-query and column-inspection failures propagate with context.
- risk: Databases with an attachments object only in a non-main schema are treated as absent, but this CLI opens one database and never attaches or creates auxiliary schemas.

## B13-05 [P1] Failed JSON serialization can destroy the previous export and leave a truncated artifact
- verdict: fixed
- files: src/bin/aleph-migrate/export.rs:211-227
- change: Export JSON is serialized to a unique sibling temporary file, flushed and synced, closed, and then renamed over the requested output. Temporary-path ownership removes incomplete files on serialization, write, flush, sync, or rename failure, leaving any prior export untouched until publication.
- risk: The temporary output uses the tempfile permission defaults, and directory-entry durability after a sudden power loss is not separately fsynced.

## B13-06 [P1] Overwrite failures corrupt previously transformed sessions
- verdict: fixed
- files: src/bin/aleph-migrate/transform.rs:107-170
- change: Each session is completely written in a temporary sibling directory before publication. New sessions are renamed into place only after success; overwrite moves the old session into a temporary backup first, restores it if publication fails, and retains the backup path if restoration itself fails.
- risk: Overwrite requires two renames, so a process crash between them can leave the destination temporarily absent and require recovery from the retained sibling backup.

## B13-07 [P1] A failed attachment write is later trusted as a complete deduplicated file
- verdict: fixed
- files: src/bin/aleph-migrate/transform.rs:337-433, src/bin/aleph-migrate/transform.rs:440-480
- change: New attachment bytes are written and synced in a temporary file in the target directory, read back to verify size and full SHA-256, and published with `persist_noclobber`. Existing or concurrently created deduplicated files must pass containment, size, and full-hash validation before a manifest references them; temporary files clean up on failure.
- risk: A pre-existing corrupt or hash-colliding attachment now fails transformation instead of being repaired automatically, which is intentional fail-closed behavior.

## B13-08 [P1] A valid relative output directory with no parent component is rejected
- verdict: fixed
- files: src/bin/aleph-migrate/transform.rs:25-27, src/bin/aleph-migrate/transform.rs:173-179
- change: Output and attachment paths are joined to `current_dir` when relative before deriving the migration root and performing containment checks. Bare paths such as `sessions` and relative `raw/sessions` layouts therefore retain the existing root rules without canonicalizing an empty parent.
- risk: Relative paths containing `..` remain subject to the existing lexical and canonical containment checks rather than being normalized away.

## B13-09 [P2] Out-of-range timestamps are silently replaced with the current time
- verdict: fixed
- files: src/bin/aleph-migrate/transform.rs:220-276, src/bin/aleph-migrate/transform.rs:483-488
- change: `format_timestamp` now returns an error when `DateTime::from_timestamp` rejects a value instead of substituting `Utc::now`. Session start, message, and tool-output call sites add session-specific context, and staging prevents the error from damaging an existing session.
- risk: Invalid timestamps now abort the affected session instead of producing a plausible but false date; only a private function signature changed.
