### B9-01 [P1] Swallowed `team_store` error in `task_review` inverts fail-closed into permission grant (Shape 8)
- Location: `src/builtin_tools/team/task_review.rs:216-224` (`TaskReviewTool::call`)
- Failure mode: When resolving the team leader for soft authorization, `self.team_store.get_team(team_id).await.ok().flatten()` turns any store/database error (e.g. SQLite busy or connection timeout) into `None`. Because `is_authorized(caller, leader)` evaluates `leader.is_none_or(|l| l == caller)` (line 134), a `None` leader evaluates to `true`. An unexpected store error bypasses the leader guard and allows any caller to approve or reject the task, directly violating Shape 8 ("fail-closed of the answer being consumed as value inverts into a permission").
- Evidence:
```rust
let leader = match task.team_id.as_deref() {
    Some(team_id) => self.team_store.get_team(team_id).await.ok().flatten().map(|t| t.leader_id),
    None => None,
};
```
- Suggested fix: Propagate the store error with `?` instead of swallowing via `.ok().flatten()`. If `get_team` fails, fail closed by returning the error:
```rust
let leader = match task.team_id.as_deref() {
    Some(team_id) => self.team_store.get_team(team_id).await?.map(|t| t.leader_id),
    None => None,
};
```
- Confidence: 0.95

    status: Some(CoordTaskStatus::Pending),
    ..Default::default()
