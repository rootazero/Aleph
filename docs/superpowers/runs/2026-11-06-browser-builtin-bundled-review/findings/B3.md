### B3-01 [P2] Direct indexing panic on malformed BoxModel border array in `rect_from`
- Location: `src/browser/page_state/fetch_obscura.rs:424` (`rect_from`)
- Failure mode: In `rect_from`, `model.border` (a `Vec<f64>` deserialized from CDP `DOM.getBoxModel`) is directly indexed through indices 0 to 7 (`q[0]` to `q[7]`) without first validating that `model.border.len() >= 8`. If the engine returns an empty or truncated quad (e.g. for an off-screen, detached, or display:none element where CDP yields an empty or partial border array), the direct indexing panics with `index out of bounds`. Because `rect_from` is executed inside a concurrent stream mapping over every element on the page (`buffer_unordered`), this panic aborts the collection task and causes the entire snapshot to fail.
- Evidence:
```rust
fn rect_from(model: &dom::BoxModel) -> Option<Rect> {
    let q = &model.border;
    let xs = [q[0], q[2], q[4], q[6]];
    let ys = [q[1], q[3], q[5], q[7]];
```
- Suggested fix: Check `if model.border.len() < 8 { return None; }` at the start of `rect_from`, matching the defensive length check in `fetch_chromium.rs:2337`.
- Confidence: 1.0

### B3-05 [P2] Unbounded synchronous file read on Tokio worker thread in `tail_of`
- Location: `src/browser/engine/obscura.rs:806` (`tail_of`)
- Failure mode: `tail_of` is called by `wait_for_endpoint` whenever obscura exits with an error status or reaches the 30-second readiness deadline. In this async function running directly on a Tokio worker thread, `std::fs::read_to_string(path)` synchronously reads the entire `serve.log` into memory. Obscura is verbose and writes logs for every script and event; if `serve.log` has accumulated significant output, reading the entire file synchronously blocks the Tokio worker thread and causes unnecessary memory allocation, only to extract the trailing 2000 bytes.
- Evidence:
```rust
fn tail_of(path: &Path, max: usize) -> String {
    let Ok(text) = std::fs::read_to_string(path) else {
        return format!("(no output captured at {})", path.display());
    };
```
- Suggested fix: Use `tokio::task::spawn_blocking` with `std::fs::File`, seek to `len.saturating_sub(max)`, and read only the requested tail bytes instead of loading the entire file into memory synchronously.
- Confidence: 0.95
