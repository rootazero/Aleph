## Window chrome feasibility / 无标题栏可行性

The desktop title bar can be removed independently of the shared Panel, but it is not a CSS-only change. On macOS, Tauri already overlays native traffic lights in the content area; NSH exposes different public frame and title-bar controls. Keep native controls where they can be overlaid, and make the Panel reserve space for the selected desktop chrome without altering Chat. On Windows and Linux, start with opaque windows and validate each host's supported decorations, drag and resize behavior before selecting a custom title bar. Do not export window commands to ordinary browser pages. / 可以在桌面壳隐藏独立标题栏，而不改共享 Panel；单靠 CSS 不行。macOS 优先保留覆盖在内容区的原生按钮，Panel 只按壳声明留位，不改 Chat。Windows 和 Linux 保持不透明，先验证各宿主的装饰、拖动与缩放能力，再选自定义标题栏方案。浏览器版不暴露桌面窗口命令。

Acceptance must cover drag regions that exclude interactive controls, keyboard and accessible window actions, resize and OS snap or tiling, G1 close-versus-quit semantics, and persistence across native reopen. No chrome change or cross-platform runtime claim is included in this candidate. / 验收须覆盖不吞控件点击的拖拽区、键盘与无障碍窗控、缩放与系统贴靠或平铺、G1 关窗与退出语义，以及重新打开时的状态恢复。本候选未改窗口装饰，也不宣称跨平台运行验证通过。
