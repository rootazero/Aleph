### E3-01 [P0] Explicit working directory defeats relative-script content binding / 显式工作目录绕过相对脚本内容绑定

- **Location**: `src/extension/hooks/executor.rs:253–256` (`command_hook_invocation`); `src/extension/hooks/executor.rs:850` (`execute_command_action`); `src/extension/hooks/consent.rs:650` (`approved_entry`), `src/extension/hooks/consent.rs:1344` (`candidate_path`)
- **Failure mode**: 已批准的命令为 `sh hooks/lint.sh`，审阅及指纹绑定的文件是插件根目录下的 `hooks/lint.sh`。通过公开的 `execute_interceptors` 入口传入一个 `working_dir` 不同于插件根目录的 `HookContext`，且该目录存在内容不同的 `hooks/lint.sh` → consent 仍校验插件根目录中未变的已批准文件，实际进程却在显式目录执行另一个脚本。命令模板、owner、scope 和批准文件指纹均不必改变，未审阅文件便获得执行许可。这里明确要求调用者设置受支持的 `working_dir`；`executor.rs:291–294` 说明当前生产 fire site 没有设置该字段，因此不声称默认生产路径已暴露此绕过。 / An explicit supported cwd override selects different executable bytes from those checked by consent; the default production cwd path is not implicated.
- **Evidence**:
  > `current_dir: context` — `src/extension/hooks/executor.rs:253`，随后依次取 `.working_dir.clone()`，最后才 fallback 到 plugin root（254–256）。
  > `let context = ScriptContext::new(plugin_name, bound_project(scope), Some(plugin_root));` — `src/extension/hooks/consent.rs:650`
  > `None => context.root.map(|root| root.join(token)),` — `src/extension/hooks/consent.rs:1344`
- **Suggested fix**: 在 command action 的授权/执行边界，对实际 cwd 与插件根目录不同、且 consent 会选择相对脚本的命令拒绝执行，并要求改用绝对路径或 `${CLAUDE_PLUGIN_ROOT}`。现有 `ShellHookConsent::unbindable_script_word` 已表达 inline 命令相同的拒绝规则，可复用其“第一个绑定脚本”判定，而非另造 shell parser。保持现有公开签名、同目录命令、显式 cwd 对其他命令的含义、scope/root/content 授权模型、Unix 数据环境变量及 Windows 命令派生不变；拒绝必须在 spawn 之前。代价是这种显式异目录调用需将相对脚本改为明确路径，不做隐式改 cwd。 / Reject the mismatched relative binding before the effect; preserve ordinary cwd and approval semantics.
- **Confidence**: 0.99

### E3-02 [P1] HTTP request failures bypass interceptor infrastructure-failure handling / HTTP 请求失败绕过 interceptor 的基础设施失败处理

- **Location**: `src/extension/hooks/executor.rs:1188–1193` (`execute_http_action`); `src/extension/hooks/executor.rs:1302–1314` (`execute_interceptors`)
- **Failure mode**: 一个已批准、已匹配的 HTTP interceptor 在 `BeforeToolCall` 请求策略服务时遇到 connection refused、DNS 错误或请求超时 → `req.send()` 的错误被包装成 `Ok(ActionResult { success: false, output: None, ... })`，而 interceptor 分支不检查 `success`，直接把空 body 作为成功传输后的决策解析。返回的 `HookResult` 既不 blocked，也不置 `action_failed`，工具因没有收到阻止决策而继续；服务暂时不可用因此改变了拦截结果。非 2xx 响应也经过相同分支，甚至错误 body 中的 `allow:` 会被当作有效决策。相比之下，响应读取失败、body 超限以及其他 `Err` 都进入 1342–1354 的 fail-closed 分支；`hooks/mod.rs:361–367` 也明确基础设施失败应阻止工具，并用 `action_failed` 让 stop gate 单独保持 fail-open。 / Request failure is treated as an empty successful decision rather than the existing infrastructure-error path.
- **Evidence**:
  > `Err(e) => Ok(ActionResult {` — `src/extension/hooks/executor.rs:1188`
  > `error: Some(format!("HTTP request failed: {e}")),` — `src/extension/hooks/executor.rs:1191`
  > `ar.output.as_deref().unwrap_or(""),` — `src/extension/hooks/executor.rs:1310`，传给 `derive_decision(None, ...)`，未检查 transport success。
- **Suggested fix**: 在 `execute_http_action` 将实际发送错误及非成功 HTTP 状态转换为现有 `ExtensionError::HookExecution`，带上请求/状态错误信息，交由现有 interceptor `Err` 分支统一设置 `blocked` 和 `action_failed`。保持未授权 HTTP action 的明确 skip 行为不变，不要笼统把所有 `success == false` 都改为 block；普通 command 的非 2 退出码同样继续保持既有 non-blocking 契约。成功 HTTP body 的解析、timeout/output cap、observer 错误隔离及 stop gate 依据 `action_failed` 的特殊失败策略均不变。 / Reuse the existing error channel, without changing deliberate consent skips or command exit-code semantics.
- **Confidence**: 1.0

### E3-03 [P2] Sanitized session-directory collisions reap another session's spill files / session 目录清洗碰撞会删除另一会话的输出

- **Location**: `src/extension/hooks/output_budget.rs:125–152` (`spill_dir`, `sanitize_segment`); `src/extension/hooks/output_budget.rs:192–217` (`prune_spill_dir`)
- **Failure mode**: 调用公开的 `budget_hook_contexts`，让 session `sess:s1` 产生一个 oversized context，再让另一个 session `sess_s1` 产生 32 个 spill → 两个原始 id 都清洗成同一个目录 `sess_s1`。清理代码只按目录枚举文件，不区分原始 session，因此第 33 个文件触发 pruning，删除第一个会话唯一的较早 spill，尽管该会话远未达到“每会话 32 文件”的上限。第一个会话已收到的 preview 仍指向该文件，随后无法恢复完整输出。这里是临时恢复材料的跨会话 retention 错误，不主张存在跨用户泄露或持久业务数据丢失。 / Distinct accepted session IDs share one retention bucket and invalidate a live recovery path belonging to another session.
- **Evidence**:
  > `Some(data.join(SPILL_DIR).join(sanitize_segment(session_id)))` — `src/extension/hooks/output_budget.rs:127`
  > `if c.is_ascii_alphanumeric() || c == '-' || c == '_' {` — `src/extension/hooks/output_budget.rs:140`，其余字符统一映射到 `_`（143）。
  > `for (_, path) in files.into_iter().take(excess) {` — `src/extension/hooks/output_budget.rs:211`，随后删除这些目录内文件。
- **Suggested fix**: 使用原始 session id 的稳定、文件名安全摘要作为目录身份（现有 sha2 即可），不要仅靠有损字符替换区分会话；若保留可读前缀，摘要仍须由未清洗的完整 id 派生。保持输出预算、短文本逐字节透传、UUID 文件名、每 session 32 文件上限、异步文件 I/O、错误时降级 preview 及 Windows 路径安全不变。无需新增映射状态或依赖；既有 preview 已携带完整旧路径，不需要为此次修复重写旧文件。 / Derive the portable bucket identity from the original ID, preserving the existing budget and retention policy.
- **Confidence**: 0.99
