### E6-01 [P0] 单点名称通过守卫，删除操作会清空整个 marketplace 缓存

- **Location**: `src/extension/marketplace/names.rs:27` (`reject_unsafe_segment`)
- **Failure mode**: 调用 `MarketplaceManager::remove(".")` → `removal_refusal` 接受该名称，即使根本没有这个 registration 也继续删除 → `cache_dir.join(".")` 指向缓存根，`remove_dir_all` 递归删除全部 marketplace 的内容，包括本应不可删除的 `aleph-official`。某些平台最终删除 `.` 本身会返回错误，但已经删除的子目录不会恢复。这不是 `../` 猜测，而是守卫明确接受的实际输入。
- **Evidence**: `names.rs:27`: `if value.is_empty() || value.contains('/') || value.contains('\\') || value.contains("..") {`；`marketplace/mod.rs:119`: `let cache = self.cache_dir.join(name);`；`marketplace/mod.rs:121`: `std::fs::remove_dir_all(&cache)`。
- **Suggested fix**: 在共享 `reject_unsafe_segment` 中同时拒绝 `value == "."`；该值不是契约所要求的直接子目录名。保留函数签名、既有错误类型和正常名称行为，并维持内置 marketplace 不可删除及删除不得越过单个缓存目录的约束。
- **Confidence**: 1.0

### E6-02 [P0] 目录摘要没有文件边界，不同可执行内容可以通过同一个 SHA-256 pin

- **Location**: `src/extension/marketplace/installer.rs:238` (`directory_digest`)
- **Failure mode**: 原始树包含 `main.py`（内容 `#`）、`payload.txt`（内容 `\nprint("injected")\n`）和一个不变的 `plugin.toml`；将 `payload.txt` 删除，并把 `main.py` 改为 `#payload.txt\nprint("injected")\n` → 两棵树排序后喂给 SHA-256 的字节流完全相同，但原先只含注释的入口现在执行注入代码。`verify_plugin_integrity` 因此接受改变后的代码；`install_to_scope` 和 `update_to_scope` 均调用该校验。无需破解 SHA-256。按源码编码规则进行的内存自检确认两树摘要同为 `ec2f5683f9f9bea8201e000f11fe967f821217cf7e862f6d0320a9cd318af633`；未运行 Rust 测试。
- **Evidence**: `installer.rs:239`: `hasher.update(portable.as_bytes());`；`installer.rs:240`: `let content = std::fs::read(entry.path())`；`installer.rs:242`: `hasher.update(&content);`。
- **Suggested fix**: 使用无歧义的文件记录编码，例如固定宽度的路径字节长度、路径字节、固定宽度的内容长度、内容，再计算摘要。保留公开函数签名、确定性排序、跨平台路径规则以及 `.git` / symlink 排除策略。摘要格式必须明确升级并重发既有 pin；不能用“新摘要失败后再接受旧摘要”的 fallback，否则绕过仍然存在。兼容旧的不安全摘要和修复此完整性边界不能同时保证。
- **Confidence**: 1.0

### E6-03 [P0] 中间路径 symlink 可以把 marketplace source 导向缓存外的宿主目录

- **Location**: `src/extension/marketplace/mod.rs:665` (`resolve_plugin_path`)
- **Failure mode**: marketplace 仓库含 `alias` symlink，指向 marketplace 外某个已存在插件目录的父目录，条目声明 `source = "./alias/existing-plugin"` 且不带可选 hash → 组件过滤认为路径安全。最终 `source_path` 的叶子 `existing-plugin` 是真实目录，因此 `copy_dir_recursive` 的 `symlink_metadata(src)` 检查也通过；中间的 `alias` 已被操作系统跟随。安装于是把缓存外插件及其附带文件复制到新安装中，越过“source 相对 marketplace 根”的边界。目标可选择一个已有合法 manifest 的插件，因而 manifest soundness 并不等同于目录归属校验；这也不是复制器已经跳过的叶子 symlink 情况。
- **Evidence**: `marketplace/mod.rs:667`: `.filter(|c| matches!(c, Component::Normal(_)))`；`marketplace/mod.rs:670`: `Some(marketplace_dir.join(safe))`；`installer.rs:254`: `let source_meta = std::fs::symlink_metadata(src)`。
- **Suggested fix**: 在 marketplace 路径解析/安装边界将 marketplace 根和 source 解析成 canonical 路径，并对 canonical source 执行 `starts_with(canonical_root)` 的组件级归属检查；解析失败或越界必须拒绝，不可把越界输入静默改写成另一个路径。保持公开 installer 的任意本地 source API、既有目标目录安全检查、manifest/hash gates 和正常仓库内路径行为；这不是要求禁止所有合法的仓库内 symlink。
- **Confidence**: 0.98

### E6-04 [P0] staging/backup 名称与允许安装的插件名称共用命名空间，清理会删除另一插件

### E6-05 [P1] 同名 marketplace 更换 source 后，update 仍从旧 Git origin 拉取
