### E4-01 [P0] Cursor 专用规则读取绕过插件根目录边界

- **Location**: `src/extension/manifest/adapters/cursor.rs:178` (`CursorAdapter::parse`)
- **Failure mode**: 加载一个包含 `.cursorrules` 符号链接的插件，链接指向插件根目录外、服务进程可读的敏感文本文件 → `read_to_string` 跟随链接，将该文件全文作为 `SkillRegistration.content` 放入返回的 capability。`.cursor/rules` 本身指向外部目录，或其下的 `.md` / `.mdc` 文件指向外部文件，也有相同效果。无需竞态或执行插件代码，即可越过其他组件解析器实施的文件读取边界；这里泄露的是能力内容本身，不依赖声称某个未检查的下游一定会发送它。
- **Evidence**: `180: if let Ok(content) = std::fs::read_to_string(&cursorrules_path) {`；`184: content,`；`201: if let Ok(content) = std::fs::read_to_string(&path) {`。
- **Suggested fix**: 在读取 `.cursorrules`、枚举 `.cursor/rules` 以及读取其每个规则文件前，复用现有 `parsers::is_path_inside(dir, target)`，失败则明确告警并跳过。该 helper 在 `src/extension/manifest/parsers.rs:1163` 对双方 canonicalize 后检查 containment，失败返回 false。保留根目录内文件及根目录内链接的导入、规则命名、capability 结构、排序和现有错误容忍方式；不引入第二套路径策略或权限表。
- **Confidence**: 0.99

### E4-02 [P1] 非 command hook 被按 shell command 注册

- **Location**: `src/extension/manifest/parsers.rs:860` (`parse_hooks_content`)
- **Failure mode**: 输入 `{"PreToolUse":[{"hooks":[{"type":"http","command":"echo wrong-action","url":"https://example.invalid"}]}]}` → `type` 虽被反序列化，却只用于告警文本；只要 `command` 非空就通过，最后生成 `HookAction::Command`。因此一个显式声明为不支持的 http/prompt/agent 类型的混合或畸形 action 被重新解释成 shell 执行，而不是按本文件声明的 command-only 策略跳过。这里不主张绕过后续 operator consent；缺陷是动作类型被错误改变。
- **Evidence**: `861: let Some(command) = a.command.as_ref().filter(|c| !c.is_empty()) else {`；`868: action = a.kind.as_deref().unwrap_or("(no type)"),`；`887: actions: vec![crate::extension::types::HookAction::Command {`。
- **Suggested fix**: 在检查 command 前，对显式存在且不等于 `"command"` 的 `a.kind` 告警并跳过；继续兼容未填写 type 的旧 command action。保留一条 action 对应一条 registration、独立 timeout、matcher、declared_event、plugin_root 和后续 consent，不扩展插件可执行动作种类。
- **Confidence**: 0.99

### E4-03 [P1] TOML 未知 runtime 静默降为 Static

- **Location**: `src/extension/manifest/cc_plugin_toml.rs:188` (`runtime_to_kind`, `runtime_to_aleph_runtime`, `parse_cc_plugin_toml_content`)
- **Failure mode**: `.claude-plugin/plugin.toml` 包含 `name = "example"` 和 `[aleph] runtime = "wasmm"` → 解析成功，`PluginManifest.kind` 和 `aleph_extensions.runtime` 都成为 Static，默认 entry 成为 `"."`，而不是确定性拒绝未知 runtime。WASM/MCP 插件的拼写错误因此变成“成功加载静态插件”，原运行时不再被选择。同等 JSON 声明会经 `AlephRuntime` 反序列化被拒绝（`src/extension/manifest/cc_plugin_json.rs:205`），TOML 的两个自由字符串映射制造了不一致的验证边界。
- **Evidence**: `193: _ => PluginKind::Static,`；`201: _ => AlephRuntime::Static,`；`251: let runtime_str = aleph.runtime.as_deref().unwrap_or("static");`。
- **Suggested fix**: 在 TOML 解析边界对显式 runtime 校验，只接受 `wasm` / `mcp` / `static`，其余通过现有 `ExtensionError::invalid_manifest` 返回包含被拒 runtime 的错误，然后才调用映射。保留三个合法值的映射、entry override、TOML 当前“未填写 runtime”默认值、权限转换及所有公共类型/签名；不要顺便改变 JSON 的默认语义。
- **Confidence**: 0.99

### E4-04 [P1] 非法 prompt scope 被提升为 System

- **Location**: `src/extension/manifest/parsers.rs:984` (`parse_v2_prompt`)
- **Failure mode**: 插件的 prompt 文件存在且位于根目录内，声明 `scope = "disabled "` 或其他未知字符串 → `PromptSection.scope` 是未经枚举限制的 String（`src/extension/manifest/toml_types.rs:176–183`），随后 fallback 把它变成 `PromptScope::System`，并成功返回含全文内容的 SkillRegistration。原本应被拒绝的禁用/工具限定 scope 拼写错误，实际成为系统级 prompt，而不是保持不生效；合法缺省 system 不需要这个未知值 fallback。
- **Evidence**: `988: "disabled" => PromptScope::Disabled,`；`989: _ => PromptScope::System,`；`996: scope,`。
- **Suggested fix**: 将未知 scope 分支改为返回具名错误，列出允许的四个值；继续由 `default_prompt_scope` 处理字段缺省。保留 `system` / `tool` / `standalone` / `disabled` 的现有映射、文件 containment、capability 内容和公开函数签名，不做静默 trim 或新增 scope。
- **Confidence**: 0.98

### E4-06 [P2] 空 hooks wrapper 错误回退到 bare event map

- **Location**: `src/extension/manifest/parsers.rs:824` (`parse_hooks_content`)
- **Failure mode**: 输入合法空配置 `{"hooks":{}}` → 首次反序列化得到空 `HooksFileConfig`，因 `!c.hooks.is_empty()` 不成立而回退；再次将整个对象反序列化为 `HashMap<String, Vec<HookMatcher>>`，其中 `hooks` 的值是对象而不是数组，因此返回类型错误，而不是 `Ok([])`。经 `src/extension/manifest/component_source.rs:114–121` 和 CC adapter 的 `?`，一个仅清空 hooks 的文件还会使带有其他有效组件的插件整体解析失败。
- **Evidence**: `825: Ok(c) if !c.hooks.is_empty() => c,`；`829: _ => HooksFileConfig {`；`830: hooks: serde_json::from_str(content)?,`。
- **Suggested fix**: 按是否存在顶层 `hooks` 字段选择 wrapped 或 bare 形状，而不是按解析后的 map 是否非空选择；存在 wrapper 时直接验证它的类型并接受空 map。不能只删掉 guard，因为 bare event map 会因 serde 忽略未知字段而被误判为空 wrapper。保留两种公开输入形状、合法事件/action 转换和 malformed 类型的错误传播，不引入宽松空值 fallback。
- **Confidence**: 1.0
