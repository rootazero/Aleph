- **Failure mode**: 已存在服务的 env 使用之前由本模块生成的稳定 secret ref，更新请求携带新凭据 → 先覆盖该 ref 对应的 vault 值。之后另一项 vault 写入失败、`remove_server` 失败，或者 `add_server(new_cfg)` 失败并成功恢复 `existing`，RPC 都会报失败，但旧配置引用的已是新凭据；最后一种情况还明确回报 “the previous configuration was restored”。因此失败更新实际改变了原服务的认证输入，恢复的不是之前的有效配置。
- **Evidence**: `let (env, writes) = plan_secret_env(&params.id, params.config.env, &existing.env);`；`if let Err(e) = vault.store_secret(name, value) {`；`let restore = mcp.add_server(existing).await;`
- **Suggested fix**: 写入前保存本次会覆盖的旧 vault 值；任一 vault/remove/add 失败时恢复已经覆盖的旧值，并如实报告恢复失败，只有整个更新成功才保留新值。不要通过单纯推迟写入、让新服务先读取旧凭据来交换错误。保留 blank-secret 表示不变、稳定 ref、remote 服务仅编辑 env、原有配置恢复及成功后的变更通知契约。
