### G2-01 [P0] Unreadable parent attribution becomes permission to register an unscoped child

- **Location**: `src/gateway/projection_reconciler.rs:476` (`ProjectionReconciler::persisted_attribution`; consumed by `heal_split_epochs` at line 409)
- **Failure mode**: Boot finds an unregistered forked epoch belonging to an attributed personal/project session, but `session_store.get_metadata(parent)` returns an error → `persisted_attribution` converts that error to `None`, and healing still calls `register_epoch` under an empty scope, counts the epoch as healed, and retires the superseded parent. The child therefore loses its owner's/scope's identity instead of deferring recovery. The downstream consequence is explicit in this file's lines 394–401: registration stamps the child from this scope, and resume reads the child's columns, so an unattributed child resumes unscoped and writes memory to the base partition. `visibility.rs:42–43` also adopts unattributed session ownership as `OWNER_USER_ID`; a member's recovered conversation is thus no longer attributed to that member. This is not the intentional pre-P1 legacy case: a failed read has not established that the parent was legacy.
- **Evidence**:
  > `src/gateway/projection_reconciler.rs:409`: `match crate::scope::with_scope(inherited, registrar.register_epoch(id)).await {`
  > `src/gateway/projection_reconciler.rs:481`: `"epoch heal: parent row unreadable; child registered without attribution"`
  > `src/gateway/projection_reconciler.rs:483`: `None`
- **Suggested fix**: Make the attribution read return `Result<Option<ScopeAttribution>, _>`. On a read error, increment the reconciliation error count and skip registration/retirement for that child; retry recovery on a later pass. Keep the existing successful legacy/no-attribution result distinct and unchanged. Preserve the persisted parent as the single attribution source, scope-before-registration ordering, register-before-retire ordering, and existing successful recovery behavior. Do not add a guessed owner or weaken visibility to compensate.
- **Confidence**: 0.99

### G2-02 [P2] Flush timeout excludes waiting for space in the bounded drain queue

- **Location**: `src/gateway/session_projector.rs:266` (`MessageProjector::flush`)
- **Failure mode**: The bounded projector queue is full while the single drain is stalled or slow in a store operation → `flush(timeout)` waits on `send(...).await` before starting its timeout. A caller supplying a shutdown deadline can therefore wait arbitrarily longer than that deadline, or indefinitely if the drain does not progress. The method's timeout currently bounds only the acknowledgement after the barrier has finally been enqueued, not the flush operation itself.
- **Evidence**:
  > `src/gateway/session_projector.rs:268`: `.send(ProjectorMsg::Flush(reply_tx))`
  > `src/gateway/session_projector.rs:269`: `.await`
  > `src/gateway/session_projector.rs:274`: `match tokio::time::timeout(timeout, reply_rx).await {`
- **Suggested fix**: Apply one timeout/deadline around both sending the barrier and awaiting its reply. Continue mapping send failure, dropped reply, and elapsed deadline to the existing `FlushTimeout`. Preserve FIFO barrier ordering, the single writer, the bounded queue, and the guarantee that `Ok(())` means all preceding events were processed; an elapsed deadline must not cancel the drain itself.
- **Confidence**: 1.0

### G2-03 [P2] Run-start cache retains every completed session for the drain's lifetime

- **Location**: `src/gateway/session_projector.rs:321` (`spawn_drain`; also populated by `heal_session` at line 489)
- **Failure mode**: A long-lived server processes runs on successively new user-created session keys → every `RunStarted` adds an owned `SessionId` to the drain's `run_start` map, but neither completed runs, flushes, nor repair passes remove entries. The map survives for the drain task's entire lifetime, so even fully completed/deleted conversations leave cache allocations behind. Memory consequently grows with the total distinct sessions ever processed, not the number of active runs; the bounded event channel does not bound this retained state.
- **Evidence**:
  > `src/gateway/session_projector.rs:321`: `let mut run_start: HashMap<SessionId, EventSeq> = HashMap::new();`
  > `src/gateway/session_projector.rs:326`: `run_start.insert(id.clone(), rec.seq);`
  > `src/gateway/session_projector.rs:334`: `run_start: run_start.get(&id).copied().unwrap_or(0),`
- **Suggested fix**: Bound this optimization cache and apply the same bound to live-drain and heal insertions. Eviction may use the already-supported missing-entry value `0`: `fold_run_bill` explicitly recovers the positional anchor from the event log in that case. This trades occasional longer log reads after eviction for bounded memory; retain that fallback rather than creating a second authoritative run registry. Preserve single-writer ownership, positional fold/stamp anchoring, retry behavior, and atomic stamp-and-bill idempotence. Do not remove an opener at `RunFinished` and assume the subsequent meta has already arrived.
- **Confidence**: 0.98
