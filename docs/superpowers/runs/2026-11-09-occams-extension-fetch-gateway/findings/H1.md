### H1-01 [P0] Concurrent hook mutations lose committed entries / 并发修改丢失 hooks

- **Location**: `src/gateway/handlers/hooks_admin.rs:213` (`append_user_hook`; also `remove_user_hooks` and `handle_hooks_remove`)
- **Failure mode**: 两个并发 RPC（或 RPC 与工具调用）在不同 runtime worker 上读取同一版 hooks，然后分别追加/删除并写回 → 后写入者覆盖前一个已提交的修改。即使两次 rename 不重叠、两个调用都成功，新增的 hook 仍会丢失；add/remove 交错还会复活已删除项。所有写入者另共用一个临时文件，写入重叠时还会互相截断临时内容或令另一方 rename 失败。这不是 atomic rename 能解决的 read-modify-write 原子性。
- **Evidence**: `let (path, _exists, mut events) = read_hooks_file()?;` (213); `write_hooks_file(&path, &events)?;` (232); `let tmp = path.with_extension("json.tmp");` (110).
- **Suggested fix**: 用同一个进程内 mutation guard 覆盖完整的 read-modify-write，在 append、共享 remove helper 和 RPC 按 index 删除三个入口都使用；只锁最终 write 不够。保留同目录 temp+rename、事件别名解析、hook 顺序、顶层字段保留、self-write 标记及成功后的 reload。不要新建第二份 hooks 状态源。该最小修复协调本进程的写入者，不声称协调外部编辑器。
- **Confidence**: 0.99

### H1-02 [P1] Hook RPCs perform blocking filesystem work on Tokio workers / 异步入口直接阻塞读写磁盘

- **Location**: `src/gateway/handlers/hooks_admin.rs:124` (`handle_hooks_list`; also `handle_hooks_add` and `handle_hooks_remove`)
- **Failure mode**: home 目录位于慢盘、网络挂载或发生磁盘延迟时，调用 hooks.list/add/remove → async handler 同步执行 read_to_string、write、rename 等系统调用，直到磁盘返回才释放 Tokio worker；并发调用可占满 worker，拖住无关 RPC、事件投递与定时任务。
- **Evidence**: `pub async fn handle_hooks_list(request: JsonRpcRequest) -> JsonRpcResponse {` (124); `match read_hooks_file() {` (125); `let raw = fs::read_to_string(&path).map_err(|e| format!("read {}: {e}", path.display()))?;` (73).
- **Suggested fix**: 保留现有同步文件 helper，在 RPC 面把完整读取或修改事务放进 `tokio::task::spawn_blocking`，显式处理 join 与文件错误。H1-01 的同步 mutation guard 应在 blocking closure 内持有，不跨 await。保留响应形状、原错误分类、原子替换及 reload 顺序；不要把每个 filesystem syscall 分拆成独立任务。
- **Confidence**: 1.0

### H1-07 [P2] Compression integers wrap during narrowing / 压缩参数整数截断

- **Location**: `src/gateway/handlers/memory_config.rs:392` (`apply_compression_update`)
- **Failure mode**: memory.config.update 传入 `compression.turn_threshold:4294967296` 或同值 background_interval_seconds → as_u64 成功，随后 `as u32` 把它变成 0，并保存成功。用户给出的阈值/间隔被替换成完全不同的值，而不是被识别为超出字段范围。
- **Evidence**: `if let Some(v) = comp.get("turn_threshold").and_then(|x| x.as_u64()) {` (392); `policy.turn_threshold = v as u32;` (393); `policy.background_interval_seconds = v as u32;` (399).
- **Suggested fix**: 两个字段都用 `u32::try_from` 做 checked conversion。按本 helper 已声明的“malformed fields remain untouched”契约，超范围值不修改旧值；若另行选择 INVALID_PARAMS，应显式统一该 API 的错误策略，不夹带在此局部修复里。保留所有合法 u32 值（包括当前允许的 0）及 partial-update 行为。
- **Confidence**: 1.0
