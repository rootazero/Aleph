## New problems

- `delivery.rs:819-822` — The diff introduces a duplicated `if !image_buf.is_empty() { flush_image_album(...); image_buf.clear(); }` block: the first one already clears the buffer, so the second `if !image_buf.is_empty()` immediately below is dead code. It is harmless but should be removed.
- `config_resolver.rs:42-46` — `assert!(lookup.insert(...).is_none(), "duplicate account id: {}", ...)` will panic in debug/test builds on duplicate account IDs. If duplicate IDs are a config-validation concern, this should be a graceful error rather than a panic; if duplicates are already rejected earlier, the assert is redundant.
- `mod.rs:898-901` — `self.config_resolver.resolve(&instance.account_id, chat_id_i64, thread_id).expect("selected instance has an effective config")` can still panic if the resolver state changes between instance selection and this call (e.g., hot-reload). A `let Some(config) = ... else { return ... }` would be safer.

## Batch verdict

Needs rework: IF1-06 is only partial (Core policy construction in `inbound_router` remains unchanged, so adapter/Core policy divergence persists), and the dead-code duplication in `delivery.rs` should be cleaned up before commit.
