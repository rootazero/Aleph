### E2-01 [P1] Manifest parse failure bypasses fail-closed settings validation
- VERDICT: UPHELD | ROUTE: FIX-NOW | claimed severity: P1
- **Location**: `src/extension/plugin_ops.rs:720` (`ExtensionManager::set_plugin_settings`)
- **Failure mode**: 已发现的插件声明了配置 schema，例如要求 `port` 为整数；其 manifest 随后损坏、被移走或变得不可读，操作方提交 `{"port":"invalid"}` → manifest 解析错误被 `if let Ok` 丢弃，当作“没有 schema”继续执行。该对象可转换为 TOML，因此会在第 752–763 行持久化并发布到 loader，方法还返回成功。恢复 manifest 后，这份未通过其 schema 的配置仍然存在。这里混淆了“成功解析且未声明 schema”和“无法确定 schema”，与该方法第 691 行声明的 fail-closed 契约相反。
- **Evidence**:
  > `if let Ok(manifest) =`  
  > `    crate::extension::manifest::parse_manifest_from_dir_cached_global(&root_dir)`  
  > `Ok(changed)`
- **Suggested fix**: 对已找到的插件目录显式传播 manifest 解析错误，转换为现有的 `Vec<String>` 错误返回；只有成功解析且 `config_schema` 为 `None` 时才跳过 schema 校验。错误时不修改配置、不发布 runtime settings。保留现有公共签名、未声明 schema 的兼容行为、JSON→TOML 校验，以及先持久化再发布的顺序；不增加 schema 缓存或第二份权威状态。
- **Confidence**: 0.99

### E2-02 [P2] Manual service control can overtake the mount's service disposer
- VERDICT: DOWNGRADE | ROUTE: FIX-CAREFULLY | claimed severity: P2
- **Location**: `src/extension/service_ops.rs:17` (`ExtensionManager::start_service`; same lifecycle serialization gap in `stop_service`)
- **Failure mode**: 一个手动 `start_service` 已取得 registration 并通过 `is_loaded` 检查，但尚未取得 service-manager 写锁；同时，挂载的 service disposer 执行第 120–121 行，停止服务并 `forget_plugin`，随后释放该锁 → 手动 start 接着取得写锁，并在 WASM 模块尚未被后续卸载步骤移除时调用原 start handler。服务于自己的清理步骤之后重新启动，重新写入已被清理的 service row，而该 mount 的一次性 service disposer 已经消费完，无法再停止它。`stop_service` 同样先捕获 registration 再等待锁，可能把旧挂载的 stop 请求送到同 id 的新挂载。service-manager 锁只序列化单次 start/stop，不序列化整个 mount/unmount/replacement。本文件第 60–65 行明确要求手动启动的服务也不能超出 mount 的寿命。
- **Evidence**:
  > `let service_manager = self.service_manager.clone().write_owned().await;`  
  > `let results = sm.stop_plugin_services(&plugin, &registrations, &ld);`  
  > `sm.forget_plugin(&plugin);`
- **Suggested fix**: 在两个公共手动入口 `start_service` / `stop_service` 的 registration 查找之前取得现有 `load_guard`，保持到阻塞任务完成，从而与生命周期控制使用同一个串行边界。不要在由 mount 内部调用的 `start_services_effect` 或其 disposer 中再次取得该锁。保留现有 service-manager→loader 锁顺序、`spawn_blocking` 执行、`ServiceInfo`/错误返回格式、自动启动语义与一次性 disposer 语义；不添加第二份挂载或服务所有权状态。
- **Confidence**: 0.96
