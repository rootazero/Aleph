### F1-02 [P1] Firecrawl ignores the configured timeout
- VERDICT: DOWNGRADE | ROUTE: FIX-NOW | claimed severity: P1
- **Location**: `src/fetch/providers/firecrawl.rs:68-94` (`FirecrawlFetchProvider::new`)
- **Failure mode**: An operator configures a fetch backend timeout different from the HTTP client's default → this constructor accepts only `base_url` and `api_key` and always calls the no-argument `build_client()`, so Firecrawl requests use the builder default rather than the configured timeout.
- **Evidence**: `pub fn new(base_url: impl Into<String>, api_key: impl Into<String>) -> Result<Self> {`; `client: build_client()?`
- **Suggested fix**: Thread the backend timeout through the constructor and into the existing client builder's timeout configuration, updating the sole construction path. Preserve the current client, bearer-auth, response-size cap, and timeout-to-error mapping semantics.
- **Confidence**: 0.92

### F1-03 [P1] Firecrawl endpoint construction appends the path after query/fragment data
- VERDICT: DOWNGRADE | ROUTE: FIX-NOW | claimed severity: P1
- **Location**: `src/fetch/providers/firecrawl.rs:112-115` (`FirecrawlFetchProvider::fetch`)
- **Failure mode**: Configure a base URL such as `https://firecrawl.example/api?tenant=a` (or one with a fragment) → `format!("{}/v2/scrape", self.base_url)` produces a URL whose query/fragment consumes the appended text, so the request is sent to the wrong endpoint instead of `/api/v2/scrape`.
- **Evidence**: `self.client`; `.post(format!("{}/v2/scrape", self.base_url))`
- **Suggested fix**: Append `v2/scrape` to the parsed URL's path component (or construct and store the endpoint URL once during `new`) rather than concatenating strings. Preserve the existing base path and all request authentication/body behavior.
- **Confidence**: 0.98

### F1-05 [P2] Crawl4ai collapses timeout and transport failures into provider errors
- VERDICT: DOWNGRADE | ROUTE: FIX-CAREFULLY | claimed severity: P1
- **Location**: `src/fetch/providers/crawl4ai.rs:34-43` (`Crawl4aiFetchProvider::fetch`)
- **Failure mode**: The configured crawl4ai request times out or loses its transport connection → every inner failure is mapped to `AlephError::provider`, so callers cannot receive the network/timeout variant used to distinguish transport failures from upstream provider failures.
- **Evidence**: `self.inner`; `.fetch_markdown(url)`; `.map_err(|e| AlephError::provider(format!("crawl4ai: {e}")))`
- **Suggested fix**: Preserve provider errors for actual upstream responses but classify the backend's timeout and transport cases as the established `AlephError::network` variant, retaining redaction and the `crawl4ai:` context. Preserve the configured timeout and fail-closed error propagation.
- **Confidence**: 0.84
