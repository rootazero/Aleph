## New problems

- `src/gateway/interfaces/nostr/message_ops/ops.rs:192` — Diff line `"Nostr: unrecognized relay message: {}"` lost its closing quote and comma before the next argument (`text.get(..100)...`), which is a syntax error: `tracing::debug!("... {}" text.get(..100).unwrap_or(&text));`. This will not compile.
- `src/gateway/interfaces/nostr/message_ops/protocol.rs:68` — `build_dm` was replaced with an unconditional `panic!("DM encryption not yet implemented; plaintext DMs are not supported for security reasons")`. This changes observable behaviour (any DM send now panics instead of returning an unsigned kind-4 event) and is unrelated to any listed finding.
- `src/gateway/interfaces/qq/mod.rs:66` — `QQChannel::capabilities()` now reports `attachments: false, images: false` (previously `true`). No finding asked for a capability change; this silently drops support the channel previously advertised.
- `src/gateway/interfaces/wechat/mod.rs:63` — `WeChatChannel::capabilities()` reports `attachments/images/audio/video: false` (previously all `true`). Same concern: unrequested behaviour change.
- `src/gateway/interfaces/wechat/outbound/markdown.rs:13` — `result = truncate(&result);` was deleted from `markdown_to_wechat`. No finding named this; removing truncation changes output length behaviour.
- `src/gateway/interfaces/wechat/inbound/mapper.rs:94` — `guess_chat_type` no longer treats `to_user_id == account_id && msg_type == 1` as a group; only `has_room` selects group. This is an unrequested semantic change to chat-type detection.
- `src/gateway/interfaces/wechat/api.rs:190` — `send_message`/`send_typing` now parse the response body as `GetUpdatesResponse` and return `Err` on non-zero `ret`. That is a behavioural change not tied to any IF5 finding (and reusing the *updates* response type for a send call is suspicious).
- `src/gateway/interfaces/slack/message_ops/socket.rs:128` — The events_api ACK block was *moved* into `acknowledge_envelope` (good), but the new helper is fine; no issue here beyond noting the change is larger than the finding required.
- `src/gateway/interfaces/slack/message_ops/debouncer.rs:47` — New `MAX_MESSAGES`/`MAX_BYTES`/`MAX_RESIDENCE_MS` flush-on-overflow logic is added. Not requested by IF5-17; it changes debounce semantics (forces a flush mid-window) beyond the finding's drain-on-shutdown scope.
- `src/gateway/interfaces/nostr/config.rs:14`, `src/gateway/interfaces/qq/config.rs:4`, `src/gateway/interfaces/slack/config.rs:16`, `src/gateway/interfaces/wechat/config.rs:36` — `Debug` derive removed from several config structs. This is a breaking change for any code that relied on `{:?}` formatting of these configs (e.g. logging startup config), not requested by any IF5 finding.

## Batch verdict

Needs rework: the four target findings (IF5-01/05/06/17) and all four new-problem items are substantively addressed, but the diff introduces an outright syntax error in `ops.rs` (unterminated format string) that will not compile, replaces `build_dm` with an unconditional `panic!`, and makes multiple unrequested capability/behaviour changes (QQ/WeChat capability flags, WeChat markdown truncation, WeChat chat-type detection, WeChat send response handling, debouncer overflow flush, removal of `Debug` on several configs). The syntax error and the `build_dm` panic must be reverted/fixed before this is safe to commit.
