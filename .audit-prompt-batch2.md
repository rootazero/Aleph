## What to look for (the 5 phases)

### Phase 1 — Seam scan
1. **Registration parity** — every `const NAME = "x"` (e.g. `AcpAdapterEntry::all_presets()`).
2. **Config-reader parity** — every config field type (e.g. `[providers]`, `[agents]`,
   `[tools]`, `[generation]`, `[policies]`, `[dispatcher]`, `[memory]`, `[voice]`,
   `[routing]`, `[route]`, `[privacy]`, `[secrets]`, `[security]`, `[skills]`) and every
   non-test read of that field.
3. **Stub sweep** — `// TODO`, `unimplemented!`, `todo!`, empty match arms.
4. **Field tables** — e.g. `&[("field", default_fn)]` — every field named must have a consumer.

### Phase 2 — Enumerate candidates
For each field/registration, list **file:line for both ends** (producer and consumer).

### Phase 3 — Triage (read-first)
For each candidate, **grep the consumer side for a live reader** before deciding CONNECT/CUT/DECIDE.

### Phase 4 — Fix recommendations
For each finding, state:
- **file:line** of the producer
- **file:line** of the consumer (or "no consumer")
- **severity** (CRITICAL/HIGH/MEDIUM/LOW)
- **triage** (CONNECT / CUT / DECIDE)
- **reason** (one sentence)
- **proposed fix** (one or two lines)

### Phase 5 — Guard recommendation
If a `[policies.*]` field is inert but has a hardcoded default fallback, suggest CONNECT.
If a `[policies.*]` field is inert with no consumer, suggest CUT.
